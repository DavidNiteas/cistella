# 01. 目标与设计：免安装发布与 portable 体验

## 1. 工单目标

把 cistella 从「开发态可运行」推进到「用户态可交付」，完成「复制即走、随时打开」的最终产品体验。

本工单解决：
- 用户无需安装即可运行 cistella。
- 用户可以把整个应用目录复制到 U 盘、另一台电脑或云同步目录，打开即用。
- 应用运行数据与 Vault 数据边界清晰，便于备份、迁移和恢复。
- 提供从安装模式到 portable 模式（或反向）的迁移路径。

## 2. 北极星

用户下载一个压缩包、解压到任意位置、双击即可打开 cistella；用户可以把整个目录复制走，再次双击，最近打开的库、设置、偏好都还在；用户也可以安装到系统，使用标准应用数据目录。

## 3. 范围边界

### 本工单包含

- portable 模式检测与运行时数据目录切换。
- 最近库列表、应用配置的持久化位置抽象。
- portable 模式下的数据隔离与迁移支持。
- Tauri 打包配置：生成安装包与 portable 压缩包两种产物。
- 备份/恢复向导的 Core 与 Tauri 接口。
- 为 M2/M3 预留更复杂的单文件 exe、自动更新、离线安装包等扩展点。

### 本工单明确不做

- M1 不做自动更新。
- M1 不做单文件 exe（把所有内容打包进一个可执行文件）。
- M1 不做数字签名、应用商店发布、安装包美化。
- M1 不做云端同步或协作。
- M1 不改动 Vault 内部文件格式（只改变 Vault 数据在外部的存放位置）。
- M1 不替代 Source 分析工作区或修改其数据布局。

## 4. 固定决议

### 4.1 A 层方向（已拍板）

- 工单 14 目标：完成 cistella「免安装发布与 portable 体验」，让产品达到可交付状态。
- 范围边界：M1 只做 portable 模式检测、数据目录切换、最近库/配置持久化与迁移接口；M2/M3 做打包产物、备份恢复向导、可选自动更新。
- 核心原则不变：库即一切、复制即走、打开即用、本地优先。

### 4.2 B 层设计（已拍板）

- portable 模式判定：
  - 检测可执行文件所在目录是否存在 `cistella-portable/` 目录（空目录即可）。
  - 存在则启用 portable 模式；否则使用系统标准应用数据目录。
- 数据目录抽象：
  - `AppDirectories` 结构，提供 `config_dir()`、`recent_vaults_path()`、`cache_dir()` 等方法。
  - portable 模式下：`<exe-dir>/cistella-portable/config/`、`<exe-dir>/cistella-portable/recent.json`。
  - 安装模式下：系统标准目录（Windows 为 `%LOCALAPPDATA%/cistella/`）。
- 最近库列表：
  - 统一用 `recent_vaults.json` 保存最近打开的 Vault 路径列表。
  - portable 模式下存储相对路径（相对于 `cistella-portable/` 目录），以便复制后仍有效。
  - 安装模式下可存储绝对路径。
- 配置外置：
  - 应用配置（主题、窗口大小、语言等）写入 `config/app.json`。
  - 不写入注册表。
- 迁移接口：
  - `migrate_to_portable(vault_paths)`：将指定 Vault 复制/链接到 portable 目录，并生成 `recent_vaults.json`。
  - `migrate_to_installed(vault_paths)`：反向迁移。
- 打包产物：
  - 安装包（Tauri msi/nsis）。
  - portable zip（包含 exe + `cistella-portable/` 空目录 + 使用说明）。

### 4.3 C 层默认（已拍板）

- portable 标志目录名：`cistella-portable/`。
- 配置目录结构：
  ```
  <portable-root>/
    config/
      app.json
    recent_vaults.json
    cache/           # M2 考虑
  ```
- 最近库 JSON 字段：`vaults: [{ path: String, name: String, opened_at: Option<String> }]`。
- Tauri 命令命名：
  - `app_directories`：返回当前 config_dir / recent_vaults_path。
  - `recent_vaults`：读取最近库列表。
  - `update_recent_vaults`：更新最近库列表。
  - `is_portable_mode`：返回是否处于 portable 模式。
  - `migrate_vaults_to_portable` / `migrate_vaults_to_installed`：迁移（M1 仅 Core 接口 + Tauri 透传，UI 可用命令行/基础按钮）。
- UI 入口：首页/设置页显示当前模式，并提供最近库列表管理。
- 测试：使用临时目录构造 portable/installed 环境，验证目录切换、最近库持久化、相对路径解析。

## 5. 身份、不变量与权威边界

### 5.1 条目标识

- Vault 内部标识（`item_id`、笔记 ID、批次 ID 等）不受 portable/installed 模式影响。
- Vault 路径在不同模式下可以改变，但 Vault 内部数据权威不变。

### 5.2 权威边界

- Vault 内部数据权威在 Vault 目录内。
- 最近库列表权威在 `recent_vaults.json`。
- 应用配置权威在 `config/app.json`。
- portable 模式启用后，上述文件必须位于 `cistella-portable/` 下。

### 5.3 不变量

- 检测到 portable 标志后，所有应用数据写入 portable 目录，不得泄漏到系统标准目录。
- 未检测到 portable 标志时，所有应用数据写入系统标准目录，不得写入 exe 所在目录。
- `recent_vaults.json` 中 portable 模式使用相对路径，安装模式可使用绝对路径。
- 切换模式（迁移）时，原 Vault 数据必须完整保留，迁移失败不得破坏原数据。
- 打包产物必须包含清晰的 portable 使用说明（如 `README-portable.txt`）。

## 6. 文件布局与模块边界

### 6.1 应用数据布局

#### portable 模式

```
<cistella-portable>/
  config/
    app.json
  recent_vaults.json
  cache/          # M2 考虑
```

#### 安装模式

```
%LOCALAPPDATA%/cistella/          # Windows
~/Library/Application Support/cistella/  # macOS（M2 考虑）
~/.config/cistella/               # Linux（M2 考虑）
  config/
    app.json
  recent_vaults.json
  cache/
```

### 6.2 Core 新增模块（建议落位）

- `cistella-core/src/app_dirs.rs`：
  - `AppDirectories` 结构体。
  - `is_portable_mode(exe_dir)`。
  - `app_directories(exe_dir)`。
  - `recent_vaults()` / `save_recent_vaults()`。
- `cistella-core/src/migration.rs`（或合入 `app_dirs.rs`）：
  - `migrate_vaults_to_portable`。
  - `migrate_vaults_to_installed`。

### 6.3 与现有模块的关系

- 不修改 `Vault` 内部接口；只改变打开 Vault 时使用的路径来源。
- 不修改 Source 分析工作区相关模块。
- 最近库列表由桌面壳层使用，Core 提供读写 API。

## 7. Core / Tauri / UI 边界

### 7.1 Core 层

- 提供纯 Rust API：
  - `AppDirectories::from_exe_dir(exe_dir)`
  - `AppDirectories::config_dir()`
  - `AppDirectories::recent_vaults_path()`
  - `load_recent_vaults(path)` / `save_recent_vaults(path, list)`
  - `migrate_vaults_to_portable(...)` / `migrate_vaults_to_installed(...)`
- Core 不依赖 Tauri、UI。
- Core 负责路径解析、JSON 序列化、文件原子写入。

### 7.2 Tauri 层

- 新增命令：
  - `app_directories`
  - `recent_vaults`
  - `update_recent_vaults`
  - `is_portable_mode`
  - `migrate_vaults_to_portable`
  - `migrate_vaults_to_installed`
- Tauri 层只做参数透传、错误映射。

### 7.3 UI 层

- 首页显示当前模式（portable / installed）。
- 设置页提供迁移入口（M1 可为基础按钮）。
- 最近库列表从 Core 读取并展示。

## 8. 成功标准

- 在 portable 目录旁存在 `cistella-portable/` 时，应用数据写入该目录。
- 复制整个目录到另一位置后，最近库列表和配置仍然有效。
- 安装模式下应用数据写入系统标准目录，不影响 exe 所在目录。
- 迁移操作不丢失 Vault 数据。
- Tauri 能生成安装包与 portable zip 两种产物。
- Source 分析工作区与 Vault 内部数据不受影响。
