## 设计输入与决议登记

本工单设计基于经理于 2026-08-28 的立项决策，A/B/C 三层决议已写入 `01-目标与设计.md`，核心摘要如下：

### A 层方向

- 工单 14 目标：完成 cistella「免安装发布与 portable 体验」，让产品达到可交付状态。
- 范围边界：M1 只做 portable 模式检测、数据目录切换、最近库/配置持久化与迁移接口；M2/M3 做打包产物、备份恢复向导、可选自动更新。
- 核心原则不变：库即一切、复制即走、打开即用、本地优先。

### B 层设计

- portable 模式判定：检测 exe 所在目录是否存在 `cistella-portable/` 目录。
- 数据目录抽象：`AppDirectories` 结构体，区分 portable/installed 两种模式。
- 最近库列表：`recent_vaults.json`，portable 模式下使用相对路径。
- 配置外置：`config/app.json`，不写入注册表。
- 迁移接口：`migrate_vaults_to_portable` / `migrate_vaults_to_installed`。
- 打包产物：安装包（msi/nsis）与 portable zip。

### C 层默认

- portable 标志目录名：`cistella-portable/`。
- 最近库 JSON 字段：`vaults: [{ path, name, opened_at }]`。
- Tauri 命令：`app_directories`、`recent_vaults`、`update_recent_vaults`、`is_portable_mode`、迁移命令。
- UI 入口：首页/设置页显示模式与最近库列表。
- 测试：临时目录构造 portable/installed 环境，验证切换、持久化、相对路径、迁移回滚。
