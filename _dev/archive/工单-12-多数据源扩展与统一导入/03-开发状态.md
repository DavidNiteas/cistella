## 设计输入与决议登记

本工单设计基于经理于 2026-08-27 的立项决策，A/B/C 三层决议已写入 `01-目标与设计.md`，核心摘要如下：

### A 层方向

- 工单 12 目标：把 cistella 从单一 OpenAlex 导入扩展为多数据源个人文献库导入，建立统一内部条目模型与可解释的导入/补全/冲突处理。
- 范围边界：M1 只做离线 BibTeX 文件导入到个人库；RIS、DOI 网络补全、OpenAlex works 导入延后到 M2/M3。
- Source 分析工作区保持独立：BibTeX/RIS 导入产生的记录不进入 Source 分析表；Source 分析工作区继续只服务 OpenAlex sources 数据。

### B 层设计

- 统一内部模型：复用并扩展 `LiteratureItem`，新增 `ExternalIdentifier { namespace, value }` 字段列表（如 DOI/ISBN/PMID/OpenAlex ID）。
- 分层适配器：
  - `RecordSource` trait：解析外部输入为原始 `SourceRecord`；M1 实现 `BibTeXRecordSource`。
  - `LibraryImporter`：负责预览、冲突检测、归一化、提交；M1 实现 BibTeX 导入器。
- 来源身份持久化：新增 `user/sources/<batch_id>.json`（M1 简单方案），保存原始 `SourceRecord` 与批次元数据。
- 冲突策略：`merge`（默认，追加 SourceRef 并补空字段）、`skip`、`create`。
- 可回滚：预览-提交两段式；提交失败时恢复 `user/sources/` 原始状态；`literature_items.json` 通过现有原子替换更新。
- 依赖：M1 原设计引入 `biblatex` crate 解析 .bib 文件；实施时因环境无法访问 crates.io，改为自研最小 BibTeX 解析器（偏离申请见 `04-施工日志.md`）。

### C 层默认

- `SourceRecord` 用结构化字段 + 原始字段映射。
- `BibTeXRecordSource` 使用自研解析器，支持 `@type{key, field = {value}, ...}` 与嵌套花括号。
- 批次 ID 用 UUID；文件名 `<batch_id>.json`。
- Tauri 命令命名：`inspect_literature_import`、`import_literature_file`。
- UI 入口放在 Reading 工作区「导入文献」按钮。
