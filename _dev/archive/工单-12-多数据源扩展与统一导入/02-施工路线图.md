## M3：OpenAlex works 本地导入与 DOI 补全接口

### M3 交付物

- 实现 `OpenAlexWorksRecordSource`：读取本地 `openalex-sources/` 目录中已下载的 works 分区（`updated_date=YYYY-MM-DD/work/*.gz`），将 OpenAlex works JSON 解析为 `SourceRecord`。
- 新增 `openalex_works_importer.rs`（或复用通用导入器），允许用户选择 OpenAlex works 记录导入个人库。
- DOI 补全抽象接口：`DoiResolver` trait，M3 提供基于本地 OpenAlex 数据的 `LocalOpenAlexDoiResolver` 实现（通过扫描本地 works 分区建立 DOI → work 内存索引），网络实现明确延后。

- 批次文件继续使用 `user/sources/<batch_id>.json`，来源命名空间固定为 `openalex`。

## 共同约束

- 所有新格式导入器必须实现 `RecordSource` 与 `LibraryImporter` 接口，不绕过统一内部模型。
- 所有批次文件写入必须原子替换；失败时保留原文件。
- 所有导入不得修改 Source 分析表、manifest tables、`openalex-sources/` 原始数据。
- 冲突处理不得覆盖用户已编辑字段；`merge` 仅补空字段。
- 新增依赖必须写入对应 crate 的 `Cargo.toml`，并在施工日志中登记。
- 测试必须覆盖空库导入、重复导入、冲突选择、提交失败回滚、非法/损坏输入。

## M1 自研 BibTeX 解析器能力边界

M1 因环境无法访问 crates.io，未引入 `biblatex` crate，改为自研最小 BibTeX 解析器，当前能力边界如下：

- 支持 `@type{key, field = {value}/"value", ...}` 基本格式与嵌套花括号。
- 支持跳过注释与空白。
- 不支持 `@string` 宏展开、跨行字段拼接、非标准引号组合、复杂的 LaTeX 转义序列。
- 解析失败时统一返回结构化错误 `invalid literature import`，并在错误消息中包含具体失败位置。

## M2 自研 RIS 解析器能力边界

M2 沿用自研最小 RIS 解析器，当前能力边界如下：

- 支持 `TY  - ...` 标签块与常见学术标签（`TI`、`AU`、`PY`、`DO`、`SN`、`IS`、`VL`、`SP`、`EP`、`AB`、`KW`、`ER` 等）。
- 支持标签续行（非标签开头的行追加到上一个字段）。
- 支持 `SN` 按条目类型区分：期刊类（`JOUR`/`CONF` 等）映射为 `issn`，书籍/章节类（`BOOK`/`CHAP` 等）映射为 `isbn`。
- `IS` 识别为期号（Issue number），不进入 `issn` 命名空间。
- 不支持完整的 RIS 标准标签全集、连接符宏、编码转换、作者拆分规则（如 `Last, First` 自动拆分）、复杂的日期格式。

## M3 OpenAlex works 解析器能力边界

- 支持本地 `.jsonl` 与 `.jsonl.gz` works 文件（依赖 `flate2`）。
- 支持单条 JSON 对象、JSON 数组或 JSONL。
- 字段映射覆盖 `id`、`doi`、`title`、`publication_year`、`type`、`authorships`、ISSN（`host_venue` / `primary_location.source`）、`biblio`、关键词与 `abstract_inverted_index` 反转。
- 不处理作者机构消歧、引文网络、实时 OpenAlex API 或外部 HTTP 调用。
- 损坏/非法 JSON 返回结构化错误 `invalid literature import`。
