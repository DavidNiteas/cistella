# 01. 目标与设计：多数据源扩展与统一导入

## 1. 工单目标

把 cistella 从单一 OpenAlex sources 导入扩展为多数据源个人文献库导入，建立统一内部条目模型、可解释的导入/补全/冲突处理，以及来源身份的持久化追溯。

本工单为后续 Reading、笔记、标注与检索提供“个人库”层的数据来源基础，同时保持 Source 分析工作区对 OpenAlex sources 数据的独立服务。

## 2. 北极星

用户能够把来自不同来源（BibTeX、RIS、DOI、OpenAlex works 等）的文献记录统一收进自己的 Vault，形成一份可维护、可追溯、可冲突处理的用户文献资产；cistella 不绑定任何单一外部来源作为条目权威。

## 3. 范围边界

### 本工单包含

- 统一内部条目模型 `LiteratureItem` 的扩展，支持多来源身份标识。
- 外部原始记录 `SourceRecord` 与内部条目的分层适配器设计。
- 离线 BibTeX 文件导入的预览、冲突检测、归一化与提交（M1）。
- 来源身份持久化：原始 `SourceRecord` 与批次元数据保存到 `user/sources/<batch_id>.json`。
- 可回滚的预览-提交两段式导入流程。
- 冲突策略：`merge`（默认）、`skip`、`create`。
- M2 实现 RIS 离线文件导入。
- M3 实现 OpenAlex works 本地导入与基于本地数据的 DOI 补全接口（网络实现延后）。

### 本工单明确不做

- M1 不做 RIS 文件导入。
- M3 不做外部 HTTP 网络调用（基于本地 OpenAlex 数据的 DOI 补全已实现）。
- M3 不做 OpenAlex works 实时 API 查询（本地已下载 works 分区导入已实现）。
- M1 不做跨来源自动合并（仅做冲突提示与策略选择）。
- M1 不把 BibTeX/RIS 导入记录写入 Source 分析表或 manifest tables。
- M1 不做云同步、协作、账号系统。
- M1 不做高级去重、作者消歧、机构归一化。
- M1 不做批量导入后的全文 PDF 自动获取。

## 4. 固定决议

### 4.1 A 层方向（已拍板）

- 工单 12 目标：把 cistella 从单一 OpenAlex 导入扩展为多数据源个人文献库导入，建立统一内部条目模型与可解释的导入/补全/冲突处理。
- 范围边界：M1 做离线 BibTeX 文件导入；M2 做离线 RIS 文件导入；M3 做 OpenAlex works 本地导入与基于本地数据的 DOI 补全接口；外部网络调用延后。
- Source 分析工作区保持独立：BibTeX/RIS/OpenAlex works 导入产生的记录不进入 Source 分析表；Source 分析工作区继续只服务 OpenAlex sources 数据。

### 4.2 B 层设计（已拍板）

- 统一内部模型：复用并扩展 `LiteratureItem`，新增 `ExternalIdentifier { namespace, value }` 字段列表（如 DOI/ISBN/PMID/OpenAlex ID）。
- 分层适配器：
  - `RecordSource` trait：解析外部输入为原始 `SourceRecord`；M1 实现 `BibTeXRecordSource`，M2 实现 `RISRecordSource`，M3 实现 `OpenAlexWorksRecordSource`。
  - `LibraryImporter`：负责预览、冲突检测、归一化、提交；M1 实现 BibTeX 导入器，M2/M3 扩展为按 `ImportFormat` 分派的多格式导入器。
- 来源身份持久化：新增 `user/sources/<batch_id>.json`（M1 简单方案），保存原始 `SourceRecord` 与批次元数据。
- 冲突策略：`merge`（默认，追加 SourceRef 并补空字段）、`skip`、`create`。
- 可回滚：预览-提交两段式；提交失败时恢复 `user/sources/` 原始状态；`literature_items.json` 通过现有原子替换更新。
- 依赖：M1 原设计引入 `biblatex` crate 解析 .bib 文件；实施时因环境无法访问 crates.io，改为自研最小 BibTeX 解析器（偏离申请见 `04-施工日志.md`）。

### 4.3 C 层默认（已拍板）

- `SourceRecord` 用结构化字段 + 原始字段映射。
- `BibTeXRecordSource` 原设计使用 `biblatex::Bibliography::parse`；实施时使用自研解析器，支持 `@type{key, field = {value}, ...}` 与嵌套花括号。
- `RISRecordSource` 使用自研解析器，支持 `TY  - ...` 标签块与常见学术标签。
- `OpenAlexWorksRecordSource` 读取本地 `openalex-sources/` 中已下载的 works 分区 JSONL/Gzip，转换为 `SourceRecord`。
- DOI 补全使用基于本地 OpenAlex 数据的 `LocalOpenAlexDoiResolver`，外部网络调用延后。
- 批次 ID 用 UUID；文件名 `<batch_id>.json`。
- Tauri 命令命名：`inspect_literature_import`、`import_literature_file`。
- UI 入口放在 Reading 工作区「导入文献」按钮。

## 5. 身份、不变量与权威边界

### 5.1 条目标识

- 每个文献条目继续使用 cistella 自己生成的 UUID 作为稳定 `item_id`，见 `../archive/工单-06-文献条目与个人库管理核心/01-目标与设计.md` 5.1。
- `item_id` 不由 DOI、ISBN、PMID、OpenAlex ID 或其他外部标识替代。
- 外部标识作为 `external_identifiers` 字段保存，是可更新的事实，不改变条目标识。

### 5.2 来源身份

- 每个 `SourceRecord` 在批次文件内拥有自己稳定的 `record_id`（UUID）。
- 来源身份持久化文件保存原始记录的全部字段与原始字段映射，使导入结果可审计、可回滚。
- 一个 `LiteratureItem` 可以引用多个 `LiteratureSourceRef`，表达“这条条目来自哪些外部记录”。

### 5.3 权威边界

- 用户字段（标题、作者、年份、类型、标签、阅读状态、收藏）的权威在用户数据文件 `user/literature_items.json`。
- 来源事实的权威在 `user/sources/<batch_id>.json`。
- Source 分析工作区中的 OpenAlex sources 数据权威在 manifest tables，不由本工单修改。
- 冲突处理时，用户字段优先保留用户已有值；`merge` 策略仅在字段为空时补全，不会覆盖已有用户编辑。

### 5.4 不变量

- `literature_items.json` 写入必须原子替换；失败时原文件必须保持完整。
- `user/sources/` 下的批次文件在提交失败时必须可恢复到提交前状态。
- 预览阶段不写入用户条目或批次文件，只返回可序列化的预览结果。
- 同一批次内 `record_id` 唯一；同一 Vault 内 `batch_id` 唯一。
- 导入器不得访问或修改 Source 分析表、manifest tables 或 `openalex-sources/` 原始数据。

## 6. 文件布局与模块边界

### 6.1 Vault 内新增文件

```
<Vault>/
  user/
    literature_items.json       # 现有：用户文献条目（扩展 external_identifiers）
    sources/
      <batch_id>.json           # 新增：原始 SourceRecord 列表 + 批次元数据
```

### 6.2 Core 新增模块（建议落位）

- `cistella-core/src/import/` 下新增：
  - `source_record.rs`：定义 `SourceRecord`、`ExternalIdentifier`、原始字段映射。
  - `record_source.rs`：定义 `RecordSource` trait 与解析错误。
  - `bibtex_source.rs`：实现 `BibTeXRecordSource`。
  - `library_importer.rs`：定义 `LibraryImporter`、预览、冲突检测、归一化、提交与回滚。
  - `bibtex_importer.rs`：实现 BibTeX 导入器。
  - `conflict.rs`：定义冲突策略与冲突项表示。

### 6.3 与现有模块的关系

- 扩展 `cistella-core/src/literature.rs` 中的 `LiteratureItem`，新增 `external_identifiers: Vec<ExternalIdentifier>`。
- `LiteratureSourceRef` 继续表达条目与来源记录的关系，M1 可在导入时自动填充。
- 不修改 `cistella-core/src/source_adapter.rs` 与 Source 分析相关模块的既有接口。

## 7. Core / Tauri / UI 边界

### 7.1 Core 层

- 提供纯 Rust API：
  - `BibTeXRecordSource::parse(bytes)` → `Vec<SourceRecord>`
  - `BibTeXLibraryImporter::preview(&self, records)` → `ImportPreview`
  - `BibTeXLibraryImporter::commit(&self, preview)` → `ImportResult`
- Core 不依赖 Tauri、UI 或任何前端状态。
- Core 负责原子写入、回滚、UUID 生成与 JSON 序列化。

### 7.2 Tauri 层

- 新增命令：
  - `inspect_literature_import`：接收文件路径/字节与格式参数，返回预览结果。
  - `import_literature_file`：接收预览确认与冲突策略，执行提交并返回结果。
- Tauri 层只做参数透传、错误映射和前端类型适配，不实现业务策略。
- 命令签名中不暴露内部 `RecordSource` 实现细节，只暴露格式枚举与可序列化 DTO。

### 7.3 UI 层

- Reading 工作区新增「导入文献」入口按钮。
- UI 负责：选择 .bib 文件、展示预览列表、展示冲突项、让用户选择策略、调用提交命令、回显结果。
- UI 不直接读写 Vault 文件，所有持久化通过 Tauri 命令完成。

## 8. 成功标准

- 用户可以通过 Reading 工作区选择 BibTeX 文件并预览即将导入的条目。
- 系统能够检测与现有条目的潜在冲突，并提供 `merge`/`skip`/`create` 策略。
- 提交成功后，新条目进入 `user/literature_items.json`，原始记录进入 `user/sources/<batch_id>.json`。
- 提交失败时，用户条目与批次文件均不处于半写入状态。
- Source 分析工作区与 manifest tables 不受导入流程影响。
- M2 实现 RIS 导入；M3 实现 OpenAlex works 本地导入与基于本地数据的 DOI 补全接口。

## 9. 施工准入判定

### A 层

cistella 需要从单一 OpenAlex 来源扩展为多数据源个人文献库导入；该方向与总路线一致，不再新增方向问题。

### B 层

统一内部模型扩展、`RecordSource`/`LibraryImporter` 分层、来源身份持久化、冲突策略、回滚机制、Source 分析工作区独立性已由经理拍板，见本节固定决议。

### C 层

`SourceRecord` 字段细节、`biblatex` 解析调用、预览 DTO 字段、Tauri 命令参数结构、UI 预览组件拆分交由干事按默认方案实现，偏离通过施工日志回填。

M1 已实施并通过经理终审；经理已授权 M2/M3 施工。
