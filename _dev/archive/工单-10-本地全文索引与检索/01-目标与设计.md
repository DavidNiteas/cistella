# 01. 目标与设计：本地全文索引与检索

## 工单定位

工单 10 在工单 08 的文献资产模型和工单 09 的受控阅读入口之上，为 cistella 建立本地、可删除、可重建、可随 Vault 复制的检索能力。它服务于“收进来—读—找—分析”的个人文献工作流，但不改变 Vault 的权威数据模型，也不让产品围绕 OpenAlex 或任何单一外部数据源组织。

## 北极星

用户可以在独立的 Search 工作区中检索自己的文献元数据与可用库内 PDF 的文本内容；检索命中稳定指向文献和资产身份，复制整个 Vault 后仍在副本中有效。索引缺失、损坏、过期或单个 PDF 无法提取时，主库、文献管理、阅读和 Source 分析仍可正常使用。

## 范围

### 包含

- Vault 内独立派生目录中的本地全文索引及其生命周期管理。
- 文献元数据（标题、作者、标签等允许字段）和资产 PDF 文本层的统一检索。
- 可用、库内（`storage_kind = vault`）PDF 的纯 Rust 文本提取与资产级失败隔离。
- 增量同步与打开 Vault 后的 reconciliation 兜底。
- 索引状态、重建、取消、问题列表、查询和受控打开命中资产的公共能力。
- 独立 Search 工作区的查询—定位文献—打开命中资产—查看索引健康状态闭环。
- portable、重建失败保留旧索引、全 Vault 写入边界和工单 08/09 回归验收。

### 不包含

- OCR、扫描件文字识别和任何云端提取服务。
- Word、EPUB、网页、图片、音视频及其他格式的内容提取。
- 向量数据库、embedding、语义检索、LLM 问答、RAG、自动总结或推荐。
- 在线搜索、远程索引、OpenAlex 专属检索通道或依赖外部服务的索引基础设施。
- 高级布尔/正则查询语言、保存搜索、搜索订阅、云同步或多人共享索引。
- 内置 PDF 阅读器、页码精确跳转、阅读进度、笔记和标注。
- 对工单 08 资产模型、工单 09 阅读会话模型或 Vault 权威数据的重构。

## 领域与数据边界

### 权威数据与派生数据

Vault 及其现有权威内容是唯一事实源。全文索引只能读取文献条目、资产关联、受控解析后的 PDF 文件和必要的内容摘要；不得将索引作为备份、恢复源或新的用户事实来源。

索引集中存放于：

```text
derived/search/
```

该目录是独立、可整体删除、可整体重建、可随 Vault 复制的派生数据单元。它绝不能写入或混入下列位置：

```text
manifest.json
tables/
user/
files/
```

删除、损坏、版本不兼容或缺失 `derived/search/` 时，Vault 必须照常打开；系统只将检索状态呈现为 `missing`、`stale`、`degraded` 或 `failed`，不得阻塞主库能力。

### 身份与路径边界

索引记录、公共 API、桌面返回值和检索结果仅使用稳定身份：

```text
item_id
asset_id
```

索引不得持久化或返回 Vault 根目录绝对路径、PDF 绝对路径、盘符、用户名、临时文件路径或可由 WebView 任意打开的路径。搜索结果打开命中资产时，必须沿用既有受控链路：

```text
item_id + asset_id
    ↓
Core 校验条目—资产归属与状态
    ↓
基于当前 Vault 根目录受控解析
    ↓
桌面后端请求系统 opener
```

### 首版可索引对象

- 每个文献条目均可建立元数据记录，因此即使没有 PDF、PDF 无文本或资产不可用，仍可按元数据���中。
- 仅 `storage_kind = vault`、运行时状态为 `available` 的 PDF 资产可建立正文内容记录。
- 外部资产不建立首版正文内容索引；它们所属条目的元数据仍可命中。
- 内容提取只读取 PDF 文本层；无文本、加密、损坏、超限或不可用均属于单资产降级，不升级为 Vault 或全局索引故障。

## 已锁定的 B 层设计

### 索引逻辑记录与文献级聚合

索引内部逻辑上分为两类记录：

1. **文献元数据记录**：每个 `item_id` 一条，包含可搜索的标题、作者、标签及元数据指纹。
2. **资产内容记录**：每个可索引 PDF 的 `item_id + asset_id` 一条，包含派生正文、内容指纹与提取器/分析器版本。

查询对外聚合为文献级结果：一个 `SearchHit` 对应一个 `item_id`，不得因多个字段或多个 PDF 命中重复展示同一文献。结果必须能说明命中字段；正文命中必须能关联到具体 `asset_id`、摘要和资产健康状态。

元数据命中优先于正文命中。M3 已回填最小可复现的 C 层值：查询词经既有分析器归一后，必须在同一个受选字段中全部命中；结果先按“含元数据命中”再按仅正文命中分组，同组以稳定 `item_id` 升序；同一条目内字段顺序为标题、作者、标签、正文，正文资产再按 `asset_id` 升序；默认每页 50 条、最大 100 条，使用 offset 分页；正文摘要从最早命中词附近开始，最多 240 个 Unicode 字符，截断两端以 `…` 标记。上述 C 层值不构成高级查询语言或评分公共契约。

### 分析、提取与实现隔离

索引采用进程内 Rust 引擎，PDF 文本提取采用纯 Rust 实现；具体 crate、索引文件布局、schema 字段和调用细节封装在 Core 内部，不进入公共 API、Tauri 命令或桌面 UI 语言。

首版分析器采用确定性的中英文混合策略：Unicode 规范化、拉丁字符大小写归一、英文和数字按词边界处理、CJK 使用 n-gram；原始字段保留用于显示与摘要。分析器参数、文件大小/页数/字符数/时间限额、并发数、批次大小和性能 golden 均标记为 **TBD by experiment**，必须在本工单关闭前回填为可复现的实施结论。

### 版本、同步与失败语义

索引 manifest 至少区分 `index_schema_version`、`text_analyzer_version`、`pdf_extractor_version`。索引版本不兼容、manifest 损坏或目录删除均视为可重建状态，不进行复杂旧格式迁移，也不得妨碍 Vault 打开。

同步采用“权威操作成功后的增量更新 + 打开 Vault 后 reconciliation”的双层策略：

- 文献元数据变化只更新对应文献记录。
- 资产新增、内容变化、删除或不可用时，只处理对应资产内容记录。
- reconciliation 对账当前条目、资产、指纹和索引记录，补充遗漏、移除孤儿、重新检查失败或不可用资产。
- `content_hash` 变化后，如果新提取失败，必须移除旧正文命中，保留文献元数据和资产级问题；不得以旧文本伪装当前文件内容。

### 重建与提交

重建必须在 `derived/search/working/` 中构建新代际，完成完整性检查后再原子切换当前可用代际。构建、取消或提交失败时，旧的成功索引必须继续可查询；只有从未存在成功索引时才可呈现为全局 `failed`。启动发现未提交的 working 数据时可安全清理。

### 公共能力与桌面边界

Core 和桌面面向领域能力表达查询、索引状态、同步、重建、取消、任务状态和问题列表；不得暴露索引引擎、segment、reader/writer、底层查询语法或文件路径。

Search 工作区是独立工作区，不塞入 Source 工作区。它应提供：搜索输入与范围、文献级结果、命中字段与正文摘要、受控打开命中资产、索引状态、同步/重建/取消和资产级问题反馈。Search 工作区不得另造阅读会话语义；打开文件继续沿用工单 09 的既有受控入口。

所有 Search 查询、索引状态读取、索引任务反馈和异步刷新必须复用工单 09 的 **generation + Vault path** 双重请求隔离。Vault 切换时立即清空旧 Search 上下文；过期响应不得污染当前 Vault，且不得只依赖路径比较。

## 工单施工硬边界

- 不改写 `manifest.json`、`tables/`、`user/`、`files/` 中的权威内容或 PDF 原件。
- 不向前端授予通用路径、提取路径或 opener 能力。
- 不因提取、索引、重建或索引失败回滚已成功的文献/资产/阅读操作。
- 不在本工单中扩张为 OCR、跨格式提取、语义能力、在线服务或 OpenAlex 专有功能。
