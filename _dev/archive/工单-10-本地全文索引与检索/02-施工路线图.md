## M1：索引契约、派生目录与生命周期基础

### 可施工步骤

1. 在 Core 内定义领域级检索记录、查询、命中、索引状态、任务和问题模型；公共类型不得泄露底层引擎或路径。
2. 固化 `derived/search/`、`working/`、当前成功代际和索引 manifest 的职责边界；仅使用 `item_id + asset_id` 作为资产稳定引用。
3. 建立索引 schema、文本分析器、PDF 提取器三类版本识别规则；版本不兼容或 manifest 损坏时返回可重建状态。
4. 以临时 working 代际构建和原子提交为骨架，确保未完成工作目录可清理、旧成功代际不会被破坏。
5. 实现元数据记录与资产内容记录的最小固定样本索引，验证字段边界、文献级聚合输入和中英文混合分析基座。
6. 建立 Core 单元测试：索引目录删除/损坏/版本过期不影响 Vault；索引记录不含绝对路径；索引操作不改写权威文件；提交失败不遗留错误临时状态或损坏旧索引。

### 关闭标准

- 对少量固定中英文文本能建立可打开的索引记录，且标题、作者、标签、正文逻辑字段可区分。
- `derived/search/` 可整体删除，Vault 仍正常打开；索引状态正确反映 missing/stale/failed，而非连接失败。
- 索引持久化与公共结果均不保存、不返回绝对路径，只引用 `item_id + asset_id`。
- 在版本不兼容、manifest 损坏和 working 残留情况下，旧成功索引不被错误破坏。
- 全 Vault 快照证明 M1 只可写入 `derived/search/`。

## M2：PDF 文本提取、失败隔离与增量/reconciliation

### 可施工步骤

1. 在 Core 内接入并封装纯 Rust PDF 文本层提取；前端与公共 API 不获得文件路径或提取器实现细节。
2. 仅对可用、库内 PDF 资产通过 `item_id + asset_id` 受控解析后提取；外部资产只参与文献元数据命中。
3. 建立资产级索引状态与受限错误信息，覆盖 `indexed`、`noText`、`missing`、`externalUnavailable`、`encrypted`、`unsupported`、`parseFailed`、`limitExceeded`、`cancelled` 等语义。
4. 使用内容 hash、版本和规范化元数据指纹实现增量判断；新增/修改/删除文献和资产时只处理受影响记录。
5. 实现打开 Vault 后的 reconciliation：补漏、移除孤儿、重试失败/不可用项并校准状态；连接 Vault 不得等待全部提取完成。
6. 用固定实验样本测量分析器参数、文件/页数/文本量/处理时间限额、并发数、批次和性能 golden，并将结果回填本工单状态账本。

### 关闭标准

- 损坏、无文本、加密、超限、缺失或外部断链的单资产不会阻塞其他资产、主库连接或元数据查询。
- 修改标题/作者/标签只更新相应文献元数据；替换一个 PDF 只重提取对应资产。
- `content_hash` 变化且新提取失败时，旧正文记录已移除，元数据记录与资产问题仍保留。
- 删除资产或文献后不存在可搜索孤儿内容；reconciliation 可收敛异常中断的增量状态。
- 已回填上述资源边界与性能实验结论，未保留无上限读取/无限并发的实现空白。

## M3：查询公共 API、桌面命令与 Search 工作区

### 可施工步骤

1. 提供领域级查询 API，支持默认全字段及标题/作者/标签/正文范围；结果按 `item_id` 聚合，返回命中字段、正文摘要、关联 `asset_id`、资产健康状态和索引状态。
2. 提供索引状态、同步、重建、取消、任务状态和问题列表能力；不得暴露索引引擎、底层查询语法或路径。
3. 增加 Tauri 受控命令，搜索结果打开资产只能提交 `item_id + asset_id` 并复用既有受控 opener/阅读入口语义。
4. 新建独立 Search 工作区：输入、范围、加载/空/错误状态、文献级结果、正文摘要、受控打开、索引健康状态、同步/重建/取消与问题查看形成最小闭环。
5. 对 Search 状态、查询结果、索引状态和任务反馈复用工单 09 的 `generation + Vault path` 请求快照；连接开始即清空旧上下文，所有成功/失败异步写入均拒绝旧代际。

### M3 C 层回填（2026-08-26）

- 查询使用既有确定性分析器；多个查询词须在同一个已选字段内全部命中，不提供布尔、正则、模糊或底层索引语法。
- 排序固定为“含元数据命中优先于仅正文命中”，同类按 `item_id` 升序；单条文献内字段顺序为标题、作者、标签、正文，正文命中资产按 `asset_id` 升序。
- 分页固定默认 50、上限 100、offset 语义；桌面首版提供上一页/下一页。
- 正文摘要固定提取最早命中词附近最多 240 个 Unicode 字符，前后截断使用 `…` 标记。

### 关闭标准

- 单一查询可命中标题、作者、标签和 PDF 正文；同一文献不会因多字段或多资产重复展示。
- 用户能区分命中字段，正文命中能定位到具体 `asset_id`；不可用资产不显示误导性打开动作。
- 前端未获得绝对路径，打开资产仍为 `item_id + asset_id` 受控链路；Search 不另造阅读会话语义。
- 无索引时显示结构化 missing 状态和建立动作，不把空结果伪装为“无命中”，也不隐式启动全量重建。
- 覆盖 A → B → A、自动恢复/手动连接重叠等顺序，证明旧 Vault 的搜索结果、状态和任务反馈不能污染当前 Vault。

## M4：portable、重建、数据边界与回归验收

### 可施工步骤

1. 建立最小 Vault、文献、库内 PDF 与索引；复制整个 Vault 后在副本搜索��同 `item_id`，并证明命中资产在副本中受控解析和打开。
2. 验证索引目录删除、manifest 损坏、版本不兼容和未提交 working 数据均不阻塞 Vault；重建后恢复等价结果集合。
3. 覆盖原子重建：新代际构建/提交失败、取消或单资产失败时，旧成功索引仍可查询；从未存在成功代际时再呈现 failed。
4. 覆盖增量新增、元数据修改、PDF 替换、资产删除、文献删除、无文本/损坏/缺失/外部断链等状态，验证无幽灵命中。
5. 用完整 Vault 相对路径—字节快照证明索引建立、同步、重建和查询只允许写入 `derived/search/`；不得改写 manifest、tables、user、files、PDF、资产、阅读会话或 Source 数据。
6. 回归工单 08 文献资产与工单 09 阅读会话 portable 语义，并记录性能 golden。

### 关闭标准

- 原 Vault 建索引后复制，副本仍可查询同一文献，并在副本路径受控打开命中 PDF；不存在对原 Vault 绝对路径的依赖。
- 删除 `derived/search/` 后主库正常，重建后得到等价文献结果；重建失败时旧索引仍可查询。
- PDF 替换后旧正文不再命中、新正文可命中；删除文献/资产后没有幽灵命中。
- 损坏或不可用 PDF 不影响其他条目；元数据仍可查询；失败不误调用 opener。
- 全 Vault 快照仅允许 `derived/search/` 变化；工单 08/09 portable 测试与全部统一验收命令通过。
