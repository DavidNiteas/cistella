## 已锁定设计事实

- 派生索引根为 `derived/search/`，可删除、可重建、可随 Vault 复制；不得写入 `manifest.json`、`tables/`、`user/`、`files/`。
- 索引、API 和桌面不得持久化或返回绝对路径；稳定引用仅为 `item_id + asset_id`。
- 首版正文仅索引可用库内 PDF 文本层；外部资产仅保留其所属文献的元数据命中。
- 逻辑记录为“文献元数据记录 + 资产内容记录”，查询结果聚合为文献级。
- 使用进程内 Rust 索引引擎与纯 Rust PDF 提取实现，具体依赖隔离在 Core 内部。
- 索引损坏、缺失、删除、版本不兼容和资产级提取失败均不得阻塞 Vault；已就绪索引在权威文献/资产操作成功后尝试身份级增量更新，失败绝不回滚权威操作，由全量 reconciliation 兜底；重建失败保留旧成功索引。
- `content_hash` 变化而新提取失败时，必须移除旧正文命中，保留元数据和资产问题。
- M3 Search 工作区复用工单 09 的 generation + path 双重隔离。

## M2 实施证据（2026-08-26，待不同实例初审）

- **依赖与许可**：新增 `lopdf = 0.44.0`，`default-features = false`；`cargo info lopdf` 与下载的 crate manifest 均确认其为 **MIT**、`rust-version = 1.88`。当前 Rust `1.96.0` 满足要求。使用的 API 为 `Document::load`、`is_encrypted`、`get_pages`、`extract_text_chunks_with_limit`；未引入网络、系统服务、OCR 或外部可执行程序。
- **schema/迁移**：`SEARCH_INDEX_FORMAT_VERSION` 从 M1 的 `1` 升级为 `2`；提取器版本由 `pending-m2` 升级为 `lopdf-0.44-text-v1`，内容分析器为 `content-v1`。M1 generation 会以 `Stale` 处理，重建后才可加载；旧 `pendingExtraction` 枚举仍可反序列化，不会被 M2 新 generation 写出。
- **资产状态与问题**：内容记录覆盖 `indexed`、`noText`、`missing`、`externalUnavailable`、`encrypted`、`unsupported`、`parseFailed`、`limitExceeded`、`cancelled`，并将非 indexed 状态映射为路径无关 `SearchIndexIssue`。外部资产不执行解析，仍随所属文献元数据存在。
- **受控提取与增量**：仅 Vault + PDF + `Available` 资产经 `item_id + asset_id → resolve_document_asset_path` 受控解析。实际文件 `SHA-256`、提取器/分析器版本及元数据 fingerprint 留在派生 record；相同 hash + 版本的 `indexed` 正文复用，metadata-only 变更只更新该 item 的元数据/fingerprint、不打开或 hash 任一 PDF。`SearchIndexChange` 只承载 `item_id + asset_id`，权威文献/资产操作成功后尝试只处理受影响 item/asset 的新 generation；失败绝不回滚权威数据。全量 reconciliation 负责补漏、移除孤儿、重试失败/不可用项和文件系统漂移。hash 变化后的解析失败记录 `content=None`，旧正文不会残留。
- **打开与 reconciliation**：新增显式 `Vault::reconcile_search_index()`；它是全量异步兜底候选，从不由 `Vault::open` 自动调用，因此连接 Vault 不等待 PDF 提取。M3 只能在其异步任务层调度该已受资源限制的操作。
- **定向回归**：真实可控 PDF 覆盖正文、空文本、加密、损坏、缺失、可用外部、unsupported、超文件限额；覆盖新增、metadata-only 修改、PDF 替换失败、资产删除、文献删除、M1 schema stale→M2 rebuild、Vault 复制与 ID-only 持久化。P1 返工新增：metadata-only 不读取/hash PDF，单资产变更不读取/hash 无关 PDF，派生发布失败不回滚权威数据且 reconciliation 可收敛。另保留 M1 全目录/文件 link/reparse 安全矩阵。
- **统一验收**：P1 返工后 `cargo fmt --check` 通过；Search 定向 21 项通过；`cargo test -p cistella-core` 为 64 library + 工单 07/08/09 portable 6 项通过；`cargo test -p cistella-desktop` 2 项通过；`cargo check -p cistella-desktop` 通过；前端 `pnpm build` 通过（629 modules）。非阻断既有提示仍为 Rust incremental 收尾 `os error 5` 与 Vite 1,374.25 kB（gzip 450.58 kB）主 bundle 超过 500 kB。
