# 03. 开发状态：Vault 与库模型

## 当前阶段

已达成，已归档。

## 已完成

- 在 core 中引入 Vault 语义层。
- 新增 Vault / VaultOpenOptions / VaultManifest / VaultSourceProvenance / VaultTableManifest / VaultTableFile。
- manifest 结构已切换为 Vault 命名作为主命名。
- `Dataset` 及相关旧命名仅作为施工期兼容层保留；不再新增 Dataset 主 API，也不作为开放设计问题。
- 桌面侧与查询/导入路径已开始围绕 Vault 语义收束。
- core 已补出 Vault 上下文摘要，便于桌面壳层读取当前库状态。
- 桌面侧已改为直接复用 core 提供的 VaultContext。
- `Vault::open` 在读取 manifest 后校验所有 table file 路径必须是非空相对路径，拒绝绝对路径、根路径、盘符前缀和 `..` 路径段。
- `Vault::table_path` 在选择物理文件后再次执行同一契约校验，并仅将合法相对路径拼接到 Vault 根目录下。
- `source.input_path` 继续仅作为来源溯源记录，不作为打开 Vault 的运行时依赖。

## 当前关闭标准

- `Vault::open` 能拒绝 manifest 中的绝对 table file 路径与路径逃逸路径。
- `Vault::table_path` 能返回相对 table file 相对于 Vault 根目录的路径，并拒绝非法路径。
- manifest / table / provenance 的职责边界保持不变，不引入多来源融合，不扩展 UI。
- Dataset 兼容别名有明确施工期定位，不阻塞后续 Vault 使用。
- core 单元测试通过，且覆盖正常相对路径、绝对路径、`..` 路径和运行时 `table_path` 校验。
