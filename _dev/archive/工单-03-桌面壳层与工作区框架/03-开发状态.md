# 03. 开发状态：桌面壳层与工作区框架

## 当前阶段

已达成，已归档。

## 已完成

- 前端主界面已重写为 cistella 的四工作区壳层：Vault、Reading、Source、Settings。
- Vault 工作区已提供连接库、选择目录与导入入口。
- Source 工作区已具备概览、表格、可视化、指标与导出任务面。
- 最近库、当前工作区与 Source 标签页具备持久化记忆。
- 启动时会尝试恢复最近可用库；恢复失败或没有最近库时，固定落到 Vault 空态，不展示误导性的 Source 分析操作。
- 连接库成功后会刷新 Vault 上下文、概览、排行与检索结果；连接或刷新失败会清空旧上下文并在库工作区显示失败状态。

## 当前批次冻结范围

- 本工单只负责桌面壳层、一级导航、工作区记忆、空态与库上下文联动。
- Reading 工作区在本批次只保留稳定入口和预留状态，不在本工单内实现阅读闭环。
- 高级窗口编排、插件化工作区、复杂设置中心推迟到后续工单。

## 本次收口结果

- 启动恢复逻辑已收口：优先按最近库列表尝试连接，全部不可用时清空当前库上下文并落到 Vault 空态。
- 恢复期间界面临时显示 Vault 空态，避免启动瞬间进入没有库的 Source 页面。
- 当前工作区与 Source 标签页继续使用 localStorage 持久化；连接库不再强制重置 Source 标签页，重启后可恢复上次标签页。
- 连接库后的上下文刷新已收口，避免状态更新尚未完成时查询使用旧的“未连接”状态。
- 连接、上下文刷新与最近库恢复失败均保留可见失败状态，且不会继续显示旧库的统计数据。

## 关闭标准

- 用户无需记忆命令即可打开库、进入工作区并返回库入口。
- 最近库、当前工作区和 Source 标签页在重启后可恢复，且无库时不会显示误导性的分析操作。
- 桌面端能稳定显示当前 Vault 与来源适配器状态。
- Reading 入口明确标注为后续能力，不阻塞本工单关闭。
