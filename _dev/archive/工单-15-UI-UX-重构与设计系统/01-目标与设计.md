# 工单 15：UI/UX 重构与设计系统

## 1. 目标与北极星

把 cistella 桌面应用从「功能可用但视觉与交互未成型」的状态，升级为**专业、一致、易用、可维护**的文献管理工作台。

北极星指标：
- 用户能在不阅读文档的情况下，凭直觉完成「打开库 → 导入文献 → 搜索 → 阅读 → 记笔记」主任务流。
- 开发者能在不读懂 2501 行单体文件的情况下，独立修改某个工作区或新增一种反馈组件。
- 所有可交互元素在浅色模式下视觉一致、焦点可见；暗色模式具备技术就绪条件。

## 3. 设计原则

1. **库即中心，状态始终可见**  
   当前 Vault 路径、连接状态、后台任务进度必须在全局 Chrome 中可见，不依赖侧边栏底部小字。

2. **Shell 稳定，Workspace 自治**  
   侧边栏、状态栏、Toast、全局遮罩作为公共 Chrome；六个工作区各自为独立页面组件，禁止在 `App.tsx` 中写大段条件渲染。

3. **Token 驱动，暗色模式就绪**  
   颜色、间距、圆角、阴影全部收敛到 CSS 变量；暗色模式通过 `data-theme="dark"` 切换，组件不感知具体色值。

4. **渐进披露 + 零死胡同**  
   空状态、错误状态、加载状态是一等公民；每个空状态都带下一步引导操作。

5. **键盘优先与可访问性**  
   所有可交互元素有可见焦点环、合理 Tab 顺序、ARIA 状态；Modal 焦点陷阱 + Esc 关闭；提供全局快捷键。

## 4. 新设计方案

### 4.1 全局信息架构

```
┌─────────────────────────────────────────────────────┐
│  [Logo] cistella        [Vault Selector ▼]  [Busy]  │  ← 顶部/侧边栏顶部
│  ─────────────────────────────────────────────────  │
│  🏠  库 (Vault)                                      │
│  📚  阅读 (Reading)                                  │
│  📝  笔记 (Notes)                                    │
│  🔍  搜索 (Search)                                   │
│  📊  Source 分析                                     │
│  ⚙️  设置 (Settings)                                 │
│  ─────────────────────────────────────────────────  │
│  [当前库路径]  [全局状态]  [版本]                    │  ← 底部状态区
└─────────────────────────────────────────────────────┘
```

- **Vault Selector**：显示当前库名，下拉展示最近库 + 打开/新建库入口。
- **图标体系**：引入 `lucide-react`，导航项使用图标 + 文字；侧边栏可折叠为图标 rail。
- **Active 状态**：统一使用 `.nav[data-active="true"]` 或 `.nav--active`，避免 `.selected` 与 `.active` 混用。
- **状态栏**：底部固定区域，展示当前库路径、操作状态、后台任务进度、版本号。

### 4.2 工作区布局

#### Vault（库）
- **无库时**：全屏 Hero，标题 + 副标题 +「打开库 / 新建库 / 从 OpenAlex 导入」三个主操作。
- **有库时**：Dashboard 式布局：
  - 顶部：库名称、ID、来源、表数、刷新按钮。
  - 左侧 2/3：资产中心（文献条目 → 其 PDF 资产）。
  - 右侧 1/3：来源信息、构建日志、最近操作。

#### Reading（阅读/文献）
三栏主从结构：
- 左侧：文献列表 + 搜索/筛选。
- 中间：条目详情/编辑器（默认收起编辑表单，选中条目后展示详情）。
- 右侧：阅读会话 + 可阅读资产。

#### Notes（笔记）
三栏结构：
- 左侧：文献筛选。
- 中间：笔记列表。
- 右侧：Markdown 编辑器 + 可折叠标注面板。

#### Search（本地全文检索）
- 顶部大搜索框（默认聚焦）。
- 右侧/顶部：索引健康状态面板（含进度条、同步/重建/取消按钮）。
- 结果列表使用 `SearchHit` 组件：标题、作者、命中高亮片段、字段标签、操作按钮。

#### Source 分析
- 左侧固定筛选面板（类型、指标、关键词、国家、OA）。
- 右侧结果区通过 Tab 切换：Overview / Table / Visual / Metrics / Export。
- Table 支持排序、列宽拖拽、列显隐、分页、导出。

#### Settings（设置）
分组展示：语言、运行模式与迁移向导入口、备份与恢复、关于/更新/来源适配器。

### 4.3 关键任务流

1. **打开/连接库**：启动后尝试恢复最近库；失败进入 Vault Hero；连接中显示全屏 Loading 遮罩；成功后状态栏反馈。
2. **导入文献**：Reading 页顶部「导入」按钮 → Modal 选择格式（BibTeX/RIS/OpenAlex Works/标识符解析）→ 预览 → 冲突策略 → 提交 → Toast 反馈结果。
3. **阅读**：选择条目 → 右侧资产区点击「开始阅读」→ 调用系统 PDF 阅读器并创建会话；资产不可用时保留历史并明确提示。
4. **搜索**：进入 Search 工作区自动聚焦搜索框；无索引时提示同步/重建；结果展示命中摘要。
5. **Source 分析**：选择筛选条件 → 查询 → Tab 切换查看统计/表格/图表/导出；支持保存最近查询与一键回放。

### 4.4 视觉系统

#### 设计令牌（`tokens.css`）
- **颜色**：`--color-bg`、`--color-surface`、`--color-primary`、`--color-text-primary`、`--color-success`、`--color-warning`、`--color-danger` 等；暗色模式通过 `[data-theme="dark"]` 覆盖。
- **字体**：`"Inter", "PingFang SC", "Microsoft YaHei", sans-serif`；等宽字体用于路径/ID。
- **字号**：Display 24px、Title 18px、Body 14px、Caption 12px、Label 11px。
- **间距**：基数 4px，主要档位 8/12/16/20/24/32。
- **圆角**：卡片 12px、按钮/输入框 8px、Pills 999px、Modal 16px。
- **阴影**：卡片 `0 1px 3px rgba(31,33,56,0.06)`、悬停 `0 4px 12px rgba(31,33,56,0.08)`、Modal `0 20px 60px rgba(31,33,56,0.25)`。

#### 组件规范
- **Button**：primary / secondary / ghost / danger / icon / loading，统一高度 32px、圆角 8px。
- **Card**：背景 surface、边框、12px 圆角、16px 内边距；头部 `.card-header` 标题 + 操作区。
- **PageHeader**：kicker + 标题 + 描述 + 右侧操作区，高度 80px。
- **DataTable**：可配置列、排序、列宽拖拽、列显隐、分页、空状态、加载态。
- **Dialog / Modal**：统一遮罩 + 卡片，焦点陷阱 + Esc 关闭；DangerDialog 用于不可逆操作，ConfirmDialog 用于一般确认。
- **Toast**：右上角栈，成功/警告/错误/信息四类，自动消失 + 手动关闭。
- **EmptyState**：图标 + 标题 + 描述 + 可选操作按钮。
- **Spinner / ProgressBar**：全局遮罩、局部骨架屏、按钮加载态。
- **Field / Select / Checkbox**：统一标签、输入、提示结构；聚焦 ring 可见。

#### 图标体系
使用 `lucide-react`：Vault→Database、Reading→BookOpen、Notes→NotebookPen、Search→Search、Source→BarChart3、Settings→Settings、收藏→Star/StarOff、删除→Trash2、导入→Upload、导出→Download、PDF→FileText、外部链接→ExternalLink、同步→RefreshCw。

#### 中文排版
- 中文字体回退 `"PingFang SC", "Microsoft YaHei", "Noto Sans SC"`。
- 中文正文行高 ≥ 1.6，避免 `font-weight: 900`。
- 日期/ID/路径使用等宽字体。

### 4.5 可访问性

- 所有按钮/链接为真实 `<button>` 或 `<a>`。
- 导航使用 `aria-current="page"`。
- 表单标签与输入框正确关联。
- `:focus-visible` 统一焦点环。
- Modal 焦点陷阱 + Esc 关闭。
- 动态内容使用 `aria-live` 区域。
- 全局快捷键：`Ctrl/Cmd+1-6` 切换工作区、`Ctrl/Cmd+K` 命令面板、`Ctrl/Cmd+N` 新建条目、`Ctrl/Cmd+S` 保存、`Esc` 关闭弹窗/退出编辑器。

### 4.6 前端架构

#### 技术选型
- **CSS 方案**：CSS Modules + 全局 CSS Variables。  
  理由：Vite 原生支持，与现有代码风格最接近，可逐步迁移，避免一次性引入 Tailwind 的依赖和工具类噪音。
- **图标**：`lucide-react`。
- **状态管理**：第一阶段用自定义 Hooks 拆分领域状态；第二阶段如全局 UI 状态传递复杂，引入 Zustand 轻量 store（`ui.workspace`、`ui.toasts[]`、`vault.current`）。
- **暂不引入**：TanStack Query、Tailwind、Radix 等，先以最小依赖完成重构。

#### Hooks 拆分（领域）
- `useI18n()`：语言与字典。

- `useVaultContext()`：vault summary、table count、assets。
- `useLiterature()`：文献列表、编辑、导入、远程解析。
- `useReadingSessions()`：会话列表、继续/暂停/结束。

- `useSourceAnalysis()`：overview、ranking、results、recent queries。

## 5. 不改动范围

- 不修改 Rust 后端 API 与业务逻辑。
- 不修改核心 crate 的数据模型与存储布局。
- 不引入新的产品功能（如新建工作区、新数据源适配器）。
- 不修改现有国际化文案语义，仅调整展示方式。

## 6. 关键术语

- **Design Tokens**：设计令牌，颜色/间距/圆角/阴影/字体等基础变量。
- **CSS Modules**：Vite 支持的局部作用域 CSS，文件名 `.module.css`。
- **Vault Generation**：当前库连接代数，用于丢弃过期异步响应。
- **Workspace**：Vault / Reading / Notes / Search / Source / Settings 六个一级工作区。
