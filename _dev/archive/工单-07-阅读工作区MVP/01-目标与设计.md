# 01. 目标与设计：阅读工作区 MVP

## 工单定位

在工单 06 的个人文献条目管理基础上，为 cistella 提供一个可直接进入的本地阅读入口。阅读工作区解决“从库中找到条目、保存文献文件、打开文件、推进阅读状态”的最小闭环，不提前承诺完整阅读器、笔记系统或全文知识管理。

## 北极星

用户可以从当前 Vault 的文献条目出发，将 PDF 收入库或明确链接到外部 PDF，使用系统默认阅读器打开它，并在 cistella 中稳定维护该条目及其阅读状态；复制 Vault 后，库内副本保持可用。

## 范围

### 本工单包含

- 以工单 06 的 `item_id` 作为阅读入口的稳定标识。
- 为文献条目关联零到多个 PDF 文件，并明确默认文件。
- 提供“加入 Vault”（复制）和“仅链接外部文件”两种关联方式。
- 在 Reading 工作区提供文件列表、设为默认、移除关联、打开默认/指定文件和既有阅读状态操作。
- 处理缺失、不可读、非法路径和系统打开失败；失败不改变条目数据或阅读状态。
- 维护库内路径的 portable 语义与路径安全约束。

### 本工单不包含

- PDF/EPUB 内置预览或自研排版引擎。
- EPUB、HTML、Office、图片、压缩包等格式支持。
- 笔记、标注、引用摘录、全文检索、OCR。
- 云同步、多设备冲突解决。
- 多来源自动合并和 OpenAlex 专属阅读逻辑。

## 已拍板的 B 层设计

### 1. 数据模型与兼容性

在 `LiteratureItem` 追加下列默认字段，旧的 `literature_items.json` 通过 `serde(default)` 直接读取，不设置迁移门槛：

```text
files: LiteratureFileRef[] = []
default_file_id: UUID | null = null
```

`LiteratureFileRef` 固定为：

```text
file_id: UUID
kind: vault | external
path: string
display_name: string
```

- `file_id` 是稳定本地标识，不使用数组位置或路径代替。
- `display_name` 仅用于展示，打开时永远以经验证的 `path` 为准。
- 不做重复文件检测、内容哈希或附件版本管理。

### 2. Vault portable 路径策略

- **标准路径**：用户选择“加入 Vault”时，原文件复制至 `files/<item_id>/<原始文件名>`，记录相对 Vault 根目录的 `kind: vault` 路径。
- **外部链接**：用户选择“仅链接外部文件”时，记录绝对本机路径并标为 `kind: external`；界面必须明确显示它不随 Vault 复制。
- 库内路径拒绝空路径、绝对路径、`..`、根目录、盘符/前缀等逃逸语义。读取、写入、复制与打开前均重复验证。
- 库内路径在解析后不得越出 Vault 根目录；可疑的符号链接或规范化逃逸按不可用处理。

### 3. 文件类型与打开边界

- 首版只允许添加并打开 `.pdf` 文件（大小写不敏感）。
- cistella 不内置 PDF 阅读器；经后端验证后交给操作系统默认应用打开。
- 不接受 URL、URI、命令行或非 PDF 文件作为打开目标。
- 系统已接受打开请求不等同于用户完成阅读；打开文件绝不自动修改 `reading_status`。

### 4. 多文件与默认规则

- 一个条目可以关联多个 PDF。
- 第一份成功添加的文件自动成为默认文件；后续添加不改变默认。
- 用户可以显式将任一现存关联设为默认。
- 删除默认关联时仅清空 `default_file_id`，不按数组顺序静默选择替代项。
- 默认文件不存在或失效时视为无默认文件；不猜测性修复或写回。
- 用户点击“打开条目”时：存在有效默认文件则打开；没有默认文件则提示其从文件列表选择。

### 5. 失败语义

> 打开失败不改数据、不改阅读状态、不删除关联；只反馈当前操作失败并保留修复入口。

- 库内文件缺失：关联保留，显示缺失，可重新关联或移除。
- 外部链接失效：关联保留，显示外部链接不可用，可重新定位、加入 Vault 或移除。
- 路径非法、没有权限或系统打开失败：拒绝当前操作，不写状态。

## 工作区边界

- Reading 工作区拥有文件关联和阅读状态入口。
- Source 工作区不得修改用户文件关联或阅读状态。
- Vault 目录中的 `files/` 是用户资产；不写入 manifest tables，也不进入 OpenAlex 导入/分析数据流。
