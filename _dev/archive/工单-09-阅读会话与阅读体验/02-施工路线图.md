## 里程碑

| 阶段 | 交付物 | 关闭标准 |
|---|---|---|
| M1 | ReadingSession模型与原子持久化 | 新旧库可打开；会话JSON可往返；asset_id/item_id关联校验；写入失败不破坏 |
| M2 | 会话命令与恢复策略 | 启动、暂停、结束、最近/继续查询命令闭环；失败打开不更新时间；core/desktop测试通过 |
| M3 | Reading工作区UI闭环 | 最近阅读、继续阅读、开始/暂停/结束、外链/缺失提示可用；新入口不使用file_id |
| M4 | portable与回归验收 | 复制Vault会话仍可恢复；manifest/Source/资产数据边界不变；全量命令通过 |

## M1实施细则

1. 在core定义`ReadingSession`、状态枚举和稳定序列化。
2. 新增`user/reading_sessions.json`原子读写。
3. 校验会话引用的条目与资产关系；不把状态运行时写回会话事实。

## M2实施细则

1. 提供开始、暂停、结束、最近列表和继续目标的公共API及Tauri受控命令。
2. 通过`item_id + asset_id`解析资产；仅成功发起打开后更新时间。
3. 任何写失败保持原JSON，错误返回可识别信息。

## M3实施细则

1. Reading工作区以会话列表和继续入口为主。
2. 资产不可用时显示原因并保留记录；不静默删除。
3. 保留工单07旧文件入口兼容，但新UI只能调用asset_id会话命令。

## M4实施细则

1. 集成测试覆盖复制Vault、会话恢复、缺失/断链、写失败保护。
2. 比较会话操作前后manifest.json、tables/sources.parquet、document_assets.json未被越权修改。
3. 复跑：

```powershell
cargo test -p cistella-core
cargo check -p cistella-desktop
pnpm build
```
