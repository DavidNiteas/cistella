# 02. 施工路线图：Source 分析工作区 MVP

## 阶段 0：定位确认

- 确认 Source 工作区是分析入口，不是数据源本体
- 确认它只承接库内分析浏览
- 确认和阅读/文献管理工作区的边界

## 阶段 1：MVP 结构

- 明确总览、表格、可视化、指标、导出五个任务面
- 明确默认进入面与切换关系
- 明确空状态和状态反馈

## 阶段 2：联动与导出

- 把 Source 工作区和当前 vault 的连接方式固化
- 明确排行和检索结果的导出方式
- 明确结果与库之间的上下文联动

## 阶段 3：收尾验收

- 检查是否仍然依赖旧的分析壳层叙事
- 检查导出与筛选是否可独立完成
- 更新开发状态与施工日志

## 里程碑

- M1：工作区定位清晰
- M2：MVP 面板成形
- M3：导出联动完成
- M4：验收归档

## 验收要点

- 用户能在单独工作区中完成分析任务
- 导入后的库可直接进入分析浏览
- 分析结果可导出并复用
- 该工作区不侵入阅读和库管理主线



## 施工准入要求

进入实现前，至少满足：
- Source 工作区的默认进入面和切换关系已固定。
- 当前筛选、最近查询、回放和导出形成最小闭环。
- 当前库上下文的展示不依赖临时命令语义。
- 空状态和状态反馈可独立支撑分析流。
