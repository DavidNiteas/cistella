# 05. 目标与设计：Source 分析工作区 MVP

## 1. 工单目标

建立一个独立的 Source 分析工作区，承接建库、检索、排行与分析，并把它稳定地定位为 cistella 中的一个工作区，而不是一个命令集合。

## 2. 北极星

用户可以在一个专门工作区里完成 source 数据的浏览、筛选、分析与导出，而不用进入底层库或命令层。

## 3. 范围边界

### 本工单包含
- Source 工作区入口与定位
- 概览卡片与关键指标
- 检索、筛选、排行与导出任务流
- 分析结果与当前库的联动
- 工作区内的基础空态与反馈
- 与库工作区之间的连接路径

### 本工单不包含
- 阅读器
- 文献笔记
- 多数据源融合策略
- 完整数据建模升级

这些内容留给后续工单。

## 4. 设计结论

Source 分析工作区是 cistella 当前最清晰的分析能力落点，应当以工作区的方式呈现，而不是以命令或脚本的方式呈现。它需要和库工作区形成明显分工：库负责资产入口，Source 工作区负责分析浏览。

## 5. 关键交付物

- Source 工作区信息架构
- MVP 功能列表
- 关键指标说明
- 检索与导出任务流说明
- 与库工作区的边界说明

## 6. 成功标准

- 用户能在单独工作区中完成分析任务
- 导入后的库可直接进入分析浏览
- 分析结果可导出并复用
- 该工作区不侵入阅读与管理主线
- 后续新增功能时不会破坏库/分析分层

## 7. 决策结论

- MVP 只覆盖库内 source 级数据，不扩展到全文语义或文献级融合。
- 导出优先支持 CSV；现有 Excel 导出作为兼容能力保留，不增加更多格式承诺。
- 检索采用字段筛选与名称关键词匹配，不在本工单引入全文语义检索。
- 表格是主结果面，可视化是排行与比较的辅助面；指标面负责解释口径。
- 最近查询记录作为工作区级轻量本地偏好保留，不写入 Vault manifest。

## 8. 施工准入判定

### 已满足的施工前条件
- 工作区定位已明确为分析入口，不是数据源本体。
- 概览、表格、可视化、指标、导出五个任务面已定义。
- 当前库上下文与最近查询历史已进入可施工范围。
- 与库工作区的边界已明确。

### 施工期关闭标准
- 当前筛选、最近查询、回放和导出之间的上下文闭环不再需要重解释。
- 该工作区不再侵入阅读和库管理主线。
- 新增分析功能只在本工作区内扩展，不重新定义库边界。
