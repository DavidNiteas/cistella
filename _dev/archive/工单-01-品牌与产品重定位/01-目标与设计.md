# 01. 目标与设计：品牌与产品重定位

## 1. 工单目标

将仓库从旧的 OpenAlex Analysis 叙事，重定位为 **cistella**：

- 本地化个人文献保管库 + 阅读/管理/分析工作台
- 桌面应用成为唯一用户入口
- CLI 不再作为对外产品功能
- OpenAlex 降级为重要数据源/导入适配器，而不是产品中心

## 2. 北极星

用户打开 cistella 时，感知到的是一个“可携带、可长期保存、可持续积累的个人文献库”，而不是一个分析命令集合。

## 3. 范围边界

### 本工单包含
- 仓库/产品名称迁移为 cistella
- 桌面应用名称、窗口标题、前端品牌文案迁移
- Core/Studio crate 命名迁移的方案确定
- CLI 对外定位移除
- 旧文档、README、架构叙事迁移
- 工程治理入口建立并接入 cistella 叙事

### 本工单不包含
- Vault 目录结构最终定版
- 文献条目模型与阅读功能设计
- OpenAlex 导入流程的功能细化
- Source 分析工作区的交互实现

这些内容留给后续工单。

## 4. 设计结论

### 4.1 产品叙事
cistella 的核心叙事是：

- 库即一切
- 复制即走
- 打开即用
- 本地优先
- 免安装可携带
- 桌面优先

OpenAlex 只是第一批重要数据源之一。

### 4.2 用户入口
唯一对外入口是桌面应用。CLI 仅保留为内部开发辅助，不能成为正式产品主路径。

### 4.3 命名原则
- 产品名统一为 `cistella`
- crate / 包名可逐步迁移为 `cistella-*`
- 旧的 `openalex-analysis-*` 命名仅作为过渡期事实，不再作为产品叙事

### 4.4 文档原则
所有面向用户/开发者的高层文档都要改写成 cistella 语境，不再以 OpenAlex 为标题中心。

## 5. 关键交付物

- 统一品牌命名清单
- crate 命名迁移清单
- 桌面应用文案迁移清单
- CLI 退出策略
- 旧文档迁移清单
- 新产品总述文档

## 6. 成功标准

本工单完成后，仓库应满足：

1. 外部可识别品牌统一为 cistella
2. 用户看到的是桌面工作台，不是 CLI 工具
3. OpenAlex 的角色清晰退到“数据源/适配器”
4. 后续工单可在 cistella 叙事下继续推进，而无需反复解释产品定位

## 7. 决策结论

- crate 与 package 立即完成 cistella 命名迁移；旧目录名只作为仓库历史路径，不作为产品叙事。
- CLI 不再保留为对外产品入口；必要的验证脚本只作为开发辅助。
- 发布产物、窗口标题、应用标识与用户文案统一使用 cistella。
- 第一轮旧 OpenAlex 文档只保留来源/历史语义，产品主文档全部切换为 cistella 语境。
