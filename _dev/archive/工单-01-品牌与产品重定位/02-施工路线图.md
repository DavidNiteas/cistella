# 02. 施工路线图：品牌与产品重定位

## 阶段 0：确认边界

- 确认 cistella 为最终产品名
- 确认桌面应用为唯一对外入口
- 确认 CLI 不再作为产品功能发布

## 阶段 1：仓库叙事切换

- 修改顶层 README / 架构说明 / 设计说明
- 建立 `_dev` 工程治理入口
- 将 OpenAlex 语义从产品中心迁移为数据源语义

## 阶段 2：应用品牌切换

- 修改 Tauri 应用标题、页面标题、欢迎文案、空状态文案
- 修改前端品牌词与工作区命名
- 修改图标、程序名、版本输出中的品牌词

## 阶段 3：crate 与包名迁移方案

- 决定是否同步重命名 Rust crate 和前端 package
- 若暂不重命名，明确兼容期策略
- 若重命名，列出影响范围与一次性替换顺序

## 阶段 4：CLI 退出与收束

- 清理对外 CLI 使用说明
- 将 CLI 仅保留在开发期或彻底移除
- 确保发布产物不再鼓励命令行使用

## 阶段 5：收尾验收

- 全仓库搜索旧品牌词
- 验证新品牌词在主文档、应用标题、UI 文案中已统一
- 更新开发状态

## 里程碑

- M1：cistella 叙事落地
- M2：应用层品牌统一
- M3：CLI 对外退场
- M4：品牌重定位完成并转入库模型工单

## 验收要点

- 仓库主文档不再以 OpenAlex Analysis 为中心
- 用户主流程不再依赖 CLI
- 后续工单可以直接使用 cistella 语境继续施工
