# 发布检查清单

本清单适用于工单 14「免安装发布与 portable 体验」M3 阶段完成后的发布验证。

## 1. 构建环境要求

- **操作系统**：Windows 10/11（64 位）。Tauri NSIS/MSI 安装包目前仅在 Windows 构建。
- **Node.js**：LTS 版本（建议 ≥ 20），需安装 `pnpm`。
- **pnpm**：11.x（仓库 `package.json` 中通过 `packageManager` 锁定）。
- **Rust**：稳定版（stable），版本需满足 `Cargo.toml` 中的 `edition = "2024"`。
- **Tauri CLI**：通过 `pnpm tauri` 调用，已作为 `cistella-desktop` 的 devDependency 安装。
- **Windows 依赖**：
  - WebView2 运行时（Windows 10/11 通常已内置）。
  - 用于 NSIS 安装包生成：Tauri CLI 会自动下载 NSIS 工具链；也可提前通过 `pnpm tauri info` 检查。

## 2. 构建命令清单

按顺序执行：

```bash
# 1. 前端资源构建
pnpm build

# 2. Tauri 发布构建（生成 MSI、NSIS 安装包）
pnpm --dir crates/openalex-analysis-studio tauri build

# 3. 打包 portable zip（依赖步骤 2 生成的 release exe）
node crates/openalex-analysis-studio/scripts/make-portable.js
```

说明：
- `pnpm build` 会触发 `crates/openalex-analysis-studio` 下的 `tsc && vite build`。
- `tauri build` 会编译 Rust 后端、生成安装包，耗时较长，需要完整构建环境。
- `make-portable.js` 不会自动运行 `tauri build`，仅基于已有的 `target/release/cistella.exe` 制作 zip。

## 3. 产物路径与命名

构建成功后应出现以下产物：

| 产物类型 | 预期路径 | 命名示例 |
|---|---|---|
| MSI 安装包 | `target/release/bundle/msi/` | `cistella_0.1.0_x64_en-US.msi` |
| NSIS 安装包 | `target/release/bundle/nsis/` | `cistella_0.1.0_x64-setup.exe` |
| Portable zip | `target/release/` | `cistella-0.1.0-portable.zip` |

> 版本号统一使用 workspace `version`（`Cargo.toml` 中 `workspace.package.version`，当前为 `0.1.0`）。`tauri.conf.json` 与 `package.json` 的 `version` 应与之保持一致。

## 4. 签名 / 未签名说明

- **当前状态**：产物为 **未签名** 二进制。
- 未签名的 Windows 可执行文件在启动时可能触发 Microsoft Defender SmartScreen 或「来自未知发布者」提示，用户需点击「仍要运行」。
- 若后续需要正式分发，建议申请代码签名证书（OV 证书或 EV 证书）并对 MSI / EXE 进行签名。
- 本阶段不引入签名流程，也不提交任何证书或密钥。

## 7. 产物格式校验

Portable zip 必须是真正的 ZIP 格式，且保留 portable 模式标记目录：

```bash
# 1. 校验 zip 文件格式
file target/release/cistella-0.1.0-portable.zip
# 预期输出应包含 "Zip archive data"，而非 "POSIX tar archive"。
```

```powershell
# 2. 校验可正常解压（PowerShell）
Expand-Archive -Path target/release/cistella-0.1.0-portable.zip -DestinationPath target/release/_portable_check -Force

# 3. 确认 portable 模式标记目录存在
Test-Path target/release/_portable_check/cistella-0.1.0-portable/cistella-portable
# 应输出 True
```

也可使用 Windows 资源管理器双击解压并目视检查 `cistella-portable/` 目录存在。

> **注意**：当前 portable zip 在 Windows 上使用 .NET `ZipFile` 生成，条目路径分隔符为反斜杠。Windows 资源管理器、PowerShell `Expand-Archive`、7-Zip、Bandizip 等均可正常识别；部分严格 POSIX 的 `unzip`（如 MSYS/Cygwin）可能会对反斜杠路径分隔符发出警告。目标用户请在 Windows 环境下使用上述原生或常见工具解压。
