# 02. 施工路线图：免安装发布与 portable 体验

## 阶段门说明

本工单采用 M1/M2/M3 三阶段推进。四件套已完成；M1 尚未授权。

## M1：Portable 模式与数据边界

### M1 交付物

- `AppDirectories` 抽象（`cistella-core/src/app_dirs.rs`）。
- portable 模式检测逻辑：`is_portable_mode(exe_dir)`。
- 最近库列表 `recent_vaults.json` 读写（支持相对路径与绝对路径）。
- 应用配置 `config/app.json` 读写接口。
- Tauri 命令：`app_directories`、`recent_vaults`、`update_recent_vaults`、`is_portable_mode`。
- UI 首页/设置页显示当前模式与最近库列表。
- 迁移接口 Core 定义：`migrate_vaults_to_portable`、`migrate_vaults_to_installed`（M1 可只做接口与基础 Tauri 命令，UI 按钮可延后到 M2）。
- 新增集成测试 `crates/openalex-analysis-core/tests/工单14_m1_portable模式与数据边界.rs`。

### M1 明确不做

- 不做完整迁移向导 UI。
- 不做 Tauri 打包配置（ installer / portable zip 延后到 M2）。
- 不做单文件 exe、自动更新、数字签名。
- 不做跨平台 macOS/Linux portable 路径细节（M2 考虑）。
- 不改动 Vault 内部格式。

### M1 关闭标准

- `cargo fmt --check` 通过。
- `cargo test -p cistella-core --lib` 通过。
- 新增集成测试 `cargo test -p cistella-core --test '工单14_m1_*'` 通过。
- `cargo test -p cistella-core` 全绿。
- `cargo test -p cistella-desktop` 全绿。
- `cargo check -p cistella-desktop` 通过。
- `pnpm build` 通过。
- 代码审阅确认：portable 模式不泄漏数据到系统目录；安装模式不写入 exe 目录；最近库路径在 portable 模式下为相对路径。

### M1 验收命令（暂定）


> 注：以上命令在 M1 施工阶段执行，作为施工完成的验证证据；设计阶段不得提前执行并以其结果作为设计依据。

## M2：打包产物与迁移向导

### M2 交付物

- Tauri 打包配置（`crates/openalex-analysis-studio/src-tauri/tauri.conf.json`）：
  - 启用 Windows msi + nsis 两种 installer。
  - portable zip 不通过 Tauri 内置 `portable` 目标生成，而是由构建后脚本 `crates/openalex-analysis-studio/scripts/make-portable.js` 组装。
- portable zip 内容脚本（`crates/openalex-analysis-studio/scripts/make-portable.js`）：构建后复制 `cistella.exe`、创建空 `cistella-portable/` 目录、生成 `README-portable.txt`。
- 迁移向导 UI：
  - 设置页「迁移」入口打开向导对话框。
  - 用户可选择本地 Vault 目录，选择目标模式（portable / installed），预览目标路径，确认后执行迁移。
  - 迁移成功后刷新最近库列表。
- 备份/恢复向导 Core 接口与 UI（M2 基础版）：
  - Core：`backup_vault(vault_path, backup_path)` 将 Vault 目录打包为 zip。
  - Core：`restore_vault(backup_path, target_path)` 将 zip 解压到目标路径。
  - 使用 `zip` crate 处理 zip 打包/解压；该依赖声明在 `crates/openalex-analysis-core/Cargo.toml`（非 workspace `Cargo.toml`）。
  - UI：设置页提供备份/恢复按钮与路径选择。
- 跨平台路径细节：M2 先完成 Windows；macOS / Linux 的 `dirs::data_local_dir()` 路径在 Core 层已通过 `dirs` crate 处理，打包配置仅针对 Windows（当前目标平台）。

### M2 关闭标准

- `cargo fmt --check` 通过。
- `cargo test -p cistella-core --lib` 通过。
- 新增集成测试 `cargo test -p cistella-core --test '工单14_m2_*'` 通过，覆盖：
  - 备份 Vault 为 zip。
  - 从 zip 恢复 Vault。
  - 迁移接口在 portable/installed 模式下的端到端路径。
- `cargo test -p cistella-core` 全绿。
- `cargo test -p cistella-desktop` 全绿。
- `cargo check -p cistella-desktop` 通过。
- `pnpm build` 通过。
- `cargo tauri build` 或等效打包命令能生成 installer 与 portable zip（在 Windows 环境可执行部分）。
- 不影响 M1 功能。

## M3：发布流程与可选增强

### M3 交付物

- 版本号规范：统一使用 workspace `version`，产物命名包含版本号（如 `cistella-0.x.x-setup.exe`、`cistella-0.x.x-portable.zip`）。
- 发布检查清单文档：`_dev/工单-14-免安装发布与portable体验/发布检查清单.md`，包含构建命令、产物路径、签名/未签名说明、回归测试步骤。
- 自动更新检测接口（占位）：
  - Tauri 命令 `check_update()` 返回当前版本与远端最新版本（本地静态 JSON 或本地文件模拟，不做真实网络请求）。
  - UI 设置页显示当前版本与是否有更新提示。
- 离线安装包/单文件 exe 评估：在文档中说明当前 Tauri 架构下是否可行、风险与决策（建议延后或不做）。
- 回归测试脚本：一键运行 `cargo test` + `pnpm build` + 打包产物存在性检查。

### M3 关闭标准

- `cargo fmt --check` 通过。
- `cargo test -p cistella-core --lib` 通过。
- 新增集成测试 `cargo test -p cistella-core --test '工单14_m3_*'` 通过（如版本解析、更新检测占位）。
- `cargo test -p cistella-core` 全绿。
- `cargo test -p cistella-desktop` 全绿。
- `cargo check -p cistella-desktop` 通过。
- `pnpm build` 通过。
- 发布检查清单文档完整。
- 产物命名规范在打包配置中体现。
- 不影响 M1/M2 功能。

## 共同约束

- portable 模式与安装模式的数据不得混用。
- 所有文件写入必须原子替换；失败时保持原数据完整。
- 最近库路径在 portable 模式下必须为相对路径。
- 新增依赖必须写入对应 crate 的 `Cargo.toml`，并在施工日志中登记。
- 测试必须覆盖 portable 检测、最近库读写、相对路径解析、模式隔离、迁移失败回滚。
