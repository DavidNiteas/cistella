# 01. 目标与设计：文献资产与收纳中心

## 工单定位

工单 08 在工单 06 的文献条目和工单 07 的 PDF 关联之上，建立 cistella 的文献资产层与收纳入口。它把“一个条目有哪些可阅读文件”从简单文件列表提升为可迁移、可识别、可管理的用户资产模型，为后续阅读会话、全文检索、笔记标注和多数据源导入提供稳定基础。

## 北极星

用户可以把本地文献文件收入 Vault，cistella 能够稳定识别、保存���去重和管理这些文件；复制或迁移 Vault 后，库内文献资产仍然可以被条目找到并打开。

## 范围

### 本工单包含

- 将文献文件从条目内嵌列表演进为独立 `DocumentAsset` 语义，同时兼容工单 07 的既有 JSON。
- 库内文件收纳、外部链接、资产元数据和资产状态。
- 资产与 `LiteratureItem` 的一对多关系。
- PDF 文件的大小、扩展名、媒体类型、导入时间和内容哈希。
- 重复文件检测与明确的重复处理结果。
- 正文、补充材料、版本和其他 PDF 资产类型。
- 将外部链接复制为库内副本的显式迁移动作。
- 文件缺失、损坏、重复、不可读等状态反馈。
- 不污染 `manifest.json`、Source 分析表和 OpenAlex 原始数据。

### 本工单不包含

- 内置 PDF 阅读器。
- 阅读会话、页码进度和阅读历史。
- 全文提取、全文索引和搜索排序。
- 笔记、标注、引用片段和知识图谱。
- 云同步、多设备冲突解决。
- DOI、OpenAlex 或其他外部来源的自动元数据合并；这些进入工单 12。

## 领域边界

### LiteratureItem：文献身份与用户元数据

`LiteratureItem` 表示用户认为“这是同一篇文献”的逻辑条目，承载标题���作者、年份、标签、收藏和阅读状态。

### DocumentAsset：用户拥有或引用的具体文件

`DocumentAsset` 表示一个具体的文件资产，承载文件位置、资产类型、文件指纹、存储方式和可用状态。一个条目可以关联多个资产，一个资产只属于一个条目。

推荐资产类型：

```text
primary       正文/主文件
supplement    补充材料
version       另一版本或修订稿
appendix      附录文件
other         其他相关 PDF
```

推荐存储方式：

```text
vault         Vault 内可复制文件
external      Vault 外部链接，不保证可迁移
```

## 已拍板的 B 层设计

### 1. 独立资产记录与兼容演进

新增用户数据文件：

```text
user/document_assets.json
```

资产记录使用 cistella 自生成 UUID `asset_id`，不使用路径、哈希或外部 ID 作为主标识。工单 07 的 `LiteratureItem.files` 与 `default_file_id` 作为读取兼容层保留；工单 08 新写入以 `DocumentAsset` 为权威，读取旧数据时按确定性规则映射为资产视图，不在无必要时重写旧文件。

`DocumentAsset` 最小字段：

```text
asset_id
item_id
asset_kind
storage_kind
relative_path / external_path
display_name
media_type
file_size
content_hash
imported_at
status
```

路径字段在 JSON 中仍使用统一 `path`，由 `storage_kind` 区分其语义；库内路径必须是 Vault 根目录内相对路径，外部路径必须是绝对路径。

### 2. 库内收纳路径

库内资产固定落位：

```text
files/<item_id>/<asset_id>-<safe_filename>.pdf
```

使用 `asset_id` 参与文件名，避免同名覆盖；原始展示名单独保存。加入 Vault 通过临时文件写入后原子发布，既有文件与用户数据失败时均不被破坏。

### 3. 内容哈希与重复规则

- 使用 SHA-256 计算文件内容哈希。
- 同一条目内，若哈希相同则返回“已存在资产”结果，不再复制第二份文件。
- 不同条目之间不自动合并，也不自动把资产从一个条目移动到另一个条目。
- 哈希只用于重复检测和完整性提示，不替代 `asset_id`。
- 首版不做全库内容去重索引；跨条目重复只报告候选，不自动处理。

### 4. 迁移与删除边界

- 外部链接转库内副本必须是显式动作，成功复制并写入新资产后才可由用户选择移除外部链接。
- 移除资产默认不删除库内文件，保护用户数据；提供单独“清理未引用库内文件”能力留给后续工单。
- 文件缺失只更新可用��判断，不自动删除资产记录。
- 文件损坏通过重新计算哈希或打开失败反馈，不静默覆盖原资产。

### 5. 资产状态

资产状态是可重新计算的运行状态，不作为用户事实覆盖：

```text
available
missing
unreadable
invalid
external_unavailable
```

读取资产时按当前文件系统重新判断状态；JSON 只保存必要的用户声明和导入信息。

### 6. 工作区边界

- Vault 工作区负责收纳、资产列表、迁移和文件健康状态。
- Reading 工作区消费资产，不重新定义资产模型。
- Source 工作区不修改用户资产。
- `manifest.json` 与分析表不保存用户资产记录。

## 施工硬边界

- 不破坏工单 06/07 的旧 JSON 可读性。
- 不以哈希、路径或外部 ID替代本地 UUID。
- 不自动跨条目合并，不静默删除用户文件。
- 不引入全文解析、笔记、同步或外部元数据自动合并。

## 阶段门结论

A 层方向由用户授权经理收口；B 层模型、兼容、路径、哈希、重复、迁移和删除语义已拍板；施工细则可直接执行。工单 08 准入施工。
