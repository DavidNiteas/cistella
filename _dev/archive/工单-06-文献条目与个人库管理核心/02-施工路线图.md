# 02. 施工路线图：文献条目与个人库管理核心

## 阶段 0：阶段门已通过

- Vault 契约已达成。
- 来源事实、用户数据、派生数据边界已明确。
- 条目标识、来源关系、用户字段和数据落位已拍板。

## 阶段 1：模型落位

- 建立文献条目与来源记录模型。
- 建立 Vault 用户数据文件的读取、写入和原子替换。
- 为后续 Reading 提供稳定 item_id 与 reading_status。

## 阶段 2：管理闭环

- 实现条目浏览与关键词筛选。
- 实现创建、编辑、删除和收藏切换。
- 实现标签维护与阅读状态切换。
- 桌面 Reading 工作区回显当前 Vault 的条目状态。

## 阶段 3：验收与交接

- 对照成功标准验收。
- 验证用户数据随 Vault 目录存在且不写入分析 manifest table。
- 为 Reading 后续工单保留条目入口。
- 回填迁移、遗留与后续扩展边界。

## 施工协议

- 不修改 Source 分析的数据契约。
- 不把用户条目写入 source 分析表。
- 不引入数据库、云同步或新的外部服务依赖。
- 用户数据更新失败时保留原文件，不能留下半写入 JSON。

## 关闭标准

- core 测试覆盖空库、写入/读取、编辑和非法数据/失败保护的关键路径。
- 桌面构建通过，Reading 工作区不再只是静态占位。
- 条目状态、标签和收藏在重启后可恢复。
- 工单 07 可以只依赖 item_id 与 reading_status 接入阅读流程。

cargo test -p cistella-core
