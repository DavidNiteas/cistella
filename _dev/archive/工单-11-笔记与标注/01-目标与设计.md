# 01. 目标与设计：笔记与标注

## 北极星与范围

cistella 在 portable Vault 中提供文献级 Markdown 笔记与基�� PDF 页码、文本片段的 quote 标注。复制整个 Vault 后，笔记、标注和稳定身份必须可读取、验证和使用；不得依赖原机器路径、外部服务或可删除的检索索引。

本工单只交付：文献级 Markdown 笔记、归属于 Vault 内可用 PDF 资产的 quote 标注、页码/文本锚点的运行态解析，以及独立 Notes 工作区与受控 Reading 打开入口。

明确不交付 OCR、云同步、协作、知识图谱、跨格式批注、坐标绘制、笔记正文全文检索、自动重绑/自动恢复，以及对外部 PDF 阅读器精确跳页的承诺。当前 Reading 不是内置 PDF 渲染器；UI 仅展示页码和引用信息，资产打开只走既有受控入口。

## 身份、不变量与权威边界

- 公共模型、Core API、Tauri 契约和 UI 状态仅使用 `item_id`、`asset_id`、`note_id`、`annotation_id` 及受限文本/状态；不得持久化或返回 Vault/PDF 绝对路径、盘符、用户名、临时路径。
- `note_id`、`annotation_id` 是稳定 UUID；`item_id`、`asset_id` 复用既有权威身份。文件路径只是 Core 内部从已验证 ID 推导的细节。
- 笔记和标注是 `user/` 下的权威用户数据；不得依赖、写入或由 `derived/search/` 恢复。删除、损坏或重建 Search 索引不得影响其事实。
- 笔记只归属一个 `item_id`；标注只归属一个 `item_id + asset_id`。删除笔记不自动删除标注；删除文献/资产也不自动删除笔记或标注，读取时报告孤儿或不可用。
- PDF 变化、缺失、损坏、外链变化均不得改写已捕获锚点或猜测绑定新内容。未来恢复必须由用户明确确认并写入新锚点；首版没有候选自动重绑。

## 权威文件布局与格式

### 一记录一文件

```text
user/
├── notes/
│   └── <note_id>.md
└── annotations/
    └── <annotation_id>.json
```

不得建立集中式 `notes.json`、`annotations.json`，不得混入 `manifest.json`、`tables/`、`files/`、`user/reading_sessions.json` 或 `derived/search/`。单条记录仅修改自己的权威文件，以限制写入范围与损坏面。

### Note：`note/v1`

文件 `user/notes/<note_id>.md` 是 UTF-8 Markdown，前置受限 front matter：

```markdown
---
cistella: note/v1
note_id: <uuid>
item_id: <uuid>
created_at: <UTC RFC3339>
updated_at: <UTC RFC3339>
archived_at: <UTC RFC3339 or null>
title: <plain text>
---
<Markdown body>
```

- `note_id` 必须与文件名（去掉 `.md`）完全一致；一个 `item_id` 可有多条笔记。
- `title` 独立于正文 Markdown 标题，必须为纯文本，最大 240 个 Unicode 标量值；`markdown_body` 最大 512 KiB UTF-8，可以为空。
- 采用手写受限解析器：只接受固定键、固定顺序、每键单行值和成对分隔线；拒绝重复/未知/缺失键、缺分隔线、非法 UUID/RFC3339、嵌入换行和格式漂移。不得添加 YAML 依赖或宽泛 YAML 语义。
- `created_at` 创建后不变，`updated_at` 仅随成功写入更新。`archived_at` 是固定 front matter 字段：未归档时严格为 `null`；`archive_note` 成功时以 UTC RFC3339 写入时间。归档是单文件、可逆的逻辑状态：默认列表排除归档笔记，按 ID 读取仍可见；不创建新目录、不物理删除。格式错误、文件名/内容 ID 不一致或不安全文件对象分别返回结构化错误（例如 `MalformedNote`、`NoteIdentityMismatch`、`UnsafeUserRecordPath`），不得静默修复或覆盖。
- `revision` 不写入 front matter：读取时对原始笔记文件字节作 SHA-256；更新/归档必须携带 `expected_revision`，不匹配返回 `NoteConflict`，禁止 silent last-write-wins。前端保留草稿，要求刷新、比较或未来显式覆盖。

### Annotation：`annotation/v1`

文件 `user/annotations/<annotation_id>.json` 保存受版本约束的 JSON：

```text
format_version = annotation/v1
annotation_id
item_id
asset_id
created_at
updated_at
kind = quote
anchor
```

`anchor` 固定包含：`asset_id`、`asset_content_hash_at_capture`、`extractor_version`、`page_number`、`selected_text`、`normalized_text_hash`、`prefix_context`、`suffix_context`。

- `annotation_id` 必须与文件名（去掉 `.json`）一致；顶层 `asset_id` 与 `anchor.asset_id` 必须一致；首版 `kind` 只接受 `quote`。
- `page_number` 为 1-based；`selected_text` 长度 1–8,192 个 Unicode 标量值；`prefix_context`、`suffix_context` 各最多 256 个 Unicode 标量值。
- `normalized_text_hash` 从受版本化的规范化文本计算；`asset_content_hash_at_capture` 是受控读取 Vault PDF 时的 SHA-256；`extractor_version` 必须持久化。
- 创建时必须验证 `item_id + asset_id` 归属正确、资产是 Vault 内存储且当前为 `available`，受控提取锚点后再原子写入。外部资产可以有文献笔记，但不得创建片段标注。

## 锚点运行态

状态运行时计算，绝不覆盖 Annotation 中的用户事实：

| 状态 | 含义 |
|---|---|
| `resolved_exact` | 当前 Vault PDF 的内容哈希、提取器版本、页码、文本和上下文精确匹配。 |
| `unavailable_missing_asset` | 资产记录或库内文件缺失。 |
| `unavailable_external_asset` | 资产为外部链接，不能作为 portable 解析目标。 |
| `unavailable_unreadable_asset` | PDF 不可读、损坏或受控提取失败。 |
| `invalidated_content_changed` | 当前 PDF SHA-256 与捕获值不同。 |
| `invalidated_page_out_of_range` | 页码超出当前文档范围。 |
| `invalidated_text_not_found` | 指定页/上下文找不到文本。 |
| `invalidated_ambiguous_text` | 文本或上下文多处匹配，不能唯一定位。 |
| `unsupported_extractor_version` | 当前解析器不能可靠解释捕获版本。 |
| `orphaned_item` | 所属文献条目不再存在。 |

解析先验证文献/资产存在与归属，再验证资产类型、可读性、内容哈希、提取器版本、页码和文本唯一性。PDF 替换必须立即 `invalidated_content_changed`，不得展示为已定位。解析失败不得影响文献、笔记、ReadingSession、Search 或其他资产。

## 安全、原子写入与错误

所有读写只允许精确落在 `user/notes/`、`user/annotations/`，以已验证 UUID 推导文件名。必须拒绝路径逃逸、symlink、junction、reparse point、悬空链接、目录/普通文件类型错误和文件名/内容 ID 不一致；前端绝不提供路径。

M1 的 Windows 安全访问不采用“路径预检查后再用普通路径 API”的模式：`Vault::open` 固定并验证 Vault root directory handle，随后 `user`、`notes`、`annotations` 以及记录文件均通过单组件名称、`NtCreateFile` 的 `RootDirectory`、`OBJ_DONT_REPARSE` 和已验证句柄访问；枚举结果先按 `IO_STATUS_BLOCK.Information` 截断，再由受长度检查的变长记录解析器读取。读取、枚举、替换、删除和临时文件清理不得回退到 `fs::read`、`read_dir`、`OpenOptions`、`remove_file` 或完整路径 `MoveFileExW`。已观察到的链接/reparse/对象类型异常统一拒绝；检查后目录项替换时，操作仍只作用于已打开对象或已验证目录句柄中的最终目录项，绝不穿越 reparse target。

M1 笔记 CAS 使用 `Global\cistella-note-cas-<sha256(vault_id)>-<note_id>` 命名内核 mutex：锁名不含绝对路径，复制 Vault 保留 `vault_id` 因而共享同一锁，不同 Vault 由哈希命名空间隔离。mutex 使用显式 owner-only SDDL ACL（Owner Rights），允许同一 Windows 账户在不同 session 共享，拒绝无关账户抢先持锁；Global 对象创建或访问失败返回结构化 `NoteCasLockUnavailable`，不回退 Local 或无锁更新；等待有界，超时同样是错误。

单记录 create/update/archive 的协议为：完整验证 payload → 在同一精确目录创建命名临时文件 → 写入并完成必要 flush → 原子替换目标文件 → 失败时尽力清理临时文件。失败不得损坏旧目标文件。笔记、标注保持松耦合，不引入跨文件强事务。

公共错误至少区分：无 Vault/过期请求、记录不存在、格式或版本不兼容、ID 不一致、不安全路径、对象类型错误、权限/IO、`NoteConflict`、归属不符、外部资产禁止标注、资产不可用、锚点输入越界与运行态不可定位；错误不得泄露绝对路径。

`archive_note` / `delete_annotation` 的施工期 TBD 已由经理于 2026-08-26 收口：`archive_note` 仅在原 `<note_id>.md` 的 `note/v1` 受限 front matter 中将 `archived_at: null` 原子更新为 UTC RFC3339；默认列表不返回归档记录，按 ID 读取仍可见，不创建新目录且不物理删除。`delete_annotation` 是用户显式、不可逆的单文件物理删除，只允许精确安全路径 `<annotation_id>.json`；不存在返回结构化 `NotFound`，不得改动其他记录。二者均不得扩大 `user/notes/`、`user/annotations/` 白名单或引入跨文件事务。

## Core、Tauri 与 Notes UI 边界

Core 返回 ID、受限文本、时间、revision、版本与结构化状态，内部自行定位文件。Notes 不读写 Search，Search 不在本工单索引笔记正文；PDF 提取和 Reading/资产操作必须走受控身份入口。

Tauri 的 ID-only 契约为：

```text
list_notes(item_id?) / get_note(note_id)
create_note(item_id, title, markdown_body, request_context)
update_note(note_id, expected_revision, title, markdown_body, request_context)
archive_note(note_id, expected_revision, request_context)
list_annotations(item_id?) / get_annotation(annotation_id)
create_annotation(item_id, asset_id, page_number, selected_text, prefix_context, suffix_context, request_context)
delete_annotation(annotation_id, request_context)
annotation_resolution(annotation_id, request_context)
open_annotation_asset(annotation_id, request_context)
```

`request_context` 固定包含 `expected_generation`、`expected_vault_path`。所有写入、受控打开、耗时 PDF 解析在选择 Vault、启动副作用和提交副作用前均验证 generation + Vault path 双快照；过期 A→B、A→B→A 请求必须零副作用且不影响当前 Vault。公共返回不得有真实路径。

Notes 为独立工作区：笔记列表与文献筛选、Markdown 标题/正文编辑、保存/冲突/格式错误状态、标注面板及 no-vault/loading/empty/error 状态。标注面板展示页码、引用和失效原因；仅 `resolved_exact` 可显示“受控打开关联资产”。打开复用 `item_id + asset_id` 的既有 Reading/资产入口；不伪造外部 opener 跳页成功。

## 固定决议

不引入面向业务的新依赖；front matter 继续手写解析。为闭合 M1 的平台安全边界，允许使用既有锁定版本的 Windows 系统 API 绑定（`windows-sys`）和现有哈希能力，不改变用户权威数据格式或 manifest/table 语义。Markdown 正文未来可引用 `annotation_id`，但本工单不做双向索引或跨文件事务。性能先测量；未来若要索引，只能为可删除重建的派生数据，不能成为权威来源。
