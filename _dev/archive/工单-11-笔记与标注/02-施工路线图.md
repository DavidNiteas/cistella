## 共同约束

- 公共接口只用 `item_id`、`asset_id`、`note_id`、`annotation_id` 和受限文本/状态，绝不公开或保存绝对路径。
- 用户权威写入只允许 `user/notes/`、`user/annotations/`；不得改写 `manifest.json`、`tables/`、`files/`、`derived/search/`、资产权威记录或阅读会话。M3 只有通过既有 Reading 受控打开语义时才可沿用已批准的 reading session 写入。
- Search 不索引笔记；锚点不依赖 Search；外部 PDF 不可标注；PDF 变化或失效绝不自动重绑。
- 各里程碑须用精确路径/字节快照或等价断言证明写入边界；覆盖临时文件、逃逸、symlink/junction/reparse、对象类型错误与文件名/内容 ID 不一致。

## M1：Core 模型、Markdown 与 portable 原子存储

**交付物**
- `Note`、`Annotation`、quote anchor、格式版本、结构化错误、ID-only DTO；`note/v1` 受限 front matter 与 `annotation/v1` JSON 的解析/序列化。
- `user/notes/<note_id>.md`、`user/annotations/<annotation_id>.json` 的单记录 create/read/update、按 `item_id` 列表；笔记 raw-file SHA-256 revision 与 `NoteConflict`。
- UUID 文件名推导、目录创建、no-follow/reparse 防护、文件名/内容身份校验、原子替换与临时文件清理。
- 不兼容版本、格式损坏、遗留临时文件的隔离或结构化失败，不自动覆盖用户文件。
- 实现已收口的单文件语义：`archive_note` 在原 Markdown 的固定 `archived_at` 字段写 UTC RFC3339，默认列表排除但按 ID 可读取，不物理删除；`delete_annotation` 仅对精确安全路径的 `<annotation_id>.json` 执行用户显式不可逆删除，不存在返回结构化 `NotFound`，不得改动其他记录。

**明确不做**：不读 PDF、不创建/解析锚点，不做 Tauri/UI；不改 Search、ReadingSession、资产、文献表、`derived/`，不做自动重绑、集中索引或跨文件事务。

**关闭标准**
- 公共记录和测试均 ID-only；复制 Vault 后同 ID 可读取笔记/标注，且没有原/副本绝对路径泄漏。
- 验证 title/body/text/context 上限、受限格式、版本、ID 一致性；原始笔记字节变更必触发 revision conflict。
- 写入失败保留旧文件并清理临时文件，变更仅发生在两个允许目录。
- 逃逸、链接/reparse、悬空链接、类型错、损坏/不兼容记录均被拒绝或结构化隔离。
- 完成实施、不同实例初审、必要返工/新实例复审及经理终审。

### M1 安全返工附加验收边界

- `NtQueryDirectoryFile` 的返回区间严格限制为 `min(IO_STATUS_BLOCK.Information, buffer.len())`；每条记录均验证 `NextEntryOffset`、记录边界、`FileNameLength` 的偶数性及其不超过当前变长记录剩余空间；任何异常返回 `UnsafeUserRecordPath`，解析器不得使用未检查的 `from_raw_parts`。
- Note revision CAS 必须绑定稳定 `vault_id` 哈希与 `note_id`，使用跨 Windows session 的 `Global` 命名 mutex、显式 ACL 与有限等待；创建/访问/等待失败不得降级为 Local 或无锁更新。
- 保留两个独立 Vault 实例的 CAS 测试，并增加两个独立 OS 进程的 CAS 测试；当前测试证明独立进程在本机 session 中一胜一冲突，跨 Terminal Services session 的真实模拟仍需具备对应宿主环境后补测，不得夸大为已覆盖。

## M2：PDF 页码/文本锚点与失效语义

**交付物**
- 仅对归属正确、Vault 内、`available` PDF 创建 quote 标注；受控提取并写入内容哈希、提取器版本、1-based 页码、选中文本、规范化哈希与前后上下文。
- 验证 selected text 为 1–8,192 Unicode 标量、上下文各 ≤256、页码 ≥1；外部资产返回结构化禁止错误。
- 只读运行态解析器，稳定返回 resolved、missing、external、unreadable、content changed、page out of range、text not found、ambiguous、extractor version、orphaned 枚举。
- 覆盖替换、缺失、删除、不可读、越页、文本消失、多义匹配；用户 Annotation 文件始终保留。

**明确不做**：OCR、坐标/画笔、跨格式锚点、外部 PDF 标注、自动候选匹配/自动重绑；不读写 `derived/search/`，锚点失败不回滚其他领域。

**关闭标准**
- 创建前的条目/资产归属、Vault 存储与 available 运行态均被验证；无关资产变化不影响无关标注。
- 内容哈希变化立刻 `invalidated_content_changed`；每类不可用/失效有可区分状态。
- 解析严格只读，写入白名单不扩大；没有隐式恢复。
- 完成独立初审、必要返工/复审和经理终审后才可进入 M3。

## M3：Tauri 契约与 Notes 工作区

**交付物**
- ID-only commands：笔记 list/get/create/update/archive；标注 list/get/create/delete/resolution/受控打开。所有写入、打开、耗时解析均有 `expected_generation + expected_vault_path`。
- 后端在选 Vault、启动后台工作、提交副作用前后验证双快照；A→B、A→B→A 过期请求零副作用。
- 独立 Notes 工作区：按文献筛选的笔记列表、Markdown 编辑、保存/loading/empty/error/no-vault、冲突草稿保留、标注面板和失效原因。
- `open_annotation_asset` 只对 `resolved_exact` 复用 `item_id + asset_id` 的现有 Reading/资产受控入口。

**明确不做**：不在 Source/Search/ReadingSession 权威数据混入笔记标注；不索引笔记；不提供前端路径/任意 opener、静默覆盖、自动恢复或 PDF 坐标绘制。

**关闭标准**
- UI/Tauri 中不存在 Vault/PDF 路径；过期请求不能创建文件、启动错误 Vault 操作或影响当前界面。
- `NoteConflict` 可见且不丢草稿；失效标注不会显示为可定位/可打开。
- 只有受控打开可按旧语义修改 `user/reading_sessions.json`；完成完整审查链后才可进入 M4。

- 全 Vault 字节快照/白名单测试：CRUD、失败写入、遗留临时文件、局部损坏、格式/版本不兼容和恢复。
- 证明删除、损坏或重建 `derived/search/` 不影响 Notes；PDF 缺失/替换不删除或误写用户数据。
- 回归工单 08、09、10 portable、安全和桌面能力，登记性能测量及非阻断项。

**明确不做**：不得以 M4 偷渡图谱、同步、OCR、跨格式批注、笔记 Search 索引或工单 12 导入能力。

**关闭标准**
- 无笔记/标注包含原/副本绝对路径；副本可按相同 ID 读取，并在符合运行态时受控打开资产。
- 笔记/标注 CRUD 只写两个白名单目录；Notes 查看/锚点解析只读；Reading 写入只限既有受控打开语义。
