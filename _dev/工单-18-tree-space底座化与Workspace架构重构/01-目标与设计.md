# 工单 18：tree-space 底座化与 Workspace 架构重构

## 1. 工单目标

把 cistella 的底层模型从 legacy Vault 目录模型收敛为基于 tree-space 的 Workspace Tree：一个 Workspace 是一棵业务树，各业务库以子树挂载，统一承接内存布局、磁盘布局、校验和聚合。

## 2. 范围与非目标

### 范围

- 定义 Workspace、Library、Domain Tree、Bucket、Block 的产品语义边界。
- 确定业务子树的稳定命名、挂载与版本策略。
- 确定 authority、derived、cache、import 四类数据的归属。
- 规定后续领域 crate、插件层、聚合门面和迁移层的依赖方向。

### 非目标

- 本工单不实现具体文献、引用、写作领域对象。
- 本工单不直接迁移历史 Vault 数据。
- 本工单不把 tree-space 的底层 API 暴露给前端。

## 3. A 层决策

### 已拍板

- tree-space 是 cistella 的唯一底层树与桶布局底座。
- Workspace 是产品级聚合根；Library 是 Workspace 下按领域划分的子树，不再作为另一套独立存储模型。
- 领域 crate 只拥有自己的子树和领域语义，通过 `cistella-tree-space` 插件层注册到 Workspace。
- Arrow 用于适合表格化、查询化的数据；PDF、Markdown、原始导入文件等不适合 Arrow 化的数据使用 Opaque block。
- `cistella-workspace` 是桌面与其他上层的稳定门面，屏蔽 tree-space 细节。

### 必须在本工单收口

- 顶层命名：`workspace/` 为根；业务子树至少预留 `literature/`、`references/`、`writing/`、`assets/`、`analysis/`、`system/`。
- 每个业务子树必须能独立校验、导出和迁移，但不能绕过 Workspace 的注册与版本机制。
- authority 数据由领域 crate 负责；索引、统计、缩略图等 derived/cache 数据必须可删除、可重建。
- legacy Vault 只作为兼容输入和迁移来源，不再作为新功能的写入目标。

## 4. B 层设计取舍

| 议题 | 采用方案 | 放弃方案 | 原因 |
|---|---|---|---|
| 存储根 | Workspace Tree | 每个库各自维护 Vault | 避免重复布局与跨库聚合困难 |
| 领域拆分 | 一个领域一个 crate | 一个超大 core crate | 领域边界清晰，未来增量更低成本 |
| 非结构化数据 | Opaque block + 元数据 | 强行 Arrow 化 | 保留原始材料和可恢复性 |
| 上层访问 | 聚合门面 API | 前端直连 tree-space | 避免底层泄漏与协议绑定 |
| 迁移策略 | 新旧并行读取、显式迁移 | 原地改写旧库 | 可回滚、可审计 |

## 5. C 层落位约束

- crate 依赖方向固定为：`tree-space` → `cistella-tree-space` → 领域 crates → `cistella-workspace` → desktop/Tauri/frontend。
- 领域 crate 不直接依赖 desktop，也不直接定义前端路由。
- 所有注册 block 必须有稳定名称、语义版本、能力声明和校验路径。
- 所有迁移写入必须先写临时目标、完成校验后再原子发布。

## 6. 里程碑与交付物

- **M1：总架构收口**：术语、子树拓扑、依赖方向、数据分类决议。
- **M2：新旧模型对照**：legacy Vault 到 Workspace Tree 的映射矩阵和兼容窗口。
- **M3：插件与聚合契约**：为工单 19、20、21、22提供可执行接口边界。

交付物：本工单设计定稿、Workspace Tree 拓扑图、crate 依赖图、数据分类表、阶段门记录。

1. A 层决议已明确 Workspace/Library/Vault 边界与兼容策略。

3. 工单 19—22均能依据本工单直接拆解施工，不需要重新争论总架构。

## 8. M1 施工输出：Workspace Tree 初版拓扑

```text
workspace/
  literature/   # 文献条目、文献身份、条目级用户状态
  references/   # 引用片段、引文关系、可复用引用材料
  writing/      # 写作项目、草稿、输出物与未来写作流程
  assets/       # PDF、Markdown、补充材料、原始文件等 Opaque 资产
  analysis/     # Source 分析、统计视图、可重建分析结果
  imports/      # 外部数据源导入批次、staging、冲突报告
  system/       # Workspace manifest、插件注册、版本、审计日志
  cache/        # 可删除、可重建缓存，不作为 authority
```

### 8.1 产品术语边界

| 术语 | 含义 | 新写入职责 |
|---|---|---|
| Workspace | 产品级聚合根，一棵完整 tree-space 业务树 | 是 |
| Library | Workspace 下的领域子树，如 literature/reference/writing | 是，但必须挂载在 Workspace 下 |
| Vault | 历史目录模型和旧版本用户认知 | 否，仅兼容读取与迁移输入 |
| Bucket | tree-space 的物理/逻辑桶承载 | 由 tree-space 管理 |
| Block | 注册后的业务数据块，分 Arrow/Opaque 能力 | 由插件层注册 |

### 8.2 数据 authority 分类

| 类别 | 示例 | 归属 | 策略 |
|---|---|---|---|
| authority | 文献条目、用户笔记、引用片段、写作草稿 | 对应领域子树 | 必须迁移、备份、校验 |
| import | OpenAlex/BibTeX/RIS/DOI 导入批次与原始记录 | imports/ 与领域子树交叉引用 | 保留来源、可重放、可审计 |
| derived | 全文索引、统计表、排行、缩略图 | analysis/ 或 cache/ | 可删除重建，不阻断迁移 |
| opaque assets | PDF、Markdown、补充材料、原始附件 | assets/ | Opaque block + 摘要/MIME/恢复元数据 |
| system | manifest、插件版本、迁移日志 | system/ | 参与打开校验 |

### 8.3 crate 依赖初版

```text
tree-space
  ↓
cistella-tree-space        # 工单19：插件注册与 block 能力
  ↓
cistella-literature        # 后续领域 crate：文献库
cistella-reference         # 后续领域 crate：引用库
cistella-writing           # 后续领域 crate：写作库
cistella-assets            # 后续领域 crate：资产库
cistella-analysis          # 后续领域 crate：分析库
  ↓
cistella-workspace         # 工单20：聚合门面
  ↓
cistella-desktop / frontend
```

约束：领域 crate 可依赖 `cistella-tree-space`，但不得互相形成循环；跨领域任务由 `cistella-workspace` 编排。

## 9. M2 施工输出：legacy Vault → Workspace Tree 映射

| legacy 位置/语义 | 当前职责 | Workspace 目标 | 数据级别 | 迁移策略 |
|---|---|---|---|---|
| `manifest.json` | Vault 身份、表清单、来源信息 | `system/manifest` + `imports/provenance` | system/import | 解析为 Workspace manifest；来源信息拆入 imports |
| `tables/*.parquet` | Source/分析表的压缩存储 | `analysis/source_tables` 或领域专属 Arrow block | authority/import/derived 视表语义判定 | 可结构化者注册为 Arrow block；派生表可重建 |
| `*.arrow` / `*.ipc` | serving cache 或单文件打开入口 | `imports/single_file_source` + `analysis/cache` | import/cache | 保留导入来源，cache 可重建 |
| `user/literature_items.json` | 用户文献条目 | `literature/items` | authority | 必须迁移，失败则阻断发布 |
| `user/reading*` | 阅读状态、阅读会话 | `literature/reading_state` | authority | 必须迁移，允许字段级兼容升级 |
| `user/notes*` | Markdown 笔记、标注、引用片段 | `references/quotes` + `literature/notes` | authority/opaque | 文本正文可 Opaque，索引元数据可 Arrow |
| `files/` / 资产路径 | PDF、补充材料、本地副本 | `assets/objects` | opaque assets | 按摘要入桶，保留 MIME、原路径、大小和恢复名 |
| `derived/search` | 本地全文索引 | `analysis/search_index` 或 `cache/search` | derived/cache | 默认不强迁移；迁移后标记需重建 |
| `exports/` | 用户导出物 | `assets/exports` 或外部目录引用 | opaque/import | 不作为核心 authority；保留可追溯记录 |
| app `cache/` | 应用级缓存 | Workspace 外 app cache 或 `cache/` | cache | 可删除，不参与核心迁移成功判定 |

### 9.1 迁移发布原则

1. 旧 Vault 原地保持不变。
2. 迁移器先执行 dry-run，输出 source → target 映射、风险和阻断项。
3. 正式迁移写入临时 Workspace 目标。
4. 临时目标通过 tree-space 校验、插件 block 校验和聚合门面打开校验后发布。
5. 失败时删除临时目标或保留为诊断目录，旧 Vault 仍可只读打开。

### 9.2 兼容窗口

- 兼容窗口内允许打开 legacy Vault，但只读。
- 新建库、新功能和新写入统一进入 Workspace Tree。
- 兼容层不承担双向同步；用户确认迁移后以 Workspace 为唯一后续写入目标。

## 10. M3 施工输出：下游契约

### 10.1 工单 19 插件层输入契约

- 必须提供 `cistella-tree-space` crate。
- 必须注册至少两类能力：Arrow block 与 Opaque block。
- block 命名采用 `cistella.<domain>.<kind>`，例如：
  - `cistella.literature.items`
  - `cistella.references.quotes`
  - `cistella.assets.object`
  - `cistella.analysis.source-table`
- 注册元数据必须包含名称、语义版本、能力、schema/元数据、编码、解码和校验入口。

### 10.2 工单 20 聚合门面输入契约

- `cistella-workspace` 是上层唯一打开入口。
- 最小 API 面必须覆盖：创建、打开、关闭、子树枚举、状态摘要、校验、只读降级。
- 返回给 desktop/Tauri/frontend 的 DTO 不包含 tree-space 内部节点或 bucket 细节。
- 跨领域操作由聚合门面编排，领域 crate 保持 authority 边界。

### 10.3 工单 21 迁移兼容输入契约

- legacy Vault 是迁移来源，不是新写入目标。
- dry-run、报告、临时目标、校验、发布、回滚是硬性流程。
- authority 数据迁移失败阻断发布；derived/cache 数据失败只标记重建。
- Opaque 资产必须保存摘要、MIME、大小、原始文件名和恢复信息。

### 10.4 工单 22 前端输入契约

- 前端从 `cistella-workspace` DTO 获取工作区状态和导航能力。
- 导航显示产品语义：阅读、写作、管理、分析、工具。
- 不显示底层 block、bucket、tree-space 路径。
- 前端修改默认构建并同步 `bin_test/cistella-frontend/`。
