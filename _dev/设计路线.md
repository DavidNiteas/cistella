# cistella 设计路线

> 设计路线只描述需求/目标层面的连贯路径，不展开具体实现细节。

## 总目标

cistella 是一个本地化个人文献保管库 + 阅读/管理/分析工作台。

核心原则：库即一切、复制即走、打开即用、本地优先、免安装可携带、桌面优先；OpenAlex 只是重要数据源之一，不是产品本体。

## 1. 产品重定位

### 目标
把仓库从旧的 OpenAlex 分析工具迁移为 cistella。

### 结果形态
- cistella 成为统一产品名。
- 桌面应用成为唯一用户入口。
- CLI 退回为内部开发辅助，不作为发布主功能。
- OpenAlex 仅保留来源/历史语义。

### 关联工单
- `_dev/archive/工单-01-品牌与产品重定位/01-目标与设计.md`

状态：已达成

## 2. 库与 Vault 模型

### 目标
定义可复制、可迁移、可备份、可长期保存的本地库模型。

### 结果形态
- 一个库可以独立存在。
- 库内包含原始数据、标准化条目、索引、缓存、导出物和用户数据。
- 路径与配置具备 portable 属性。
- 库是软件核心对象，而不是某个数据源目录的附属物。

## 23. cistella 单库化

### 目标
将 cistella 的用户心智、前端工作流与后端聚合模型收敛为单一 cistella 库。用户只打开、创建和管理一个当前库；文献、PDF 资产、笔记、标注、阅读会话、来源数据、导入批次、全文索引、写作材料和系统记录均作为该库内部的混合数据存在。

### 结果形态
- 用户可见对象只有一个：cistella 库。
- Reading、Notes、Search、Source、Settings 等是当前库的不同工作面，不是不同的库。
- tree-space / cistella-workspace 负责统一承载多类业务子树、Named Block、派生缓存和兼容信息。
- Vault 保留为 legacy/internal 兼容语义，不再作为新增用户界面的主术语。
- 导入操作表达为“导入到当前库”，不再让用户理解“输出库”或 Source 独立库。

- `_dev/工单-23-cistella单库化/01-目标与设计.md`
