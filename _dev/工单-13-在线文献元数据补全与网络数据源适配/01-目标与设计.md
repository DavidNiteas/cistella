# 01. 目标与设计：在线文献元数据补全与网络数据源适配

## 1. 工单目标

在工单 12（离线/本地数据源导入）基础上，把 cistella 的文献来源能力扩展到互联网公开数据源。用户只需输入 DOI、PMID、ISBN、PMCID 或 OpenAlex ID，cistella 即可从网络解析并补全文献元数据，再按统一内部模型导入个人库。

本工单解决：
- 用户手动录入文献元数据成本高。
- 离线导入无法覆盖用户只有标识符、没有完整记录文件的场景。
- 本地 OpenAlex 分区数据可能滞后或缺失，需要实时网络补全通道。
- 多个网络数据源结果需要统一归一化到 cistella 内部条目模型。

## 2. 北极星

用户在 Reading 工作区输入一个 DOI，cistella 在数秒内从网络解析出标题、作者、年份、类型、期刊、外部标识符，并让用户确认后导入 Vault；网络失败时给出清晰提示并允许手动补全；解析结果不覆盖用户已有编辑，只填充空字段。

## 3. 范围边界

### 本工单包含

- 统一网络元数据解析抽象：`RemoteMetadataResolver` trait。
- 标识符输入规范化：DOI、PMID、PMCID、ISBN、OpenAlex ID。
- M1：基于 Crossref API 的 DOI 解析（真实 HTTP 网络请求）。
  - 解析结果转换为 `SourceRecord`，复用工单 12 的 `LibraryImporter` 预览/提交流程。
  - 解析结果本地缓存，避免重复请求。
- M2：PubMed/Europe PMC 适配器（PMID/PMCID 解析）。
- M3：OpenAlex API / Semantic Scholar 适配器，以及多解析器结果合并/择优策略。
- 网络错误处理：超时、限流、无结果、解析失败的结构化错误与 UI 提示。
- 缓存管理：按 Vault 存储，可配置过期时间，可手动刷新。

### 本工单明确不做

- M1 不做 PMID/PMCID/ISBN/OpenAlex ID 网络解析。
- M1 不做批量标识符导入（先支持单条解析）。
- M1 不做引文网络、推荐系统、作者消歧。
- M1 不做付费数据库或需要 API Key 的数据源。
- 不做全文 PDF 自动下载。
- 不做云同步、协作、账号系统。
- 不做 Source 分析工作区改造（继续只服务本地 OpenAlex sources 数据）。

## 4. 固定决议

### 4.1 A 层方向（已拍板）

- 工单 13 目标：在工单 12 基础上扩展在线文献元数据补全与网络数据源适配能力，让用户通过标识符从网络补全文献元数据。
- 范围边界：M1 做 Crossref DOI 解析；M2 做 PubMed/Europe PMC；M3 做 OpenAlex API / Semantic Scholar 与多解析器择优。
- 核心原则不变：本地优先、库即一切；网络数据作为补全来源，不替代 Vault 内用户数据权威。
- 网络请求必须可禁用、可缓存、可错误回退。

### 4.2 B 层设计（已拍板）

- 抽象层：
  - `RemoteMetadataResolver` trait：输入规范化后的标识符，输出 `Result<SourceRecord, CoreError>`。
  - `RemoteResolverRegistry`：按标识符类型（DOI/PMID/PMCID/ISBN/OpenAlexId）分派到具体解析器。
- 缓存层：
  - 缓存目录：`<Vault>/cache/remote_metadata/<resolver_namespace>/<sha256(identifier)>.json`。
  - 缓存内容：原始响应 + 解析后的 `SourceRecord` + 缓存时间戳。
  - 默认缓存有效期：30 天；用户可在设置中清除缓存或强制刷新。
- 网络层：
  - 使用 `reqwest` 进行异步 HTTP 请求（Cargo.lock 中已存在，本工单需显式声明依赖）。
  - 默认超时 10 秒，重试 1 次（指数退避）。
  - 请求头必须包含合理的 `User-Agent`（含产品名与联系邮箱）。
- 与工单 12 集成：
  - 解析得到的 `SourceRecord` 直接送入 `LibraryImporter::preview`，复用冲突检测、策略选择、提交与回滚。
  - 不修改 `LiteratureItem` 内部模型（已支持 `external_identifiers`）。
- 错误策略：
  - 网络超时/无连接：返回 `CoreError::RemoteMetadataUnavailable`，UI 提示检查网络。
  - 标识符未找到：返回 `CoreError::RemoteMetadataNotFound`，UI 提示未找到。
  - 响应解析失败：返回 `CoreError::RemoteMetadataMalformed`，记录原始响应用于调试。

### 4.3 C 层默认（已拍板）

- 标识符规范化：
  - DOI：去除 `doi:`、`https://doi.org/` 等前缀，统一大写或小写存为 `namespace = "doi"`。
  - PMID/PMCID：去除 `pmid:`、`pmc:` 前缀，纯数字。
  - ISBN：去除连字符与空格，保留 10/13 位数字（允许 X）。
  - OpenAlex ID：去除 `W`、`https://openalex.org/` 前缀，统一大写 `W` + 数字。
- 解析器默认顺序：
  - DOI：Crossref → Semantic Scholar（M3）→ OpenAlex API（M3）。
  - PMID/PMCID：PubMed（Europe PMC fallback）。
  - OpenAlex ID：OpenAlex API。
- Tauri 命令：
  - `resolve_remote_metadata(identifier: String, force_refresh: bool) -> SourceRecordDto`
  - `import_by_identifier(identifier: String, strategy: String) -> ImportResultDto`
- UI 入口：Reading 工作区「通过标识符导入」输入框 + 解析按钮 + 预览对话框。
- 测试：
  - Core 层：使用本地 mock HTTP server 或录制响应文件测试解析逻辑（不依赖真实网络）。
  - 集成测试：验证缓存命中/失效、错误回退、与 `LibraryImporter` 的端到端流程。

## 5. 身份、不变量与权威边界

### 5.1 条目标识

- `item_id` 继续由 cistella 生成，不由外部标识符替代。
- 外部标识符（DOI/PMID/ISBN/OpenAlex ID）作为 `external_identifiers` 保存，是可补全的事实。

### 5.2 权威边界

- 用户字段权威仍在 `user/literature_items.json`。
- 网络解析结果权威在远程数据源；cistella 只作为补全来源。
- `merge` 策略仅填充空字段，不覆盖用户已有值。

### 5.3 不变量

- 网络解析失败不得破坏 Vault 现有数据。
- 缓存写入必须原子替换。
- 预览阶段不写入用户条目或批次文件。
- 网络请求可禁用：当用户关闭网络解析时，所有解析命令立即返回错误提示。
- 不得将网络解析结果写入 Source 分析表或 manifest tables。

## 6. 文件布局与模块边界

### 6.1 Vault 内新增文件

```
<Vault>/
  cache/
    remote_metadata/
      crossref/
        <sha256(doi)>.json
      pubmed/
        <sha256(pmid)>.json
      ...
```

### 6.2 Core 新增模块

- `cistella-core/src/import/remote/`
  - `resolver.rs`：`RemoteMetadataResolver` trait 与 `ResolveContext`。
  - `registry.rs`：`RemoteResolverRegistry` 与标识符分派。
  - `crossref.rs`：Crossref DOI 解析器。
  - `pubmed.rs`：PubMed/Europe PMC 解析器（M2）。
  - `openalex_api.rs`：OpenAlex API 解析器（M3）。
  - `semantic_scholar.rs`：Semantic Scholar 解析器（M3）。
  - `cache.rs`：缓存读写与过期判断。
  - `identifier.rs`：标识符解析与规范化。
- `cistella-core/src/error.rs`：新增 `RemoteMetadataUnavailable` / `RemoteMetadataNotFound` / `RemoteMetadataMalformed` 错误变体。

### 6.3 与现有模块的关系

- 扩展 `cistella-core/src/import/` 现有结构，不破坏 BibTeX/RIS/OpenAlex works 导入。
- `LibraryImporter` 增加从 `SourceRecord` 直接生成预览的入口（如果尚不存在）。
- Tauri 命令复用现有 `ImportPreview` / `ImportResult` DTO。

## 7. Core / Tauri / UI 边界

### 7.1 Core 层

- 纯 Rust API：
  - `RemoteResolverRegistry::resolve(identifier, vault_path, force_refresh)`
  - `RemoteResolverRegistry::import_by_identifier(identifier, vault_path, strategy)`
- Core 负责网络请求、缓存、解析、错误映射。

### 7.2 Tauri 层

- 新增命令：
  - `resolve_remote_metadata(identifier, force_refresh)`：返回 `SourceRecordDto`。
  - `import_by_identifier(identifier, strategy)`：返回 `ImportResultDto`。
- Tauri 层只透传参数、调用 Core、映射错误为字符串。

### 7.3 UI 层

- Reading 工作区新增「通过标识符导入」入口。
- 输入框支持 DOI/PMID/PMCID/ISBN/OpenAlex ID，自动检测类型。
- 展示解析结果预览，让用户选择冲突策略后提交。
- 网络错误在对话框内显式展示。

## 8. 成功标准

- 用户输入 DOI 后，系统能从 Crossref 解析出标题、作者、年份、类型、期刊、外部标识符。
- 解析结果可预览、可选择冲突策略、可提交到 Vault。
- 网络失败时给出清晰错误，不破坏 Vault。
- 重复解析同一标识符优先使用缓存，不重复发起网络请求。
- M2/M3 按路线图扩展更多数据源与择优策略。

## 9. 施工准入判定

### A 层

cistella 需要从离线/本地数据源扩展到在线数据源，提升用户录入效率；该方向与总路线一致，不再新增方向问题。

### B 层

`RemoteMetadataResolver` 抽象、缓存层、网络层、与 `LibraryImporter` 集成、错误策略已由经理拍板，见本节固定决议。

### C 层

标识符规范化规则、解析器默认顺序、Tauri 命令命名、UI 入口位置交由干事按默认方案实现，偏离通过施工日志回填。

本四件套完成后，等待经理正式授权进入 M1 实施。
