# 工单 21：legacy Vault 迁移与兼容层

## 1. 工单目标

提供从 legacy Vault 到 tree-space Workspace 的兼容读取、迁移、校验、备份和回滚能力，确保既有用户数据可平滑进入新架构。

## 2. 范围与非目标

### 范围

- 识别 legacy `manifest.json`，生成只读兼容报告。
- 提供可审计的迁移计划、备份、临时目标、发布和失败清理流程。
- 在迁移产物的 `system/` 子树保留 legacy 备份和迁移报告。
- 通过 desktop/Tauri 暴露只读检查和显式迁移命令。

### 非目标

- 不继续扩展 legacy Vault 写入能力。
- 不执行双向长期同步。
- 不猜测或静默删除无法解析的 legacy 数据。

## 3. A/B/C 决策

### A 层：已确认

- 新 Workspace 是唯一的新写入目标；legacy Vault 只作为兼容读取和迁移输入。
- 迁移是显式用户动作，原 Vault 保持不变。
- 目标已存在时拒绝迁移，禁止覆盖用户数据。

### B 层：施工裁定

- `cistella-workspace` 负责兼容报告、迁移计划和迁移发布编排。
- 迁移先创建 zip 备份，再构建临时 Workspace；校验通过后重命名发布。
- 派生索引/cache 不构成迁移成功的必要条件；原 Vault 通过备份归档保真。

### C 层：实现约束

- `inspect_legacy_vault` 只读取 legacy manifest，不改写来源。
- `migrate_legacy_vault_to_workspace` 使用 staging 根目录，失败自动清理 staging。
- 迁移成功时在 `system/legacy-vault.zip` 和 `system/legacy-vault-migration.json` 留存审计材料。
- Tauri 命令：`inspect_legacy_vault`、`migrate_legacy_vault_to_workspace`。

## 4. 施工结果

- M1：兼容检查报告已实现。
- M2：迁移计划、备份、staging 发布、Workspace 校验和迁移报告已实现。
- M3：目标存在保护、失败清理和 legacy 只读过渡已固化。

## 5. 终审结论

状态：**已达成**。工单 22 可消费 Workspace contract 与迁移命令状态继续完成前端映射和回归。
