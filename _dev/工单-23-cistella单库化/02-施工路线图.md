# 施工路线图：cistella 单库化

## 总体策略

本工单采用“先设计收敛，再分层施工”的方式推进：

1. 先完成术语盘点和页面职责映射，避免边做边改方向。
2. 再进行用户可见前端文案与流程改造，优先解决多库心智。
3. 后端 façade 采用兼容增量方式，不一次性删除 legacy `Vault`。
4. 每个施工阶段都保留可回归入口，尤其是 `bin_test` 前端热更新规范。

## M1：术语盘点

### 输入

- `src/lib/i18n/dict.ts`
- `src/components/layout/workspaceNavigation.ts`
- `src/App.tsx`
- `src/features/**`
- `src/hooks/**`
- Tauri command 名称与 DTO 类型

### 输出

在 `05-术语与页面映射.md` 中记录：

- 用户可见文案中的 `Vault`、`Workspace`、`Library`、`库`、`文献库`、`Source`。
- 哪些是产品术语，哪些只是代码变量或历史兼容名。
- 哪些文案会造成“多个库”的错觉。
- 每处建议替换成什么。

### 完成标准

- 现状清单覆盖主要前端页面和导航入口。
- 清单中每一项都有“保留 / 替换 / 延后”的处理建议。

## M2：产品模型与页面映射

### 输出

- 当前库产品模型：用户可见根对象、内部数据域、portable 边界、外部链接边界。
- 页面映射表：每个页面对应哪些数据域、哪些操作、哪些文案禁区。
- 后端分层表：`Library façade`、`Workspace`、`legacy Vault`、`tree-space` 的职责边界。

### 完成标准

- 不再存在需要用户拍板的 A 层方向问题。
- M3 前端施工可以按表逐项执行。
- M4 后端 façade 可以按接口清单逐项设计或实现。

## M3：前端单库化施工

### 施工范围

- 调整 `dict.ts` 中用户可见文案。
- 调整侧边栏和命令面板中“库”相关入口文案。
- 调整 `VaultPage` 的导入流程表达：从“选择输出目录/构建库”收敛为“打开/创建当前库，然后导入到当前库”。
- 调整 Reading、Notes、Search、Source、Settings 的说明文字，使其全部指向当前库。
- 保留必要的内部类型名，不追求本阶段完全重命名 React hook 或 Rust 类型。

### 验收命令

- `pnpm --dir crates/openalex-analysis-studio build`
- `pnpm --dir crates/openalex-analysis-studio build:bin-test`

### 完成标准

- 用户可见 UI 中不再把 Vault、Workspace、Library 表达为三个并列根对象。
- `bin_test/cistella-frontend/` 已同步最新前端产物。

## M4：后端 façade 收敛

### 施工范围

- 明确现有 `connect_vault`、`vault_context`、`workspace_contract` 是否新增 `library_*` 别名。
- 若新增别名，保持旧命令兼容，不破坏前端现有调用。
- 新 façade 返回产品级 DTO，不泄漏 tree-space 内部 block/bucket/ref。
- legacy Vault 相关接口保留 `legacy_vault_*` 命名，以免与当前库混淆。

### 验收命令

- `cargo check -p cistella-workspace --locked --offline`
- `cargo check -p cistella-desktop --locked --offline`

### 完成标准

- 新增接口有清晰命名边界。
- 旧接口兼容策略明确。
- Rust 检查通过。

## M5：终审回归

### 回归项目

- 文档：设计路线、开发状态、工单状态、施工日志均同步。
- 前端：构建通过，bin_test 同步完成。
- 后端：Rust 检查通过。
- 产品：用户只面对单一当前库，页面是库的工作面。

### 终审标准

- M1—M4 全部完成。
- 没有未解决的 A/B 层开放问题。
- 已知剩余 `Vault` 命名均属于 legacy/internal 或延期重命名，并在文档中列明。

## 阶段门

构建中 → 施工中 的放行条件：

1. A 层方向已由用户确认。
2. M1/M2 的术语表、页面映射和后端分层方案足够明确。
3. 不再存在需要用户拍板的范围问题。

施工中 → 已达成 的放行条件：

1. M3/M4 实施完成或明确裁定为延期项。
2. 验收命令完成。
3. bin_test 同步完成。
4. 施工日志记录终审结论。
