# 术语与页面映射：cistella 单库化

> 本文件是工单 23 的 M1/M2 盘点、设计与验收依据。它区分用户心智、产品界面与 legacy/internal 实现，避免把一个混合库误解成多个并列的库。

## 1. 术语边界

| 术语 | 用户可见性 | 单库化定位 | 处理原则 |
|---|---|---|---|
| 库 / cistella 库 | 应该可见 | 唯一用户可见根对象 | 保留并强化 |
| 当前库 | 应该可见 | 当前打开的 cistella 库 | 保留 |
| Library | 英文 UI 可见 | `库` 的英文 | 英文 UI 统一使用 |
| Workspace | 普通用户不应看见 | 技术聚合根 / tree-space 业务树 | 只在开发文档、诊断或 contract 中出现 |
| Vault | 普通新增 UI 不应看见 | legacy/internal 兼容对象 | 逐步替换为“库”；必要时写作“legacy Vault” |
| Source | 可见，但不是库 | 当前库中的来源数据/分析域 | 避免表达成 Source 库 |
| 文献库 | 谨慎可见 | 容易与“库”混淆 | 优先替换为“库管理”或“文献”页面 |
| 资产 / PDF 资产 | 可见 | 当前库内或外部链接的文件资产 | 明确库内副本 vs 外部链接 |
| 索引 | 可见 | 当前库的可重建缓存 | 不称为库 |
| portable 目录 / app config | 可见但需区分 | 应用运行方式与配置位置 | 不称为用户库 |

### 用户界面允许与禁止词

- **允许**：库、当前库、打开库、选择库、库管理、最近打开的库、导入到当前库、库内副本、Library、current library。
- **禁止作为普通产品文案**：Vault、Vault Workspace、Workspace、Source library、输出库、构建库。
- **允许在技术上下文残留**：`Vault` Rust 类型、`VaultConnection` React 类型、`vault_*` 兼容命令、`Workspace` contract/schema 与导航内部标识；这些不是普通用户可见概念。

## 2. 页面映射

| 前端入口 | 当前路由/组件 | 产品页面名 | 当前库内职责 | 文案禁区 |
|---|---|---|---|---|
| 库管理 | `vault` / `VaultPage` | 库管理 / Library | 打开、创建、导入、查看当前库及其资产 | Vault 专属页、输出库 |
| 阅读 | `reading` / `ReadingPage` | 阅读 / Reading | 管理当前库中的文献条目、文件与阅读会话 | 阅读库、Reading Workspace |
| 笔记 | `notes` / `NotesPage` | 笔记 / Notes | 管理当前库中的笔记、标注 | Notes Workspace |
| 检索 | `search` / `SearchPage` | 检索 / Search | 检索当前库的元数据和可重建全文索引 | 独立检索库 |
| 来源分析 | `source` / `SourcePage` | 来源分析 / Source Analysis | 浏览、筛选、排行与导出当前库的来源数据 | Source 库、独立工作区 |
| 设置 | `settings` / `SettingsPage` | 设置 / Settings | 应用设置、运行方式、当前库备份与恢复 | 另一套库配置 |
| 命令面板 | `CommandPalette` | 命令面板 | 跳转当前库页面、打开最近库 | 工作区是另一库 |

## 3. 数据域映射

| 数据域 | WorkspaceKind 归属建议 | 现有主要承载 | 前端页面 | 是否独立库 |
|---|---|---|---|---|
| 文献条目 | `literature` | legacy user records / future `cistella.literature.items` | Reading、Search、Notes、库管理资产分组 | 否 |
| PDF/附件 | `assets` | document assets / future `cistella.assets.object` | 库管理、Reading、Search、Notes | 否 |
| 笔记 | `literature` 或 `writing` | `user/notes` | Notes | 否 |
| 标注 | `literature` + `assets` | `user/annotations` | Notes、Reading | 否 |
| 阅读会话 | `literature` + `assets` | `user/reading_sessions` | Reading | 否 |
| 来源记录 | `analysis` / `imports` | OpenAlex sources table | Source | 否 |
| 导入批次 | `imports` / `system` | import preview/result | 库管理、Reading | 否 |
| 全文索引 | `cache` | local search index | Search | 否，可重建缓存 |
| 最近库列表 | app-level config | app directories | 库管理、命令面板、Settings | 否，应用配置 |

## 4. 后端分层与兼容策略

| 层 | 职责 | 对前端暴露 | 本轮落地 |
|---|---|---|---|
| tree-space | 内容寻址 bucket、block、tree/workspace 的基础能力 | 否 | 由 `cistella-tree-space` 与 `cistella-workspace` 间接使用 |
| cistella-workspace | 统一混合库的业务聚合和 contract | 仅产品级 contract | `library_contract` 返回既有聚合 contract，不暴露 block/bucket/ref |
| Library façade | 面向产品的当前库连接、上下文、导入、概览、最近库、备份与恢复 | 是 | 新增 `library_*` 和 `import_to_library` Tauri 命令 |
| legacy Vault | 历史存储格式、已有命令和内部运行实现 | 仅兼容/迁移 | 保留 `vault_*`、`connect_vault`、`import_sources` 与 legacy 迁移接口 |

兼容约束：新前端调用 `library_*` / `import_to_library`；旧命令保持注册并转发至同一实现，因此不破坏现有 headless、旧界面或迁移路径。

## 6. 已知且允许的残留

- Rust 内部类型：`Vault`、`VaultOpenOptions`、`VaultContext`。
- Tauri 兼容命令：`connect_vault`、`vault_context`、`vault_overview`、`import_sources`、`recent_vaults`、备份/恢复旧命令。
- React 内部 hook、props、状态：`useVaultConnection`、`useVaultContext`、`VaultConnection`、`vaultPath`。
- legacy 迁移接口：`inspect_legacy_vault`、`migrate_legacy_vault_to_workspace`。
- `Workspace` 作为 tree-space/cistella-workspace 技术概念、contract schema 和内部导航标识。

这些残留均不属于普通用户文案；本工单的目标是产品层单库化，而不是一次性破坏兼容协议或全量重命名内部实现。

## 7. M1/M2 验收结论

- M1 已覆盖导航、命令面板、六个页面、关键 hooks、Tauri 命令与 Workspace 聚合底座；每项都给出了替换、保留或延后结论。
- M2 已明确唯一用户根对象、内部数据域、portable/外部链接边界、页面职责、禁用术语和 Library façade 分层。
- A/B 层无剩余开放问题，施工按本文件执行。
