# 施工路线图：cistella tree-space 插件层

## 1. 里程碑

| 里程碑 | 状态 | 施工内容 | 验收重点 |
|---|---|---|---|
| M1 | ✅ 已完成 | 注册协议、命名空间、版本与错误模型 | API 稳定、无领域泄漏 |
| M2 | ✅ 已完成 | Arrow/Opaque 最小 block 注册 | 两类 block 均可读写 |
| M3 | ✅ 已完成 | 编码、解码、校验、重载与兼容测试 | 可验证、可恢复 |

## 2. 已执行步骤

1. 引入并锁定 tree-space 的 `RegisteredBlock` / `BlockCaps` / `register_block` 公共 API。
2. 创建 `cistella-tree-space` crate，接入 workspace。
3. 实现幂等注册入口 `register()`。
4. 实现 `LiteratureItemsBlock` 作为最小 Arrow block。
5. 实现 `AssetObjectBlock` 作为最小 Opaque block，保留 MIME、原文件名、扩展名、大小和 SHA-256。
6. 补齐注册、schema mismatch、Arrow roundtrip、Opaque roundtrip、digest mismatch 测试。
7. 执行格式化、crate 级检查/测试和 workspace 串行回归。

## 3. 验收命令

- ✅ `cargo fmt --check`
- ✅ `cargo check -p cistella-tree-space`
- ✅ `cargo test -p cistella-tree-space`
- ✅ `cargo test --workspace -j 1`

说明：首次 `cargo test --workspace` 并行执行时触发 Windows 页面文件/并行编译资源问题；按工程治理判定为环境并发问题，使用 `-j 1` 串行复跑后通过。

## 4. 风险

- tree-space API 变化：已通过集中 crate 封装降低影响面。
- Opaque 恢复信息不足：最小 Opaque block 已强制保留 MIME、大小、摘要和恢复名。
- block 命名漂移：注册名称常量与测试已固化。
