# 工单 19：cistella tree-space 插件层

## 1. 工单目标

建立 cistella 专用 tree-space 插件层，把文献、引用、写作、资产、分析等领域对象注册为稳定的 Named Block，并统一 Arrow 与 Opaque 两种承载能力。

## 2. 范围与非目标

### 范围

- 定义 `cistella-tree-space` 插件 crate 的注册入口、命名空间、版本和能力声明。
- 提供结构化 Arrow block 与非结构化 Opaque block 的最小适配。
- 规定 block 的编码、校验、恢复和兼容策略。

### 非目标

- 不实现各领域业务流程。
- 不承担 Workspace 聚合 API。
- 不直接处理 legacy Vault 迁移。

## 3. A 层决策

- 插件层是 tree-space 与 cistella 领域 crate 之间的唯一适配边界。
- 所有业务 block 必须具备稳定名称和语义版本；禁止领域自行拼接未注册的桶布局。
- Arrow/ Opaque 是能力选择，不是产品层数据分类；同一领域可以同时使用两者。
- 原始材料保真优先：无法可靠结构化的数据保留 Opaque，不强行转换。

## 4. B 层设计取舍

| 议题 | 采用方案 | 放弃方案 |
|---|---|---|
| 注册方式 | 集中 `PluginRegistry` 注册 + 领域显式挂载 | 运行时扫描文件猜测类型 |
| block 命名 | `cistella.<domain>.<kind>` | 以路径或 Rust 类型名作为身份 |
| 版本兼容 | 语义版本 + 明确升级器 | 依赖文件名隐式判断 |
| 原始材料 | Opaque block 与描述元数据分离 | 将二进制塞进 Arrow 字段 |

## 5. C 层约束

- 最小注册对象包含：名称、版本、能力、编码器/解码器、校验器。
- block 读写错误必须区分未知版本、损坏、缺失和不支持能力。
- Arrow schema 变更必须提供兼容策略；Opaque 必须保留 MIME/扩展名/摘要等恢复元数据。
- 插件 crate 不依赖 desktop/frontend。

## 6. 里程碑与阶段门

- **M1：注册契约**：完成命名、版本、能力和错误模型。
- **M2：最小 block**：至少注册一个 Arrow block 和一个 Opaque block。
- **M3：双形态验证**：完成内存、持久化、校验和重载测试。

进入施工期的条件：工单 18 M3 完成，且插件契约可被领域 crate 直接调用。

## 7. 终审结论

工单 19 已完成，无 A 类遗留问题。

- `cistella-tree-space` crate 已建立。
- 已实现 Arrow 最小 block：`cistella.literature.items`。
- 已实现 Opaque 最小 block：`cistella.assets.object`。
- 已实现幂等注册入口、版本常量、schema 校验、Opaque 元数据校验和摘要校验。
- 已通过格式化、crate 级验证和 workspace 串行回归。
