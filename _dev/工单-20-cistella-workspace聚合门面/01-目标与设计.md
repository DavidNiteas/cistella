# 工单 20：cistella-workspace 聚合门面

## 1. 工单目标

建立 `cistella-workspace` 聚合 crate，将多个领域子树组合成一棵 Workspace Tree，并向 desktop、Tauri 和前端提供稳定、面向业务的 API。

## 2. 范围与非目标

### 范围

- 聚合文献、引用、写作、资产、分析等领域 crate。
- 管理 Workspace 的打开、创建、关闭、校验和子树挂载。
- 为上层提供工作区列表、状态摘要和命令所需的业务操作。

### 非目标

- 不重复实现领域对象。
- 不暴露 tree-space 原始 bucket/block API 给前端。
- 不在聚合层承载迁移算法。

## 3. A 层决策

- `cistella-workspace` 是唯一的 Workspace 聚合根和上层门面。
- 领域 crate 可独立演进，但只能通过明确的挂载契约加入 Workspace。
- 聚合层负责跨领域编排，不负责改变领域数据的 authority。
- 新领域通过新增 crate + 注册器接入，不修改既有领域内部布局。
- 桌面/Tauri 的首个稳定契约以 `workspace_contract` 形式对外暴露。

## 4. B 层设计取舍

| 议题 | 采用方案 | 放弃方案 |
|---|---|---|
| 上层 API | 面向业务的 command/query | 直接返回 tree-space 节点 |
| 子树挂载 | 启动时显式注册、按版本校验 | 运行时隐式发现 |
| 状态模型 | ready/degraded/read-only/failed | 仅返回 bool |
| 跨域操作 | 聚合层编排、领域层执行 | 领域互相直接调用 |

## 5. C 层约束

- API 覆盖 Workspace 生命周期、子树枚举、状态摘要、校验和只读降级。
- 错误类型保留领域来源，禁止统一吞成字符串。
- 聚合层不得让前端依赖 Rust 内部类型；桌面协议负责序列化稳定 DTO。

## 6. 里程碑与阶段门

- **M1：聚合 API 草案**
- **M2：子树挂载与依赖边界**
- **M3：桌面门面与命令协议**
