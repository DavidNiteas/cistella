# 施工路线图：cistella-workspace 聚合门面

## 1. 里程碑

| 里程碑 | 状态 | 施工内容 | 验收重点 |
|---|---|---|---|
| M1 | ✅ 已完成 | Workspace 生命周期与 command/query 草案 | 业务语义稳定 |

## 2. 已执行步骤

1. 创建 `cistella-workspace` crate 并定义公开 API 与错误模型。
2. 接入 `cistella-tree-space` 插件注册器，固化聚合前置。
3. 为 ready、只读降级、部分领域不可用建立状态摘要。
4. 输出稳定 DTO，补入桌面/Tauri 的 `workspace_contract` 命令。
5. 添加聚合测试和旧入口兼容测试。

## 3. 验收命令

- ✅ `cargo fmt --check`
- ✅ `cargo check -p cistella-workspace`
- ✅ `cargo test -p cistella-workspace`

## 4. 风险

- 聚合 API 过度扩大：目前仅保留 manifest/summary/contract 的最小面。
- 领域 crate 互相依赖：通过 Workspace 编排解决。
- 部分子树损坏：支持降级打开并给出可定位错误。
