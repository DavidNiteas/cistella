# 工单 17：前端结构升级

## 1. 总体策略

先收口信息架构，再实现导航状态，最后做命令面板、快捷键和响应式回归。施工期间不修改后端数据协议。

## 2. 里程碑

| 里程碑 | 内容 | 关闭标准 | 依赖 |
|---|---|---|---|
| M1 | 信息架构与导航模型 | 一级分类、二级映射、命名与兼容 ID 拍板 | 无 |
| M2 | 两级侧边栏施工 | 当前类别展开、当前入口选中、折叠/响应式正常 | M1 |
| M3 | 快速入口与回归 | 命令面板、快捷键、构建与交互回归通过 | M2 |

## 3. M1：信息架构收口

- [x] 确认一级类别集合与排序：阅读 / 写作 / 管理 / 分析 / 工具。
- [x] 确认现有 `Workspace` 归属，并记录 `search` 双归属。
- [x] 确认“写作”作为当前可见类别，暂为未来能力占位。
- [x] 确认二级入口命名规则：阅读下为“检索”，分析下为“本地全文检索”；具体图标进入 B 层。
- [x] 确认保留现有 Workspace ID 与快捷键；折叠状态暂不持久化。

## 4. M2：侧边栏施工

- [ ] 新增导航模型类型：类别、入口、图标、权限/可见性、快捷键提示。

- [ ] 命令面板按类别展示二级入口。

- [ ] Ctrl/Cmd+1—6 快捷键兼容验证。
- [ ] 前端类型检查和生产构建通过。
- [ ] 手工回归所有现有 workspace。
- [ ] 更新 BUILD/工单文档。

## 6. 验收命令

## 7. 风险

- 分类命名不稳定导致后续反复改 UI：M1 先收口。
- 折叠状态与当前路由冲突：当前类别永远优先展开。
- 导航改造影响命令面板：共用同一导航模型，不维护两份列表。
- 小屏幕出现遮挡：M2 进行多宽度验证。
