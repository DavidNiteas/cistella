# tree-space 设计路线

定位：本文是 `tree-space` crate 需求/目标层的**连贯路线图**（技术无关，只描述本 crate 及以下层级），把工单从目标层面串成一颗树。具体 schema、协议、实现细节在各工单 `01-目标与设计.md`，状态真相在各工单 `03-开发状态.md`。

## 北极星

**tree-space 是「领域无关的通用数据层」**——树形组织 Arrow 数据、内容寻址持久化、三形态磁盘 IO、身份/验证/交换/插件化。

## 目标树

```text
tree-space：领域无关的通用数据层（树 + 桶）

├─ 基础设施与编码
│   ├─ 磁盘协议与基础设施        [已达成] → archive/V4-磁盘协议/
│   ├─ 树运行时契约与叶子系统    [已达成] → archive/V5-树运行时/
│   └─ 编码使命（块/树 canonical Arrow）[已达成] → archive/树与桶模型改造/
├─ 磁盘 IO 与数据能力
│   ├─ 磁盘 IO 管道（对象落盘/GC/重开/verify/ephemeral/三布局）[已达成] → 树与桶管道/
│   ├─ 数据流动统一（交换：块抽象+权限+同步+转换器）[已达成] → archive/交换协议/
│   ├─ 统一验证系统（L1/L2/L3 + validate/assert）[已达成] → archive/数据验证系统/
│   ├─ 版本化插件体系 + 身份语义化  [已达成] → archive/插件化改造/
│   ├─ 插件注册面注入（B1：TbLibrary 持有 Arc<PluginRegistry> + 注入构造器 + 引导链路由走字段，组合生命周期）[已达成] → archive/注册面注入/
│   └─ polars 桥（独立 crate tree-space-polars）[已达成] → ../../tree-space-polars/_dev/archive/polars 桥/；承接插件化改造的「converter 实体 + View 族列边界」
├─ 第三种布局
│   └─ 层化目录（树中心布局）      [挂起] → suspended/层化目录/（解锁条件：P-IO-7 已关闭，等下游「目录即导航」需求触发）
└─ 未立项（待立项工单池）
    └─ 下游 v4→TB 迁移（mzml-db / uni-mass-db）[已达成] → TB 迁移工单闭合（2026-08-29）；v4 Library 面已删除（遗留卫生收尾工单，2026-08-31）
```

图例：节点状态 = `建议`（待立项，新工单立项依据从这里开始）/ `构建中`（已立项，设计阶段）/ `施工中`（已过阶段门，稳定施工）/ `已达成`（工单已归档达成目标）；`挂起` 为生命周期状态（暂停施工、未闭合）。`→` 后为工单引用（相对路径）。引用中相对路径基准为本文所在目录：`archive/`、`suspended/`、活跃工单目录位于 `_dev` 下；`crates/_dev/联合开发.md` 位于 `tree-space` 的上级目录。

## 未立项说明

「未立项（待立项工单池）」不是工单，是待立项目标的归集处——立项时以对应节点为起点建工单，无需改动本树其他部分。
