## 4. 施工协议（给实现者）

### 4.1 工作方式

1. 开工前通读：[`01-目标与设计.md`](01-目标与设计.md) 全文、[`03-开发状态.md`](03-开发状态.md)、本文件；核实源码基线（`src/tb_library.rs` 三处 `PluginRegistry::global()` 落点、`src/plugin/registry.rs` 公开面、`src/plugin/semantic.rs:637` 红线行、`src/layout/materializer.rs::select_materializer` 签名）；
2. 按 §5–§6 小节顺序施工。每个小节：实现 → 自测 → §3 五条命令全绿 → 在 [`04-施工日志.md`](04-施工日志.md) 追加施工日志 → 进入下一个；
3. **不自行宣布里程碑关闭**：日志只陈述「已完成 + 证据」，关闭由验收方裁定。

### 4.2 实现反馈要求（施工日志）

每个小节完成时，在 `04-施工日志.md` 按模板追加一节（实际落位 / 三处路由改造的逐点证据（改造前 vs 后行号）/ 默认构造等价性论证 / 测试证据 / 遇到的问题 / 偏离申请）——宁详勿略。

### 4.3 偏离处理协议

- **能停就停**：发现规范缺陷/歧义 → 先编辑 01 对应小节（附理由与日期）→ 日志注明 → 再实现；
- **来不及**：日志记「偏离申请」继续施工，验收方裁定后回写或返工；
- **禁止静默偏离**（尤其：任何「不动就编译不过」的签名/路由形态调整必须登记——本工单改动面极小，任何超出 §6.2 审计面的源码改动即自动成为偏离申请）。

### 4.4 硬性禁止（违反即返工）

- **红线五条（01 §2.2）**：`plugin/semantic.rs` 零改动（Named `byte_value` 分支, `:637`）；M2 身份 golden 零变动（既有 golden 测试逐字原样）；tree-space 既有测试零破坏；`select_materializer` 公开签名不动；`global()`/`LazyLock` 实现不动；
- **B2 / 内核查询入口永久否决**：任何以本工单为名的「Named 身份公式钩子 / 内核查询面」形态不立项、不实现；
- **改动面审计**：源码 diff **只允许** `src/tb_library.rs`（含私有协同函数/签名透传）；`registry.rs`/`semantic.rs`/`materializer.rs`/`block/*` 零 diff（`git diff --stat` 入关闭标准）；
- **默认等价义务**：默认构造必须与改造前逐字节等价（B1-T1）——不允许「默认也换实现」的隐性行为漂移；
- **领域无关**（业务语义字面量禁入）；**不 git 写操作**（本工单自身）；不提交副产物；测试不设 timeout 中断。

### 4.5 代码风格

- `cargo fmt` 干净、workspace 零 warning（含 `--all-targets`）；
- 源码 doc 注释英文；测试命名 `<批次><N>_<主题>_<断言>` 风格（如 `t_s_b1_1_default_equivalent`、`t_s_b1_2_injected_lifecycle`）；
- 遵守仓库 AGENTS.md：一切命令经 pixi 环境。

### 5.2 编译单位逐个 + 改动面

- **`src/tb_library.rs`**：

```rust
pub struct TbLibrary<L: TbLayout = FlatDirLayout> {
    layout: L,
    registry: Arc<PluginRegistry>,   // 新增（01 §3.1）
    state: Option<LoadedState>,
}

impl TbLibrary<FlatDirLayout> {
    /// 默认创建（语义/签名不变）：委托 create_with_registry(root, Arc::new(PluginRegistry::new()))。
    pub fn create(root: impl Into<PathBuf>) -> Result<Self>;
    pub fn create_with_materialization(root: impl Into<PathBuf>, materialization: Materialization) -> Result<Self>;

    /// 注入式创建（新增，01 §4）：registry 为库实例插件路由注册面。
    pub fn create_with_registry(root: impl Into<PathBuf>, registry: Arc<PluginRegistry>) -> Result<Self>;

    /// 默认打开（语义/签名不变）：委托 open_with_registry(root, Arc::new(PluginRegistry::new()))。
    pub fn open(root: impl Into<PathBuf>) -> Result<Self>;

    /// 注入式打开（新增，01 §4）。
    pub fn open_with_registry(root: impl Into<PathBuf>, registry: Arc<PluginRegistry>) -> Result<Self>;

    /// 只读访问器（默认加；02 §9-3 可调）。
    pub fn plugin_registry(&self) -> &Arc<PluginRegistry>;
}

impl SingleFileTbLibrary for TbLibrary<SingleFileLayout> {
    // create / create_with_materialization / open —— 签名不变；构造时 registry = Arc::new(PluginRegistry::new())
}

impl<L: TbLayout> TbLibrary<L> {
    /// 共享引导链（pub(crate)：签名按需收敛 registry 参数——默认/注入共用一条实现）。
    pub(crate) fn open_with(layout: L, registry: &Arc<PluginRegistry>) -> Result<Self>;
    // step 2：registry.tree_plugin(tree_disk)（改造点 #1）
    // verify：self.registry.route_disk(disk, &kind)（改造点 #3）
}

// restore_bucket_from_refs(layout, rows, versions) → 增 registry: &PluginRegistry 参数（改造点 #2）
// write_commit 的 select_materializer 调用不动（红线）
```

- **改造三点的逐点形态**：

| 改造点 | 前 | 后 |
|---|---|---|
| `open_with` step2 `tree_plugin` | `PluginRegistry::global().tree_plugin(tree_disk)` | `registry.tree_plugin(tree_disk)` |
| `restore_bucket_from_refs` step5 `route_disk` | `PluginRegistry::global().route_disk(disk, &kind)` | 参数 `registry: &PluginRegistry` → `registry.route_disk(disk, &kind)`（调用方传 `self.registry`） |
| `verify` 行循环 | `PluginRegistry::global().route_disk(disk, &kind)` | `self.registry.route_disk(disk, &kind)` |

- **默认等价实现**：`create` → `create_with_registry(root, Arc::new(PluginRegistry::new()))`（materialization 同理，注入面保持物化参数）；`open` → `open_with_registry(root, Arc::new(PluginRegistry::new()))`；`SingleFileTbLibrary` 内部构造含 `Arc::new(PluginRegistry::new())`。等价性论证 01 §3.3。

### 6.2 贯穿硬边界（TS-B1-2）

- **组合语义完整性**：同一 `Arc<PluginRegistry>` 贯穿 create 与 open（两端一致 → 全链路由自洽）；注入 registry 的**组合性**由调用方编排（内建/部分注册/定制插件），库实例不代编排；

## 7. 待确认问题（可调项，施工须在验收报告注明实际取值）

> 以下为 C 层实现细节的默认取值；干事按默认施工，若需偏离 → 按 §4.3 偏离协议登记，主代理终审裁定。

1. **single-file 注入构造器**：默认**不加**（`SingleFileTbLibrary` 三构造器签名不变、内部默认注册面）——保持最小改动面；若下游出现 single-file 组合需求 → 后续独立增量（涉及 trait 面加法，默认不预支）。
2. **引导链共享实现的参数形态**：默认 `open_with(layout, registry)` 显式传参（自由函数 `restore_bucket_from_refs` 同理）——签名收敛由施工按实际调用面裁定并登记 04；不引入全局态。
3. **`plugin_registry()` 访问器**：默认**加**（只读 `&Arc<PluginRegistry>`）；若审计认为暴露面多余 → 改 `pub(crate)` 或删除，属 C 层取舍，登记即可。
4. **默认注册面的等价性证明载具**：默认 = B1-T1 行为断言（同输入同输出 + 内容核对）；是否再加「注册面内容逐项相等等价」（`global()` vs `new()`）由施工按测试便利裁定。
5. **退化路径在组合态的断言粒度**：默认 = 分类/行数级（`DegradedBlock` 入槽 + verify 计入总数）；字节级退化载荷断言不属本工单（既有退化面已冻结）。
6. **消费样例**：默认不把阶段 1 桥的 `indexed-table` 块引入本工单测试依赖（桥为串行前置，非本工单依赖面）；若组合测试需要 Named 块样本 → 用最小自制 `RegisteredBlock`（测试内定义）达成两套注册面正交性演示（01 §3.4 注记）。
