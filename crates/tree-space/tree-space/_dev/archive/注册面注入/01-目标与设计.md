## 0. 背景与定位

### 0.1 承接关系（前置声明）

- **插件化改造工单（设计源，`archive/插件化改造/`，PL-1+PL-2 全关）**：`PluginRegistry` 是已落地的插件注册与路由面（`src/plugin/registry.rs`）——`PluginRegistry { blocks, trees, converters }`（Arc 插件向量）；`new()`（内建自动注册 `ArrowIpcBlockPlugin` + `ArrowParquetBlockPlugin` + `Arrow55TreePlugin` + `Arrow55→Arrow55` 恒等 `MemoryConverter`）/ `empty()` / `register` / `register_tree` / `register_converter`（重名 `TypeConflict` 拒绝）/ `route_disk(disk, kind)` / `tree_plugin(disk)` / `validate_pair` / `converter`（M2 内存转换挂钩）；`global()` = **进程级不可变 `LazyLock` 单例**；
- **现状落差**：`TbLibrary` 引导链（`src/tb_library.rs`）**三处路由写死 `PluginRegistry::global()`**——① `open_with` 引导树插件（step 2 `tree_plugin`），② `restore_bucket_from_refs` 按行路由块插件（`route_disk`），③ `verify` 逐行路由（`route_disk`）。测试与组合场景**无法注入自定义 registry**：缺插件隔离、多注册表场景不可表达（「我这套块只有这些插件」的组合态不存在）；
- **消费侧触发（阶段 1 桥回归基线）**：`tree-space-index` 桥（先行工单，TS-I-1→3 全关后本工单开工）注册 Named 块 `indexed-table` 进 tree-space **进程级块注册表**（`register_block`）；B1 后消费方（如 uni-mass-db）可自持 `Arc<PluginRegistry>` 与库实例解耦——注入式注册面使「组合生命周期」显式可表达、可测试；
- **红线基线事实**：`src/plugin/semantic.rs:637` `BlockKind::Named(_) => byte_value(payload)`（M2 Named 身份公式，**不动**）；`src/layout/materializer.rs::select_materializer`（块物化器选择，**公开签名不动**）；M2 身份 golden 测试为既有冻结断言（**零变动**）。

### 0.2 北极星（一句话）

**在不动 `PluginRegistry` 语义、不动 `global()` LazyLock、不动 M2 身份公式的前提下，把 `TbLibrary` 的插件路由从「写死进程单例」改为「持有 `Arc<PluginRegistry>` 字段 + 注入构造器 + 引导链三处路由改走字段」，以最小改动面开放可组合的注册面生命周期。**

- **做（B1）**：注入式 registry——`TbLibrary` 增 `registry: Arc<PluginRegistry>` 字段；`create_with_registry` / `open_with_registry` 注入构造器；默认 `create`/`open`（及 `SingleFileTbLibrary` 面、`create_with_materialization`）委托同实现、以 `PluginRegistry::new()` 自建；引导链三处路由改走字段/参数。
- **不做（永久否决）**：B2（Named 身份公式钩子）、**内核查询入口**（把 table-index 等外部查询语义塞进内核——任何形态都否决）；不做 `PluginRegistry` 本体改造（只被注入，不改注册/路由/冲突检查/内建自动注册语义）；不动 `global()`/`LazyLock` 形态；不动 `select_materializer` 公开签名。
- **碰面**：tree-space 本体（`src/tb_library.rs` 及其私有协同函数——本工单是**内核工单**，离开阶段 1 桥的「零内核」旗界）。

### 0.4 决策期定稿的关键结论（A 层已拍板不可改）

## 1. 北极星

**把「插件路由 = 进程单例」降格为「插件路由 = 库实例字段」，让 tree-space 库与插件注册面可组合、可隔离、可测试——而不改变任何既有的路由结果、身份公式与公共 API 签名。**

- **可组合生命周期**：调用方自建/自持 `Arc<PluginRegistry>`（内建、部分注册、定制插件编排）→ `create_with_registry`/`open_with_registry` 注入 → 库实例全程走该注册面（写侧物化面经 `select_materializer` 不变，读侧/验证侧路由经字段）→ 同一 `Arc` 可复用于多个库实例（跨库共享注册面）；
- **可隔离**：缺某一插件的 registry → 引导/退化语义按既有规则表达（树插件缺失 → `BootstrapIncomplete`；块插件缺失 → `DegradedBlock`——行为不变，只是注册面可注入）；
- **零行为漂移（默认路径）**：`create`/`open` 默认委托 = 与改造前逐字节等价（B1-T1 断言：默认注入与 `global()` 路由同输入同输出）；
- **最小改动面**：字段 + 平行构造器 + 三处路由点（§3.2 逐点）；不引入新的错误变体、不改变任何既有签名。

## 3. 架构决策（B 层，已拍板）

### 3.1 字段与构造器形态

```rust
pub struct TbLibrary<L: TbLayout = FlatDirLayout> {
    layout: L,
    registry: Arc<PluginRegistry>,   // 新增：插件路由的注册面（引导链/验证侧消费）
    state: Option<LoadedState>,
}
```

- **默认构造**：`create` / `create_with_materialization` / `open`（flat-dir）与 `SingleFileTbLibrary` 全部委托到内部实现、以 `registry = Arc::new(PluginRegistry::new())` 落字段——签名、顺序、行为与改造前逐字节等价（§3.3）；
- **注入构造器**（flat-dir inherent impl）：

```rust
pub fn create_with_registry(root: impl Into<PathBuf>, registry: Arc<PluginRegistry>) -> Result<Self>;
pub fn open_with_registry(root: impl Into<PathBuf>, registry: Arc<PluginRegistry>) -> Result<Self>;
```

- **single-file 面**（`SingleFileTbLibrary` trait）：`create(path)` / `create_with_materialization(path, m)` / `open(path)` 保持现状签名，内部同样落字段（默认 `PluginRegistry::new()`）；**不加** single-file 注入构造器（最小面默认，02 §9-1 可调）；
- **只读访问器**：`pub fn plugin_registry(&self) -> &Arc<PluginRegistry>`（默认加——供 B1-T 断言与消费方自检；02 §9-3 确认去留）。**落位 `impl<L: TbLayout>` 泛型**（字段在泛型结构体、且覆盖 single-file 面，2026-08-26 施工定，C 层取值登记）。

### 3.2 引导链三处路由改走字段（逐点）

| # | 现落点（`src/tb_library.rs`） | 现状（写死） | 改造后（走字段） |
|---|---|---|---|
| 1 | `open_with` 引导链 step 2（树插件路由） | `PluginRegistry::global().tree_plugin(tree_disk)` | `registry.tree_plugin(tree_disk)`（registry = 本库实例字段/参数） |
| 2 | `restore_bucket_from_refs` step 5（每行块插件路由） | `PluginRegistry::global().route_disk(disk, &kind)` | `registry.route_disk(disk, &kind)`（registry 以参数透传——该函数为自由函数，经调用方传入本库 registry） |
| 3 | `verify` 行循环（块插件路由） | `PluginRegistry::global().route_disk(disk, &kind)` | `self.registry.route_disk(disk, &kind)` |

- **写侧**（`write_commit` step 1 的 `select_materializer`）**不碰**——红线段（§2.2）；
- **性质**：路由结果函数只依赖「registry 内容」，不依赖「哪个全局静态」——改走字段后默认路径结果与改造前**逐字节一致**（§3.3 论证 + B1-T1 断言）。

### 3.3 行为等价性论证（默认 == global）

- `PluginRegistry::global()` 是 `LazyLock<PluginRegistry>` 静态——初始化后**不可变**（只暴露 `&` 面，无 `&mut`），任何调用方无法事后增删插件；
- `PluginRegistry::new()` 自动注册同一组内建（Ipc/Parquet 块插件 + Arrow55 树插件 + Arrow55 恒等转换器）——与 `global()` **内容等价**；
- 因此默认构造（`Arc::new(PluginRegistry::new())`）与改造前（写死 `global()`）在**同一输入下路由结果逐字节一致**——等价性由构造内容证明 + B1-T1 测试断言（默认构造 vs 显式 `global()` 注入：同输入同输出）；
- **残余差异登记**：进程内若存在「改造前代码路径」仍直接读 `global()` 与其他库实例并存（过渡期）——本工单**全部三处路由改造完成后**不存在混合路径；测试面保证改造后库实例自洽（B1-T3 全链）。

### 3.4 组合生命周期语义

- 调用方持 `Arc<PluginRegistry>` → 可同时用于 create 与 open（**同一注册面贯穿建库/重开**）——`check_anchor` 并非本工单内容，但「库生命周期两端注册面一致」是组合语义的完整性主张（B1-T3）；
- 缺插件场景语义不变：树插件缺失 → `BootstrapIncomplete`（树结构不可解析）；块插件缺失 → `DegradedBlock`（退化槽）——**都是既有行为**，注入只是让「缺什么」可编排；
- 跨库共享：同一 `Arc` 可注入多个库实例（多库同注册面）；互不影响（registry 内容在组合期由调用方编排）。
- 注记：tree-space 的**块类型注册表**（`block::registry`，Named 块如阶段 1 的 `indexed-table`）是另一张**进程级**表，与 `PluginRegistry`（块/树/转换器插件）**两套注册面并存**、互不替换——B1 只注入后者；Named 块注册仍是进程级（阶段 1 桥 `register()` 的语义不变）。

### 3.5 边界与错误语义

- **不新增错误变体**：引导失败（`BootstrapIncomplete`）、退化（`DegradedBlock`）、路由 miss（`None` → 既有分类）语义全部沿用；注入的 registry 内容不足 → 沿既有错误/退化路径表达；
- **不吞错**：错误透传与改造前一致（`Result` / `TreeSpaceError` 归口不变）；
- **线程安全**：`Arc<PluginRegistry>` 满足 `Send + Sync`（`PluginRegistry` 全 `Arc` 字段、无 `RefCell`）——`TbLibrary` 并发性不变。

## 4. 公共 API（契约，已拍板）

```rust
use std::sync::Arc;
use crate::plugin::registry::PluginRegistry;

impl TbLibrary<FlatDirLayout> {
    /// 注入式创建：registry 为库实例的插件路由注册面（引导链/验证侧消费，§3.2）。
    pub fn create_with_registry(
        root: impl Into<std::path::PathBuf>,
        registry: Arc<PluginRegistry>,
    ) -> Result<Self>;

    /// 注入式打开：以同注册面重开（组合生命周期完整性，§3.4）；恢复语义与 `open` 一致。
    pub fn open_with_registry(
        root: impl Into<std::path::PathBuf>,
        registry: Arc<PluginRegistry>,
    ) -> Result<Self>;

    /// 只读访问器：当前库实例的插件注册面（默认加；02 §9-3 可调）。
    pub fn plugin_registry(&self) -> &Arc<PluginRegistry>;
}

// 既有签名全部不变：
//   TbLibrary::create(root) / create_with_materialization(root, m) / open(root)   —— 委托，等价（§3.3）
//   SingleFileTbLibrary::{create, create_with_materialization, open}               —— 签名不变，内部落字段
//   select_materializer(…)                                                          —— 不动（红线）
```

### 4.1 语义注记

- 既有构造器的行为 = 改造前（默认注册面 = `PluginRegistry::new()`，与 `global()` 内容等价，§3.3）——**零迁移**；
- `create_with_registry`/`open_with_registry` 是**平行加法**：不取代、不改变既有入口；调用方可混用（create 默认 + open 注入是合法但非推荐组合——语义以各自注册面为准）；
- `plugin_registry()` 默认返回内部 `Arc` 引用（共享语义：调用方可克隆 `Arc` 编排组合，不绕过库实例路由）。
