# tree-space 模块化子树改造 · 目标与设计

- 立项：2026-08-30（用户 A 层直接指令；上游 = uni-mass-db MVP 重设计工单 R0 前置区域）
- **语义 authority：本文档 §1 为用户 2026-08-30 口述拍板的忠实落纸，后续修订须经用户确认。**

## 1. 语义定义（用户拍板，最高优先级）

**模块化子树 = 编译期的树模板组合系统。**

1. **组合发生在编译期**：用户通过组合，基于小树的**模板**融合成大树模板。一旦融合，它们就是一棵树。模板是编译期就定死的东西——这是 Rust 侧的特性（类型/const 层面）。
2. **融合的永远是模板，不是实例**：不能把两个实例（装了数据的库）融合成新的树。运行时实例之间只有**数据覆盖或复制**逻辑，变成其中一棵树的形态（同构数据搬运）。
3. **运行时不可以组合出新的树**：运行期树结构不可变。
4. **树嵌套**（一个树的叶子实际上是另一棵树）：运行时动态能力的补齐方向，**之后再考虑实现**，不在本工单范围。
5. **组合两模式**（承 Q5 拍板，为模板融合的编译期规则）：
   - **正交组合**：树与树完全正交；非正交情况**编译期直接报错**；
   - **合并形态**：允许交叉，后来的把先来的交叉部分**覆盖**。
6. **读侧宽容**（运行时投影）：实例文件中存在模板声明之外的数据没关系——一棵树只读取自己定义的部分，无视额外部分（现有 `open_multi` foreign-skip 语义即此投影）。

## 2. 现状与差距

- 现有载体：`TbLayout` trait——当前每 crate 一个**单体** layout（mzml-db、uni-mass-db 各一套），无子模板概念、无组合算子、无编译期冲突检查。
- 内核已有可复用零件：开放命名树（DynamicNode）、内容寻址桶、三对象注册、manifest/TypeId——这些是**实例层**机制，模板层在其上另起。
- 编译期正交检查的现状：无（同路径冲突现在只会是运行时行为）。

## 3. 目标

tree-space 提供**可组合的树模板**机制：

1. **子树模板**：一棵"小树"的形状（子域/表/层级结构）可定义为一个可复用模板单元（Rust 类型/const 形态，具体载体在施工图纸定：trait 泛型组合 vs const definition 组合，或混合）。
2. **组合算子**：模板 × 模板 → 大树模板；两模式（正交——冲突编译期报错 / 合并——后到覆盖）。
3. **实例关系**：实例 = 大树模板的运行时载体；运行期结构不可变；同构数据覆盖/复制走现有 exchange 面语义（**本工单不改 exchange/运行时 IO**——"物理 IO 整树"约束维持，模块化不破它）。
4. **下游消费**：uni-mass-db 的大树模板 = 点云/地理/链接/mapping/chem 各小树模板的组合；mzparse-workspace 将来 = uni-mass-db 模板 + 私有模板组合（其定位文档的"超集"在模板层的实现路径）。

## 4. 边界

- 不做树嵌套（运行时动态能力，用户明示之后考虑）。
- 不改运行时 IO/存储形态（整树 IO 维持；不引入懒加载/物理分库）。
- 不动现有两个 layout 的实例层行为（向后兼容：现有 mzml-db/uni-mass-db 库文件照常打开）。

## 5. 多位置派生（用户 2026-08-30 增补，核心语义第七条）

7. **模板与挂载位置解耦（多位置派生）**：同一棵树模板可以挂在**不同位置**，完全相同的结构、语义由位置注入（例：spectrum 树挂 /{study}/ 下=参考谱、挂（远期）/{lib}/ 下=独立库资源；库分组由挂载路径承载）。挂载位置坐标系可扩展（/{study}/r{run}/ 现行 + /{lib}/ 远期）。组合系统必须支持：模板定义纯结构，位置/语义角色在挂载（组合声明）时赋予。
