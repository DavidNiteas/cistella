# 插件化改造：01 目标与设计

> 本工单是「tree-space 版本化插件体系」这一架构方向的独立立项（工单名：tree-space 插件化改造；批次代号 PL）。authority 覆盖：把 tree-space 从「物化器半插件」改造成**版本化插件体系**——数据块（含树这个特殊块）拥有两个正交的布局版本（内存布局 ⊥ 磁盘布局），插件声明配套映射并注册，IO 只走配套直读直写，转换走内存运行时转换；树版本存 boot 块、各块版本存树伴生版本侧表；缺插件块退化为原始字节；v4 在 tree-space 内部废弃并门控。设计形态（A 层决策 + 三个新拍板 + B 层方案）均已由主代理拍板，本文件是唯一规范 authority；施工细则见 [`02-施工路线图.md`](02-施工路线图.md)；状态真相见 [`03-开发状态.md`](03-开发状态.md)。

## 0. 背景与定位

**承接与现状**：tree-space 目前的「插件」能力是**半插件化**的——`BlockMaterializer` trait（Ipc/Parquet 双实现）抽象了块物化格式，但**版本概念缺失**：内存表达与磁盘表达 1:1 绑死（`Materialization` 枚举即磁盘格式，`RefId`/`TreeId` 一律由 canonical 字节公式给出），没有「内存布局版本 ⊥ 磁盘布局版本」的维度，没有插件配套映射声明，没有运行时路由，没有退化语义（缺插件即整体不可读）。同时 v4 表空间面（`Library` 及 `io/` LeafIo 原型）与树+桶面并存，历史包袱仍在（详见 §5 现状盘点）。

**北极星**：把 tree-space 改造成「版本化插件体系」（§1）。插件声明「内存布局版本 ↔ 磁盘布局版本」配套映射；IO 链路按版本路由、可达才 IO；各块版本存树伴生版本侧表、树版本存 boot 块；缺插件的块退化为原始字节、其余保持可读；身份与版本正交（RefId 不含版本）。

**核心分界（铁律）**：
- **版本是「两个正交维度」，不是一组并列格式**：内存布局版本 ⊥ 磁盘布局版本（§2-1），插件声明两者之间的配套映射（§2-2）；
- **IO 与转换分开**：IO = 磁盘版本 ↔ 配套内存版本直读直写（§2-3）；跨插件转换 = 内存→内存运行时转换（M2+ 通道，`converter` 挂钩）；
- **身份不进版本**：RefId/TreeId 不含版本（§2-8）；M1 身份仍走字节公式 → 零 golden 变更（硬门槛，§4-4）；
- **boot 块布局写死**：固定 arrow-rs 单批 4 列，独立于插件体系（§4-3）；
- **v4 只动内部、不做垫片**：tree-space 内部废弃 v4 表空间面，`Library` 面 `#[deprecated]` 门控；下游 v4→TB 迁移另开工单（§2-10 / §6）。

## 1. 北极星

一句话：**把 tree-space 改造成「版本化插件体系」——数据块与树各有两个正交的布局版本（内存 ⊥ 磁盘），插件声明配套映射并注册，IO 只走配套直读直写，转换走内存运行时转换；树版本存 boot 块、各块版本存树伴生版本侧表；缺插件块退化为原始字节、其余保持可读；身份与版本正交。**

- **正交版本**：`MemLayout`（内存表达）⊥ `DiskLayout`（磁盘表达），两者独立演进（§2-1 / §4-2）；
- **配套插件**：`BlockPlugin` / `TreePlugin` 声明 `(内存版本, 磁盘版本)` 配套对，`PluginRegistry` 注册 + 冲突检查 + 路由（§2-2 / §4-1）；
- **直读直写**：IO 链路 = 磁盘版本 ↔ 配套内存版本，按版本路由、可达才 IO（§2-3 / §2-4）；
- **版本落点**：树的版本存 boot 块（全局、独立、写死），各块的版本存树伴生版本侧表（每 commit 一张，§2-5 / §2-6 / §3-1）；
- **部分可读**：缺插件的块退化为原始字节，树布局等同→结构可解析，其余块照常读（§2-7 / §4-5）；
- **身份正交**：RefId/TreeId 不含版本；M1 身份走字节公式（零 golden 变更），M2 语义化（§2-8 / §4-4）。

## 2. A 层决策（用户已拍板，10 条）

> 以下 10 条为 A 层（方向/范围层）决策，已由用户拍板，本工单直接承载，**不得擅改**。

1. **两个正交的布局版本**：数据块（含树这个特殊块）有两个正交的布局版本——**内存布局版本** ⊥ **磁盘布局版本**。两者独立存在、独立演进，不是同一维度上的多个并列值。
2. **插件声明配套映射**：插件声明**配套映射**（内存 X ↔ 磁盘 Y）；不配套的组合不允许标定（不允许写入/创建）；配套声明做**冲突检查**（同一组合重复/矛盾声明 → 拒绝）。
3. **IO = 配套直读直写；转换 = 内存运行时转换**：IO 是「磁盘版本 ↔ 配套内存版本」的直读直写；转换是「内存→内存」的运行时转换（先直读成 A 插件内存态，再在内存里转 B）。IO 链路与转换链路分离。
4. **IO 链路可达性**：读/写时**找链路**（按磁盘版本路由到配套插件），**可达才 IO，不可达没法 IO**（缺插件/版本不可达 → 不产生 IO，走退化或错误语义，§2-7）。
5. **版本存树伴生结构**：各块的（内存+磁盘）版本存**树伴生结构**（版本侧表，§3-1）；树的版本存 boot 块（§2-6）。
6. **boot 块独立**：boot 块固定 arrow-rs 布局（**写死不变**），存「库版本 id（给人看）+ 树内存布局版本 + 树磁盘布局版本」（§4-3）。
7. **部分可读 + blob 退化**：树布局等同 → 结构可解析；**缺插件的块退化为原始字节**（DegradedBlock，§4-5），其余块保持可读；verify 对退化块只验地址、报 degraded。
8. **身份正交**：RefId 不含版本（TreeId 同理）——身份是语义的（或 M1 的字节公式），与「以什么布局版本存储/表达」无关。
9. **版本形式**：内存枚举 + 磁盘字符串——`MemLayout` 是 Rust 枚举（封闭、编译期），`DiskLayout` 以磁盘字符串表达（`"arrow-ipc"` / `"arrow-parquet"` 等），显式映射（§4-2）。
10. **v4 废弃（无存量数据包袱）**：**只动 tree-space 内部**——v4 表空间面在 crate 内废弃，`Library` 面 `#[deprecated]` 门控；不做 v4 兼容垫片；下游（`mzml-db` / `uni-mass-db`）v4→TB 迁移**另开工单**（§6）。

## 4. B 层方案（顾问已出，照此落 02）

### 4.1 插件 trait（`src/plugin/` 新模块面）

由现有 `BlockMaterializer` **泛化**（`Materialization` 枚举 → 磁盘版本 + 配套插件），三层：

```rust
/// 块插件：声明内存/磁盘配套对 + kind 范围 + 探测 + 身份 + 直读直写 + 地址。
/// [M2] 追加 `semantic`（语义值，§4-4）。
pub trait BlockPlugin: Send + Sync {
    const MEMORY: MemLayout;              // 配套内存布局版本（M1 恒 Arrow55）
    const DISK: DiskLayout;               // 声明的磁盘布局版本
    fn kinds(&self) -> &'static [BlockKind];   // 该插件可处理的块 kind 集合
    fn matches(&self, kind: &BlockKind) -> bool;  // 探测：某 kind 是否归本插件
    fn ref_id(&self, kind: BlockKind, payload: &[u8]) -> RefId;  // M1 = 字节公式；[M2] = 语义公式
    fn encode(&self, envelope: &Envelope) -> Result<Vec<u8>>;    // 内存态 → 磁盘字节（配套直写）
    fn decode(&self, physical: &[u8]) -> Result<Envelope>;       // 磁盘字节 → 内存态（配套直读）
    fn address(&self, physical: &[u8]) -> Digest;                // 恒 hash 字节，§2-8 / §4-4
    // [M2] fn semantic(&self, envelope: &Envelope) -> SemanticValue;
}

/// 树插件：与块插件对称（encode/decode/tree_id/address）。
/// M1 由 `Arrow55TreePlugin` 包装 `tree::codec`（encode/decode/tree_id）实现。
pub trait TreePlugin: Send + Sync {
    const MEMORY: MemLayout;              // boot 块 tree_mem_version 匹配
    const DISK: DiskLayout;               // boot 块 tree_disk_version 匹配
    fn tree_id(&self, bytes: &[u8]) -> Digest;     // M1 = tree::codec::tree_id；[M2] = semantic_tree
    fn encode(&self, image: &TreeImage) -> Result<Vec<u8>>;
    fn decode(&self, bytes: &[u8]) -> Result<TreeImage>;
    fn address(&self, bytes: &[u8]) -> Digest;     // 恒 hash 字节
    // [M2] fn semantic(&self, image: &TreeImage) -> SemanticTree;
}

/// 插件注册表：注册 + 配套冲突检查 + 路由。
pub struct PluginRegistry { /* 进程级单例（对齐 block::registry 的进程级模式） */ }
impl PluginRegistry {
    pub fn register(&mut self, plugin: Arc<dyn BlockPlugin>) -> Result<()>;  // 冲突检查（§4-1 配套）
    pub fn validate_pair(&self, mem: MemLayout, disk: DiskLayout) -> Result<()>;  // 配套冲突检查
    pub fn route_disk(&self, disk: DiskLayout, kind: &BlockKind) -> Option<&dyn BlockPlugin>; // 读路由
    pub fn tree_plugin(&self, disk: DiskLayout) -> Option<&dyn TreePlugin>;  // 树插件按磁盘版本路由
    // [M2] pub fn converter(&self, from: MemLayout, to: MemLayout) -> Option<&dyn ...>;
}
```

分层保留（**不合一**）：
- `RegisteredBlock`（kind 命名、canonical payload、`ArrowCaps`）**保留现状**——插件体系在其上路由，不重写注册面；
- `TbLayout`（落盘：对象通道、`committed`、块/树/引用读写）**保留现状**——插件体系在 `TbLayout` 之上路由 IO，不改落盘通道；
- 现有 `BlockMaterializer` 双实现改写为**磁盘插件**：`IpcMaterializer` → `ArrowIpcBlockPlugin`（`DISK = ArrowIpc`），`ParquetMaterializer` → `ArrowParquetBlockPlugin`（`DISK = ArrowParquet`，仅 `ArrowTable`）；`Arrow55TreePlugin` 包装 `tree::codec`（`DISK = ArrowIpc`、内存 = Arrow55）；
- `Materialization` 枚举与 `probe_block_materialization`（`ARROW1`/`PAR1` 魔术）语义升级为「磁盘版本探测」（`DiskLayout` 面），`select_materializer` 由「布局默认 + kind 约束」迁移为「版本路由」（布局默认 = 默认磁盘版本，kind 约束不变：`Blob`/opaque 恒原生字节）。

**配套冲突检查语义**：对每个 `(MEMORY, DISK)` 组合，块侧至多一个 `BlockPlugin`、树侧至多一个 `TreePlugin`；`validate_pair(mem, disk)` 无插件声明（不可达组合）→ 不允许标定（`create`/写入时 `Err`，§2-2 / §2-4）。内置配对（Arrow55↔ArrowIpc、Arrow55↔ArrowParquet）由 `PluginRegistry::new()` 自动注册。

### 4.2 版本枚举（内存枚举 + 磁盘字符串）

```rust
/// 内存布局版本（正交于磁盘布局，§2-1）。Rust 枚举，封闭、编译期。
#[derive(Clone, Copy, Debug, Eq, PartialEq, Hash)]
pub enum MemLayout { Arrow55 }   // [M2] 追加 Polars 等

/// 磁盘布局版本（正交于内存布局，§2-1）。以磁盘字符串表达 + 显式映射。
#[derive(Clone, Copy, Debug, Eq, PartialEq, Hash)]
pub enum DiskLayout {
    ArrowIpc,        // "arrow-ipc"（`ARROW1` 魔术）
    ArrowParquet,    // "arrow-parquet"（`PAR1` 魔术）
    // [M2] 追加 PolarsIpc / PolarsParquet
}
```

- `MemLayout::as_str()` / `DiskLayout::as_str()`：小写 kebab 磁盘字符串（`"arrow55"` / `"arrow-ipc"` / `"arrow-parquet"`）；
- `DiskLayout::from_str(&str) -> Option<DiskLayout>`：磁盘字符串 → 枚举的**显式映射**；`None` = **未知磁盘版本**——块侧 → 退化（`DegradedBlock`，§4-5）；树侧（boot 的 `tree_disk_version`）→ `Err(BootstrapIncomplete)` 硬失败（§4-3）；
- 版本形式纪律（§2-9）：**内存枚举 + 磁盘字符串**——枚举不进磁盘字节，字符串显式映射回枚举。

### 4.3 boot 块（独立、写死）

- **固定 arrow-rs 单批 4 列**（写死不变，独立于插件体系）：
  - `boot_version: u16`（本工单 = 1）；
  - `library_id: Utf8`（库版本 id，给人看）；
  - `tree_mem_version: Utf8`（树的**内存**布局版本字符串，如 `"arrow55"`）；
  - `tree_disk_version: Utf8`（树的**磁盘**布局版本字符串，如 `"arrow-ipc"`）。
- **落点**：FlatDir 走 `<root>/tb-boot/boot.ipc` 固定名；SingleFile 走 `ObjectKind::Boot` 进对象目录（single_file.rs:57 的 `ObjectKind` 枚举**新增 Boot 变体**）；
- **写**：`create`（含 `create_with_materialization`、SingleFile 入口）创建库时**写 boot**（`boot_version = 1` + `library_id` + 树版本对）；**读**：`open` 引导第一步读 boot（§4-3 引导八步）；
- **失败语义**：boot 缺 / 坏 / `boot_version` 不支持 / `tree_disk_version` 未知 → **`Err(BootstrapIncomplete)` 硬失败**（不退化——树是结构的骨架，没有树版本就无法进入结构解析，§2-7）。

**引导流程八步（`TbLibrary::open` 重排，§4-3）**：

1. 读 boot（`tb-boot/boot.ipc` / `ObjectKind::Boot`）→ 校验 boot_version、解析树版本对（未知树磁盘版本 → `BootstrapIncomplete`）；
2. 路由树插件：`registry.tree_plugin(tree_disk_version)`（不可达 → `BootstrapIncomplete`）；
3. `read_head` → `read_commit` → 解码 `TbPointers`（commit 批 9 列，§3-1）；
4. 读树字节（`*_unchecked` + `tree_id` 重算 + `assert_tree_address`）→ **树插件 `decode`** → `TreeImage`；
5. 读 ref 表字节（`tb-refs`）→ `decode_ref_table` → 行列表；读版本侧表（`tb-versions`，第 9 列非空时）→ `xpath → (mem_ver, disk_ver)` 映射；
6. **逐行路由/退化重建桶（ref 表驱动，§4-5）**：每行按 `(address, disk_ver)` 读块对象 → `route_disk` 路由插件 decode 装桶；缺插件/未知版本 → `DegradedBlock` 进 `bucket.degraded`；对象文件缺失 → `Err(DanglingReference)`（对象缺失 ≠ 插件缺失）；
7. `XPathIndex` 重建（ref 表行，与现状一致）；
8. 结构可解析检查（verify 面）：树布局等同 → 结构可解析；退化块只验地址、报 degraded（§4-5）。

### 4.4 身份-字节解耦

- **地址恒 hash 字节、不动**：`tb-blob` / `tb-tree-blob` / `tb-refs` 三域地址公式（`block_blob_address` / `tree_blob_address` / `ref_table_address`）**永远 hash 字节**，不随版本变化；
- **身份 M1 仍走字节公式 → 零 golden 变更（硬门槛）**：`BlockPlugin::ref_id` / `TreePlugin::tree_id` 的 M1 实现 = 现状公式（`block_ref_id` / `tree::codec::tree_id`），**M1 期间身份类 golden（11–15、content golden、p_io 系 TREE_ID 等）一个字节不改**；
- **M2 身份语义化**（PL-2，§3-2）：新增 `src/plugin/semantic.rs`——
  - `SemanticValue`：非 arrow 的**极小自描述字节流**标量（不依赖 arrow metadata）；
  - `semantic_table`：表的**粗粒度逻辑类型指纹**（不含 arrow metadata——字段名/类型/nullability/嵌套的逻辑形状）；
  - `semantic_tree`：树的**确定性 walk**（复用 `order_children` 排序，结构形状 + 叶子语义指纹）；
  - `RefId / TreeId = hash(域, [semantic_*])`，**domain tag 不变**（仍 `tb-blob`/`tb-tree-blob`/`tb-refs`/`tb-tree` 等既有域）；
  - 箭头插件（`ArrowIpcBlockPlugin` / `ArrowParquetBlockPlugin` / `Arrow55TreePlugin`）的 `ref_id`/`tree_id` 切换语义公式；
- **M2 golden 影响（已裁定范围）**：**身份类 golden 重冻**（11–15、content golden、p_io_3 TREE_ID 等）；**地址/schema 字节类 golden 保住**（17/18 地址、19 字节、22/23 地址——地址恒 hash 字节、树/引用/commit 的 schema 字节不变）。

### 4.5 退化（部分可读 + blob 退化）

- **新增 `DegradedBlock{kind, disk, raw}`**：不复用 `Blob`（Blob 是 IPC 包装、非裸字节；退化块保留的是**原始磁盘字节**）：
  ```rust
  /// 缺插件块的退化驻留：保留原始磁盘字节。
  /// `disk` = 版本侧表/探测标定的磁盘版本；未知版本以 `DiskVersion` 原样记录（不参与路由/配对）。
  #[derive(Clone, Debug, Eq, PartialEq)]
  pub struct DegradedBlock {
      pub kind: BlockKind,      // 从对象帧头解析的 kind（无法解析 → PayloadMalformed，不退化）
      pub disk: DiskVersion,    // 磁盘版本指示（标定值/未知值原样）
      pub raw: Vec<u8>,         // 原始磁盘对象字节
  }
  pub struct DiskVersion(pub String);   // 磁盘版本字符串（"arrow-ipc" 等；未知字面量原样）
  ```
- **`Bucket` 加并行槽**：`degraded: BTreeMap<RefId, DegradedBlock>`（与 `blocks` 并行，`RefId` 仍由 `block_ref_id(kind, payload)` 对可解析帧头计算——身份正交，§2-8）；
- **重建流程从「扫描 `tb-blocks/`」改「ref 表驱动」**（§4-3 第 6 步）：以 ref 表行 + 版本侧表行为准逐行恢复，不再全目录扫描——扫描式重建无法感知「缺插件的块」与「未被树引用的孤儿对象」的语义区别；
- **投影语义**：`project<T>` 命中退化块 → `Err(PluginMissing{kind, disk})`（缺插件即不可物化，§2-4）；
- **verify 语义**：退化块只验地址（`address == hash(raw)`）、报 degraded（不比对 canonical 身份——无插件无法 decode 回 canonical），其余块照旧全量校验。

## 6. 范围边界（明确不做的）

- **不迁移下游**：`mzml-db` / `uni-mass-db` 的 v4→TB 迁移是**另一个工单**（§2-10）；本工单只动 tree-space 内部，下游冻结/解冻状态不受影响；
- **不做 v4 兼容垫片**：`Library` 面只 `#[deprecated]` 门控，不做任何「新实现塞进 v4 面」的过渡垫片；v4 面不再新增消费点；
- **不做 Dictionary 版本**：`Dictionary`（或任何第三种磁盘表达）不在本工单范围内；
- **不改树 8 列 / committed / 64B 头**：树对象（flat entry table）的 schema 列集、`committed` 对象、SingleFile 容器 64B 头**一律不动**（树对象 schema 改动会改变所有 TreeId，超出本工单授权）；commit 批 8→9 列是**唯一** schema 例外（§3-1，接受 golden 19 重冻）；
- **M1 零新依赖**：PL-1 全程零新增第三方依赖（M2 的 semantic 流为自描述字节流，同样不新增）；
- **身份不进版本**：RefId/TreeId 不含版本（§2-8）；版本侧表/插件体系不参与身份计算（M1 恒字节公式）；
- **不物理合并注册面**：`RegisteredBlock`（kind 命名）与 `TbLayout`（落盘）分层保留、不合一（§4-1）。
