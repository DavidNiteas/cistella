## 4. 施工协议（给实现者）

### 4.1 工作方式

1. 开工前通读：[`01-目标与设计.md`](01-目标与设计.md) 全文、[`03-开发状态.md`](03-开发状态.md)、本文件、`src/` 现状（尤其 `layout/materializer.rs`、`layout/tb.rs`、`tb_library.rs`、`layout/mod.rs`）、归档工单 [`../archive/树与桶模型改造/01-目标与设计.md`](../archive/树与桶模型改造/01-目标与设计.md)（规范基线）、[`../archive/V4-磁盘协议/设计与路线图-v4.md`](../archive/V4-磁盘协议/设计与路线图-v4.md)（v4 协议，S7 废弃边界参照）；
2. 按 §5/§6 小节顺序施工。每个小节：实现 → 自测 → §3 四条命令全绿 → 在 `04-施工日志.md` 追加施工日志 → 进入下一个；
3. **不自行宣布里程碑关闭**：日志只陈述「已完成 + 证据」，关闭由验收方裁定。

### 4.2 实现反馈要求（施工日志）

每个小节完成时，在 `04-施工日志.md` 按模板追加一节（实际落位 / 关键实现决策 / 测试证据 / golden 值 / 遇到的问题 / 偏离申请）——宁详勿略，模板同归档工单先例。

### 4.3 偏离处理协议

- **能停就停**：发现规范缺陷/歧义 → 先编辑 01 对应小节（附理由与日期）→ 日志注明 → 再实现；
- **来不及**：日志记「偏离申请」继续施工，验收方裁定后回写或返工；
- **禁止静默偏离**。

### 4.4 硬性禁止（违反即返工）

- **M1 零 golden 变更（本工单核心红线之一）**：现存所有 golden 断言数值**一个字节不改**——唯一例外 golden 19（commit 9 列重冻，§5.7，需主代理逐条核对）；M2 身份类 golden 重冻只限 §6.2 已裁定清单；
- **地址公式不动**：`block_blob_address` / `tree_blob_address` / `ref_table_address` 恒 hash 字节（01 §4-4），`tb-*` 域标签不动；
- **boot 块布局写死**：4 列 schema（`boot_version u16` / `library_id utf8` / `tree_mem_version utf8` / `tree_disk_version utf8`）、`tb-boot/boot.ipc` 固定名、`ObjectKind::Boot`——冻结，改动须显式声明取代关系（01 §7）；
- **树对象 schema / committed / 64B 头不动**（01 §6）：树 8 列 flat entry table、`committed` 对象、SingleFile 容器 64B 头一律不碰；commit 批 8→9 列是唯一 schema 例外；
- **M1 零新增第三方依赖**（tree-space / tree-space-derive）；M2 同样不新增；
- **v4 面只废弃不删除下游入口**：`Library` 面 `#[deprecated]` 门控（下游仍编译）；删 `io/` 与 v4 专属测试/golden 按 §5.7 精确清单执行，同步登记 03；
- **领域无关**（业务语义字面量禁入）；**不 git 写操作**；不提交 `target/`、缓存、临时环境等副产物；测试不设 timeout 中断，跑完看汇总。

### 4.5 代码风格

- `cargo fmt` 干净、workspace 零 warning（含 `--all-targets`）；
- 源码 doc 注释英文；测试命名 `<批次><N>_<主题>_<断言>` 风格（如 `p_l_1_boot_roundtrip`、`p_l_1_route_unknown_degrades`、`p_l_2_semantic_table_fingerprint_frozen`）；
- 遵守仓库 AGENTS.md：一切命令经 pixi 环境。

- 新增 `src/plugin/version.rs`（+ `src/plugin/mod.rs` 挂 `pub mod version;`）：

```rust
//! 布局版本（01 §2-1/§2-9/§4-2）：内存枚举 + 磁盘字符串，显式映射。

/// 内存布局版本（正交于磁盘布局）。Rust 枚举，封闭、编译期。
#[derive(Clone, Copy, Debug, Eq, PartialEq, Hash)]
pub enum MemLayout { Arrow55 }

impl MemLayout {
    pub const fn as_str(self) -> &'static str;   // "arrow55"
}

/// 磁盘布局版本（正交于内存布局）。以磁盘字符串表达 + 显式映射。
#[derive(Clone, Copy, Debug, Eq, PartialEq, Hash)]
pub enum DiskLayout { ArrowIpc, ArrowParquet }   // [M2] PolarsIpc/PolarsParquet

impl DiskLayout {
    pub const fn as_str(self) -> &'static str;           // "arrow-ipc" / "arrow-parquet"
    pub fn from_str(s: &str) -> Option<DiskLayout>;      // 显式映射；None = 未知磁盘版本
    pub fn probe_magic(payload_first: &[u8]) -> Option<DiskLayout>;  // ARROW1 → ArrowIpc, PAR1 → ArrowParquet, 其它 → None
}
```

- `src/lib.rs`：`pub mod plugin;` + 根级 re-export `MemLayout` / `DiskLayout`（后续 S2/S6 同批 re-export）。

**测试义务**（`tests/p_l_1_versions.rs` 起步）：

- `p_l_1_mem_disk_orthogonal`：`MemLayout` 与 `DiskLayout` 是不同枚举类型（编译即证），`as_str` 互不重叠。

**关闭标准（S1）**：§3 四命令全绿；三组测试绿；零新依赖；零既有公共 API 改动（纯新增）。

### 5.4 S2 插件 trait + arrow55 插件化（编译单位 + 签名 + 测试）

**编译单位逐个 + 签名**：

- 新增 `src/plugin/block.rs`：

```rust
/// 块插件：声明内存/磁盘配套对 + kind 范围 + 探测 + 身份 + 直读直写 + 地址（01 §4-1）。
pub trait BlockPlugin: Send + Sync {
    const MEMORY: MemLayout;                          // M1 恒 Arrow55
    const DISK: DiskLayout;                           // ArrowIpc / ArrowParquet
    fn kinds(&self) -> &'static [BlockKind];          // 可处理 kind 集合（内置四类 + 注册块）
    fn matches(&self, kind: &BlockKind) -> bool;      // 默认 = kinds().contains(kind)
    fn ref_id(&self, kind: BlockKind, payload: &[u8]) -> RefId;   // M1 = crate::block::block_ref_id(kind, payload) 转发
    fn encode(&self, envelope: &Envelope) -> Result<Vec<u8>>;     // 内存态 → 磁盘字节（配套直写）
    fn decode(&self, physical: &[u8]) -> Result<Envelope>;        // 磁盘字节 → 内存态（配套直读）
    fn address(&self, physical: &[u8]) -> Digest;     // = block_blob_address(physical)（恒 hash 字节）
}

/// Arrow IPC 磁盘插件（由 IpcMaterializer 泛化；行为复刻，golden 17 字节不变）。
pub struct ArrowIpcBlockPlugin;
impl BlockPlugin for ArrowIpcBlockPlugin { /* MEMORY=Arrow55, DISK=ArrowIpc, kinds=全部；encode=Envelope::encode, decode=Envelope::decode */ }

/// Arrow Parquet 磁盘插件（由 ParquetMaterializer 泛化；仅 ArrowTable，P-IO-7.2 约束保留）。
pub struct ArrowParquetBlockPlugin;
impl BlockPlugin for ArrowParquetBlockPlugin { /* MEMORY=Arrow55, DISK=ArrowParquet, kinds=&[Table]；encode=parquet 写, decode=parquet 读 → canonical envelope */ }
```

- 新增 `src/plugin/tree.rs`：

```rust
/// 树插件：与块插件对称（01 §4-1）。M1 由 Arrow55TreePlugin 包装 tree::codec。
pub trait TreePlugin: Send + Sync {
    const MEMORY: MemLayout;                            // 树内存布局版本（boot 匹配）
    const DISK: DiskLayout;                             // 树磁盘布局版本（boot 匹配）
    fn tree_id(&self, bytes: &[u8]) -> Digest;          // M1 = crate::tree::codec::tree_id 转发
    fn encode(&self, image: &TreeImage) -> Result<Vec<u8>>;          // 内存树 → 磁盘字节
    fn decode(&self, bytes: &[u8]) -> Result<TreeImage>;             // 磁盘字节 → 内存树
    fn address(&self, bytes: &[u8]) -> Digest;          // = tree_blob_address(bytes)
}

/// M1 树插件：包装 tree::codec 的 encode/decode/tree_id（DISK = ArrowIpc）。
pub struct Arrow55TreePlugin;
impl TreePlugin for Arrow55TreePlugin { /* encode = crate::tree::codec::encode(image), decode = crate::tree::codec::decode(bytes), tree_id = tree::codec::tree_id */ }
```

- 新增 `src/plugin/registry.rs`：

```rust
/// 插件注册表：进程级单例（对齐 block::registry 的进程级模式，01 §4-1）。
pub struct PluginRegistry { /* blocks: Vec<Arc<dyn BlockPlugin>>, trees: Vec<Arc<dyn TreePlugin>> */ }

impl PluginRegistry {
    /// 内置插件自动注册：ArrowIpcBlockPlugin + ArrowParquetBlockPlugin（块侧）；
    /// Arrow55TreePlugin（树侧，DISK=ArrowIpc）。
    pub fn new() -> Self;
    pub fn register(&mut self, plugin: Arc<dyn BlockPlugin>) -> Result<()>;  // 冲突检查（§冲突语义）
    pub fn register_tree(&mut self, plugin: Arc<dyn TreePlugin>) -> Result<()>;
    /// 配套冲突检查：给定 (mem, disk) 组合的块侧/树侧是否恰好可路由（0/多个 → Err）。
    pub fn validate_pair(&self, mem: MemLayout, disk: DiskLayout) -> Result<()>;
    /// 读路由：按磁盘版本 + kind 找块插件（缺 → None = 退化候选）。
    pub fn route_disk(&self, disk: DiskLayout, kind: &BlockKind) -> Option<&dyn BlockPlugin>;
    /// 树插件按磁盘版本路由（缺 → None → 引导链硬失败 BootstrapIncomplete）。
    pub fn tree_plugin(&self, disk: DiskLayout) -> Option<&dyn TreePlugin>;
    /// 全局单例访问子（lazy 静态，供 tb_library 与测试共用）。
    pub fn global() -> &'static PluginRegistry;
}
```

**冲突检查语义**（01 §4-1 / §2-2）：同 `(MEMORY, DISK)` 下第二个块插件、第二个树插件 → `Err(TypeConflict)`；`validate_pair` 无声明组合 → `Err(SchemaMismatch)`（不标定）；内置配对自动注册后 `validate_pair(Arrow55, ArrowIpc)` / `(Arrow55, ArrowParquet)` 恒可路由。

**接线（旧面兼容，公共签名不动）**：

- `layout/materializer.rs`（S2 内完成）：`IpcMaterializer` / `ParquetMaterializer` **删除**，改写为 `ArrowIpcBlockPlugin` / `ArrowParquetBlockPlugin`（行为逐字节复刻——golden 17 IPC 帧、parquet 临时 scratch 文件路径保留）；`Materialization` 枚举保留并加 `impl From<DiskLayout>` / `TryFrom<Materialization>`（内部互转）；`probe_block_materialization`（`ARROW1`/`PAR1`）语义升级为委托 `DiskLayout::probe_magic`（返回值映射回 `Materialization`，签名不动）；`materializer_for` / `select_materializer` 保留为「布局默认 + kind 约束」的兼容薄面（内部转发插件路由，公开签名不动——`TbLibrary::write_commit` 等既有调用点不改）；
- `TbLayout::block_materialization()` 语义升级：返回布局默认磁盘版本对应的 `Materialization`（行为等价，实现换轨道）。

**测试义务**：

- `p_l_1_plugin_ipc_byte_identical`：`ArrowIpcBlockPlugin` 对样本 envelope 的 encode 字节 == 既有 golden 17/`p_io_2` IPC 帧常量（零字节变化证明）；
