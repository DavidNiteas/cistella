## 5. V-1 施工细则（补地址重算，可执行）

> 本节把 01 §4.1 / §4.4 / §5 的「两个地址公式读侧消费」落为可执行步骤。

### 5.1 现状参照（01 §7-1 / §7-2 / §7-3）

- 写侧已消费两个公式：`commit` 内 `tree_blob_address(tree_bytes)`（tb_library.rs:345）、`ref_table_address(&ref_bytes)`（tb_library.rs:357）；
- 读侧零调用：open 恢复只验块（`restore_bucket`，tb_library.rs:522/525）；`verify()` 三列互验（tb_library.rs:400/423）不含 tree / ref 两地址；
- 地址公式（xxh3-128）：`layout/tb.rs:45/50/55`（`block_blob_address` / `tree_blob_address` / `ref_table_address`）。

### 5.2 编译单位逐个 + 签名

不改任何公共签名，crate 内新增两个 helper（就近放 `tb_library.rs` 内或 `layout/tb.rs` 上方，按施工选择；可视情况登记 03）：

```rust
/// 读侧地址重算：tree bytes 的地址必须等于已提交头的 tree_blob 锚点。
/// 不匹配 → Err(DigestMismatch)（不修复，01 §4.1 / §4.4）。
pub(crate) fn assert_tree_address(tree_bytes: &[u8], pointers: &TbPointers) -> Result<()>;
// == tree_blob_address(tree_bytes) == pointers.tree_blob

/// 读侧地址重算：ref table bytes 的地址必须等于已提交头的 refs 锚点。
pub(crate) fn assert_ref_table_address(ref_bytes: &[u8], pointers: &TbPointers) -> Result<()>;
// == ref_table_address(ref_bytes) == pointers.refs
```

插桩点（两处）：

1. **open 恢复**：`TbLibrary::open` 读 commit / `TbPointers` 之后、构造 `LoadedState` 之前——对读出的 tree bytes 与 ref bytes 各调一次（原点已有块校验，补全三类对象）。
2. **`TbLibrary::verify()`**：保留三列互验不动；新增两个地址重算调用（读侧消费闭环，01 §5）。

### 5.3 测试义务

**测试夹具两分法**（V-1 冒烟起用、V-5 §9.1 全量锚定沿用）——因为 `assert_tree_address` 与 `tree_id` **同源同参**（均对同一段树字节做内容哈希、仅 domain tag 不同），「字节篡改」必然先命中 `tree_id` 校验（既有 open 核对面），**永远到不了 `assert_tree_address`**；ref 字节篡改同理先被 verify 三列互验等既有校验命中。故：

- **字节篡改夹具**（改对象文件内容字节、文件名地址不变）：命中 tree_id / 三列互验面，**不能**用来测地址断言；
- **commit 指针篡改夹具**（**测地址断言专用**）：改 commit 的 `tb_tree_blob` / `tb_refs` 指针列，指向**原字节副本的新地址**（内容未改、tree_id 重算仍过）→ 命中地址断言 → `Err(DigestMismatch)`。

冒烟断言（正负向各一；全量锚定在 V-5 §9.1）：

- 正向：正常 commit（指针列 = 各对象真实地址）后 open / verify 通过；
- 负向——**open 与 verify 两路都要锚**（tree / ref 均覆盖）：
  - 字节篡改夹具：open / verify → `Err(DigestMismatch)`（tree 由 tree_id 校验命中；ref 由三列互验命中）；
  - commit 指针篡改夹具：open / verify → 地址断言 `Err(DigestMismatch)`（tree→verify 负向补进 V-5 指针夹具清单，§9.1）；
  - **且库数据未被改写**（不修复语义，01 §8）。
- 既有 `tests/p_io_4_reopen_verify.rs` 零回归。

### 5.4 关闭标准（V-1）

- 四条命令全绿 + 既有零回归；
- §5.3 冒烟断言绿（负向含「篡改后 Err 且数据未被改写」）；
- 零新依赖；公共 API 零破坏（仅 crate 内 helper + 两处插桩）；
- 工作树改动待验收方裁定。

## 6. V-2 施工细则（统一字典 + 总入口 + assert 骨架，可执行）

> 本节把 01 §3 落为可执行步骤：**统一面 = 新模块 `src/validate/`**（不改任何既有模块），根级 re-export 加法。

### 6.1 编译单位逐个 + 签名

**新增 `src/validate/mod.rs`**：

```rust
//! 统一验证面（01 §3）：字典 + 请求 + 报告 + 总入口 + 断言族骨架。

/// 验证深度（01 §2；与 v4 `VerifyLevel` 命名隔离）。
#[derive(Clone, Copy, Debug, Eq, PartialEq, Ord, PartialOrd)]
pub enum ValidateDepth { Integrity, Consistency, Schema }

/// 验证对象面（01 §3.3）。
#[derive(Clone, Debug, Eq, PartialEq)]
pub enum ValidateSubject { Library, Block(RefId) }

/// 总入口请求（01 §3.3）。
#[derive(Clone, Debug)]
pub struct ValidateRequest {
    pub depth: ValidateDepth,
    pub subject: ValidateSubject,
    pub schema: Option<Arc<Schema>>,
    pub path: Option<XPath>,
}

/// 统一报告（01 §3.2；entries 复用 `VerifyEntry` 风格）。
#[derive(Clone, Debug, Eq, PartialEq)]
pub struct ValidateReport {
    pub depth: ValidateDepth,
    pub subject: ValidateSubject,
    pub entries: Vec<ValidateEntry>,
}

/// 报告条目（对齐 `verify::VerifyEntry`：目标 + 结果 + 错误信息）。
#[derive(Clone, Debug, Eq, PartialEq)]
pub struct ValidateEntry {
    pub name: String,
    pub ok: bool,
    pub error: Option<String>,
}

/// 总入口：按 depth 调度。
/// Integrity → assert_integrity + 两个地址重算；
/// Consistency → `TbLibrary::verify()`（三列互验 + 两个地址重算）；
/// Schema → L3 断言族（按 subject / schema / path）。
/// 两参（library + req）：crate 无全局「当前库」概念，需库句柄调度到库级
/// 断言面；保留 free function 形态可根级 re-export（偏离最小解，
/// 03 偏离 D-3 已裁定接受）。
pub fn validate<L: TbLayout>(
    library: &TbLibrary<L>,
    req: ValidateRequest,
) -> Result<ValidateReport>;
```

**断言族骨架**（fail-fast，返回 Result；`&self` 落点见 §6.3）：

```rust
pub fn assert_integrity(&self) -> Result<usize>;                              // L1 全库字节↔地址，返回已验证块数
pub fn assert_schema<T: DecodeTree>(&self) -> Result<()>;                     // L3 结构 + kind（V-4 实现）
pub fn assert_table_schema(&self, id: RefId, expected: &Schema) -> Result<()>; // L3 Table 深 schema（V-4）
pub fn assert_block_schema(&self, id: RefId) -> Result<()>;                   // L3 注册块 ArrowCaps.schema（V-4）
```

V-2 只落**签名 + fail-fast 骨架**：`assert_integrity` 基于 V-1 已就位的地址重算 + 块校验给出可用实现；其余三条断言先落签名与 `Ok`/`Err` 行为骨架（V-4 填实现，保证编译绿）。

**接线 `src/lib.rs`（只加 re-export，不改）**：`pub mod validate;` + 根级 re-export `ValidateDepth` / `ValidateSubject` / `ValidateRequest` / `ValidateReport` / `ValidateEntry` / `validate`。

### 6.2 测试义务

- 字典三变体构造 / 匹配；
- `ValidateRequest` 字段 roundtrip（构造 → 取值）；
- `validate()` 最小调度链路：`ValidateDepth::Integrity` 对 Healthy 库返回含 `ok == true` entries 的报告；不匹配场景 → 报告内 error 条目非空（fail-fast 面由断言层 `Err` 承接，报告面记录）；
- 断言族骨架编译绿（三变体签名可调、行为可跑）。

### 6.3 落地假设（可调，施工须在验收报告注明实际取值）

- **`&self` 落点**：断言族是「库级验证」——落 `TbLibrary<L>`（`impl<L: TbLayout> TbLibrary<L>` 内，或经 crate 内 `pub(crate)` 接缝复用 layout；公共签名零改动）。施工在验收报告注明实际落点。
- **`validate()` 形态**：取**两参 free function** `validate<L: TbLayout>(library: &TbLibrary<L>, req: ValidateRequest)`——crate 无全局「当前库」概念，需库句柄调度到库级断言面；保留 free function 形态可根级 re-export（权威单参 → 两参，偏离最小解，03 偏离 D-3 已裁定接受）。
- **`ValidateSubject` 两变体**（Library / Block(RefId)）为权威裁定形态；树路径范围统一走 `request.path` 字段（`subject::Path` 不是对象面而是过滤条件，已裁定移除，见 §6.4）。
- **`validate()` 的 Schema 面**：`schema: Option<Arc<Schema>>` 为期望 schema 通道，落到 `assert_table_schema` 的 `expected`；`subject::Path` + `depth::Schema` → `assert_schema<T>` 需调用侧自供 `T`（`schema` 缺省时对注册块走 `assert_block_schema`）。
- **报告 self-contained**：`ValidateReport` 序列化「够用」即可（01 §8：不碰 wire）。

### 6.4 待确认问题（已裁定，主代理 2026-08-23）

1. `ValidateSubject` 两变体（Library / Block(RefId)）+ `&self` 库级：**已裁定**——树路径范围统一走 `request.path`，`subject::Path` 移除。
2. `validate()` 的 Consistency 面：**已裁定包成报告条目**（entries）；`TbLibrary::verify()` 的 `Result<usize>` 保留为内部实现，不直接作为报告面。
3. `assert_schema<T>` 的 `&self`：**已裁定库级**（`TbLibrary<L>`）。

## 7. V-3 施工细则（整块读默认验，可执行）

> 本节把 01 §4.2 / §4.3 落为可执行步骤。

### 7.1 现状参照

- `TbLayout::read_*_object`（read_block_object / read_tree_object / read_ref_object）当前整块读后**不验**；
- 既有 4 处已验点（restore_bucket tb_library.rs:522 / verify tb_library.rs:423 / IPC receive / `LazyIpcSnapshot::block`）与默认验构成**双算风险** → 改走 `*_unchecked`。

### 7.2 编译单位逐个 + 签名

对 `TbLayout`（layout/mod.rs）新增（**只加不改**；`MemoryLayout` 非 `TbLayout` 实现方——仅实现 `StorageLayout`，无磁盘对象、无同步对象（事实修正））：

```rust
/// 整块读（默认验）：trait **default method**，转发 `read_*_object_verified`。
/// 对外语义 = 既有 `read_*_object` 的行为升级（方法体从「必实现」改为 default，签名不变）。
fn read_block_object(&self, address: Digest) -> Result<Vec<u8>> { self.read_block_object_verified(address) }
fn read_tree_object(&self, address: Digest) -> Result<Vec<u8>> { self.read_tree_object_verified(address) }
fn read_ref_object(&self, address: Digest) -> Result<Vec<u8>> { self.read_ref_object_verified(address) }

/// 整块读（免验）：**实现方必须提供**（两磁盘布局 `FlatDirLayout` / `SingleFileLayout`
/// 各一份，原始读逻辑保留）；供内部已验路径复用，避免双 hash。
fn read_block_object_unchecked(&self, address: Digest) -> Result<Vec<u8>>;
fn read_tree_object_unchecked(&self, address: Digest) -> Result<Vec<u8>>;
fn read_ref_object_unchecked(&self, address: Digest) -> Result<Vec<u8>>;

/// 整块读（默认验）：trait **default method** = `*_unchecked` 之后多算一次
/// xxh3 地址公式并比对，不匹配 → Err（不修复，01 §4.2）。
fn read_block_object_verified(&self, address: Digest) -> Result<Vec<u8>> { /* default：unchecked + 比对 */ }
fn read_tree_object_verified(&self, address: Digest) -> Result<Vec<u8>> { /* default：unchecked + 比对 */ }
fn read_ref_object_verified(&self, address: Digest) -> Result<Vec<u8>> { /* default：unchecked + 比对 */ }
```

实现方式（V-3 实际落位）：`*_unchecked` 由两磁盘布局（`FlatDirLayout` / `SingleFileLayout`）各实现一份（既有原始读逻辑原样保留）；`read_*_object` 与 `read_*_object_verified` 均为 **trait default method**——verified 默认 = `*_unchecked` 之后多算一次地址公式并比对，**不经心的第三方实现方自动获得默认验**；既有 `read_*_object` 语义升级（default 转发 verified，签名不变）。`MemoryLayout` 非 `TbLayout` 实现方、无同步对象（事实修正，原「Memory 布局同步三实现」误述）。

**统一原则（每对象每公式只算一次）**：任一路径对同一对象读入内存后，同一地址公式至多计算一次——读侧默认 verified 与内部已验路径 `*_unchecked` 二选一，绝不双算。**断言面读同样走 `*_unchecked`**：`assert_integrity` / `validate()` L1 面读 block / tree / ref 字节不起用默认 verified，由断言自身在紧随其后的地址重算（`assert_*_address` 调用 / `block_blob_address` 比对）承担与该公式唯一的一次比对（对齐 restore_bucket 的既有纪律）。

插桩（内部已验读位共 **5 处**，均改走 `*_unchecked`，保持「每处只算一次」）：

- restore_bucket / verify / IPC receive / `LazyIpcSnapshot::block`（原字面四点）；
- **open 恢复的 tree / ref 两读**（第五点）：`TbLibrary::open` 对树字节走 `read_tree_object_unchecked` 后由 `assert_tree_address` 承担地址比对，ref 字节同构（`read_ref_object_unchecked` + `assert_ref_table_address`），不再二次默认验；
- 其余整块读（物化 / 外部调用）走默认 verified。

### 7.3 零拷贝显式验（01 §4.3）

- `map_*_disk` / `MappedView::bytes` / IPC 共享区 bytes() **不默认验**（零拷贝承诺：不物化不 hash）；
- 显式验入口 = 断言族 / `validate()`（`depth: Integrity | Schema` 时调用方在映射字节上显式触发）；
- V-5 固化「三处显式验入口清单」断言（§9.1 `v_5_zero_copy_no_default_hash`）。

### 7.4 测试义务

- 冒烟：篡改磁盘整块字节 → 默认 verified 路径 `Err`；`*_unchecked` 不验（既有 4 处 hash 校验路径回归绿，无双算行为回归）；

## 8. V-4 施工细则（L3 三件套，可执行）

> 本节把 01 §6 落为可执行步骤：三个断言族从 V-2 骨架填为可用实现。

### 8.1 编译单位逐个 + 签名（在 `src/validate/` 与落点模块各就各位）

```rust
/// L3-1（01 §6.1）：Table 块深 Arrow schema 断言。
/// 实解 `block/table.rs` 的 Table payload → 与 expected 深比对
/// （字段名 / 数据类型 / nullability / 嵌套结构；不比对行内容）。不匹配 → Err(SchemaMismatch)。
pub fn assert_table_schema(&self, id: RefId, expected: &Schema) -> Result<()>;

/// L3-2（01 §6.2）：注册块断言。块 payload 实解 schema == ArrowCaps.schema
/// （block/registry.rs:18 声明，当前零消费点——本断言即首个消费点）。
/// kind 错误语义（§8.3-1 已裁定）：非 Named（内建）kind / 注册为 Opaque / 未注册
/// → 同归 Err(SchemaMismatch)；payload 本身不可实解（非法 IPC）→ 传播 Err(PayloadMalformed)。
pub fn assert_block_schema(&self, id: RefId) -> Result<()>;

/// L3-3（01 §6.3）：typed 投影结构断言。T 声明的结构期望 ↔ 块内容结构；
/// 只走结构 + kind，不物化叶子 payload。
pub fn assert_schema<T: DecodeTree>(&self) -> Result<()>;
```

实现要点：

- L3-1：复用 `block/table.rs` 的实解路径（其构造 / 读取已自洽重建 schema 的面），在其上补「与 expected 深比对」；`expected` 来源 = `validate()` 的 `schema` 或调用方直传。
- L3-2：查 `Kind → ArrowCaps`（`block_caps` / registry），比对实解 schema；此即 `ArrowCaps.schema` 的**首个消费点**。
- L3-3：经 `DecodeTree::check_image_children`（**derive 生成结构面专版**：叶子只验 kind / 身份面——`check_block_leaf_identity`，不调 `B::decode_block`；与 `from_image_children` 同校验面、零 payload 解码）走结构 + kind 面校验；手工实现方退化默认方法（完整投影兜底，仍不物化叶子 payload）。
- 落点注记（三断言共性）：均消费**恢复态**——open 后的 `bucket()` / `tree_image()` 接缝（与 `project()` 同路径）；commit 后未 open 的句柄 → `Err(RequiredDataMissing)`。

### 8.2 测试义务

- 冒烟：三断言正负向各一（Table 深 schema 任选维度不符 → `Err`；注册块 payload 篡改 → `Err`；typed kind / 结构不符 → `Err`；各正向 `Ok`）；
- L3-2 隔离证明：断言自身走 `ipc::decode_batch` 实解 schema（用户解码器不触达——不经注册块用户自定义解码路径，验证与解码面隔离）；
- L3-3 不物化叶子行为证明归 §9.1 `v_5_assert_schema_no_leaf_materialization`（**计数器级**）；
- 既有 `registry_m1.rs` / `ab2_registered_blocks.rs` 零回归（L3 是纯加法，不改注册面）。

### 8.3 待确认问题（已裁定，主代理 2026-08-23）

1. `assert_block_schema` 的 kind 错误语义：**已裁定 `SchemaMismatch`**——未注册 kind、非 Named（内建）kind 与注册为 `Opaque` 的 kind **同归** `SchemaMismatch`（均无期望 schema 可断言，语义属结构/类型不符，非引用不存在）；payload 本身不可实解（非法 IPC，非 schema 可比对）→ 传播 `PayloadMalformed`（01 §9 复用既有错误码，不新增分类）。

### 9.1 测试义务（新增 `tests/v_5_validation.rs`；命名 `<批次><N>_<主题>_<断言>`；fixture 用既有 tb 树 + `Blob` 叶；**共 18 项 = L1 8 + L2 1 + L3 7（含计数器项）+ 总入口 2**）
