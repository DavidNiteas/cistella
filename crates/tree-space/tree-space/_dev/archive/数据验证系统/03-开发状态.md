> D-1 / D-2 同一条理由：**V-1 后 open 必验 ref 地址（`assert_ref_table_address`）**，先篡改引用表会在 open 层 `Err` 而非 verify 层——时序调整使负向真正到达 verify 层校验面。详见 [`04-施工日志.md`](04-施工日志.md) 终审批注。

> D-3 理由：**crate 无全局「当前库」概念**，总入口需库句柄才能调度到库级 `&self` 断言面；两参**保留 free function 形态**，根级 re-export 与单参无差，是偏离最小解。详见 [`04-施工日志.md`](04-施工日志.md) V-2 终审批注。

> D-4 理由：open 恢复读 tree / ref 两读后紧跟 V-1 地址断言（`assert_tree_address` / `assert_ref_table_address`），已是内部已验路径——清单扩容第五位，避免其走默认 verified 双算（02 §7.2）。

> D-5 理由：single_file `block_objects()` 是单遍批量原始读（direct IO），逐条重构为 verified 读会引入 O(N×catalog) 地址重查；由 `assert_integrity` 在批量读后逐条比对兜底（「断言面读走 `*_unchecked`，断言自身承担比对」，02 §7.2 统一原则）。

> D-6 理由：事实核对——`MemoryLayout` 只实现 `StorageLayout`（layout/memory.rs:37），非 `TbLayout` 实现方，无磁盘对象、无同步对象；原细则「Memory 布局同步三实现」表述与代码事实不符，已回改 02 §7.2 并与 01 §9 注记一致。

> D-7 理由：flat_dir `block_objects()` 对「读后发现对象消失 / 变更」（并发删除 / 重写）原报 `StorageCorrupt` → 实为并发下悬垂引用，归 `DanglingReference` 更贴切；低风险（既有测试零变化，全量回归绿）。

> D-8 理由：断言面（`assert_integrity` / `validate()` L1）原三处读走默认 verified，其后断言自身又比对地址 → 同一公式在一路径上算两次；返工为读走 `*_unchecked`、由断言自身的地址重算承担与公式唯一的一次比对（02 §7.2 统一原则「每对象每公式只算一次」）。

> D-V4-1 理由：L3-3 权威语义「不物化叶子 payload」（01 §6.3）要求结构面校验，但既有 `DecodeTree::from_image_children` 是完整投影（会物化叶子）——故加 `check_image_children` trait default method（默认退化为完整投影兜底，手工实现方自动获得语义）+ `#[derive(TreeCodec)]` 生成结构面专版（与 `from_image_children` 同校验面、零 payload 解码，叶子只验 kind / 身份面、调 `check_block_leaf_identity`、不调 `B::decode_block`）。纯加法，不改既有投影语义。

> D-V4-2 理由：v_2 骨架期对三条 L3 断言只保 `Ok(())` 占位；V-4 填为真实实现后，骨架期测试正负向预期须随真实行为（结构比对命中 / §8.3-1 错误码落地）适配——测试义务的正常演进，非行为回退（02 §8.4「全部新增」边界内）。

> D-V4-3 理由：三断言均需读块 / 树内容，直接消费 open 恢复态接缝（`bucket()` / `tree_image()`，与 `TbLibrary::project()` 同路径）——commit 后未 open 的句柄 → `Err(RequiredDataMissing)`；L3-2 实解走 `ipc::decode_batch`（直接解 IPC batch，不经 `to_batch` 批量物化路径），与「断言只实解 schema、不物化行内容」一致（02 §8.1 落点注记，V-4 终审）。

## 初审勘误（V-3，2026-08-23）

- 初审认定 v_3 测试 `tests/v_3_read_object_verified.rs` 存在「2 处死导入」（`Block` / `SingleFileTbLibrary`，仅现于 use 行、无路径显式引用）判为应删——**判错**。二者实为 **load-bearing trait 导入**：`Block` 提供 `envelope()` 等 trait 方法、经 `blob.envelope()` 方法调用解析（block/mod.rs:151 `pub trait Block`）；`SingleFileTbLibrary` 提供 `TbLibrary::<SingleFileLayout>::create` / `open` 构造面——因避免第二 inherent impl 与 flat 默认 `create` 歧义，特意用 trait 承载（tb_library.rs:115-123 设计说明）。删去任一将触发编译器 **E0599（method not found）**。干事据 E0599 证据纠正、未删；四命令（含 fmt `--check` 与全量测试）全绿佐证保留正确。
