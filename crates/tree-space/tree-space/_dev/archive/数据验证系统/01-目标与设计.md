# 数据验证系统：01 目标与设计

> 本工单是「数据验证（data validation）」这一需求族的独立立项。authority 覆盖：把 tree-space 的验证能力升级为**统一「验证系统」**——统一字典 + 统一报告 + 统一总入口；三个验证深度各自落点，不物理合并。验证只**见证不治理**：L1/L3 一律「不匹配 → Err」，绝不修复/自愈/迁移（见 §8 范围边界）。

## 0. 背景与定位

**承接与现状**：tree-space 的验证能力目前是**碎片化**的——块通道 4 处 hash 校验、树通道经 tree_id 全量 hash 覆盖、`TbLibrary::verify()` 三列互验、v4 表空间 `verify.rs`、kind 级 / 部分 schema 级断言（详见 §7 现状盘点），彼此不互通、无统一深度语义、无统一入口。本工单把这些能力**建立在同一字典 / 报告 / 入口之上**（不拆除既有实现，只做统一面与补齐面）。

**北极星**：把 tree-space 的验证能力升级为统一「验证系统」——统一字典 `ValidateDepth` + 统一报告 `ValidateReport` + 总入口 `validate()`；三个验证深度（Integrity / Consistency / Schema）**实现各自落点、不物理合并**。

**核心分界（铁律）**：
- 验证只**见证**，不**治理**：不修复、不自愈、不迁移（L1/L3 一律「不匹配 → Err」，绝不改写数据）；
- 统一的是**入口 / 字典 / 报告**，不是把三层代码物理合并成一个巨 verify；
- 身份（hash）**不进物理寻址**——只在读侧消费地址公式做验证，不改存储格式、不改地址公式（§8）。

---

## 1. 北极星

一句话：**统一「验证系统」——统一字典 + 统一报告 + 总入口，三个验证深度各自落点，不物理合并。**

- 统一字典：`ValidateDepth { Integrity, Consistency, Schema }`（与 v4 `VerifyLevel` 保持命名隔离，§2）；
- 统一报告：`ValidateReport`（复用 / 扩展现有 `VerifyEntry` 风格）；
- 总入口：`validate<L: TbLayout>(library: &TbLibrary<L>, req: ValidateRequest) -> Result<ValidateReport>`（两参 free function——crate 无全局「当前库」概念，需库句柄调度到库级断言面，02 §6.3 取值，03 偏离 D-3 已裁定接受）；
- 三个深度（实现面）各自落点：**L1** → 块 / 树 / ref 读路径 + 断言；**L2** → `TbLibrary::verify()` 原位不动；**L3** → `block/table.rs` + `registry.rs`（`ArrowCaps.schema`）+ typed 投影。
- 蕴含关系：**L3 ⊃ L2 ⊃ L1**——按 depth 验证必含其下全部层次（L3 深 schema 断言蕴含 L2 引用一致、蕴含 L1 字节完整）。

## 2. 三层定义（ValidateDepth）

| 深度 | 变体 | 验证什么 | 姿态 | 现状 |
|---|---|---|---|---|
| L1 完整性 | `Integrity` | 块字节 ↔ 哈希（防传输 / 磁盘损坏） | **必选** | 「一半」：块通道 4 处 hash；树通道 tree_id 全覆盖；磁盘整块读 / mmap / ref 对象零校验（§7-2） |
| L2 引用一致性 | `Consistency` | 树引用表 ↔ 块身份 | 必选（已落地） | `TbLibrary::verify()` 三列互验完整，有测试锚定（§7-3） |
| L3 结构 | `Schema` | 块内容 schema ↔ 类型声明期望 | **可选 opt-in**，聚焦「快速断言」（比对失败即 `Err`，不修复） | kind 级 + 内建块 payload 结构已做；Table Arrow schema / 注册块 `ArrowCaps.schema` 零校验（§7-4） |

**命名隔离**：本枚举命名为 `ValidateDepth`，避免与 v4 表空间的 `VerifyLevel` 撞名（两套 verify 不互通，见 §7-5）。

## 3. 系统形态

### 3.1 统一字典

```rust
/// 验证深度（三层；与 v4 `VerifyLevel` 命名隔离，01 §2）。
#[derive(Clone, Copy, Debug, Eq, PartialEq, Ord, PartialOrd)]
pub enum ValidateDepth {
    Integrity,     // L1 完整性：块字节 ↔ 哈希（必选）
    Consistency,   // L2 引用一致性：树引用表 ↔ 块身份
    Schema,        // L3 结构：块内容 schema ↔ 类型声明期望（opt-in）
}
```

### 3.2 统一报告

```rust
/// 统一验证报告：复用 / 扩展现有 `VerifyEntry` 风格（verify.rs 的字段风格：
/// 目标 + 结果 + 错误信息；本工单在其上扩展 depth/subject 面）。
#[derive(Clone, Debug, Eq, PartialEq)]
pub struct ValidateReport {
    pub depth: ValidateDepth,          // 本次验证深度（蕴含其下全部，§2）
    pub subject: ValidateSubject,      // 本次验证对象面
    pub entries: Vec<ValidateEntry>,   // 每个验证目标的逐条结论
    // 汇总字段（total / failed 等）在 V-2 按 VerifyEntry 风格扩展（见 02 §6）
}

/// 报告条目（对齐 `verify::VerifyEntry`：目标 + 结果 + 错误信息）。
#[derive(Clone, Debug, Eq, PartialEq)]
pub struct ValidateEntry {
    pub name: String,          // 验证目标（块 id / 引用表 / 路径等）
    pub ok: bool,
    pub error: Option<String>, // 失败信息（不匹配 → Err 的文本；记录用，不触发修复）
}
```

### 3.3 总入口

```rust
/// 验证对象面（入参侧；「三个 subject 各自落点」指三层实现各自落点，不物理合并，§1）。
#[derive(Clone, Debug, Eq, PartialEq)]
pub enum ValidateSubject {
    Library,               // 整库（块 + 树 + 引用表）
    Block(RefId),          // 单个桶块
}

/// 总入口请求。
pub struct ValidateRequest {
    pub depth: ValidateDepth,          // 验证深度（必含其下全部，§2 蕴含）
    pub subject: ValidateSubject,      // 验证对象面
    pub schema: Option<Arc<Schema>>,   // L3 期望 schema（深 schema 断言 / assert_table_schema 用）
    pub path: Option<XPath>,           // 可选树路径范围过滤
}

/// 总入口：按 depth 调度到对应落点，富集为统一报告。
/// 两参（library + req）：crate 无全局「当前库」概念，需库句柄调度到库级
/// 断言面；保留 free function 形态可根级 re-export（权威单参 → 两参，
/// 偏离最小解，已裁定接受，03 偏离登记 D-3）。
pub fn validate<L: TbLayout>(
    library: &TbLibrary<L>,
    req: ValidateRequest,
) -> Result<ValidateReport>;
```

调度语义：`Integrity` → `assert_integrity`（全库字节↔地址）+ 树 / ref 两个地址重算；`Consistency` → `TbLibrary::verify()`（三列互验 + 两个地址重算，02 §5 V-1）；`Schema` → L3 断言族（按 subject / schema / path，02 §8 V-4）。

### 3.4 断言族（fail-fast，返回 Result）

```rust
/// L1 全库字节↔地址（含树 / ref 两个地址重算），返回已验证块数。
pub fn assert_integrity(&self) -> Result<usize>;

/// L3 结构 + kind：typed 投影结构断言，不物化叶子 payload（§6.3）。
pub fn assert_schema<T: DecodeTree>(&self) -> Result<()>;

/// L3 Table 深 Arrow schema 断言（§6.1）：块 payload 实解 schema == expected。
pub fn assert_table_schema(&self, id: RefId, expected: &Schema) -> Result<()>;

/// L3 注册块断言（§6.2）：块 payload 实解 schema == ArrowCaps.schema。
pub fn assert_block_schema(&self, id: RefId) -> Result<()>;
```

**断言族与报告是两条面**：断言 = fail-fast 计算面（返回 `Result`，一遇不匹配即 `Err`，不收集）；报告 = `validate()` 的总入口聚合面（富集 entries，仍遵循「不修复」——报告只记录，不改数据）。`&self` 的落点（库级 / 布局级）与模块形态在 02 §6 施工细则落地并申报验收（02 §6.3/§6.4）。

## 4. L1 落地（必选，混合）

### 4.1 open 恢复必验
open 恢复时**块已验**（`restore_bucket` 内按 `block_blob_address` 比对，tb_library.rs:522/525）；**补 tree / ref 两个地址重算**：
- `tree_blob_address(tree_bytes) == pointers.tree_blob`
- `ref_table_address(ref_bytes) == pointers.refs`
失败 → `Err(DigestMismatch)`（不修复）。

### 4.2 整块读默认验哈希
`read_*_object`（`read_block_object` / `read_tree_object` / `read_ref_object`）**默认验哈希**——bytes 已在内存，多算一次 xxh3（三个地址公式均为 xxh3-128，`xxhash-rust` 已在依赖，零新依赖）。
- **verified / _unchecked 变体**避免 `verify()` / `restore_bucket` 双 hash：默认路径即 verified（既有 `read_*_object` 签名不动、行为升级为「验后返回」——行为升级先例见交换协议 E-4 改断言，非 API 破坏）；新增 `*_unchecked` 变体供**内部已验路径**（restore_bucket / verify / IPC receive / `LazyIpcSnapshot::block`）复用，避免已验处重复计算。
- 姿态：「不匹配 → Err」，绝不改写数据。

### 4.3 零拷贝显式验
零拷贝路径（mmap `map_*_disk` / `MappedView::bytes`、IPC 共享区）**保持零拷贝承诺，显式验**——验证只在断言 / 总入口显式触发，**不默认**在零拷贝读路径插 hash（零拷贝不物化即不默认 hash）。三处显式验入口在 V-5 测试锚定中固化清单（02 §9.1：`v_5_zero_copy_no_default_hash`）。

### 4.4 两个地址公式读侧消费（当前读侧零调用）
`tree_blob_address(tree_bytes) == pointers.tree_blob`、`ref_table_address(ref_bytes) == pointers.refs` 目前在**读侧零调用**（写侧已消费于 `commit`，tb_library.rs:345/357）——本工单在 open 恢复（§4.1）与 `TbLibrary::verify()`（§5）两处补读侧消费，形成闭环。

## 5. L2 现状与落地

**保留不动**：`TbLibrary::verify()` 三列互验（树引用表 xpath / ref_id ↔ 桶块身份 ↔ 地址）完整，测试锚定 `tests/p_io_4_reopen_verify.rs` 不动。
**只补**：两个地址重算（§4.1/§4.4）——`tree_blob_address(tree_bytes) == pointers.tree_blob`、`ref_table_address(ref_bytes) == pointers.refs` 进入 verify() 检查面（读侧消费闭环）。

## 6. L3 落地（可选 opt-in，显式断言）

三件套，全部显式断言（比对失败即 `Err`，不修复）：

### 6.1 Table 块期望 schema 断言
`assert_table_schema(&self, id: RefId, expected: &Schema)`——堵 `block/table.rs` 的「任意接受」洞（Table 包装任意 RecordBatch，构造 / 读取仅自洽重建自己的 schema，无期望约束）。断言为**深 Arrow schema 比对**（字段名 / 数据类型 / nullability / 嵌套结构），不比对行内容。`expected` 来源 = `validate()` 的 `schema: Option<Arc<Schema>>` 或调用方直传。

### 6.2 消费注册块 ArrowCaps.schema
`assert_block_schema(&self, id: RefId)`——`registry.rs` 的 `ArrowCaps.schema` **声明了但零消费点**（block/registry.rs:18-20）：断言注册块 payload 实解 schema == `ArrowCaps.schema`。本断言即该声明的**首个消费点**。

### 6.3 typed 投影结构断言
`assert_schema<T: DecodeTree>(&self)`——`T` 声明的结构期望 ↔ 块内容结构：只走**结构 + kind**，**不物化叶子 payload**（叶子只验 kind / 身份面，不展开 payload 内容）。

## 8. 范围边界（明确不做的）

- **不修复 / 不自愈 / 不迁移**：L1/L3 一律「不匹配 → Err」，绝不改写数据；报告亦不触发任何修复流程。
- **不做 schema 演进 / 版本化**：schema 一经声明即期望，无版本协商。
- **不做 runtime 配置开关**：L3 是 API / 类型级 opt-in（传 `depth: Schema` 或调断言族即开启）；L1 直接默认验（`read_*_object` 默认验），**不用 cargo feature**。
- **不碰 RPC / 校验 wire 协议**：本工单不新增 wire；`ValidateReport` 的序列化以「够用」为准。
- **不碰 v4 表空间 `verify.rs` / MZWC v1 面**（suspended）：v4 面保持现状。
- **不改存储格式 / 不改地址公式**：地址公式（`block_blob_address` / `tree_blob_address` / `ref_table_address`）是既成事实，只在读侧消费；**身份不进物理寻址，只验证**。

## 9. 纪律与接续

- **先文档后实现**：实现偏离先改本文件 + `03-开发状态.md` 登记，再动代码。
- **零破坏公共 API**：所有工作 = 新增（新模块 `src/validate/`、新枚举 / 新方法 `*_unchecked`）+ 根级 re-export 加法；`TbLibrary` / `TbLayout` / `SharedRegion` / `block` 既有公共签名与行为契约零改动（`read_*_object` 的「默认验」为行为升级、签名不变；既有已验路径走 `*_unchecked` 保持零双算）。
  - **边界注记（V-3 收口，2026-08-23）**：`read_*_object` 由 trait **必实现方法**改为 **default method**（转发 `read_*_object_verified`）；同一 trait 内 `read_*_object_verified` 亦为 default method（`*_unchecked` + 地址公式比对），`read_*_object_unchecked` 为**必实现**。对仓外既有实现方（第三方自实现 `TbLayout`）这是一次**编译级迁移**：必须补 3 个 `*_unchecked` 方法方能编译；迁移后**自动获得默认验**（verified 语义由 default 提供，无需自实现）。仓内两磁盘实现方（`FlatDirLayout` / `SingleFileLayout`）已于 V-3 同步迁移；`MemoryLayout` 非 `TbLayout` 实现方，无同步义务。
- **零新增第三方依赖**：`xxhash-rust`（xxh3-128）/ `arrow` / `parquet` 均已在 Cargo.toml。
- **承接与依赖**：本工单独立立项，无未闭合批次的阻塞项；建立在既有已验证路径（P-IO / E 系列 / TB/AB/A-2）之上，下游（polars 桥等）不受影响。
- **错误语义**：失败复用既有错误码语义（`DigestMismatch` / `SchemaMismatch` / `DanglingReference` 等），不破坏既有错误分类。
