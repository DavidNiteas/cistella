### 5.2 关键架构决策（E-1 先立，后阶段沿用）

1. **交换层 = 新模块 `src/exchange/`**，不改 `TbLibrary` 既有公共 API（延续 P-IO-7 零破坏纪律）。
2. **「块」抽象落地 = `ExchangeKey` 枚举**：不强行把树塞进 `Envelope`（树仍是 `TreeImage` + 引用表），而是引入「交换单元身份」统一「所有权/访问/同步」的寻址面——`ExchangeKey::Tree` / `ExchangeKey::Block(RefId)`。
3. **运行时配置系统** = `RuntimeConfig`（L1 默认 + L2 覆盖）+ `RuntimeTable`（L3 生成产物，含运行时事件）。「配置系统 = 生成器，运行时表 = 输出」（01 §2）。
4. **E-1 只做「类型 + schema」，不实现行为**——映射/全量/惰性读是 E-2，同步/merge 是 E-3，布局翻译器是 E-4。

### 6.1 现状盘点（对齐 E-1 落地 + 现状代码，2026-08-23 核实）

### 6.2 关键设计决策（E-2 新增，严守零破坏既有公共 API）

1. **新增三个 `exchange` 子模块，不改 E-1 已冻结类型**：`src/exchange/ownership.rs`（所有权判定 + 写门）、`src/exchange/access.rs`（映射/全量/惰性读）、`src/exchange/proxy.rs`（代理写语义结构）。对 E-1 已有类型**只做加法**（新增方法/字段访问器），不改任何既有签名、变体、`Default` 值——`TbLibrary`/`TbLayout`/`SharedRegion`/`BlockMaterializer` 公共 API **零改动**。
2. **所有权判定 = 读 `RuntimeEntry.holder`**：`Holder::Own` 是唯一写者；`Holder::Mapped(..)` 只读。判定入口是 `require_owner(&RuntimeTable, ExchangeKey) -> Result<()>`，返回 `Err(ErrorCode::OwnershipDenied)` 当且仅当「非所有者」。写路径 = `TbLibrary::commit/commit_pruned`（所有者直写）与 `handle_proxy_request`（代理写），二者最终都经 `commit` 的 `metadata_lock()` 串行（§3.2 逻辑单写者）。
3. **访问形式只针对读**（§4）：`MappedView`（非持有、零拷贝、可失效）复用 `SharedRegion`；`OwnedSnapshot`（全量：树+桶瞬间副本，所有权归读取者）；`LazySnapshot`（惰性：先树后桶，树不可惰性由 `TreeAccess` 类型层保证）。树的读只有 `Mapped`/`Full`，无 Lazy 入口。
4. **代理写只落「语义结构 + 本进程处理器 + 传输封装」**：`ProxyRequest`/`ProxyReceipt`/`RejectReason`/`ProxyPolicy` 是语义类型；`handle_proxy_request` 在所有者侧跑（同进程建模，串行经 `metadata_lock`）；传输载体复用 `Source::Ipc`/`SharedRegion`（`publish_request/receive_request/publish_receipt/await_receipt`）。真实跨进程异步由 E-3/E-4 消费同一语义结构，本阶段不 spawn 子进程。
5. **失效语义暴露两处**：`MappedView::invalid_state()`（视图级查询）+ `RuntimeTable` 树/块入口的 `invalid` 字段（表级，经 `mark_invalid` 更新）。`UpstreamChanged` 下读仍可进行（数据还在，只是不保证两次一致）；`UpstreamDead` 下读返回 `Err(RequiredDataMissing)`（可能已无数据，§7）。
6. **映射仅支持 `Source::Ipc`**：磁盘零拷贝映射是 E-4 布局翻译器的事，`Source::Disk` 的映射读返回 `Err(MappingAmbiguous)`。

**新增 `src/exchange/ownership.rs`（所有权判定 + 写门）**：

```rust
//! Ownership determination (01 §3.1): only `Holder::Own` may write.

use crate::error::{ErrorCode, Result, TreeSpaceError};
use crate::exchange::{ExchangeKey, RuntimeTable};

/// The single-writer gate (01 §3.1): returns `Ok` iff the runtime table marks
/// `key` as `Holder::Own`; any mapped holder or an absent block entry is
/// `Err(ErrorCode::OwnershipDenied)`.
///
/// This is the ownership check the write path consults. Owner direct writes
/// (`TbLibrary::commit`/`commit_pruned`) and proxy writes (`handle_proxy_request`)
/// both serialize through the owner's `metadata_lock`, so all writes remain
/// logically single-writer (01 §3.2).
pub fn require_owner(table: &RuntimeTable, key: ExchangeKey) -> Result<()> {
    let holder = match key {
        ExchangeKey::Tree => &table.tree_entry().holder,
        ExchangeKey::Block(id) => match table.block_entry(id) {
            Some(entry) => &entry.holder,
            None => return Err(ownership_denied("block is not locally owned")),
        },
    };
    if holder.is_owner() {
        Ok(())
    } else {
        Err(ownership_denied("only the owner may write"))
    }
}

fn ownership_denied(message: impl Into<String>) -> TreeSpaceError {
    TreeSpaceError::new(ErrorCode::OwnershipDenied, message)
}
```

//! Read access forms (01 §4): mapped (zero-copy, invalidatable), full (owned
//! copy), lazy (tree up front, blocks on demand). Access forms concern reads
//! only; writes are bound to the holder (01 §3).

use crate::block::{Envelope, RefId};
use crate::bucket::Bucket;
use crate::error::{ErrorCode, Result, TreeSpaceError};
use crate::exchange::{InvalidState, RuntimeTable, Source};
use crate::shared::SharedRegion;
use crate::tb_library::TbLibrary;
use crate::tree::codec::{DecodeTree, TreeImage};
use crate::layout::TbLayout;
use std::collections::BTreeMap;
use std::sync::Mutex;

/// A zero-copy mapped view of a single exchange unit (tree or block), 01 §4
/// Mapped. The reader does **not** own the data: reads are live against the
/// shared region and may invalidate (01 §7). `Send + Sync` is preserved by
/// guarding the invalidation flag with a `Mutex`.
pub struct MappedView {
    region: SharedRegion,           // opened zero-copy region (Arc-backed)
    source: Source,                 // kept for re-open on refresh()
    invalid: Mutex<InvalidState>,   // runtime event; never persisted (01 §2)
}

impl MappedView {
    /// Opens a mapped view over a peer's shared region (01 §4). Only
    /// `Source::Ipc` is supported in E-2; `Source::Disk` is `Err(MappingAmbiguous)`
    /// (disk zero-copy mapping is the E-4 layout translator).
    pub fn open(source: Source) -> Result<Self>;

    /// Borrows the mapped canonical bytes live (tree bytes or block envelope
    /// bytes). `Err(RequiredDataMissing)` when `invalid == UpstreamDead`
    /// (the region may hold no data, 01 §7 case 2). `UpstreamChanged` still
    /// reads (the upstream's current view), but consecutive reads are not
    /// guaranteed to agree (01 §7 case 1).
    pub fn bytes(&self) -> Result<&[u8]>;

    /// Current invalidation state (01 §7 exposure, view level).
    pub fn invalid_state(&self) -> InvalidState;

    /// Overlays a runtime invalidation event (01 §7); called when the upstream
    /// is observed to have changed or died.
    pub fn mark_invalid(&self, state: InvalidState);

    /// Best-effort re-open from the recorded source. Re-open failure →
    /// `UpstreamDead`. Returns the new state.
    pub fn refresh(&mut self) -> InvalidState;
}

/// A full owned snapshot: tree + bucket instant copy; ownership belongs to the
/// reader and never invalidates (01 §4 Full).
#[derive(Clone, Debug, PartialEq)]
pub struct OwnedSnapshot {
    pub image: TreeImage,
    pub bucket: Bucket,
}

impl OwnedSnapshot {
    /// Full read: instant tree+bucket snapshot of a library (01 §4). The copy
    /// is owned by the caller; no invalidation applies (01 §7).
    pub fn read_full<L: TbLayout>(library: &TbLibrary<L>) -> Result<Self>;
    /// Projects the snapshot image into a typed tree (mirrors `TbLibrary::project`).
    pub fn project<T: DecodeTree>(&self) -> Result<T>;
}

/// A lazy owned snapshot (01 §4 Lazy): the tree is copied up front; bucket
/// blocks are copied on demand from `source` and cached by the reader, which
/// owns them. Only bucket blocks are lazy — the tree never is (type level:
/// `TreeAccess` has no `Lazy`).
pub struct LazySnapshot<'a> {
    image: TreeImage,
    source: &'a Bucket,                              // read-only block source (not owned)
    copied: Mutex<BTreeMap<RefId, Envelope>>,        // reader-owned on-demand copies
}

impl<'a> LazySnapshot<'a> {
    /// Lazy read: copies the tree up front, defers bucket blocks (01 §4).
    pub fn new<L: TbLayout>(library: &'a TbLibrary<L>) -> Result<Self>;
    /// The up-front tree copy (owned by the reader).
    pub fn image(&self) -> &TreeImage;
    /// On-demand copy: returns the reader-owned envelope for `id`, copying it
    /// from the source on first access and caching it. Unknown id →
    /// `Err(DanglingReference)`.
    pub fn block(&self, id: RefId) -> Result<Envelope>;
    /// Whether `id` has already been copied into the reader's ownership.
    pub fn is_materialized(&self, id: RefId) -> bool;
}

// ---- Tree access (TreeAccess: Mapped / Full only, 01 §4) ----

/// Tree mapped read (zero-copy, invalidatable).
pub fn open_tree_mapped(source: Source) -> Result<MappedView> { MappedView::open(source) }
/// Tree full read (owned tree+bucket snapshot).
pub fn read_tree_full<L: TbLayout>(library: &TbLibrary<L>) -> Result<OwnedSnapshot> {
    OwnedSnapshot::read_full(library)
}

// ---- Block access (AccessMode: Mapped / Full / Lazy, 01 §4) ----

/// Block mapped read (zero-copy, invalidatable; per-block independent, 01 §4).
pub fn open_block_mapped(source: Source) -> Result<MappedView> { MappedView::open(source) }
/// Block full read: an owned copy of one bucket block (instant snapshot, 01 §4).
/// Unknown id → `Err(DanglingReference)`.
pub fn read_block_full<L: TbLayout>(library: &TbLibrary<L>, id: RefId) -> Result<Envelope>;

}

```rust
//! Proxy write (01 §3.2): a non-owner asks the owner to write on its behalf
//! (async "sudo"). The receipt confirms success / rejects with a reason / times
//! out (upstream death). Transport reuses `Source`/`SharedRegion`; only IPC is
//! in scope (01 §8).

use crate::block::RefId;
use crate::bucket::Bucket;
use crate::error::Result;
use crate::exchange::{ExchangeKey, RuntimeTable, Source};
use crate::shared::{RegionHandle, SharedRegion};
use crate::tb_library::TbLibrary;
use crate::layout::TbLayout;
use crate::xpath::XPath;
use std::time::Duration;

/// A proxy write request (01 §3.2): a non-owner asks the owner to commit on its
/// behalf. The payload mirrors the owner's direct write (`TbLibrary::commit`).
#[derive(Clone, Debug, Eq, PartialEq)]
pub struct ProxyRequest {
    /// Stable request identity (monotonic, caller-supplied); receipts echo it.
    pub request_id: u64,
    /// The target owner, identified by its `Source` (routing hint; IPC only).
    pub target: Source,
    /// Canonical tree bytes (the whole tree — never splittable/lazy, 01 §1/§4).
    pub tree_bytes: Vec<u8>,
    /// Leaf references (xpath → block identity), mirrors `TbLibrary::commit`.
    pub leaf_refs: Vec<(XPath, RefId)>,
    /// The bucket to commit (envelopes), mirrors `TbLibrary::commit`.
    pub bucket: Bucket,
}

/// Why the owner rejected a proxy write (01 §3.2 rejection semantics).
#[derive(Clone, Copy, Debug, Eq, PartialEq)]
pub enum RejectReason {
    /// The recipient is not the owner of the target (routed to a non-owner).
    NotOwner,
    /// The write payload failed validation (dangling refs, malformed tree, …).
    InvalidPayload,
    /// The owner's policy refuses proxy writes entirely.
    ProxyRefused,
}

/// The owner's reply to a proxy request (01 §3.2: async, receipt-confirmed).
#[derive(Clone, Debug, Eq, PartialEq)]
pub enum ProxyReceipt {
    /// The owner accepted and committed the write.
    Accepted { request_id: u64 },
    /// The owner rejected the write with a reason.
    Rejected { request_id: u64, reason: RejectReason },
    /// The upstream died before replying — manifests as timeout (01 §3.2).
    TimedOut { request_id: u64 },
}

/// Proxy-write policy gate on the owner side (01 §3.2). Default = `Allow`
/// (§6.6 落地假设「默认 Allow」).
#[derive(Clone, Copy, Debug, Eq, PartialEq)]
pub enum ProxyPolicy { Allow, Deny }

impl Default for ProxyPolicy {
    /// Default `Allow` (§6.6): proxy writes are permitted unless the owner
    /// opts into `Deny`.
    fn default() -> Self { ProxyPolicy::Allow }
}

impl ProxyReceipt {
    /// True iff the receipt is `Accepted` (the write succeeded).
    pub fn is_accepted(&self) -> bool;
    /// The echoed request id.
    pub fn request_id(&self) -> u64;
}

/// Handles a proxy write on the owner's side (01 §3.2): checks ownership +
/// policy, then commits through the owner's `metadata_lock` (via
/// `TbLibrary::commit`), so all writes serialize logically single-writer.
///
/// Ownership check: `require_owner(table, ExchangeKey::Tree)` must pass, else
/// `Rejected(NotOwner)`. Policy `Deny` → `Rejected(ProxyRefused)`. Commit
/// failure (dangling ref / malformed tree / digest mismatch) →
/// `Rejected(InvalidPayload)`.
pub fn handle_proxy_request<L: TbLayout>(
    library: &TbLibrary<L>,
    table: &RuntimeTable,
    policy: ProxyPolicy,
    request: &ProxyRequest,
) -> ProxyReceipt;

/// The proxy-write client (01 §3.2, IPC only): publishes the request into a
/// shared region, hands the handle to the owner, and collects the receipt from
/// a reply region. An expired wait yields `TimedOut` (upstream death = timeout).
#[derive(Clone, Debug)]
pub struct ProxyClient {
    timeout: Duration,
}

impl ProxyClient {
    /// Builds a client from a runtime config's sync timeout.
    pub fn with_timeout(timeout: Duration) -> Self;
    /// Sends a proxy request to `owner` and awaits the receipt. Same-process
    /// model (the owner library lives in this process; cross-process modeling
    /// is the same shape as `shared_region_test`). Runs `handle_proxy_request`
    /// and returns its receipt; timeout is exercised by the transport helpers.
    pub fn request<L: TbLayout>(
        &self,
        owner: &TbLibrary<L>,
        table: &RuntimeTable,
        policy: ProxyPolicy,
        request: ProxyRequest,
    ) -> ProxyReceipt;
}

// ---- IPC transport (reuses Source/SharedRegion; zero new deps) ----

/// Publishes a proxy request into a shared region, returning the region and its
/// export handle (for hand-off to the owner). Byte form reuses existing codecs:
/// tree canonical bytes + `encode_ref_table` (leaf_refs) + per-envelope framing
/// (bucket); no new dependencies.
pub fn publish_request(request: &ProxyRequest) -> Result<(SharedRegion, RegionHandle)>;
/// Decodes a proxy request received via a shared region.
pub fn receive_request(region: &SharedRegion) -> Result<ProxyRequest>;
/// Publishes a proxy receipt into a shared region (small fixed framing).
pub fn publish_receipt(receipt: &ProxyReceipt) -> Result<(SharedRegion, RegionHandle)>;
/// Waits for a receipt reachable by `handle`, timing out after `timeout`.
/// Open failure (region never published) or deadline expiry → `TimedOut`
/// (upstream death = timeout, 01 §3.2).
pub fn await_receipt(handle: &RegionHandle, timeout: Duration) -> ProxyReceipt;
```

### 6.6 落地假设（默认取值/边界，可调，施工须在验收报告注明实际取值）

- **映射仅 `Source::Ipc`**：`Source::Disk` 的映射读返回 `Err(MappingAmbiguous)`（磁盘零拷贝映射 = E-4 布局翻译器）。E-2 不实现磁盘 mmap。
- **代理传输 = 同进程建模**：`handle_proxy_request`/`ProxyClient::request` 在单进程内跑（与 `shared_region_test` 的「第二进程」同构）；`publish_*`/`receive_*`/`await_receipt` 提供 `SharedRegion` 字节封装作为 IPC 载体。不 spawn 子进程；真实跨进程异步由 E-3/E-4 复用同一语义结构。
- **惰性源 = 就地源库的 `&Bucket`**：`LazySnapshot` 借源库的桶做按需复制；跨进程逐块拉取（pull）推迟到 E-3。树永不惰性（`TreeAccess` 无 `Lazy`）。
- **映射读返回 canonical 字节**：`MappedView::bytes()` 返回树 canonical bytes / 块 envelope bytes，调用方自行解码（解码是布局翻译器职责，但本 crate 已有 `tree::codec::decode`/`Envelope::decode` 可直接复用，不算新增转换）。
- **`ProxyRequest.request_id` = 调用方自供单调 `u64`**；回执按 `request_id` 匹配。
- **`ProxyPolicy` 默认 `Allow`**；`RuntimeConfig` 不新增字段（E-2 不加 schema，策略在调用点传参）。
- **缺席块入口在写门 = `Err(OwnershipDenied)`**（「非本地所有」统一语义）；在 `mark_invalid` = `Err(DanglingReference)`（「表内无此块」语义）。
- **超时语义**：`await_receipt` 的 deadline/打开失败统一映射 `TimedOut`；`RuntimeConfig.sync_timeout`（默认 5s）作为 `ProxyClient` 默认超时来源。

### 6.7 待确认问题（规范歧义/缺口，不动权威，留待主代理裁定）

1. **映射块映射的是「envelope 字节」还是「payload 字节」**：01 §4 说「目标必须是 Arrow」，但块的最小交换单元是 `Envelope`（frame ≠ Arrow IPC file，payload 才是 `ARROW1`）。本细则按「映射 canonical envelope 字节」落地（与 E-1 的 `IpcMaterializer` 对象 = envelope 全字节一致）。是否需改为「映射 payload 字节 + 旁挂 kind/version」？
2. **Lazy「先整树同步」对 E-3 pull 的前置依赖**：01 §4 Lazy 的「先整树同步」本质是 pull（E-3），E-2 只落 `LazySnapshot` 容器 + 就地源。跨进程逐块拉取是否必须在 E-2 就接 IPC，还是推迟 E-3？本细则推迟 E-3。
3. **代理回执超时的真实性**：单进程测试只能「模拟」超时（`await_receipt` 对未发布回执/过期 deadline）。真实「上游死亡」依赖跨进程存活检测。E-2 用超时机制覆盖，不做真实子进程——是否满足「上游死亡 = 超时」的关闭语义？
4. **`RuntimeTable` 树入口 setter 与 E-1 的「树入口只读 getter」意图**：E-1 只给了 `tree_entry()` getter；E-2 增 `set_tree_entry` 以标记树 `Mapped`/失效事件。按 01 §2「运行时事件可叠加、不持久」应允许，但需确认不与 E-1 的冻结语义冲突。

## 7. E-3 施工细则（同步 pull/push/merge，可执行）

> 本节把 §1 的 E-3 从概念阶段落到「编译单位逐个 + 签名 + 测试义务 + 关闭标准」。E-3 把 01 §5（同步：pull/push/merge）落地为**行为**，并落地 §6 的「枚举可达」作为 pull 抓取的遍历底座。E-4（布局翻译器：读/原子读/写/原子写/删除/GC 逐项落地 + 失效语义）不在本阶段实现。

### 7.2 关键设计决策（E-3 新增，严守零破坏既有公共 API）

1. **新增两个 `exchange` 子模块，不改 E-1/E-2 已冻结类型**：`src/exchange/merge.rs`（同步范围类型 + merge 原语 + 可达块枚举，纯函数无 IO）、`src/exchange/sync.rs`（pull/push 入口 + 抓取）。对 E-1/E-2 已有类型**只做加法**，不改任何既有签名、变体、`Default` 值——`TbLibrary`/`TbLayout`/`SharedRegion`/E-1/E-2 类型公共 API **零改动**。
2. **同步无历史语义**（01 §5.1）：不引入 commit 链/新旧概念；`pull`/`push` 只关心「源头」与「目的地」。pull 的物理操作恒为**整棵替换**（`dest.commit`），即使范围是片段——merge 产出「改了片段的整棵树」，再整棵写回。
3. **范围类型 `SyncScope`**：`FullTree`（全树）/ `TreeFragment(Vec<XPath>)`（树片段，前缀匹配）/ `Blocks(Vec<RefId>)`（桶的若干块）。树级同步（pull 的 merge、可达块枚举）用前两变体；块级同步用 `fetch_blocks`。范围匹配复用 `is_pruned_path` 的 canonical 字节前缀语义（零新增依赖，无 regex）。
4. **merge 原语 `MergeOp` + `MergeSpec`**：`MergeOp{Overwrite, AddOnly, ModifyOnly, DeleteOnly, Combine(MergeFlags)}`，`MergeSpec{op, scope}`。merge 作用于**已解码的 `TreeImage`**（`merge_image`），产出合并后的 `TreeImage`；替换前再 `encode`。`Overwrite` = 最简形态（子树整体复写）；增/改/删按「命名/键控字段」细粒度递归，位置型容器原子化（见 §7.3 语义表）。
5. **pull 复用 E-2 读原语**：抓取 = `OwnedSnapshot::read_full(source)`（本地源全量快照）→ 按范围取桶（`FullTree` → 源全桶不裁剪；`TreeFragment` → 按 `reachable_refs(image, scope)` 裁剪到范围内可达块）→ `merge_image` → `encode` + `image_leaf_refs` → `dest.commit`。块级抓取 = `read_block_full`。
6. **push 复用 E-2 代理**：push = 代理同步，语义结构（`ProxyRequest`/`ProxyReceipt`/`handle_proxy_request`/`ProxyClient`）**零改动**。E-3 只补：`build_push_request`（把库的已提交树+桶编成 `ProxyRequest`）+ `push`（对 `ProxyClient::request` 的薄封装）。push 范围 = 全树（代理写 = 整棵 commit）；片段/块级 push = 「先本地 merge 再 push 全树」的组合（见 §7.7）。
7. **可达块枚举 `reachable_refs`**：从树的引用表（`image_leaf_refs`）推导可达块集，范围指定时只保留「范围内可达块」——回答「pull 要抓哪些块」（01 §5.2 + §6「枚举可达」）。

### 7.3 编译单位逐个 + 签名

**新增 `src/exchange/merge.rs`（同步范围 + merge 原语 + 可达块枚举，纯函数）**：

```rust
//! Merge primitives for fine-grained tree edits (01 §5.4) + sync scope (01 §5.1)
//! + reachable-block enumeration (01 §6 枚举可达). Pure: no disk/IO.

use crate::block::RefId;
use crate::error::Result;
use crate::tree::codec::TreeImage;
use crate::xpath::XPath;
use std::collections::BTreeSet;

/// Synchronization / merge scope (01 §5.1 范围可指定: 全树 / 树片段 / 桶的若干块).
#[derive(Clone, Debug, Eq, PartialEq)]
pub enum SyncScope {
    /// The whole tree (and its reachable bucket blocks).
    FullTree,
    /// A tree fragment: the subtree under each xpath prefix. Prefix matching
    /// reuses the collision-safe canonical-byte rule (`layout::tb::is_pruned_path`).
    TreeFragment(Vec<XPath>),
    /// A subset of bucket blocks (bucket-level sync; no tree merge).
    Blocks(Vec<RefId>),
}

/// The built-in merge operations (01 §5.4): overwrite (simplest), add-only,
/// modify-only, delete-only, and arbitrary combinations.
#[derive(Clone, Copy, Debug, Eq, PartialEq)]
pub enum MergeOp {
    /// Overwrite: in-scope destination subtrees converge to the source ("复写").
    Overwrite,
    /// Add-only: source-only fields/leaves are inserted; existing ones untouched.
    AddOnly,
    /// Modify-only: common fields/leaves are replaced; nothing added/deleted.
    ModifyOnly,
    /// Delete-only: destination-only fields/leaves are removed; nothing added/modified.
    DeleteOnly,
    /// Arbitrary combination of the three primitive behaviors.
    Combine(MergeFlags),
}

/// Bitmask of the primitive merge behaviors (01 §5.4 "任意组合").
#[derive(Clone, Copy, Debug, Eq, PartialEq, Default)]
pub struct MergeFlags {
    pub add: bool,
    pub modify: bool,
    pub delete: bool,
}

impl MergeOp {
    /// Whether this op inserts source-only fields/leaves.
    pub fn adds(&self) -> bool;
    /// Whether this op replaces common fields/leaves with the source's.
    pub fn modifies(&self) -> bool;
    /// Whether this op removes destination-only fields/leaves.
    pub fn deletes(&self) -> bool;
}

/// A merge operation plus its scope (01 §5.4 op + xpath range).
#[derive(Clone, Debug, Eq, PartialEq)]
pub struct MergeSpec {
    pub op: MergeOp,
    pub scope: SyncScope,
}

/// Applies a merge spec to combine a destination tree image with a source tree
/// image, returning the merged image (01 §5.4: load whole → edit by scope →
/// write whole back). The returned image is validated by `encode` on replace.
///
/// Scope semantics (`in_scope(path)`):
/// - `FullTree` → always true;
/// - `TreeFragment(prefixes)` → `is_pruned_path(canonical_xpath_bytes(path),
///   &prefixes.map(canonical_xpath_bytes))` (a field is in scope when its xpath
///   is a descendant-or-self of any prefix);
/// - `Blocks(_)` → always false (block-level sync has no tree merge → the image
///   is returned unchanged).
///
/// Merge unit = a field (subtree). At an in-scope field position:
///
/// | 场景（作用域内） | Overwrite | AddOnly | ModifyOnly | DeleteOnly | Combine(f) |
/// |---|---|---|---|---|---|
/// | 双侧都有，且都是 `Node`（命名/键控） | 递归 | 递归 | 递归 | 递归 | 递归 |
/// | 双侧都有，其他（原子字段） | 取源 | 保留目的 | 取源 | 保留目的 | `f.modify` ? 取源 : 保留目的 |
/// | 仅目的有 | 删除 | 保留 | 保留 | 删除 | `f.delete` ? 删除 : 保留 |
/// | 仅源有 | 插入 | 插入 | 跳过 | 跳过 | `f.add` ? 插入 : 跳过 |
///
/// 「取源/插入」= 源字段深拷贝；「保留目的」= 目的字段克隆；「删除」= 丢弃。
/// 作用域外的字段一律保留目的（不递归、不增删改）。递归仅进入 `Node` 子节点且
/// 子节点为 `Named`/`Keyed` locator（稳定寻址）；`Positioned` 子节点（Vec 元素、
/// chunk 条目、view 输入）与 `Inline`/`Ref`/`ChunkGroup`/`ChunkEntry`/`View` 内容
/// 均按**原子字段**处理（不逐条目 merge，避免序数重排，与 `prune_image` 粒度一致）。
/// 双侧 `Node` 与非 `Node` 类型不匹配时按「原子字段」处理（modify 才整棵替换）。
pub fn merge_image(dest: &TreeImage, source: &TreeImage, spec: &MergeSpec) -> Result<TreeImage>;

/// Enumerates the reachable block set of an image, restricted to `scope`
/// (01 §6 枚举可达 + §5.2 只抓范围内可达块). Drives the pull fetch:
///
/// - `FullTree` → every leaf ref of `image_leaf_refs(image)`;
/// - `TreeFragment(prefixes)` → only the refs whose xpath is under a prefix;
/// - `Blocks(ids)` → the ids themselves (they *are* the scope).
pub fn reachable_refs(image: &TreeImage, scope: &SyncScope) -> Result<BTreeSet<RefId>>;
```

**新增 `src/exchange/sync.rs`（pull/push 入口 + 抓取）**：

```rust
//! Synchronization (01 §5): pull (fetch → merge → replace), push (proxy sync)
//! and the fetch/reachability helpers that back them. No history, no old/new —
//! only source and destination (01 §5.1).

use crate::block::RefId;
use crate::bucket::Bucket;
use crate::error::{ErrorCode, Result, TreeSpaceError};
use crate::exchange::access::OwnedSnapshot;
use crate::exchange::merge::{MergeSpec, SyncScope};
use crate::exchange::proxy::{ProxyClient, ProxyPolicy, ProxyReceipt, ProxyRequest};
use crate::exchange::{ExchangeKey, RuntimeTable, Source};
use crate::layout::TbLayout;
use crate::tb_library::{TbCommitReceipt, TbLibrary};

/// Fetches the source's scoped data: the full tree image plus the bucket blocks
/// in scope (01 §5.2 抓取). The image is always whole (the tree is never
/// splittable, 01 §1). Bucket semantics: `FullTree` → the source's **full
/// bucket, untrimmed**; `TreeFragment(prefixes)` → trimmed to the in-scope
/// reachable set via [`crate::exchange::merge::reachable_refs`].
///
/// `Blocks` scope is not a tree fetch → `Err(PayloadMalformed)` (use
/// [`fetch_blocks`]). Source is a local `TbLibrary` (same-process modeling,
/// §7.6); mapped IPC fetch is E-4.
pub fn fetch_snapshot<L: TbLayout>(
    source: &TbLibrary<L>,
    scope: &SyncScope,
) -> Result<OwnedSnapshot>;

/// Fetches the given blocks from the source bucket into a caller-owned bucket
/// (01 §5.2 桶的若干块 — bucket-level sync). No tree merge. Unknown id →
/// `Err(DanglingReference)`. Persisting the result into a TB destination is the
/// caller's/E-4's concern (§7.7).
pub fn fetch_blocks<L: TbLayout>(source: &TbLibrary<L>, ids: &[RefId]) -> Result<Bucket>;

/// pull = 抓取 → merge → 整棵替换 (01 §5.2). The tree's physical operation is
/// always whole-tree replacement via the destination's `commit`.
///
/// Steps: (1) `require_owner(dest_table, ExchangeKey::Tree)` — only the owner
/// writes (01 §3.1); (2) `fetch_snapshot(source, spec.scope)`; (3)
/// `merge_image(dest.tree_image(), snapshot.image, spec)`; (4) merged bucket =
/// `snapshot.bucket ∪ dest.bucket`; (5) `encode` + `image_leaf_refs` +
/// `dest.commit`. Returns the commit receipt (same as a direct `commit`).
///
/// `spec.scope` must be `FullTree` or `TreeFragment`; `Blocks` → `Err(PayloadMalformed)`
/// (block-level sync uses [`fetch_blocks`]).
pub fn pull<L: TbLayout>(
    source: &TbLibrary<L>,
    dest: &TbLibrary<L>,
    dest_table: &RuntimeTable,
    spec: &MergeSpec,
) -> Result<TbCommitReceipt>;

/// Builds a proxy-sync request from a library's loaded state (whole tree):
/// `encode(tree_image())` → `tree_bytes`, `image_leaf_refs(tree_image())` →
/// `leaf_refs`, `bucket().clone()` → `bucket`. Mirrors the owner's direct
/// `commit` (01 §5.3 push = 代理同步). This is the E-3 convenience E-2 did not
/// ship (E-2 tests built `ProxyRequest` by hand).
pub fn build_push_request<L: TbLayout>(
    library: &TbLibrary<L>,
    request_id: u64,
    target: Source,
) -> Result<ProxyRequest>;

/// Proxy-sync push (01 §5.3): submits a sync application to the owner; the
/// owner writes it through the E-2 proxy handler (async "sudo", receipt-
/// confirmed). Thin wrapper over `ProxyClient::request` — the E-2 proxy
/// semantics are reused verbatim (zero new transport).
pub fn push<L: TbLayout>(
    client: &ProxyClient,
    owner: &TbLibrary<L>,
    table: &RuntimeTable,
    policy: ProxyPolicy,
    request: ProxyRequest,
) -> ProxyReceipt {
    client.request(owner, table, policy, request)
}
```

- `e_3_build_push_request_matches_library`：`build_push_request(lib, id, target)` → `tree_bytes == encode(lib.tree_image())`、`leaf_refs == image_leaf_refs(lib.tree_image())`、`bucket == lib.bucket()`；
- `e_3_build_push_request_byte_roundtrip`：`build_push_request` 的 `ProxyRequest` 经 `publish_request → SharedRegion::open → receive_request` 字节还原相等；
- `e_3_push_accepts_owned`：`push(&ProxyClient, owner, Own表, Allow, build_push_request(...))` == `Accepted{request_id}`，且 `owner.verify()` 通过；
- `e_3_push_rejects_not_owner_and_policy`：`Mapped` 表 → `Rejected{NotOwner}`；`ProxyPolicy::Deny` → `Rejected{ProxyRefused}`（复用 E-2 语义，经 push 入口走一遍）。

### 7.5 关闭标准（E-3）

- 四条验收命令（§3）全绿 + `--workspace --all-targets` 全绿；E-1 的 12 断言 + E-2 的 20 断言 + 既有 P-IO-2..7 / v4 全套**零回归**；
- §7.4 断言全绿；
- **pull 抓取+merge+替换 roundtrip 绿**：`fetch_snapshot`（全树/片段裁剪）+ `merge_image` + `dest.commit` 组合后重开/`verify` 通过；写门（`require_owner`）拒绝非所有者；
- **push 代理写入绿**：`build_push_request` + `push` 经 E-2 代理接受/拒绝/策略全路径绿，零新增传输；
- **merge 各原语 + xpath 范围绿**：覆盖/只添加/只修改/只删除/任意组合 + `TreeFragment` 前缀范围、范围外不动；
- **可达块枚举绿**：`reachable_refs` 全树/片段/块三种范围正确；
- **零新增第三方依赖**（xpath 范围用 `is_pruned_path` 前缀语义，不引 regex）；
- 既有公共 API（`TbLibrary`/`TbLayout`/`SharedRegion`/E-1/E-2 类型）**零破坏**——仅 `exchange/` 内加法 + `lib.rs` re-export 加法；
- 工作树改动待验收方裁定（子智能体不留 git 写操作）。

### 7.6 落地假设（默认取值/边界，可调，施工须在验收报告注明实际取值）

- **pull 源 = 本地 `TbLibrary`**（同进程建模，沿用 E-2 §6.6 先例）：`fetch_snapshot` 走 `OwnedSnapshot::read_full`。跨进程映射抓取（map 树字节 → `decode` → 枚举可达 → 逐块 map）属 E-4 布局翻译器，E-3 不实现。
- **xpath 范围 = canonical 字节前缀**（`is_pruned_path`），**非字面正则**：01 §5.4 的「xpath 正则」以「前缀列表」落地（零新依赖）。字面 regex 需引 `regex` crate（违反零依赖），留 §7.7。
- **merge 单元 = 字段（子树）**：`Overwrite` = 子树整体复写；增/改/删只对 `Named`/`Keyed` 子字段细粒度递归；`Positioned` 子节点与 `Inline`/`Ref`/`ChunkGroup`/`ChunkEntry`/`View` 是原子字段（不逐条目 merge，与 `prune_image` 的序数粒度一致）。inline 值作为原子字段参与「改」（modify 整值替换），不做 value 级合并。
- **push 范围 = 全树**：`build_push_request` 编整棵树（代理写 = 整棵 commit）。片段/块级 push = 「先本地 merge 再 push 全树」的组合，不在 E-3 单列原语。
- **pull 返回 `TbCommitReceipt`**（同 `commit`）；`commit` 只落盘、不刷新内存态，故 pull 的可观测效果在磁盘上——测试用 `re-open dest` 或 `verify()` 观察，不依赖内存态刷新。
- **合并桶 = `snapshot.bucket ∪ dest.bucket`**：`commit` 只写 `leaf_refs` 引用的块，多余块被忽略，故并集安全覆盖「范围内源块 + 范围外目的块」。
- **`SyncScope::TreeFragment(vec![])`（空前缀）** = 空作用域 → merge 无操作（返回目的不变）；`FullTree` = 全作用域。
- **默认 merge op = `Overwrite`**（最简，01 §5.4）；调用方未显式给 op 时取 `Overwrite`。

### 7.7 待确认问题（规范歧义/缺口，不动权威，留待主代理裁定）

1. **「xpath 正则」（01 §5.4）的字面含义**：本细则以「canonical 字节前缀列表」落地（复用 `is_pruned_path`，冲突安全、零依赖）。若权威确要**字面正则**语义，需引入 `regex` crate（违反「零新增第三方依赖」铁律）或在 E-4 布局翻译器实现——请裁定「前缀列表」是否满足「控制要修改的树范围」的语义。
2. **块级同步的写回路径缺失**：`fetch_blocks` 只抓取（返回 `Bucket`）；把块「写进」TB 目的地需要一个**单块写入口**（`TbLibrary` 无 `write_block`，块只有被树引用才经 `commit` 落盘、否则被 GC，01 §6）。E-3 是否只交付「抓取 + 由调用方/后续 commit 引用」？还是需在 E-3 加一个 `TbLibrary` 加法方法（破坏零改动纪律，需登记偏离）？
3. **pull 的跨进程映射抓取归属**：E-3 用本地 `read_full` 建模；真实「map 树字节 → 枚举可达 → 逐块 map」的 IPC 抓取是否属 E-4（布局翻译器/失效语义）？E-2 §6.7 第 2 项「跨进程逐块拉取推迟 E-3」在本细则收敛为「E-3 只做本地源、IPC 抓取再推迟 E-4」——请确认。
4. **push 的范围语义**：01 §5.1 说范围可指定适用于同步，但 push = 代理写 = 整棵 `commit`。片段/块级 push 是否就是「本地 merge 后 push 全树」的组合（本细则如此假定），还是需要扩展 `handle_proxy_request` 支持「代理侧 merge」（改动 E-2 冻结类型，需偏离裁定）？
5. **merge 是否触碰 inline 值**：本细则把 inline 标量当原子字段参与「改」（modify 整值替换）。若「增/改/删」只应作用于**块引用叶**（不碰 inline 标量），则需把 inline 值排除出 merge 范围——请裁定。
6. **`commit` 不刷新内存态**：pull 后 dest 内存态仍是 pull 前旧树（只有重开才见新树）。是否需要在 E-3 加「pull 后刷新内存态」（`TbLibrary` 加法）？本细则假定不刷、以重开/`verify` 为准。
7. **`TreeFragment` 前缀与叶集的一致性**：`reachable_refs` 用 `image_leaf_refs` 的叶 xpath 判前缀；merge 用字段 xpath 判前缀。二者对「前缀落在非叶节点」的语义一致（字段 in-scope 但无叶也可能插入结构），无歧义，但前缀落在 chunk/view 内部（位置型子节点）时按「原子字段」处理会连整棵 chunk/view 一起替换——是否符合预期，请确认。**边界语义（终审裁定）**：前缀匹配须按 **step 种类对齐**——`Field` 前缀落在位置型容器（`Index` step）或 `Index` 前缀落在命名节点（`Field` step）时，step 种类不匹配，该前缀**不视为「落内部」**（匹配失败、按范围外处理），据此约束 `touched` 在原子容器替换上**不越权**（种类不匹配的前缀不会误触整棵 chunk/view 替换）。

### 8.2 关键设计决策（E-4 新增，严守零破坏既有公共 API）

1. **「布局翻译器」= 既有 `TbLayout`，不新增平行 trait**：`FlatDirLayout`/`SingleFileLayout` 的 `TbLayout` impl 就是「扁平翻译器/单文件翻译器」，七原语已实现六项（物理差异被 `L: TbLayout` 多态吸收）。E-4 新增 **`exchange/translator.rs`** 作「命名适配层」：`LayoutTranslator<L: TbLayout>`（零大小**结构体**，非 trait）把七原语映射成 01 §6 的命名面，并补齐缺项。七原语 → 既有实现对照：**读**=`read_*_object`（扁平=按文件读；单文件=offset 定位读）；**原子读**=桶块单块读完整=`read_block_object`（块不可变、读到即完整；**树不支持原子读**=无树拆分入口，类型层保证）；**写**=`write_*_object`（content-addressed `exists→skip`）；**原子写**=扁平 `atomic_write_bytes`（tmp+rename）/ 单文件 `stage`+`write_committed`（全量写 append epoch）；**删除**=由 GC 承担（扁平 unlink / 单文件标记失效待 compaction）；**GC**=`layout.gc`（扁平 sweep 孤儿 / 单文件 compaction repack）；**枚举可达**=`block_objects` + `image_leaf_refs`/`decode_ref_table`。
2. **磁盘零拷贝映射 = `MappedObject`（后备 + 范围）**：`MappedBacking::{Ipc(SharedRegion), File(memmap2::Mmap)}` + `Range<usize>`；`bytes()` 每次重切片，避免自引用结构。扁平=直接 mmap 对象文件（`tb_*_path` 真实文件）；单文件=mmap 整个 `.umdb`（`root()`）+ 按对象目录 offset 切片。对象解析经 crate 内 `ObjectSpan` trait（`pub(crate)`，见 §8.7-2）统一为「(文件, offset, length)」三元组。
3. **`MappedView::open(Source::Disk)` 落地 = 映射「已提交树 blob」**：`Source::Disk(PathBuf)` 只带库路径，唯一可经路径单独定位的对象是已提交树（`read_head` → commit → `TbPointers.tree_blob`）。路径经 `detect_disk_layout` 探测布局种类（目录→`FlatDir`；`TSDB` 头文件→`SingleFile`；否则 `Err(MappingAmbiguous)`）。`MappedView` 私有字段 `region: SharedRegion` → `object: MappedObject`（+ `mapped_id: Mutex<Option<Digest>>` 供 refresh 变更检测），公共方法签名零改动。**块级磁盘映射**（需块地址）走 `translator::map_block_disk(layout, address)`，address 来自引用表行——遵守 01 §1 寻址铁律。
4. **失效语义真实暴露**：`MappedView::invalid_state()`（视图级）+ `RuntimeTable::mark_invalid`（表级）已在 E-2 就位。E-4 接线磁盘路径：`refresh()` 重探测+重映射，**树 blob 地址变化 → `UpstreamChanged`**（映射上游当前视图，两次读不保证一致，01 §7 例 1）、**文件消失/打不开 → `UpstreamDead`**（随后 `bytes()` → `Err(RequiredDataMissing)`，01 §7 例 2）。IPC `refresh()` 行为不变（E-2）。
5. **跨进程 IPC 抓取**：新增 `publish_snapshot`/`receive_snapshot`（snapshot wire = 树字节 + 引用表 + 桶 envelope 段，复用 `publish_request` 的 framing 风格、translator 内自含助手不动 proxy.rs）；`fetch_snapshot_ipc` = map 树字节 → `decode` → `image_leaf_refs`+`reachable_refs`（枚举可达）→ 整 snapshot 解码后按 scope 裁剪（急切变体；逐块零拷贝惰性切片由 `LazyIpcSnapshot` 提供）；`fetch_blocks_ipc` 补块级抓取。同进程建模（沿用 E-2/E-3 先例，不 spawn 子进程）。
6. **单块写 = `persist_block(layout, envelope)`**：`select_materializer` + `materializer.address` + `write_block_object`（content-addressed `exists→skip`，返回物理地址）。**可达性规则**：块只有被树引用、经 `commit` 落盘才可达（01 §6 GC 行「桶块生命周期=树叶子的引用」）——故不新增 `TbLibrary` 独立写块方法（保持 `TbLibrary` 零改动）；`persist_block` 供 commit 路径复用与测试级验证（见 §8.7-5）。
7. **Lazy 跨进程逐块拉取 = `LazyIpcSnapshot`**：先整树（`decode` 树段）、块惰性。持 snapshot region + `ref_id → Range` 惰性索引；`block_bytes(id)` 零拷贝切片（逐块 map）、`block(id)` 按需解码+缓存。树不可惰性由 `TreeAccess` 类型层保证（复用 E-1）。真实「每块一个 region 的按需传输」推迟（见 §8.7-7）。
8. **严守零破坏**：`TbLayout`/`TbLibrary`/`SharedRegion`/`BlockMaterializer`/E-1/E-2/E-3 类型公共 API 零改动；改动仅限 `exchange/translator.rs`（新增）+ `exchange/access.rs`（`MappedView` 私有字段替换、公共签名不变）+ `exchange/mod.rs`/`lib.rs` re-export 加法 + `layout/{flat_dir,single_file}.rs` 的 `pub(crate)` `ObjectSpan` 实现（crate 内，见 §8.7-2）。`MappedView` 仍须 `Send + Sync`（E-2 第 12 断言延续）。

/// 把 (通道, 地址) 解析为「(磁盘文件, offset, length)」三元组（crate 内，磁盘
/// mmap 底座）。扁平 = 对象文件整文件（offset=0, length=文件长）；单文件 =
/// `.umdb` + 对象目录偏移。`None` = 对象不存在。`Memory` 布局不实现（无磁盘）。
pub(crate) trait ObjectSpan {
    fn object_span(&self, channel: TbChannel, address: Digest)
        -> Result<Option<(PathBuf, u64, u64)>>;
}

/// 零拷贝字节后备：IPC 共享区 或 磁盘 mmap。
pub enum MappedBacking {
    /// 跨进程共享区（01 §8 IPC）。
    Ipc(SharedRegion),
    /// 磁盘文件 mmap（01 §7 零拷贝映射读的磁盘底座）。
    File(memmap2::Mmap),
}

/// 零拷贝映射对象（后备 + 字节范围）。`bytes()` 每次重切片，避免自引用结构。
pub struct MappedObject {
    backing: MappedBacking,
    range: Range<usize>,
}

impl MappedObject {
    /// 零拷贝字节切片（不复制）。
    pub fn bytes(&self) -> &[u8];
    /// 是否为磁盘 mmap 后备（IPC 恒 false）。
    pub fn is_file_mapped(&self) -> bool;
    /// 从 `SharedRegion` 构造（IPC 后备，范围为整个 region 字节）。
    pub fn from_ipc(region: SharedRegion) -> Self;
}

/// 布局翻译器适配器：把 `TbLayout` 映射成 01 §6 七原语的命名面。零大小、非
/// trait（物理差异已由 `L: TbLayout` 多态吸收）。
pub struct LayoutTranslator<L: TbLayout> { layout: L }

impl<L: TbLayout> LayoutTranslator<L> {
    pub fn new(layout: L) -> Self;

    // —— 读（整块读；扁平=按文件读；单文件=offset 定位读）——
    pub fn read_block(&self, address: Digest) -> Result<Vec<u8>>;
    pub fn read_tree(&self, address: Digest) -> Result<Vec<u8>>;
    pub fn read_ref(&self, address: Digest) -> Result<Vec<u8>>;

    // —— 原子读（桶块单块一次读完整；树不支持原子读）——
    /// == `read_block`：块不可变，读到即完整（01 §6 原子读行）。
    pub fn atomic_read_block(&self, address: Digest) -> Result<Vec<u8>>;

    // —— 写（整块写，content-addressed `exists→skip` 去重）——
    pub fn write_block(&self, address: Digest, bytes: &[u8]) -> Result<()>;
    pub fn write_tree(&self, address: Digest, bytes: &[u8]) -> Result<()>;
    pub fn write_ref(&self, address: Digest, bytes: &[u8]) -> Result<()>;

    // —— 原子写（扁平=tmp+rename；单文件=全量写 append epoch）——
    /// == `write_block`：`TbLayout` 的写已原子（扁平 tmp+rename / 单文件 append epoch）。
    pub fn atomic_write_block(&self, address: Digest, bytes: &[u8]) -> Result<()>;

    // —— 删除（扁平=unlink；单文件=标记失效待 compaction）—— 无独立删除入口，
    //    由 GC 承担（01 §6 删除行 = GC 前奏）。
    // —— GC（扁平=sweep 孤儿；单文件=compaction repack）——
    pub fn gc(&self, keep_from_sequence: u64) -> Result<GcReport>;

    // —— 枚举可达（复用对象目录 / 引用表；01 §6 枚举可达行）——
    /// 列出全部已存块对象（对象目录）。
    pub fn block_objects(&self) -> Result<Vec<(Digest, Vec<u8>)>>;
    /// 已提交头的可达引用表行（读 head → commit.tb.refs → `decode_ref_table`，
    /// 单跳、不解码树字节，与 GC 同法）。
    pub fn enumerate_reachable_blocks(&self) -> Result<Vec<RefRow>>;
}

// —— 磁盘零拷贝映射（01 §7 底座）——

/// 探测 `Source::Disk` 路径的布局种类：目录→`FlatDir`；`TSDB` 头文件→`SingleFile`；
/// 其他→`Err(MappingAmbiguous)`。`SingleFileLayout` 的头魔术 `TSDB\0\0\0\0` 见
/// `layout/single_file.rs::HEADER_MAGIC`。
pub fn detect_disk_layout(path: &Path) -> Result<StorageKind>;

/// 磁盘零拷贝映射：已提交树 blob（唯一可经库路径单独定位的对象）。
pub fn map_tree_disk<L: TbLayout + ObjectSpan>(layout: &L) -> Result<MappedObject>;
/// 磁盘零拷贝映射：块对象（`address` 须来自引用表行——寻址铁律 01 §1）。
pub fn map_block_disk<L: TbLayout + ObjectSpan>(layout: &L, address: Digest) -> Result<MappedObject>;
/// 磁盘零拷贝映射：引用表对象。
pub fn map_ref_disk<L: TbLayout + ObjectSpan>(layout: &L, address: Digest) -> Result<MappedObject>;

// —— 单块写（01 §6 写行：content-addressed，`exists→skip`）——

/// 物化并写一个块对象，返回其物理存储地址。可达性规则：块只有被树引用、经
/// `commit` 落盘才可达（01 §6 GC 行）——本入口不制造孤儿持久语义，供 commit
/// 路径复用与测试级验证（§8.7-5）。
pub fn persist_block(layout: &impl TbLayout, envelope: &Envelope) -> Result<Digest>;

// —— 跨进程 IPC 抓取（01 §5.2 前阶段推迟项）——
//
// snapshot wire（复用 `publish_request` 的 `push_*`/`Reader` 风格，translator 内
// 自含助手，零新依赖、不动 proxy.rs）：
//
// ```text
// [tree_len u64 LE][tree bytes]
// [ref_table_len u64 LE][ref_table ipc]   = encode_ref_table(derive_ref_rows(image_leaf_refs, bucket))
// [block_count u64 LE]
//   每块: [ref_id 16B][envelope_len u64 LE][envelope bytes]
// ```

/// 把完整快照帧进一个共享区（树字节 + 引用表 + 桶 envelope 段），返回 region
/// 与导出句柄（供对端 `receive_snapshot`/`fetch_snapshot_ipc`）。
pub fn publish_snapshot(snapshot: &OwnedSnapshot) -> Result<(SharedRegion, RegionHandle)>;

/// 从 snapshot region 解码回完整快照（树 + 全桶；逐块 `Envelope::decode` +
/// 身份比对）。`ref_id` 与重算身份不符 → `Err(DigestMismatch)`。
pub fn receive_snapshot(region: &SharedRegion) -> Result<OwnedSnapshot>;

/// 跨进程 IPC 抓取（**急切变体**：整 snapshot 解码后按 scope 裁剪；真正的逐块
/// 零拷贝惰性切片由 [`LazyIpcSnapshot`] 提供）：map 树字节 → `decode`（整
/// snapshot 解码）→ `image_leaf_refs`+`reachable_refs`（枚举可达）→ 按 scope
/// 裁剪桶。`scope` 仅 `FullTree`/`TreeFragment`；`Blocks` → `Err(PayloadMalformed)`
/// （走 [`fetch_blocks_ipc`]）。仅 `Source::Ipc`（磁盘走 `map_tree_disk`）。
pub fn fetch_snapshot_ipc(source: Source, scope: &SyncScope) -> Result<OwnedSnapshot>;

/// 跨进程块级抓取：从 snapshot region 取指定块（01 §5.2 桶的若干块）。未知 id
/// → `Err(DanglingReference)`。
pub fn fetch_blocks_ipc(source: Source, ids: &[RefId]) -> Result<Bucket>;

// —— Lazy 跨进程逐块拉取（E-2 推迟项）——

/// 惰性 IPC 快照（01 §4 Lazy 的跨进程形态）：先整树、块惰性。持 snapshot region
/// + `ref_id → Range` 惰性索引；`block_bytes` 逐块零拷贝切片、`block` 按需解码+
/// 缓存。树不可惰性（类型层 `TreeAccess` 无 `Lazy`，01 §4）。
pub struct LazyIpcSnapshot {
    image: TreeImage,
    region: SharedRegion,
    spans: BTreeMap<RefId, Range<usize>>,
    copied: Mutex<BTreeMap<RefId, Envelope>>,
}

impl LazyIpcSnapshot {
    /// 打开 IPC 源、解码树段（先整树）、建 `ref_id → Range` 惰性索引（不解码块）。
    pub fn new(source: Source) -> Result<Self>;
    /// 先整树副本（读取者所有）。
    pub fn image(&self) -> &TreeImage;
    /// 逐块 map：块 envelope 字节的零拷贝切片（`Err(DanglingReference)` 未知 id）。
    pub fn block_bytes(&self, id: RefId) -> Result<&[u8]>;
    /// 按需解码 + 缓存（首次解码后缓存命中）。
    pub fn block(&self, id: RefId) -> Result<Envelope>;
    /// 是否已解码进读取者缓存。
    pub fn is_materialized(&self, id: RefId) -> bool;
}

### 8.6 落地假设（默认取值/边界，可调，施工须在验收报告注明实际取值）

- **磁盘 mmap 仅 FlatDir + SingleFile**：`Memory` 无磁盘，`detect_disk_layout` 探测不到 → `Err(MappingAmbiguous)`；`ObjectSpan` 只由两磁盘布局实现。
- **`MappedView::open(Source::Disk)` 映射「已提交树 blob」**：树是唯一可经库路径单独定位的对象；`mapped_id` 记录 tree blob 地址。块级磁盘映射必须走 `map_block_disk(layout, address)`（`address` 来自引用表行，寻址铁律 §1）。
- **单文件 mmap = 整 `.umdb` mmap + catalog offset 切片**：`ObjectSpan`（crate 内）复用 `read_latest_tb_state` + `catalog_row`；对象不存在 → `None` → `map_block_disk` 报 `Err(DanglingReference)`（与 `read_block_object` 的错误语义一致）。
- **失效判定粒度**：磁盘 `refresh()` 以「已提交树 blob 地址变化」判 `UpstreamChanged`、以「文件消失/打不开」判 `UpstreamDead`；不做「每次 `bytes()` 读时实时比对」（读时无锁快照语义，见 §8.7-6）。IPC `refresh()` 行为不变（E-2：重开成功→Valid、失败→UpstreamDead）。
- **单块写 = `persist_block` + commit 引用达可达**：不新增 `TbLibrary` 写块方法（保持 `TbLibrary` 零改动）；`persist_block` 语义为「内容寻址写 + exists→skip」，可达性由后续 `commit` 引用决定（01 §6 GC 行）。
- **IPC 抓取同进程建模**：`fetch_snapshot_ipc`/`fetch_blocks_ipc`/`LazyIpcSnapshot` 复现 `shared_region_test` 的「第二进程」同构，不 spawn 子进程（沿用 E-2 §6.6/E-3 §7.6 先例）；snapshot wire 助手（`push_*`/`Reader`）在 translator 内自含，不动 `proxy.rs`。
- **Lazy IPC = 惰性解码 + 零拷贝切片**：`block_bytes` 逐块切片于 snapshot region（零拷贝），`block` 首次解码后缓存；非「每块一个 region」的真实按需传输（见 §8.7-7）。
- **原子读「树不支持」落地 = 类型层无树拆分入口**：`TbLayout` 无半棵树读取方法，`read_tree` 恒整棵；无运行时断言（01 §6 原子读行「树不支持」以「无入口」表达）。
