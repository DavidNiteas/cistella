# 交换协议：01 目标与设计

> 本工单是「交换」这一需求族的独立立项。authority 覆盖：数据在**内存/硬盘、进程间、库间**流动时的**权限、访问形式、同步、代理、转换器接口**。交换协议只谈「交换」——**不涉及转换**；转换由布局的「翻译器」在交换原语之下实现。

## 0. 背景与定位

**承接与取代**：本工单统一承接 `../树与桶管道/` 工单的 **P-SH（SharedRegion 共享）** 与 **P-IO-8（sync + 并发写）** 两个后置批次——二者本质是「交换」需求族的不同侧面（内存↔内存、硬盘↔硬盘），不应各自为政。本工单立项后，树与桶管道的 P-SH / P-IO-8 标记为「移交交换协议工单」。

**北极星**：以「交换行为」为支点，统一「数据在内存与硬盘、进程与库之间的流动」，而非把搬运与转换混为一谈。

**核心分界（铁律）**：
- 内存数据（展开态 `LoadedState`：`TreeImage` + 桶 + 索引）与硬盘数据（canonical IPC 字节）**异构**；
- 交换协议只覆盖「同构 canonical 形态之间的流动」+「异构形态之间流动所需的**语义约定**（不实现转换本身）」；
- **转换**（编/解码、物化器）是布局自己的翻译器，挂在交换原语**之下**，物理差异被翻译层吃掉。

**范围边界（§8）**：本工单只做 **IPC（同机跨进程）**；RPC（跨机）另开工单——RPC 自带编解码器，与磁盘 IO 同级，其物理差异同样由翻译层吸收。

## 1. 核心抽象：块（树 = 特殊块）

**交换协议唯一的核心抽象是「块」（data block）**。树是「带约束的块」，不是与块并列的另一类对象。

| 类型 | 本质 | 约束 |
|---|---|---|
| **桶块** | 普通块 | 叶子级所有权；三种访问形式（映射/全量/惰性）；支持原子读（单块） |
| **树** | 特殊块 | **整棵 IO**；**不可拆分**（不可能映射半个树持半个树）；**不可惰性**（树惰性 = 整库啥也没读）；**库级所有权**；读仅两种：映射（零拷贝）或全读 |

**推论**：树放进桶里是自洽的——映射的物理底层（`SharedRegion`/mmap）对「一大块 Arrow 字节」和「一小块 Arrow 字节」无区别；树只是「必须整棵读、整棵替换」的特例约束。

**寻址铁律**：**不支持随机读**——读取的前提是知道地址，而地址无论如何都要靠树（引用表）寻址；桶块不对外暴露「绕过树直接按地址取」的入口。

## 2. 运行时配置系统（cmake 式 + 部分持久）

运行时行为由一套**标准化配置系统**决定，类比 C 语言编译机制（cmake 式）：

```
L1 代码内嵌默认配置（编译期，库自带）
L2 用户配置文件覆盖（编译后 / 部署时，下游可改）
L3 运行时生成 → 决定每个块的实际行为
```

- **运行时表 = 配置系统的生成产物**：记录每个块的运行时视图——`持有者`（我 / 别人）、`来源`（哪个库 / 谁）、`获取方式`（IPC 同步 / RPC 同步 / 磁盘零拷贝映射）、`访问形式`、`失效状态`（有效 / 上游已改 / 上游死亡）、树另含 `库级所有权` 标记。
- **部分持久**：规则（L1/L2）可持久；运行时事件（上游死亡→失效、来源变更）是运行时叠加、不持久。
- **可魔改**：schema 先覆盖当前用到的字段（见上），下游用户可扩展；配置决定行为，改配置 = 改运行时系统行为。
- **生成器 + 产物表**：配置系统是「生成器」，运行时表是「输出」；二者合称「运行时配置系统」。

## 3. 权限：所有权 + 代理

### 3.1 所有权

- **所有权粒度**：树 = **库级**（整树一个所有者）；桶 = **叶子级**（每个块独立归属）。
- **只有数据所有者拥有写权限**。不存在惰性写：所有者写入 = 直接写。

### 3.2 代理（异步 sudo 写）

- 非所有者向所有者发送**代理请求**（类比 `sudo`）：请求所有者替我改，通过则等同所有者直写。
- **代理写是异步的**：请求发出后完成时间不保证，靠回执确认。
- **失败语义**：
  - **拒绝**：所有者回执拒绝原因；
  - **上游死亡**：表现为**超时**。
- **并发解决**：所有写（所有者直写 + 全部代理写）都串行经过**所有者自己的锁**——逻辑上单写者，无分叉、无锁竞争。
- **共享区生命周期契约**：代理请求/回执经共享区（`SharedRegion`）传递时，发布方须持有 `SharedRegion` 至接收方消费完——IPC 共享区随发布方进程生命周期回收，提前释放 = 接收方读空/读脏（上游死亡 = 超时）。

## 4. 访问形式（读的三种模式）

「写」与所有权绑死（§3），**访问形式只针对「读」**：

| 模式 | 语义 | 树是否可用 |
|---|---|---|
| **零拷贝映射** | 不持有数据，访问时实时读；目标必须是 Arrow；数据可能失效（§7） | ✅（映射别人的库） |
| **全量复制** | 访问瞬间生成「树+桶」完整副本；**副本所有权归读取者** | ✅（全读） |
| **惰性复制** | 先整树同步过来，桶块按需在访问时复制；**新数据所有权归读取者** | ❌（树不可惰性） |

- 桶块的三种模式**按块独立选择**，可自写高级同步算法（某块立即读、某块惰性、某块零拷贝映射）。
- **树的读只有两种**：映射（零拷贝）或全读（全量）；**树不可惰性**——树惰性 = 整库惰性，那是库外层的语义，不放库内部。

## 5. 同步：pull / push / merge

### 5.1 同步的本质

- **没有 commit 链、没有「新旧」**——数据只有「源头」与「目的地」。commit 是业务（上层）的概念，不属本协议。
- 同步 = **用源头数据复写目的地**；范围可指定（全树 / 树片段 / 桶的若干块）。

### 5.2 pull（同步拉取）

```
pull = 抓取（把源头的东西抓过来）→ merge → 整棵替换
```

- 树的同步逻辑：抓取 → merge → **替换**（树的物理操作恒为整棵替换）。
- 桶的同步粒度 = 叶子块，可按块范围指定。

### 5.3 push（代理同步）

- push = **代理同步**：我向目标主动提交数据同步申请，**写入由代理完成**。

### 5.4 merge 原语（树的细粒度修改）

- 树虽然只能整棵 IO，但允许**细粒度修改**：加载整树 → 按范围做增/改/删 → 整棵写回。
- **merge 逻辑可自定义**，内置基础原语：**覆盖（最简）、只添加、只修改、只删除、及任意组合**。
- 可引入 **xpath 正则** 控制要修改的树范围。
- 「覆盖」是 merge 的最简形态；「复写」是其口语化简称。

## 6. 同步原语清单（转换器实现面）

交换协议要求以下**语义原语**，每个布局的**翻译器**逐项实现（物理差异被翻译层吸收）：

| 原语 | 语义 | 布局翻译器示例 |
|---|---|---|
| **读** | 整块读 | 扁平=按文件读；单文件=offset 定位读 |
| **原子读** | 桶块单块一次读完整（块不可变，读到即完整）；**树不支持原子读**（整棵，不可分） | — |
| **写** | 整块写（content-addressed，`exists→skip` 去重） | — |
| **原子写** | 原子替换语义 | 扁平=tmp+rename；单文件=**全量写**（append epoch） |
| **删除** | 显式删除块 | 扁平=unlink；单文件=标记失效待 compaction |
| **GC** | 桶块生命周期 = 树叶子的引用：树标记某块失效后自然消除 | 扁平=sweep 孤儿；单文件=compaction repack |
| **枚举可达** | 按身份枚举可达对象（sync 的遍历底座） | 复用对象目录 / 引用表 |

**不支持随机读**（§1 寻址铁律）：一切读都必须经树寻址。

---

## 7. 失效语义（零拷贝映射的失效）

零拷贝映射「可能失效」有且仅有两类：

1. **上游发生更改**：不保证本次读与上次读一致（映射的是上游当前视图）。
2. **上游死亡**：可能已无数据（共享区随进程生命周期回收）。

代理写亦有超时失效（§3.2）。全量/惰性复制因「副本所有权归读取者」，**无失效问题**。

---

## 8. 范围边界

- **本工单只做 IPC**（同机跨进程）；**RPC（跨机）另开工单**——RPC 带 RPC 编解码器，与磁盘 IO 同级，传输物理差异由翻译层吃掉。
- **不做转换本身**：编/解码、物化器是布局翻译器，不在交换协议内。
- **不做 commit / 历史 / 版本**：数据无新旧，只有源头与目的地（§5.1）。
- **不做树惰性、不做树拆分、不做随机读**（§1/§4/§6）。
