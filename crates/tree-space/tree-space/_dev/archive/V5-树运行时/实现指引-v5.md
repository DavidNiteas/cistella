## 0. 总则（先读，避免返工）

### 0.1 命名决策：`Multiplicity`（新类型，不与 v4 冲突）

v4 已有 `types::Cardinality { ExactlyOne, ZeroOrOne, ZeroOrMore, OneOrMore }`（domain child 的**运行时**基数声明，`validate_cardinality` 用）。v5 的字段基数修饰与之**语义不同**（编译期从字段类型推断），故**另立新名**，避免同名冲突：

```rust
// 位于 tree-space-derive crate（v5 新增）
pub enum Multiplicity {
    Single,     // T            对应 ExactlyOne
    Optional,   // Option<T>    对应 ZeroOrOne
    Sequence,   // Vec<T>       顺序容器 [i]
    Map,        // BTreeMap<K,T> 按键容器 [key]
}
```

> 本文所有「基数」均指 v5 的 `Multiplicity`；v4 `Cardinality` 原样保留、不触碰。

### 0.2 crate 拆分与依赖

- **新 crate `tree-space-derive`**（proc-macro）：`#[derive(TreeNode)]`。依赖 `syn`/`quote`/`proc-macro2`（**仅此 crate**）。
- **`tree-space` 主库**：`tree-space` 依赖 `tree-space-derive`（feature 或直接依赖），**主库零新增第三方依赖**（叶子注册用静态 LUT）。
- workspace 根 `Cargo.toml` 注册新 crate；`[workspace]` members 补 `crates/tree-space-derive`。

### 0.3 测试命名与文件

- v5 测试文件统一 `n<里程碑>_<主题>.rs`，放 `tree-space/tests/`（主库）与 `tree-space-derive/tests/`（derive 的 ui/展开测试）。
- golden 文件后缀 `_golden.rs`；契约文件后缀 `_contract.rs`（对齐 v4 现有习惯）。
- 本节各里程碑的「单元测试清单」给出**测试函数名 + 断言要点**，直接照写即可。

### 0.4 纪律（沿用 v4 §3.4 + AGENTS）

- 任何 shared 字节协议 / golden 变更：先改 [`设计与路线图-v5.md`](设计与路线图-v5.md)，再动实现。
- 领域无关守则：`tree-space` 与 `tree-space-derive` 源码禁止出现 `mz`/`rt`/质谱字面量。
- MSRV 1.89、edition 2024；`#![deny(missing_docs)]` 延续。

## 1. N-1 Leaf 地基

**目标**：定义叶子类型系统地基 + 第一个叶子 `Table`。

**前置**：无。

### 1.1 交付物与接口

```rust
// src/leaf/kinds.rs
pub type LeafHash = crate::ids::Digest;   // [u8;16]，xxh3-128

#[derive(Copy, Clone, PartialEq, Eq, PartialOrd, Ord, Hash, Debug)]
pub struct RefId(pub LeafHash);

#[derive(Copy, Clone, PartialEq, Eq, Hash, Debug)]
pub enum LeafKind { Table, Scalar, Struct, Array, Blob }

#[derive(Clone, PartialEq, Debug)]
pub struct SchemaDesc {               // 供 xpath 的 schema 反射用，递归最小结构
    pub kind: LeafKind,
    pub name: String,                 // 如 "Table" / "Scalar"（列/字段用 String）
    pub children: Vec<(String, SchemaDesc)>,  // table 的列 / struct 的字段
}
```

```rust
// src/leaf/trait_.rs —— dyn 兼容形态（见 v5 设计 authority §14 决策 #6）
pub trait Leaf: Send + Sync + 'static {
    fn kind(&self) -> LeafKind;                 // 取代 const KIND
    fn content_hash(&self) -> LeafHash;         // 内容寻址核心
    fn write_blob(&self, out: &mut Vec<u8>);    // → 规范字节（哈希的输入）
    fn schema(&self) -> SchemaDesc;             // 无关联类型
}
// read_blob 移到各具体 leaf（fn try_read_blob(&[u8]) -> Result<Self> / fn read_blob(&[u8]) -> Self），
// 注册分派走 N-3 read_leaf（静态 LUT）。

pub trait LeafSchema: Send + Sync + 'static {
    fn describe(&self) -> SchemaDesc;
}
```

```rust
// src/leaf/slot.rs
pub enum LeafSlot<L: Leaf> {
    Inline(L),      // 小值内联
    Ref(RefId),     // 大值外置到 store
}
impl<L: Leaf> LeafSlot<L> {
    pub fn content_hash(&self) -> LeafHash;  // Inline → L::content_hash(); Ref → as_ref_id()
    pub fn is_ref(&self) -> bool;
}
```

```rust
// src/leaf/table.rs
pub struct Table { pub(crate) batch: RecordBatch }
pub struct TableSchema { /* 列名 + Arrow Field */ }

impl Leaf for Table {
    const KIND: LeafKind = LeafKind::Table;
    type Schema = TableSchema;
    // content_hash / write_blob / read_blob 复用 v4 既有 canonical IPC 编码
    // （hash::canonical_digest + ipc 编码，含 in_hash=false 列规则）
}
```

### 1.2 实现要点

- `Table::content_hash` **不得**新造公式，直接对现有 v4 的「规范化 IPC 字节」取 `xxh3_128`（复用 `src/hash.rs`），保证与既有表数据一致（超集关系 §11）。
- `read_blob` 需处理「损坏字节 → 明确错误」；用现有 `ErrorCode` 体系扩展一个 `LeafDecode` 变体（或复用）。
- `SchemaDesc` 的 `children` 第一版满足反射即可，不进 digest（它只是描述，不参与内容寻址）。

### 1.3 单元测试（`tests/n1_leaf_foundation.rs` + `tests/n1_leaf_golden.rs`）

| 测试函数 | 断言要点 |
|---|---|
| `table_content_hash_is_stable` | 同一 `Table` 两次 `content_hash` 相等，且跨进程可复算（纯函数、无内存地址依赖） |
| `table_content_hash_reflects_content` | 改一列数据 → hash 变；仅改 `in_hash=false` 列 → hash 仍变（content_hash 含全列） |
| `table_write_read_roundtrip` | `write_blob` → `read_blob` 恢复后逐值相等（含空表、单列、多列、null） |
| `table_write_blob_is_deterministic` | 同一 `Table` 两次 `write_blob` 字节逐位相等 |
| `refid_derives_eq_ord_hash` | `RefId` 可作 `HashMap`/`BTreeMap` key；`PartialOrd` 按字节序 |
| `leaf_kind_has_five_variants` | 枚举变体恰为 `Table/Scalar/Struct/Array/Blob` |
| `leaf_slot_content_hash` | `LeafSlot::Inline(x)` 与 `LeafSlot::Ref(x.content_hash())` 的 hash 一致 |
| `table_content_hash_golden` （golden） | 固定小 fixture（3 列 × 5 行，含 null 与 string）→ 冻结 16 字节常量 |

### 1.4 验收

- `pixi run -e dev-rust cargo test --manifest-path mzparse/rust/Cargo.toml -p tree-space n1_` 全绿。
- golden 字节入库冻结（`n1_leaf_golden.rs` 内 `const`），任何改动需说明。

## 2. N-2 叶子全类 + IO 契约

**目标**：补齐 `Scalar`/`Struct`/`Array`/`Blob`；定 IO 布局分派 trait 雏形。

**前置**：N-1。

### 2.1 交付物与接口

```rust
// scalar.rs —— 标量叶子，复用 arrow 的 ScalarValue 作内部表示
pub struct Scalar(pub(crate) ScalarValue);
impl Leaf for Scalar { const KIND = Scalar; type Schema = ScalarSchema; /* ... */ }

// struct_.rs —— 小结构体：有序 (name, Scalar) 字段集
pub struct Struct { pub(crate) fields: Vec<(String, Scalar)> }
pub struct StructSchema { pub(crate) names: Vec<String> }

// array_.rs —— 数组叶子：数值向量（基数不变，区别于容器）
pub struct Array { pub(crate) values: Vec<Scalar> }   // 或 arrow PrimitiveArray
pub struct ArraySchema { pub(crate) elem_desc: SchemaDesc, pub(crate) len: usize }

// blob.rs —— 原始字节块
pub struct Blob(pub(crate) Vec<u8>);
```

```rust
// src/io/mod.rs —— IO 布局分派 trait 雏形（N-10 补齐，此处只定型契约）
pub trait LeafIo: Leaf {
    // 单文件 vs 目录化由布局层决定；叶子只需声明自己的编码格式名
    const FORMAT: &'static str;            // "arrow-ipc" / "scalar" / "json-like" / "raw"
    fn write_blob_into(&self, mode: IoMode, out: &mut Vec<u8>);  // 预留 mode（单文件/目录化）
}
pub enum IoMode { SingleFile, Directory }
```

### 2.2 实现要点

- 所有叶子的 `content_hash` 遵循同一 `canonical_digest` 原则：`kind 前缀 + 长度分隔字段`；每个叶子自己的「规范编码」要唯一、无歧义（可复用 `hash::canonical_digest` 的 `tag,parts` 原语）。
- `Scalar`/`Array` 若借 arrow `ScalarValue`，注意其 `PartialEq`/哈希语义；content_hash 必须基于**规范字节**而非 `ScalarValue` 的哈希实现（后者不稳定）。
- `Blob::content_hash` = 对原始字节取 `xxh3_128`（这就是纯内容哈希的标准形态）。

### 2.3 单元测试（`tests/n2_leaf_roundtrip.rs` + `tests/n2_leaf_golden.rs`）

| 测试函数 | 断言要点 |
|---|---|
| `scalar_roundtrip` | 各标量子类（i64/u64/f64/bool/utf8）write→read 等价 |
| `scalar_hash_reflects_value` | 不同值 hash 不同；同值 hash 相同 |
| `struct_roundtrip` | 字段序稳定：写入 `{a,b}` 与 `{b,a}` 是**不同**内容（字段序参与哈希） |
| `struct_field_order_matters` | 上述「序敏感」显式断言 |
| `array_roundtrip` | 数值向量 write→read 等价；空数组 / 单位数组边界 |
| `array_hash_reflects_len` | 长度参与哈希（改变长度 hash 变） |
| `blob_roundtrip` | 任意字节（含 0x00、高位字节）逐位往返 |
| `blob_hash_is_raw` | `Blob::content_hash == xxh3_128(raw)` |
| `leaf_io_format_decl` | 每种叶子 `FORMAT` 声明唯一且符合契约 |
| `n2_*, _golden`（golden） | 每种叶子取一个固定 fixture，冻结 `content_hash` 常量 |

### 2.4 验收

- `cargo test -p tree-space n2_` 全绿；各叶子 golden 冻结。

## 3. N-3 叶子注册（静态 LUT）

**目标**：kind→reader 静态分派；漏注册编译报错。

**前置**：N-2。

### 3.1 交付物与接口

```rust
// src/leaf/registry.rs
pub struct LeafReader {
    pub kind: LeafKind,
    pub read: fn(&[u8]) -> Box<dyn Leaf>,       // 类型擦除反序列化入口
}

pub fn read_leaf(kind: LeafKind, bytes: &[u8]) -> Box<dyn Leaf> {
    match kind {                                // 枚举穷尽：漏分支 = 编译报错
        LeafKind::Table  => Box::new(Table::read_blob(bytes)),
        LeafKind::Scalar => Box::new(Scalar::read_blob(bytes)),
        LeafKind::Struct => Box::new(Struct::read_blob(bytes)),
        LeafKind::Array  => Box::new(Array::read_blob(bytes)),
        LeafKind::Blob   => Box::new(Blob::read_blob(bytes)),
    }
}

pub const LEAF_READERS: &'static [LeafReader] = &[ ... ];  // 与 match 一致的分派表（供 store 元信息）
pub fn registered_kinds() -> Vec<LeafKind>;               // LEAF_READERS 覆盖的 kind 集合
```

### 3.2 实现要点

- `LEAF_READERS` 与 `read_leaf` 必须**同源**，不得出现「match 补了、表没补」的分叉；实现上让 `read_leaf` 由 `LEAF_READERS` 派生（查表），或单测断言两者覆盖的 kind 集合一致（`registered_kinds` 由 `LEAF_READERS` 派生）。
- 「漏注册编译报错」是 `match` 穷尽检查的**语言保证**，无需运行时测试；但要留一个文档注释说明新增叶子类型的唯一路径 = `impl Leaf` + 补 `read_leaf` 分支。

### 3.3 单元测试（`tests/n3_leaf_registry.rs`）

| 测试函数 | 断言要点 |
|---|---|
| `read_leaf_dispatches_all_kinds` | 对 5 种 `LeafKind`，用各自 `write_blob` 的字节经 `read_leaf` 恢复，返回类型正确（`Leaf::KIND` 匹配） |
| `read_leaf_rejects_corrupt` | 坏字节 → 明确错误，不 panic |
| `readers_covers_all_kinds` | `LEAF_READERS` 的 kind 集合 == `LeafKind` 全部 5 变体 |
| `readers_matches_read_leaf` | 对每个 reader，`read` 与同 kind 的 `read_leaf` 行为一致 |

### 3.4 验收

- `cargo test -p tree-space n3_` 全绿。
- 「支持新叶子类型 = impl + 补分支」的编译期强制由 `match` 穷尽性静态保障（评审时人工核对）。

## 4. N-4 字段注册表 derive

**目标**：新建 `tree-space-derive`，`#[derive(TreeNode)]` 生成 `NodeMeta`/`FieldMeta` + `Multiplicity` 推断。

**前置**：N-1（`Leaf` trait 存在即可）。

### 4.1 交付物与接口

```rust
// tree-space-derive/src/lib.rs
#[proc_macro_derive(TreeNode)]
pub fn derive_tree_node(input: TokenStream) -> TokenStream;
```

生成物（目标形态，与主库定义对齐）：

```rust
// 主库 src/tree/meta.rs（N-4 先放 derive 与主库共享的类型定义处）
pub struct NodeMeta {
    pub type_name: &'static str,
    pub fields: &'static [FieldMeta],
}
pub struct FieldMeta {
    pub name: &'static str,
    pub multiplicity: Multiplicity,
    pub target: FieldTarget,
}
pub enum FieldTarget {
    Node(&'static NodeMeta),                          // 子节点（递归）
    Leaf { kind: LeafKind, schema: &'static LeafSchemaMeta },
}
```

（`LeafSchemaMeta` 是 `LeafSchema` 的静态可查面，由叶子类型提供 `const`；若难共享，第一版可用 `&'static str` 描述替代，N-5 再定。）

### 4.2 基数推断规则（derive 核心）

| 字段 Rust 类型 | 推断 `Multiplicity` |
|---|---|
| `T`（T: TreeNode 或 T: Leaf） | `Single` |
| `Option<T>` | `Optional` |
| `Vec<T>` | `Sequence` |
| `BTreeMap<K, T>`（K: 稳定键） | `Map` |

- 其它容器/类型（如 `HashMap`、`usize`、裸 `RecordBatch` 未包装）→ **编译报错**（给出清晰 `compile_error!` 指明非法字段类型）。
- `BTreeMap` 的 `K` 若为非 `String`/`[u8;16]` → 编译报错（禁止插入序不稳定的键）。
- 字段若既非 `TreeNode` 也非 `Leaf` → 编译报错。

### 4.3 单元测试（derive crate 内 + 主库配套）

- **derive 内部单测**（`tree-space-derive/src/lib.rs` 的 `#[cfg(test)] mod tests`）：断言 `strip_containers` 的基数推断（`T`/`Option`/`Vec`/`BTreeMap` → 四态）与 `target_tokens` 的 Map 键校验（`String`/`[u8; 16]` 放行、`u32`/`usize` 拒绝）。
- **主库集成**（`tests/n4_multiplicity.rs`）：

| 测试函数 | 断言要点 |
|---|---|
| `multiplicity_infer_single` | `config: Config` → `Single` |
| `multiplicity_infer_optional` | `meta: Option<Metadata>` → `Optional` |
| `multiplicity_infer_sequence` | `runs: Vec<Run>` → `Sequence` |
| `multiplicity_infer_map` | `scenarios: BTreeMap<String, Scenario>` → `Map` |
| `node_meta_fields_preserve_order` | 字段表顺序 == 声明顺序 |
| `derive_generates_get_set` | 生成的 `get`/`set` 在简单树上可达 |

### 4.4 验收

- generate crate 编译通过；主库 `cargo test -p tree-space n4_` 全绿。
- `NodeMeta`/`FieldMeta` 字节 golden（如有）冻结。

## 5. N-5 xpath 解析与导航

**目标**：`XPath`/`Step` + `TreeNode` trait（强类型主路 / 弱类型桥）。

**前置**：N-4（derive 已生成 META）。

### 5.1 交付物与接口

```rust
// src/xpath/mod.rs
pub struct XPath { pub(crate) steps: Vec<Step> }
impl XPath {
    pub fn parse(s: &str) -> Result<XPath>;          // "/a/b[3]/c" → steps；非法报错
}
pub enum Step {
    Field(String),   // /field
    Index(usize),    // [i]
    Key(String),     // [key]
}
```

```rust
// src/tree/（主库）—— dyn 兼容形态（见 v5 设计 authority §14 决策 #6）
pub trait TreeNodeMeta: 'static {
    const META: &'static NodeMeta;          // 静态字段表（const 独立，保 TreeNode dyn 兼容）
}

pub trait TreeNode: 'static {
    fn get(&self, xpath: &XPath) -> Result<AccessOut>;      // 弱类型桥（N-5）
    fn set(&mut self, xpath: &XPath, v: LeafSlot<Box<dyn Leaf>>) -> Result<()>;  // N-7 落地
    fn leaf_refs(&self) -> Vec<(XPath, RefId)>;             // 遍历叶子引用（GC/verify 用）
}

pub enum AccessOut {
    Leaf(Box<dyn Leaf>),
    Node(Box<dyn TreeNode>),
}
```

### 5.2 实现要点

- **强类型主路**：由 derive 生成的 `get`/`leaf_refs`（`set` 随 N-7）直接基于结构体字段访问（零成本），用户热路径直接 `exp.runs[3].x`，不经 trait object。
- **弱类型桥**：`get` 沿 `META` 导航（derive 按字段生成 match arm）；`AccessOut` 用 `Box<dyn Leaf>`/`Box<dyn TreeNode>` 兜底，**不引入 `Any`**（已定决策 §14.3）。
- **strict vs best_effort**：`get` 为 strict（不可达抛 `ErrorCode::XpathUnreachable`）；`get_best_effort`（已落地）返回 `(AccessOut, remaining XPath)`——尽力导航到最深可达值，返回未消费的剩余 path，供实例化阶段从弱类型地址逐步解析到强类型值。
- **derive 生成条件**：用户节点 struct 需 `#[derive(Clone, TreeNode)]`（get 内部对子节点做 `Box::new(self.field.clone())`）；字段类型为内置叶子（`Table`/`Scalar`/`Struct`/`Array`/`Blob`）时按 Leaf 目标，否则按 Node 目标（`<Ty as TreeNodeMeta>::META`，编译期保证 Ty: TreeNode）。
- `XPath::parse` 的规范形（用于后续 xpath_hash）必须与步骤序列一一对应、无歧义；`[i]`/`[key]` 转义规则要定死（`[`/`]` 在字段名中的转义，golden 冻结）。

```rust
// src/tree/mod.rs —— 模板实例化的脚手架（derive 配合生成）
pub trait TreeInstance: TreeNode {

    //   Table / Array / Blob → Ref（缺省，配合 store write 时外置）
```

- `TreeInstance` 改为 derive（`#[derive(TreeInstance)]`）而非手写 impl：`new_empty` 基于 `Default` 生成 `Self { f: Default::default(), .. }` 形式，字段类型锁定在编译期。

```rust

```

### 7.2 实现要点（关键设计点，务必读）

1. **树实例 = 用户写的 `#[derive(TreeNode)]` struct**，本身是强类型值；叶子字段类型 = `LeafSlot<L>`（内联小值 / `Ref(RefId)` 外置大值）。
2. **「树不存 payload」落地**：外置时树实例只占 16 字节 `RefId`，payload 在 store（N-9）。
3. **「部分动态」**：字段集合与类型由 `struct` 定义编译期锁死；运行时可变仅 `Option` 的 Some/None、`Vec` 长度、`BTreeMap` 键集。
4. **内联/外置策略**是 `LeafSlot` 的**缺省构造规则**（非叶子类型属性）；`default_slot` 用 `L::kind()` 分派缺省。`LeafSlot<L>` 已 `#[derive(Clone)]`，并对 `L: Leaf + Default` 提供 `Default`（经 `default_slot`）。
5. 已为 `Box<dyn Leaf>` 提供 `Leaf` 的 blanket impl（FieldTarget 里 `Box<dyn Leaf>` 弱桥），实现要点：`kind()` 代理内部值的 kind，`content_hash` 代理内部值，`schema()` 代理。
6. **derive 统一 leaf 感知的取用**：`get` 中叶子分支一律改走 `tree::LeafToOut::to_out(&self.field)`（裸 leaf → `Out::Leaf(Box)`；slot Inline → `Out::Leaf(Box)`；slot Ref → `Out::LeafRef(RefId)`）。`leaf_refs` 中叶子分支一律 `tree::LeafRefOf::leaf_ref(&self.field)`（裸 leaf / slot 均取 `RefId`）。这样派生代码不再需要 per-field is_slot 分支级联。
7. **`set` 语义（弱写桥 MVP）**：仅单值/可选 leaf slot 字段可写——存储为 `LeafSlot::Ref(v.content_hash())`；单值/可选 node 字段递归 `node.set(&rest, v)`；**根替换、Sequence/Map 及裸非 slot leaf 不可写**，返回 `ErrorCode::XpathUnreachable`。

## 8. N-8 xpath 索引哈希表

**目标**：`xpath_hash → RefId` 扁平索引 + 碰撞降级。

**前置**：N-5、N-7。

**状态**：✅ 已完成（`src/index/mod.rs`）。

### 8.1 交付物与接口

```rust
// src/index/mod.rs
pub type XPathHash = [u8; 16];

pub fn canonical_xpath_bytes(xpath: &XPath) -> Vec<u8>;
pub fn xpath_hash(xpath: &XPath) -> XPathHash;   // canonical_digest(b"xpath", [规范字节])

pub struct XPathIndex { /* BTreeMap<XPathHash, Vec<(XPath, RefId)>> */ }
impl XPathIndex {
    pub fn insert(&mut self, xpath: &XPath, id: RefId);
    pub fn get(&self, xpath: &XPath) -> Option<&RefId>;      // 命中后二次确认
    pub fn remove(&mut self, xpath: &XPath) -> Option<RefId>;
    pub fn iter(&self) -> impl Iterator<Item = (&XPath, &RefId)>;
}
```

（碰撞降级探针 `insert_debug_with_hash` / `get_debug_with_hash` / `debug_bucket_len` 为 `#[doc(hidden)]`，仅供测试注入。）

### 8.2 实现要点

- `xpath_hash` 输入是 `XPath` 的**规范字节**，绝不能用用户原始字符串直接哈希。
- **规范字节与 Display 解耦**（决策）：`Display` 会把 `Index(3)` 与 `Key("3")` 都渲染成 `[3]`，会让两个不同地址共用同一索引键。`canonical_xpath_bytes` 改用**注入编码**：`Field → 0x46 ++ u64le(len) ++ bytes`、`Index → 0x49 ++ u64le(i)`、`Key → 0x4b ++ u64le(len) ++ bytes`。不同 xpath 永不规范化为相同字节。
- **碰撞降级**：内部 `BTreeMap<XPathHash, Vec<(XPath, RefId)>>`；`get` 命中 hash 后沿链做**完整 `XPath` 相等二次比对**，不匹配继续。128-bit 碰撞是保险丝，不是主路径。真实碰撞无法轻易构造，测试用探针把第二个 xpath 塞进同一 hash 桶，验证链内区分；在同一测试中同时断言碰撞见证不污染真实查询（`get(&p2)` 仍按其自身 hash 查空桶）。
- 守住**双哈希铁律**：`XPathHash` 只作索引键，物理 blob 寻址仍是 `RefId`（`content_hash`）。

## 9. N-9 store 泛化

**目标**：blob 从「只 table」扩到「任意 `Box<dyn Leaf>`」；保持 commit-tree/GC/verify 不变。

**前置**：N-3、N-8。

**状态**：✅ 已完成（`src/store/mod.rs`）。

### 9.1 交付物

- **落地决策**：为实现「保持 commit-tree/GC/verify 不变」，store 泛化以**独立 `src/store/`（`LeafStore`）** 交付，而非改写 `src/layout/` 的三布局 blob 路径。`LeafStore` 与 v4 content-addressed 布局语义一致（`RefId → blob`、不可变、按内容去重、可达性 GC），但 blob 编码从「只 Arrow 表」泛化为**任意 `Leaf::write_blob` 产物 + 自描述 kind 前缀**：
  - `StoreBlob { kind: LeafKind, bytes: Vec<u8> }`
  - `get` 经 N-3 `read_leaf(kind, bytes)` 类型擦除恢复（无需带类型的树在场）。
- 遗留 `src/layout/` 的表专用路径原样保留（v4 兼容，表是叶子一种；ParquetDir 的目录化 leaf blob 落盘留给 N-10 布局分派闭环）。

### 9.2 实现要点（超集关系关键）

- **不改** v4 的 commit-tree、`committed` 唯一可见性点、GC 可达性、`PreparedCommit` 顺序——`LeafStore` 平行提供同语义的独立实现（`put`/`get`/`verify`/`gc`）。
- `content_hash` 仍由 `Leaf::content_hash` 提供（不是 `write_blob` 结果哈希——两者必须一致，`verify` 重算 digest 与 `RefId` 比对兜住）。
- `StoreBlob` 自带 `kind`：自描述、可独立 verify，无需 tree `META`。
- 弱类型桥入口 `put_boxed(Box<dyn Leaf>)` 与强类型 `put(&dyn Leaf)` 并存。

## 12. 风险与依赖提醒

- **最大坑**：把「blob 编码」从表专用换成 `Leaf` 编码时，绝不可破坏 v4 既有 `content_hash` 计算路径——已全程复用 `hash::canonical_digest`，v4 layout 未改。

- 依赖新增唯一来源：`tree-space-derive` 的 `syn`/`quote`/`proc-macro2`；主库零新增第三方（N-10 IO 驱动仅用 std）。
