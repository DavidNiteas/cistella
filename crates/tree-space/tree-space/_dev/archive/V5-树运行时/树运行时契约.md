## 1. 三层架构

| 层 | 职责 | 运行时实体 | 承载 |
|---|---|---|---|
| **模板** | 编译期类型，定义合法 xpath + 叶子期望 + 基数 | 无（编译期 DAG） | 结构**形状** |
| **树实例** | 运行时结构 | 有，轻量 | 拓扑（容器长度 / 键集 / Option 有无）+ 叶子槽（`Slot`） |
| **桶** | payload | 有 | 不可变内容寻址块（`RefId → envelope`） |

- 模板 = `#[derive(TreeNode)]` 的 struct 组合；编译期锁死形状，运行时只允许空态与数量变化，**类型不可变**（Rust 类型系统天然保证，无需运行时校验）。
- 树实例不承载块 payload：块叶子在实例中只占 16 字节 `RefId`（`Slot::Ref`）；内联标量值住实例（`Slot::Inline(Value)`）。
- 一个「库」= 一棵树实例 + 一个桶。**持久库与临时 view 是同一机制的两种姿态**：都是树实例，共享同一个桶；临时 view 引用主库块不产生复制（同 `RefId` 即同内容）。

## 2. 树元素：节点与叶子位置

树上有且仅有两类元素：

- **节点（Node）**：`trait TreeNode`，承载结构与导航；
- **叶子位置（leaf position）**：字段层面的终止点，持有 `Slot`（内联值或块引用）。

> 术语铁律：**叶子位置**（树侧概念）与**块**（桶侧对象）是两个概念（《树与桶模型》§1）。

### 2.1 TreeNode trait

```rust
/// 静态元数据（含 const，独立于 dyn 友好的导航 trait）。
pub trait TreeNodeMeta: 'static {
    const META: &'static NodeMeta;
}

/// 导航 trait（dyn 友好：无 const / 关联类型 / Self: Sized 方法）。
pub trait TreeNode: 'static {
    fn get(&self, xpath: &XPath) -> Result<AccessOut>;               // strict：不可达报错
    fn get_best_effort(&self, xpath: &XPath) -> (AccessOut, XPath);  // 尽力：到达值 + 未消费剩余步
    fn set(&mut self, xpath: &XPath, v: Slot) -> Result<()>;         // 弱类型写桥
    fn leaf_refs(&self) -> Vec<(XPath, RefId)>;                      // 全部块引用（GC/verify 可达性）
}
```

- `get` 为 strict 导航：不可达步骤报 `ErrorCode::XpathUnreachable`；
- `get_best_effort` 永不失败：返回最深可达值 + 剩余 xpath（实例化 / 去收集阶段的前沿桥，避免丢失未消费地址）；
- `set` 是弱类型写桥：按槽语义写入（`Inline(Value)` 或 `Ref(RefId)`）；节点字段递归、容器按步定位；
- **get 不触桶（MUST）**：导航永不物化块内容——块叶子位置以**身份**（`RefId`）应答，物化是显式的 `Bucket::get`。若实现为类型化块字段保留了内存驻留值，`get` 仍以身份应答（`RefId` 可从驻留值即时计算）。

### 2.2 AccessOut（弱桥返回值）

```rust
pub enum AccessOut {
    Value(Value),               // 内联标量值
    Node(Box<dyn TreeNode>),    // 子节点（含 DynamicNode、view 节点）
    Ref(RefId),                 // 块引用（未物化）
}
```

- v5 的 `Leaf(Box<dyn Leaf>)` 变体随叶子层重塑退场：弱桥不再携带块 payload——块物化一律显式走桶。这强化「树不存 payload」，并消灭「桥上克隆大块」的隐性路径。
- view 节点实现 `TreeNode`（自身零 payload、无子字段可导航），经 `Node` 变体返回；其输入引用由 `leaf_refs` 覆盖（§8）。

### 2.3 强/弱二分（不变）

- **强类型主路**：热路径直接字段访问（`exp.runs[3].x`），零成本、编译期类型；
- **弱类型桥**：xpath 字符串、序列化、反射走 `get`/`set`，只出现在非热路径，不得腐蚀主路。

## 3. 多重性与键约束

编译期从字段类型自动推断（`#[derive(TreeNode)]` 负责）：

| Rust 字段类型 | Multiplicity | xpath 实例步 | 语义 |
|---|---|---|---|
| `T` | `Single` | `/field` | 恰好 1 个 |
| `Option<T>` | `Optional` | `/field` | 可空 0..1 |
| `Vec<T>` | `Sequence` | `/field[i]` | 顺序容器 |
| `BTreeMap<K, T>` | `Map` | `/field[key]` | 按键容器 |

- 「部分动态」的精确定义：实例化后字段集合与类型固定；可变的只有 `Option` 有无、`Vec` 长度、`BTreeMap` 键集。
- **`BTreeMap` 键约束（MUST）**：`K` ∈ {`String`, `[u8;16]`}（稳定可复算）；derive 静态拒绝任意整数键等引入插入序不稳定风险的写法。
- 块类型的 `Vec<T>` 字段即 chunk 组（《树与桶模型》§3.2）；在字段注册表中就是 Sequence 多重性 + 块叶子目标。

### 3.1 字段注册表（derive 生成）

```rust
pub struct FieldMeta {
    pub name: &'static str,
    pub multiplicity: Multiplicity,
    pub target: FieldTarget,
}

pub enum FieldTarget {
    Node(&'static NodeMeta),                          // 子节点
    Inline { schema: &'static LeafSchemaMeta },       // 内联 TB 标量（Value）
    Block { kind: BlockKind, schema: &'static LeafSchemaMeta }, // 块叶子（期望 kind；类型化校验契约见《树与桶模型》§2.6）
}

pub struct NodeMeta {
    pub type_name: &'static str,
    pub fields: &'static [FieldMeta],
}
```

（v5 的 `Leaf { target: LeafTarget }` 口袋已随 TB 重塑折叠为 `Inline`/`Block` 两个枚举变体；`LeafTarget` 类型保留为兼容导出，不再由 derive 构造。）

derive 同时生成 `TreeNodeMeta::META` 与 `get`/`get_best_effort`/`set`/`leaf_refs` 实现；其接受的字段类型语法表由《树与桶模型》§3.1 定义。

## 4. xpath 寻址

### 4.1 XPath 与 Step

```rust
pub struct XPath { steps: Vec<Step> }

pub enum Step {
    Field(String),   // /field
    Index(usize),    // [i]
    Key(String),     // [key]
}
```

xpath 有两层，必须显式区分：

- **类型路径**（schema 级）：纯 `/field` 步，稳定、可 digest；
- **实例路径**（数据级）：含 `[i]`/`[key]` 步，指向具体实例。

### 4.2 规范字节（与 Display 解耦）

`canonical_xpath_bytes` 用注入编码：`Field → 0x46`、`Index → 0x49`、`Key → 0x4b`，步内容带长度前缀。`Display` 会把 `Index(3)` 与 `Key("3")` 渲染成相同 `[3]`，规范字节保证不同 xpath 永不规范化为相同字节（N-8 决策，golden 冻结）。

## 5. 索引与双哈希铁律

- `XPathIndex`：`BTreeMap<XPathHash, Vec<(XPath, RefId)>>`；`xpath_hash = canonical_digest(b"xpath", [规范 xpath 字节])`；
- **碰撞降级（保险丝）**：hash 命中后用完整规范 xpath 字节二次比对；128-bit 碰撞概率天文数字，降级仅为严谨性兜底；
- **双哈希铁律（MUST）**：`xpath_hash` 只作索引键（可碰撞，绝不用于物理寻址）；`content_hash`（块身份，`tb-block-*` 域）是全内容哈希，用于 blob 地址/去重——二者绝不互相替代。

## 6. domain 标签

- domain = 贴在**模板（类型）**上的性质标签（marker trait），与树结构正交；实例继承；运行时可查面用 `BlockKind`；
- 「叶子必定属于叶子 domain」由块类型约束静态成立；细分 domain 用 marker trait（`TableDomain`/`SpatialDomain` 先例）；
- 编译期约束助手：`assert_leaf`/`assert_tree_node`；
- 待办（未排期）：domain 标签 → 注册表整合（现为编译期约束）。

## 7. dyn 兼容技术决策（仍然有效）

`Block`/`TreeNode` 承载于 `Box<dyn …>` 弱桥，而关联常量、关联类型、`Self: Sized` 方法三者都会破坏 dyn 兼容。因此（v5 §14 决策 6，TB 沿用）：

1. `Block::kind()` 方法取代 `const KIND`；
2. 无关联类型；`describe() -> BlockDesc` 直接返回；
3. `read_blob` 移到各具体块的静态方法，经静态 LUT `read_block(kind, bytes)` 分派（`match kind` 穷尽检查，漏分支编译报错）；
4. `TreeNodeMeta` 独立承载 `const META`；`TreeNode` 保持纯 `&self`/`&mut self` 方法；
5. **弱类型桥不引入 `Any`**：类型擦除只做 `content_hash`/`write_payload`/`describe`；需要具体类型走强类型主路。半途出现「运行期才知道类型又要拿具体数据」的硬场景再补 `as_any` 兜底（未发生）。

## 8. leaf_refs 与 GC 可达性

- `leaf_refs` 是 GC / verify 的可达性权威：返回子树全部块引用及其绝对 xpath；
- **覆盖范围（MUST，TB 扩展）**：块叶子槽（`Slot::Ref`）、chunk 组条目（含嵌套子组的传递条目）、view 节点输入（含嵌套 view 的传递输入）、物化缓存注记引用（若旁挂）；
- **GC 双域（MUST）**：内存域 GC 根 = 存活实例的全部 `leaf_refs`（**含 ephemeral 子树**——实例活着，它的引用就活着）；磁盘域 GC = 持久树可达（未来 IO 批次）。两域根集不同，混用即丢数据，实现与测试必须显式区分。
