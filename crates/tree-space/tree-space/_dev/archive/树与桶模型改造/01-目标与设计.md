## 0. 背景与定位

### 0.1 tree-space 的最终定位

tree-space 是为下游库提供**通用数据层**的基础库，目标能力有三：

1. **以树的形式组织 Arrow 格式数据**：表格运行时面向 polars（经 Arrow 边界交互；tree-space 本体不引入 polars 依赖）；
2. **基于 Arrow 的数据共享**：零拷贝只读 + 惰性拷贝读取（table-space 时期设计初衷的延续）；
3. **磁盘 IO**：单文件、多文件（content-addressed 目录）两种既有形态，外加层化目录（NestedTreeModule 式树拓扑镜像目录）新形态。

**开发决策（2026-08-20）**：tree-space 功能完善之前，`mzml-db` / `uni-mass-db` 两业务库冻结在 v4 公共 API 上，不向 v5/TB 新面迁移。已核实（2026-08-20 grep）：v5 层目前零下游消费方，重塑无迁移成本。

### 0.2 本工单范围与批次划分

本工单覆盖整个树与桶化改造，按批次推进（阶段总览与里程碑见 [`02-施工路线图.md`](02-施工路线图.md)）：

- **TB 批次（已闭合 2026-08-21）**：模型层——数据块规范 + 树语义，纯内存落地验收。
- **AB 批次（已闭合 2026-08-22）**：块格式统一——内建四块 payload 全 canonical Arrow IPC + 块集合开放注册制。
- **A-2 批次（已立项 2026-08-22，规范定稿待施工）**：树对象 Arrow 化——北极星的另一半「结构（树）也是 Arrow」（§5）。
- **管道批次（独立工单，未立项）**：磁盘 IO（三形态 + 层化目录）、共享（SharedRegion）、polars 桥；类型化实例 ephemeral 标注与树上下文 schema 校验回补。**颗粒度决策（2026-08-22）：本工单范围止于编码（TB/AB/A-2），随 A-2 验收闭合归档；管道另立工单并在其 01 声明接续关系。**

各批次范围纪律见 §9（尤其「不做管道」对编码批次持续有效）。

### 0.3 北极星与两道门

**北极星（讨论定稿）**：tree-space 的目标是把「树的序列化形态」与「数据的序列化形态」统一为 **canonical Arrow IPC**——v4 已令 payload 全 Arrow，AB 批次补齐「块（数据）是 Arrow」，A-2 批次补齐「树（结构）也是 Arrow」。一旦统一，IO（三形态复用 content-addressed 存储）、跨进程共享（SharedRegion 吃 Arrow buffer）、verify/sync（canonical IPC digest）全部由既有机制**组合**获得，无需为树另起炉灶。

**两道门模型（讨论定稿，规范）**：

| | 第一道门：注册适配器（入场券） | 第二道门：Arrow 化（红利券） |
|---|---|---|
| 条件 | 提供稳定注册名 + canonical payload 编解码 + 确定性契约 | 任意 Arrow 化编码 / RecordBatch 投影 |
| 获得 | 进桶、被树引用、身份/去重/GC、sync 收敛、L1（身份复算级）verify | L2/L3 内容级 verify（框架代劳 canonical）、零拷贝共享、polars 直通 |

> **桶级红利不需要 Arrow**：桶「不解释字节」（铁律 1），身份/去重/GC 对任意注册块天然成立。因此「非 Arrow 块什么红利都没有」不准确——确切表述是「非 Arrow 块享受桶级，不享 Arrow 级」（完整矩阵见 §2.8）。

### 0.4 讨论定稿的关键结论（本文展开为规范）

1. 块集合 = 内建四元（table / sequence / kv / blob）+ `BlockKind::Named` 开放注册（§2.1）；
2. 「值在块、结构在树」：桶只存不可变字节；一切解释（类型上下文、chunking、view、持久化策略）都在树上（§1）；
3. kv 键型对齐 Arrow 全标量；值编码一次性做全（§2.4）；
4. 内建块 payload 全部规范化为 canonical Arrow IPC（§2.4，AB 批次定稿）；
5. chunking 是树结构，不是块属性（§3.2）；
6. view 是带组合器语义的树节点，不是叶子（§3.3）；
7. 持久化标记是树节点注记：默认持久，ephemeral 子树写盘剪枝、读取尽力、内存交换忽略（§3.5）；
8. 内建动态树节点承载运行时构造的 view / chunk 组（§3.4）；
9. 树对象规范序列化 = 平面条目表 + `tb-tree` 身份域 + 无信封 + 注记与类型名不进 canonical + 两级解码（§5，A-2 定稿）。

## 1. 本体论与铁律

模型有两极：

- **桶（bucket）**：全局内容寻址的不可变字节大桶。`RefId → envelope`，仅此而已。
- **树（tree）**：一切解释的宿主。结构、类型上下文、chunking、view 组合、持久化策略，全部是树的内容。

**五条铁律（MUST）**：

1. **桶不解释数据**：桶只见「身份 → 不可变字节」。桶不做类型判断、不做语义校验（verify 仅重算哈希）。
2. **一切解释在树**：哪个位置是什么类型、怎么 chunk、怎么组合成 view、是否持久，只由树决定。
3. **块容器装同质值，异构结构是树**：块只承载同质「值」的序列/映射/表/字节；异构命名字段 = 树节点。空值/缺省用 `Optional` 多重性或值级 Null 表达，不需要新块种类。
4. **身份即字节**：`RefId = hash(规范字节)`，与语义、内存布局、构造路径无关。同字节必同址，跨 kind 必不同址。
5. **引用只在树上**：桶内字节不得内嵌 `RefId`。chunk 组、view 组合都是树节点；自引用/组合内容不进桶。

**术语表**：

| 术语 | 定义 |
|---|---|
| **块（block）** | 桶中的对象：内建 Table / Sequence / Kv / Blob + 注册（Named）块（§2.1） |
| **桶（bucket）** | `RefId → envelope` 的内容寻址存储（当前纯内存；磁盘形态属管道批次） |
| **信封（envelope）** | 桶中一个块的存储单元：kind 标签 + 版本 + payload |
| **payload** | 块的规范字节，`RefId` 的唯一哈希输入 |
| **叶子（leaf）** | 树上的终止**位置**（树侧概念） |
| **槽（Slot）** | 叶子位置的持有形态：`Inline(Value)` 或 `Ref(RefId)` |
| **内联值（Value）** | 白名单标量值，直接住在树实例里，不进桶 |
| **chunk 组** | Sequence 多重性的同型块叶子集合（chunking 的树表达） |
| **view 节点** | 带组合器语义的树节点，零 payload |
| **持久化标记** | 树实例注记：默认持久，ephemeral 前缀标记不落盘子树 |

> **术语铁律**：「叶子」（树上的位置）与「块」（桶里的对象）是两个概念，行文与命名必须区分。`BlockKind::Sequence`（块种类）与 `Multiplicity::Sequence`（树多重性）同名不同物，按命名空间区分。树级 Map 的键是 xpath `Key` 步（`String`，v5 既定约束）；KV **块**的键是类型化 `Value`——两者是数据级/结构级的不同机制，禁止混谈。

## 2. 数据块规范（桶侧）

> 本节为 AB 批次定稿后的现行版本：内建块 payload 全 Arrow + 开放注册制。原 TB 批次的手写 tag 线格式已被取代（历史原文见 [`04-施工日志.md`](04-施工日志.md) 各批次日志与 git 历史）。

### 2.1 块集合：内建四元 + 开放注册

内建四块（payload 全 Arrow，§2.4）：

| 块 | 内容 | 自描述级别 | 备注 |
|---|---|---|---|
| `Table` | 一个 Arrow RecordBatch | **完整**（IPC 内嵌 schema） | 复用 v4 canonical IPC 编码，主实现 |
| `Sequence` | 同质值的定长序列 | **完整**（单列 IPC schema；typed 或 DenseUnion） | 元素类型期望值由树上下文提供 |
| `Kv` | 键值对容器 | **完整**（双列 IPC schema） | 键/值类型期望值由树上下文提供 |
| `Blob` | 任意字节 | **完整**（单行单列 Binary） | 解析规则全在树（内容类型标注归树 schema） |

注册块：`BlockKind::Named(name)`，稳定注册名（§2.7 适配器契约）。

```rust
pub enum BlockKind {
    Table, Sequence, Kv, Blob,          // 内建四元（全 Arrow）
    Named(Arc<str>),                    // 注册块：稳定注册名（实现为 Arc<str>，去 Copy）
}
```

**注册名规则（MUST）**：

- 合法 UTF-8，非空，≤ 64 字节，无 ASCII 控制字节，不含 `/` `%` 与保留字；
- **禁止**以 `tb-block-` 开头（域名由框架拼 `tb-block-{name}`，用户不得自带前缀）；
- 建议用命名空间风格（如 `org.example.foo`）降低碰撞。

**同名同编码契约（MUST，注册者责任）**：同一注册名在任何进程、任何时间必须对应同一 canonical payload 编码；违反即内容寻址失效（同名不同字节 → 虚假去重/校验失败）。此契约与身份域世代隔离（§2.2）共同保证跨进程一致性。

**显式排除清单（不因开放注册复活）**：

- **Scalar 不是块**：单值走内联槽（§2.5），根本不进桶——「桶里只有容器级以上的东西」。
- **Struct 不是块**：异构命名字段集 = 树节点（`#[derive(TreeNode)]` 本来就是它）。
- **Array → Sequence**：更名并升级值编码（§2.4）。
- **Ref 不是块**：引用只在树上（铁律 5）。

内建名 `table` / `sequence` / `kv` / `blob` **保留不可注册、不可覆盖**（对齐 `CombinatorRegistry` 封闭核先例，注册时报 `TypeConflict`）。

### 2.2 块身份公式（RefId）

沿用 `hash::canonical_digest`（tag 与各 part 均带 u64 长度前缀的 xxh3-128）。身份域通式：

```text
RefId(内建 Table)       = canonical_digest(b"tb-block-table",    [ipc_bytes])
RefId(Sequence/Kv/Blob) = canonical_digest(b"tb-block-sequence" | b"tb-block-kv" | b"tb-block-blob", [payload])
RefId(注册块 NAME)      = canonical_digest(b"tb-block-" + NAME,  [payload])
```

性质（MUST）：

- **kind（含注册名）参与身份**：同 payload 不同 kind / 不同注册名必得不同 `RefId`（跨 kind、跨名不去重）。name 经身份域参与 digest，且通过 envelope 帧的 name（§2.3）可重建 kind 以便弱解码。
- **身份域世代隔离**：`tb-block-*` 与 v5 的 `leaf-*` 前缀不同，跨世代不去重。
- **编码版本与身份**：内容寻址的对象是字节不是语义。payload 编码演进 → 字节变 → `RefId` 变。这是内容寻址的正确行为，不是缺陷。
- **哈希输入仅为 domain + payload**：envelope 帧字节与 name 字段不参与哈希（name 已在 domain 中体现）。

### 2.3 块信封（envelope）

桶中一个块的存储单元：

```text
v1（kind 1–4，内建块，兼容不变）:
  envelope = [kind:u8][envelope_version:u16 LE = 1][payload_len:u64 LE][payload]

v2（kind = 5，注册块）:
  envelope = [kind:u8 = 5][name_len:u8][name_utf8][envelope_version:u16 LE = 2][payload_len:u64 LE][payload]

kind: 1=table  2=sequence  3=kv  4=blob  5=named
```

- `payload` 是身份唯一依据（§2.2）；`kind`、`name` 与 `envelope_version` 是**桶内存储框架**，不参与哈希。name 是桶存储框架的一部分（用于重建 kind 查注册表），不是额外身份输入。
- `envelope_version` 管框架演进；payload 自身格式版本：内建块由 Arrow IPC 自带版本表达，注册块由适配器自定。
- **信封演化前向契约（MUST）**：任何 `envelope_version` 升级必须保证旧 payload 字节在新旧版本下解码结果一致（追加式演进，如新增 kind 标签值）。v2 的 tag 5 即首次兑现：kind 1–4 的 v1 帧字节不变；v1 解码器读到 tag 5 报「未知 kind」（旧系统对新块的合理降级，不破坏旧数据）。

### 2.4 canonical 编码（内建块 payload 全 Arrow）

**规范字节 = the canonical IPC 编码**，走既有 `encode_batch` + `canonicalize_null_slots`（null 槽数据缓冲清零）管道；**IPC 的 schema/footer 等框架字节为 payload 的一部分**，是身份输入（与 v4 Table 一致）。

#### 2.4.1 Value ↔ Arrow 映射与类型序

运行时 `Value` 枚举**不变**（白名单 22 型语义保留，原 tag 序 `0x00`–`0x15` 保留为 union type_id 序）；线格式从手写 tag 字节改为 Arrow。内建 union 的 child 类型顺序**固定为 type_id = 原 tag 序**：

| type_id | Value | Arrow 类型（同构路径） | canonical 值字节 |
|---|---|---|---|
| 0 | Null | `DataType::Null`（仅 union child） | 无 |
| 1 | Bool | `Boolean` | 1 字节 `0`/`1` |
| 2–5 | I8–I64 | `Int8..Int64` | 定宽小端补码 |
| 6–9 | U8–U64 | `UInt8..UInt64` | 定宽小端 |
| 10/11 | F32/F64 | `Float32/Float64`（**位模式保持**，NaN 不做隐藏规范化） | IEEE 754 位模式小端 |
| 12 | Utf8 | `Utf8` | UTF-8 字节 |
| 13 | Binary | `Binary` | 原始字节 |
| 14/15 | Date32/Date64 | `Date32/Date64` | 小端 |
| 16 | Time32 | `Time32(unit)` | 小端 |
| 17 | Time64 | `Time64(unit)` | 小端 |
| 18 | Timestamp | `Timestamp(unit, tz)` | 小端 |
| 19 | Duration | `Duration(unit)` | 小端 |
| 20 | Decimal128 | `Decimal128(p,s)` | 16B 小端补码 |
| 21 | Decimal256 | `Decimal256(p,s)` | 32B 小端补码 |

**Value 白名单显式排除（v1）**：Float16、Interval 三态、Dictionary、LargeUtf8/LargeBinary（单值层面无语义增量）、嵌套值（Struct/List——嵌套属于树或表，铁律 3）。扩展 = 新 type_id + payload 格式版本升级，追加式。

**同构优先（MUST）**：Sequence/Kv 的块内容若全部元素能归入**同一个具体 Arrow 类型**（含参数化：`Time32(ms)`、`Timestamp(ns, "UTC")`、`Decimal128(10,-2)` 等数组级参数），则该块 = 对应 **typed 单列（Sequence）或双列（Kv）RecordBatch**——这是默认与首选路径（polars 直通、零拷贝、共享红利）。

**异构兜底（允许，降级）**：元素大 kind 或参数化参数不一致时，该列 = **DenseUnion（22 child，type_id 序固定）**。参数化类型（Time32/Time64/Timestamp/Duration/Decimal128/Decimal256）在**异构 union 上下文**中的 child 一律降级为「参数袋」：`FixedSizeBinary(len)`，字节布局 = 原 encode 除 tag 外（unit/tz/p/s + 定宽值）——**保留值级自描述，牺牲 Arrow typed（不含 polars typed 直通承诺）**。Big kind 一致的参数化异构（同 Timestamp 两种 tz）一并走参数袋 child；纯同参归一应尽量走同构路径。

**编码性质（MUST）**：

- **按位编码**：F32/F64 的 NaN payload 不做隐藏规范化（与 v4 IPC 行为一致）；相等性与去重以位为准。
- **`Value: Ord` 是规范化序，不是数值/语义序**——禁止用于范围查询语义，文档与命名必须言明（Kv 规范序见 §2.4.3）。

#### 2.4.2 Sequence payload

规范形 = 单列 RecordBatch（`Schema{ col: T }`，T 见 §2.4.1，含参数化与 union 兜底），行数 = 元素数。`Value::Null` 元素在 typed 路径 = 该列合法 null 槽；union 路径 = type_id 0。

- 逻辑顺序即内容：顺序是 payload 的一部分（与 Kv 不同）。
- 长度是内容的一部分（改长度即改 `RefId`；与树多重性的动态长度对照——那是拓扑，这是数据）。
- 解码负向：截断、错误 schema → 报错。

#### 2.4.3 Kv payload 与键规范序

规范形 = 双列 RecordBatch（`Schema{ key: Tk, value: Tv }`，依 §2.4.1）。

- **canonical 键序（MUST）**：entry 按 key 的「逻辑规范序」升序排列——comparator 定义见下。同一映射无论何种构造序，payload 必须字节相同（去重稳定性）。
- **重复键拒绝**：构造时报错。
- **Null 键拒绝**（typed 路径 = null 槽的键行拒绝；union 路径 = type_id 0 的键行拒绝）；**Null 值允许**。

**键规范序 comparator（规范序，非语义序——禁止用于范围查询语义）**。比较逐 `(type_id 升序, 规范值字节升序)`：

- type_id（= 原 tag 序）优先；
- 同 type_id 内：
  - 整型：小端补码字节序（位模式序——负数排在正数之后，规范行为，非 bug）；
  - 无符号：小端字节序；
  - F32/F64：位模式小端；
  - Utf8 / Binary：**内容字典序**（长度是 IPC 句法，不是逻辑键序；「内容先于长度」）；
  - Date32/64、Duration、Time32/64、Timestamp：unit 参数序 → 小端值；
  - Decimal128/256：precision → scale → 值字节。

> Utf8/Binary 键的内容字典序是 AB 批次对 TB 原长度前缀序的修订（长度是 IPC 句法，不是逻辑键序）；该行为变更已随 AB 批次进 golden 重冻结。

#### 2.4.4 Table payload

v4 canonical Arrow IPC（`encode_batch` + `canonicalize_null_slots`，null 槽数据缓冲清零），**编码冻结不动**。身份域前缀 `tb-block-table`（§2.2），payload 字节不变。

#### 2.4.5 Blob payload

规范形 = 单行单列 `Binary` RecordBatch。**已决策（含体积代价记录）**：每 blob 增加一份 IPC schema/footer 元数据（约 200–400 字节）；空 blob 由 0 字节变为约 300 字节。代价经讨论接受，理由：envelope 之后只有一种 payload 语义，工具链零特判；10KB+ blob 开销 <5%，真实成本（文件碎片）由树模型 chunk 化与 ParquetDir 既有语义覆盖，非新增。

### 2.5 内联槽（Slot）

```rust
pub enum Slot {
    Inline(Value),   // 白名单标量，直接住在树实例里
    Ref(RefId),      // 块引用：树实例只持 16 字节身份
}
```

- **固定策略（v1）**：标量叶子一律 `Inline`，块叶子一律 `Ref`。v5 的「策略可覆盖」收窄为固定策略；显式覆盖留给管道批次（按需复活，先记录）。
- 内联值不进桶、不占 `RefId`。单个大标量（如长字符串）需要外置时，正确做法是升格为 Sequence 块（1 元素）或 Blob 块。
- `Slot` 非泛型（v5 `LeafSlot<L>` 退场）。

### 2.6 解码：弱解码注册表化与类型化重建

两级解码：

- **弱解码（值级，无需树）**：`read_block(kind, payload) -> Result<Box<dyn Block>>`。kind ∈ 内建四元 → 静态编码器直解（Sequence 解码为值序列、Kv 解码为规范序 entries、Table/Blob 天然自足）；kind = `Named(name)` → **`BlockRegistry`** 查 `name`，未注册报 `TypeNotFound`（负向契约）。静态 LUT + `match kind` 穷尽检查（v5 §10.2 机制原样保留）。
- **类型化解码（树上下文）**：树在叶子位置携带期望类型（Table 的 schema 期望 / Sequence 的元素类型 / Kv 的键值类型 / Blob 的内容类型标注），解码时校验实际值与期望一致，不一致报 `SchemaMismatch`。API 形状由实现定，**必须记录进施工日志**。

注册表形态（进程级静态注册）为 AB 批次实现选定；规范要求（MUST）：**同一进程内同一名字全流程一致**，注册冲突（重名）报 `TypeConflict`。

弱桥导航（`get`）对块叶子以**身份**应答（`AccessOut::Ref`；get 不触桶、不物化，见 §4.2）；物化时的弱解码走 `read_block`。强类型主路直接字段访问（「强/弱」二分不变，§4.2）。

### 2.7 注册适配器契约（RegisteredBlock）

```rust
pub trait RegisteredBlock: Send + Sync {
    const NAME: &'static str;              // 稳定注册名（§2.1 规则）
    fn encode(&self) -> Vec<u8>;           // canonical payload bytes（身份输入）
    fn decode(name: &str, bytes: &[u8]) -> Result<Self>;
    fn capabilities() -> BlockCaps;        // Opaque | Arrow(ArrowCaps)（类型级关联函数）
}
```

- `encode`/`decode` 必须有「同名同编码」的确定性（§2.1 契约）；误配会破坏内容寻址，是注册者的责任。
- `Opaque` 块：仅桶级红利；`Arrow` 块：享受全部 Arrow 级红利（verify L2/L3 canonical、共享、polars），其 `to_batch` 输出必须 deterministic-可重编码（canonical IPC），否则不承诺 verify。
- 注册 = 进程级注册表登记；内建名覆盖拒绝（`TypeConflict`）。
- 强类型主路不引入 `Any`/`as_any`：注册值由 `RegisteredBlock::decode(canonical_payload)` 从桶字节重建，`Block` trait 形状不变（对齐 §4.7 决策 5）。

### 2.8 红利边界（矩阵，规范）

| 能力 | 内建块 | 注册 Arrow 块 | 注册 Opaque 块 |
|---|---|---|---|
| 进桶 / 身份 / 去重 / GC | 自动 | 自动 | 自动（桶不解释字节） |
| 树引用 / 弱解码 | 自动 | 自动 | 自动（经适配器） |
| L1 verify（身份复算） | 自动 | 自动 | 自动 |
| L2/L3 verify（内容级） | 自动 | 自动 | ✗（或适配器自证 canonical） |
| sync 收敛 | 自动 | 自动 | 契约转嫁（编码确定性由适配器自负） |
| 零拷贝共享 / polars | 自动 | 自动 | ✗ 手动 |

## 3. 树语义（解释侧）

### 3.1 块 vs 树：双层判定表

同质值既能放块（bulk），也能放树（结构化）。判定准则：

| 需求 | 用块 | 用树 |
|---|---|---|
| 同质值批量、整体读写、内容寻址去重 | `Sequence` / `Kv` 块 | |
| 元素需要独立 xpath 寻址、结构性身份、单独增删 | | `Vec<Value>` / `BTreeMap<K, Value>` 树多重性 |
| 异构命名字段 | | 树节点（`#[derive(TreeNode)]`） |
| 表数据 | `Table` 块 | |
| 大块分片、追加写、按元数据剪枝 | chunk 组（§3.2） | |
| 运行时组合（concat/join/投影展开） | view 节点（§3.3） | |
| 任意字节（解析规则后置） | `Blob` 块 | |

**模板字段类型语法**（derive 接受的语法，语义如下）：

| 字段类型 | 语义 |
|---|---|
| `Value` | Single 标量叶子（内联） |
| `Table` / `Sequence` / `Kv` / `Blob` | Single 块叶子（外置引用） |
| `Option<T>` | Optional 多重性 |
| `Vec<T>`（T = 节点或 `Value`） | Sequence 多重性（结构） |
| `Vec<T>`（T = 块类型） | **chunk 组**（§3.2 的类型化形态） |
| `BTreeMap<K, T>` | Map 多重性（K：`String` / `[u8;16]`，v5 既定约束不变） |

字段在 Rust 中的运行时表示（直接持有块值 vs 持有 `Slot`）是**实现自由度**；对外可观察语义（`get` / `leaf_refs` / 身份 / GC 可达性）必须符合本模型，选择记录进施工日志。

### 3.2 chunking 即树结构

**立场（MUST）**：块本身不可分片。chunking 是树对一组同型块的**组织方式**：

- **chunk 组** = Sequence 多重性的同型块叶子集合（类型化形态 `Vec<Table>`；动态形态 `DynamicNode` 的 `Chunks` 字段，§3.4）。
- **同型约束**：组内所有 chunk 必须同 `BlockKind`；`Table` chunk 另要求 schema 相同（v1 口径：列名+类型+顺序一致）。
- **per-chunk stats**：每个 chunk 条目可携带注记 `ChunkStats`（`BTreeMap<String, Value>`，键名由调用方定义）。**stats 是派生数据**：不参与 `RefId`、可缺失、可重算；其价值是**不打开块即可剪枝**。提供 `ChunkGroup::select(pred: impl Fn(&ChunkStats) -> bool) -> Vec<RefId>`。
- **扇出嵌套**：大扇出时 chunk 组可嵌套（组节点包含子组），树无限递归白送的能力；v1 建议每组扇出上限 64–256（实现选定具体值并记录）。
- **追加语义**：追加一个 chunk = 树进入新状态，引用全部旧 chunk `RefId` + 新 chunk；**旧块字节零重写**（不可变块天然成立，但必须以测试断言固化：追加前后旧 `RefId` 集合与桶内对应字节不变）。
- chunk 的 xpath 定位：`/runs[0]/chunks[3]`。

**与 view 的关系**：chunk 组就是 `Concat` view 的特例（§3.3）——「chunked 表」逻辑上等价于「对这些 chunk 做 concat」。两个机制刻意同构。

### 3.3 view：带组合器语义的树节点

**立场（MUST）**：view 是**树节点**，不是叶子/块。view 节点 = 组合器 + 有序输入（输入为块 `RefId` 或嵌套 view 节点），自身零 payload、不占桶。理由（讨论定稿）：view 的内容是「引用 + 组合规则」= 结构身份，属于树；若进桶则引用进 blob，破坏铁律 5 与 GC 可达性，且与 chunking 特例自相矛盾。

```rust
pub enum Combinator {
    Concat,
    Join { keys: Vec<String>, mode: JoinMode },   // JoinMode: Inner | Left
    Select { columns: Vec<String>, rows: Option<(usize, usize)> },  // (offset, len)
    Registered(String),                            // 注册扩展名
}
```

**封闭核（内核实现，语义 golden 冻结）**：

| 组合器 | 输入约束 | 语义 |
|---|---|---|
| `Concat` | N ≥ 1，全部同 `BlockKind`（封闭核不含 Named 块） | `Table`：schema 相同 → 行拼接；`Sequence`：元素按输入序拼接；`Kv`：合并（重复键报错）；`Blob`：字节拼接 |
| `Join` | 恰 2 个 `Table` | 键列名须存在于两侧；结果列 = 左全部列 + 右非键列（v1 顺序规则固定）；`Inner` / `Left` 两模式 |
| `Select` | 恰 1 个 `Table` | 列投影（按给定顺序，列必须存在）+ 行区间切片（越界报错，不静默 clamp） |

- **解析（resolve）**：`resolve(view, bucket) -> Result<Box<dyn Block>>`，在消费边缘物化。实现基于 arrow compute 内核（无新依赖）。
- **等价性要求（MUST）**：view resolve 结果必须与手工组合（逐块物化后手工拼）语义相等——以等价性测试关闭。
- **注册扩展**：`CombinatorRegistry`（名字 → 类型擦除 resolve 函数），对齐 `transform.rs` `FunctionRegistry` 先例。封闭核名字**不可覆盖**（注册时报错）；注册扩展接受变参 arity（≥ 1）。
- **物化缓存**：resolve 结果可 `put` 进桶得 `RefId`；view 节点旁注记「materialized: RefId」。注记是缓存提示，不是内容：失效 = 删注记；内容寻址自动去重（同组合结果 = 同 `RefId`）。
- **计算性操作禁入（MUST）**：谓词过滤、聚合、表达式求值不进内核组合器——那是下游运行时（polars 擅长）的事。`Select` 的行选取是**区间**（结构性），不是谓词。

### 3.4 内建动态树节点（DynamicNode）

v5 树是编译期定形的；运行时任意构造的 view/chunk 组/无模板数据区需要宿主：

```rust
/// 内建动态树节点：运行时构造的任意树区域。
/// 手写 impl TreeNode（非 derive）；Map 多重性承载命名子字段。
pub struct DynamicNode {
    fields: BTreeMap<String, DynamicField>,
}

pub enum DynamicField {
    Node(DynamicNode),      // 命名子节点
    Slot(Slot),             // 内联值或块引用
    Chunks(ChunkGroup),     // chunk 组（§3.2）
    View(ViewNode),         // view 节点（§3.3）
}
```

- xpath 导航：`Field` 步进 `fields`，`Index` 步进 `Chunks` 位置，`Key` 步进按键寻址。
- 临时 view = `DynamicNode` 的 ephemeral 实例（§3.5）；类型化场景（业务明确知道形状）仍走 derive。
- **持久库与临时 view 是同一机制的两种姿态**：都是树实例，共享同一个桶；临时 view 引用主库块不产生复制（同 `RefId` 即同内容）。不需要独立「运行时叠加层」。

### 3.5 持久化标记（注记层）

回答「树上的解释数据也是数据，都要持久化吗」——分层：

- **注记层**：当前仅由内建 `DynamicNode` 承载 `Persistence { ephemeral_prefixes: Vec<XPath> }`。默认**全持久**；`mark_ephemeral(prefix)` 标记子树。类型化（derive）实例的 ephemeral 标注随 IO 管道批次提供。
- **单调性（MUST）**：ephemeral 前缀覆盖下所有子路径皆 ephemeral；子节点标记仅在祖先全持久时有意义。
- **语义（三条，精确措辞）**：
  1. **写盘剪枝**（未来 IO 批次实现）：写入跳过 ephemeral 子树的 payload，commit metadata 记录被剪 xpath（供 verify 与诊断）。
  2. **读取尽力**（未来）：重开时模板物化结构，ephemeral 字段回到默认值；若旧提交中曾有持久化数据（GC 保留窗口内可达）则找得回，找不到**不报错**——「字段在（形状在），数据找不到不是损坏」。
  3. **内存交换忽略标记但注记随行**：共享时不因标记扣留数据（ephemeral 子树的引用照常可共享）；但注记作为元数据随实例传递，否则接收方写盘时会误判全持久。
- **ephemeral ⊥ Optional（MUST）**：`Optional` 是结构基数（字段可缺省），ephemeral 是 IO 策略（数据是否落盘）。`Single` + ephemeral 重开后 = 默认值，不是「缺失」。两者不可互相替代。
- **不进 canonical（MUST，A-2 已兑现）**：树实例规范编码（§5）不含注记层内容；翻转标记不得改变逻辑内容身份（`TreeId` 不变）。
- **GC 双域（MUST）**：内存域 GC 根 = 存活实例的全部 `leaf_refs`（**含 ephemeral 子树**——实例活着，它的引用就活着）；磁盘域 GC（未来）= 持久树可达。两域根集不同，混用即丢数据，实现与测试必须显式区分。
- TB 批次交付：注记 API（mark/query）+ 单调性 + clone 保持 + 「标记不影响 `RefId`/`leaf_refs`」断言 + 内存 GC 根语义测试。写盘/读取行为是前向契约，不在已闭合批次实现。

## 4. 树运行时契约

> 本节由原《树运行时契约》全文吸收（该文档已归档至 [`../V5-树运行时/树运行时契约.md`](../V5-树运行时/树运行时契约.md)）。**树运行时管「树怎么长、怎么导航、怎么索引」；§2/§3 管「叶子上挂什么（块/值）、桶怎么存」。**

### 4.1 三层架构

| 层 | 职责 | 运行时实体 | 承载 |
|---|---|---|---|
| **模板** | 编译期类型，定义合法 xpath + 叶子期望 + 基数 | 无（编译期 DAG） | 结构**形状** |
| **树实例** | 运行时结构 | 有，轻量 | 拓扑（容器长度 / 键集 / Option 有无）+ 叶子槽（`Slot`） |
| **桶** | payload | 有 | 不可变内容寻址块（`RefId → envelope`） |

- 模板 = `#[derive(TreeNode)]` 的 struct 组合；编译期锁死形状，运行时只允许空态与数量变化，**类型不可变**（Rust 类型系统天然保证，无需运行时校验）。
- 树实例不承载块 payload：块叶子在实例中只占 16 字节 `RefId`（`Slot::Ref`）；内联标量值住实例（`Slot::Inline(Value)`）。
- 一个「库」= 一棵树实例 + 一个桶。**持久库与临时 view 是同一机制的两种姿态**：都是树实例，共享同一个桶；临时 view 引用主库块不产生复制（同 `RefId` 即同内容）。

### 4.2 树元素：节点与叶子位置

树上有且仅有两类元素：

- **节点（Node）**：`trait TreeNode`，承载结构与导航；
- **叶子位置（leaf position）**：字段层面的终止点，持有 `Slot`（内联值或块引用）。

> 术语铁律：**叶子位置**（树侧概念）与**块**（桶侧对象）是两个概念（§1）。

#### 4.2.1 TreeNode trait

```rust
/// 静态元数据（含 const，独立于 dyn 友好的导航 trait）。
pub trait TreeNodeMeta: 'static {
    const META: &'static NodeMeta;
}

/// 导航 trait（dyn 友好：无 const / 关联类型 / Self: Sized 方法）。
pub trait TreeNode: 'static {
    fn get(&self, xpath: &XPath) -> Result<AccessOut>;               // strict：不可达报错
    fn get_best_effort(&self, xpath: &XPath) -> (AccessOut, XPath);  // 尽力：到达值 + 未消费剩余步
    fn set(&mut self, xpath: &XPath, v: Slot) -> Result<()>;         // 弱类型写桥
    fn leaf_refs(&self) -> Vec<(XPath, RefId)>;                      // 全部块引用（GC/verify 可达性）
}
```

- `get` 为 strict 导航：不可达步骤报 `ErrorCode::XpathUnreachable`；
- `get_best_effort` 永不失败：返回最深可达值 + 剩余 xpath（实例化 / 去收集阶段的前沿桥，避免丢失未消费地址）；
- `set` 是弱类型写桥：按槽语义写入（`Inline(Value)` 或 `Ref(RefId)`）；节点字段递归、容器按步定位；
- **get 不触桶（MUST）**：导航永不物化块内容——块叶子位置以**身份**（`RefId`）应答，物化是显式的 `Bucket::get`。若实现为类型化块字段保留了内存驻留值，`get` 仍以身份应答（`RefId` 可从驻留值即时计算）。

#### 4.2.2 AccessOut（弱桥返回值）

```rust
pub enum AccessOut {
    Value(Value),               // 内联标量值
    Node(Box<dyn TreeNode>),    // 子节点（含 DynamicNode、view 节点）
    Ref(RefId),                 // 块引用（未物化）
}
```

- 弱桥不携带块 payload——块物化一律显式走桶。这强化「树不存 payload」，并消灭「桥上克隆大块」的隐性路径。
- view 节点实现 `TreeNode`（自身零 payload、无子字段可导航），经 `Node` 变体返回；其输入引用由 `leaf_refs` 覆盖（§4.8）。

#### 4.2.3 强/弱二分（不变）

- **强类型主路**：热路径直接字段访问（`exp.runs[3].x`），零成本、编译期类型；
- **弱类型桥**：xpath 字符串、序列化、反射走 `get`/`set`，只出现在非热路径，不得腐蚀主路。

### 4.3 多重性与键约束

编译期从字段类型自动推断（`#[derive(TreeNode)]` 负责）：

| Rust 字段类型 | Multiplicity | xpath 实例步 | 语义 |
|---|---|---|---|
| `T` | `Single` | `/field` | 恰好 1 个 |
| `Option<T>` | `Optional` | `/field` | 可空 0..1 |
| `Vec<T>` | `Sequence` | `/field[i]` | 顺序容器 |
| `BTreeMap<K, T>` | `Map` | `/field[key]` | 按键容器 |

- 「部分动态」的精确定义：实例化后字段集合与类型固定；可变的只有 `Option` 有无、`Vec` 长度、`BTreeMap` 键集。
- **`BTreeMap` 键约束（MUST）**：`K` ∈ {`String`, `[u8;16]`}（稳定可复算）；derive 静态拒绝任意整数键等引入插入序不稳定风险的写法。
- 块类型的 `Vec<T>` 字段即 chunk 组（§3.2）；在字段注册表中就是 Sequence 多重性 + 块叶子目标。

#### 4.3.1 字段注册表（derive 生成）

```rust
pub struct FieldMeta {
    pub name: &'static str,
    pub multiplicity: Multiplicity,
    pub target: FieldTarget,
}

pub enum FieldTarget {
    Node(&'static NodeMeta),                          // 子节点
    Inline { schema: &'static LeafSchemaMeta },       // 内联 TB 标量（Value）
    Block { kind: BlockKind, schema: &'static LeafSchemaMeta }, // 块叶子（期望 kind；类型化校验契约见 §2.6）
}

pub struct NodeMeta {
    pub type_name: &'static str,
    pub fields: &'static [FieldMeta],
}
```

（v5 的 `Leaf { target: LeafTarget }` 口袋已随 TB 重塑折叠为 `Inline`/`Block` 两个枚举变体；`LeafTarget` 类型保留为兼容导出，不再由 derive 构造。注册块的树字段经 `FieldTarget::Block { kind: Named }` 手工声明，derive 字段语法维持内建四块。）

derive 同时生成 `TreeNodeMeta::META` 与 `get`/`get_best_effort`/`set`/`leaf_refs` 实现；其接受的字段类型语法表由 §3.1 定义。

### 4.4 xpath 寻址

#### 4.4.1 XPath 与 Step

```rust
pub struct XPath { steps: Vec<Step> }

pub enum Step {
    Field(String),   // /field
    Index(usize),    // [i]
    Key(String),     // [key]
}
```

xpath 有两层，必须显式区分：

- **类型路径**（schema 级）：纯 `/field` 步，稳定、可 digest；
- **实例路径**（数据级）：含 `[i]`/`[key]` 步，指向具体实例。

#### 4.4.2 规范字节（与 Display 解耦）

`canonical_xpath_bytes` 用注入编码：`Field → 0x46`、`Index → 0x49`、`Key → 0x4b`，步内容带长度前缀。`Display` 会把 `Index(3)` 与 `Key("3")` 渲染成相同 `[3]`，规范字节保证不同 xpath 永不规范化为相同字节（N-8 决策，golden 冻结）。

### 4.5 索引与双哈希铁律

- `XPathIndex`：`BTreeMap<XPathHash, Vec<(XPath, RefId)>>`；`xpath_hash = canonical_digest(b"xpath", [规范 xpath 字节])`；
- **碰撞降级（保险丝）**：hash 命中后用完整规范 xpath 字节二次比对；128-bit 碰撞概率天文数字，降级仅为严谨性兜底；
- **双哈希铁律（MUST）**：`xpath_hash` 只作索引键（可碰撞，绝不用于物理寻址）；`content_hash`（块身份，`tb-block-*` 域）是全内容哈希，用于 blob 地址/去重——二者绝不互相替代。

### 4.6 domain 标签

- domain = 贴在**模板（类型）**上的性质标签（marker trait），与树结构正交；实例继承；运行时可查面用 `BlockKind`；
- 「叶子必定属于叶子 domain」由块类型约束静态成立；细分 domain 用 marker trait（`TableDomain`/`SpatialDomain` 先例）；
- 编译期约束助手：`assert_leaf`/`assert_tree_node`；
- 待办（未排期）：domain 标签 → 注册表整合（现为编译期约束）。

### 4.7 dyn 兼容技术决策（仍然有效）

`Block`/`TreeNode` 承载于 `Box<dyn …>` 弱桥，而关联常量、关联类型、`Self: Sized` 方法三者都会破坏 dyn 兼容。因此（v5 §14 决策 6，TB 沿用）：

1. `Block::kind()` 方法取代 `const KIND`；
2. 无关联类型；`describe() -> BlockDesc` 直接返回；
3. `read_blob` 移到各具体块的静态方法，经静态 LUT `read_block(kind, bytes)` 分派（`match kind` 穷尽检查，漏分支编译报错）；
4. `TreeNodeMeta` 独立承载 `const META`；`TreeNode` 保持纯 `&self`/`&mut self` 方法；
5. **弱类型桥不引入 `Any`**：类型擦除只做 `content_hash`/`write_payload`/`describe`；需要具体类型走强类型主路。半途出现「运行期才知道类型又要拿具体数据」的硬场景再补 `as_any` 兜底（未发生）。

### 4.8 leaf_refs 与 GC 可达性

- `leaf_refs` 是 GC / verify 的可达性权威：返回子树全部块引用及其绝对 xpath；
- **覆盖范围（MUST，TB 扩展）**：块叶子槽（`Slot::Ref`）、chunk 组条目（含嵌套子组的传递条目）、view 节点输入（含嵌套 view 的传递输入）、物化缓存注记引用（若旁挂）；
- **GC 双域（MUST）**：内存域 GC 根 = 存活实例的全部 `leaf_refs`（**含 ephemeral 子树**——实例活着，它的引用就活着）；磁盘域 GC = 持久树可达（未来 IO 批次）。两域根集不同，混用即丢数据，实现与测试必须显式区分。

## 5. 树对象规范序列化（A-2 批次规范）

> 2026-08-22 讨论定稿。A-2 补齐北极星另一半：树（结构）的序列化形态统一为 canonical Arrow IPC。范围：纯内存编码（编解码 + 身份 + golden + 负向）；IO / 共享 / polars / 树存储封装 / commit 可见性一律不做（§9 纪律 6 延续），归管道工单。

### 5.0 关键推论：树不是块

铁律 5（桶内字节不得内嵌 `RefId`）+ 序列化树必然携带块引用 ⇒ **树对象不能进桶**。树是与桶并列的独立内容寻址对象家族：一个「库」= 树实例 + 桶，各自内容寻址、互不嵌套。三个直接推论：

1. **无信封**：块需要 envelope 是因为 payload 不自描述；树规范字节本身是完整自描述 Arrow IPC（schema 内嵌）。A-2 不定义树信封；存储包装（磁盘帧等）归管道工单。
2. **组合落点**：管道工单的磁盘树对象映射到 v4 ParquetDir 既有 content-addressed commit-tree 机制（tree/commit 对象身份已 golden 冻结），由组合获得，不另起炉灶。
3. **GC 语义不变**：内存域 GC 根 = 存活实例 `leaf_refs`（含 ephemeral）；磁盘域 = 持久树可达——树对象家族天然就是可达性结构。

### 5.1 TreeId 身份公式

```text
TreeId = canonical_digest(b"tb-tree", [ipc_bytes])
```

- **身份即字节**（铁律 4 同源）：拓扑、内联值、块引用任一变化 ⇒ `TreeId` 变。
- **注记不参与**：persistence 前缀、view 物化缓存注记、ChunkStats 的增删不改 `TreeId`（§3.5 契约、§3.3「缓存提示不是内容」、§3.2「stats 是派生数据」）。
- **域隔离**：`tb-tree` ⊥ `tb-block-*` ⊥ v5 `leaf-*` ⊥ v4 各域，互不去重。
- 实现自由度：`TreeId` 建议为独立 newtype（与 `RefId` 同 16 字节形状，防混用），选择记录进施工日志。

### 5.2 规范式：平面条目表（flat entry table）

规范字节 = 单 RecordBatch 的 canonical IPC（复用 §2.4 管道：`encode_batch` + `canonicalize_null_slots`）。**一行一个条目，行序 = 先序遍历序**（父行必先于子行）。核心不变量：**parent < self（按行号）**；根行 parent = u64::MAX 哨兵、kind = Node。

列集（规范冻结；schema 即格式版本——任何列集变更 = 字节变 = `TreeId` 变，必须先修订本节并重冻结 golden）：

| 列 | Arrow 类型 | 语义 |
|---|---|---|
| `parent` | UInt64 | 父条目行号；根行 = u64::MAX |
| `name` | Utf8（nullable） | 命名定位：字段名 / String Map 键 / ViewParam 参数名 |
| `key16` | FixedSizeBinary(16)（nullable） | `[u8;16]` Map 键（与 `name` 互斥） |
| `kind` | UInt8 | 条目种类 tag（下表 1–7） |
| `value` | DenseUnion（22 child，§2.4.1 映射 + 参数袋） | Inline 值 / ViewParam 标量值 |
| `ref` | FixedSizeBinary(16)（nullable） | 块引用（Ref 槽 / ChunkEntry / view 输入引用） |
| `block_kind` | Utf8（nullable） | ChunkGroup 行的统一块种类（`BlockKind::as_str()`；Named 用注册名；嵌套组重复携带，解码校验一致） |
| `combinator` | Utf8（nullable） | View 行：封闭核名（`concat`/`join`/`select`）或注册组合器名 |

条目种类：

| tag | 条目 | 携带 | 子条目 |
|---|---|---|---|
| 1 | Node（结构节点 / Vec、Map 容器；typed 与 dynamic 同形） | name | 子条目（命名或位置定位，见下） |
| 2 | Inline（内联槽） | name + value | — |
| 3 | Ref（块引用槽 / view 输入引用） | name（槽）/ null（输入）+ ref | — |
| 4 | ChunkGroup | name + block_kind | ChunkEntry、嵌套 ChunkGroup（位置定位，保序） |
| 5 | ChunkEntry | ref（stats 不进 canonical） | — |
| 6 | View | name + combinator | 输入（Ref / 嵌套 View，位置定位）+ ViewParam（命名定位） |
| 7 | ViewParam | name + value | — |

**子条目定位规则（MUST）**：命名定位（`name` / `key16`，按字节字典序）或位置定位（`name` = `key16` = null，按行序 = 语义序）。**Node 行的子条目不得混用两种定位**（struct 字段 / Map 键 = 命名；Vec 元素 = 位置）；View 行例外——输入（位置）与 ViewParam（命名）经 kind tag 天然区分。同一父行内同类定位的兄弟序：命名集字节字典序严格递增（重复报错），位置集保序。

**多重性映射（结构即形状，无额外编码）**：

| 模板形态 | 条目表达 |
|---|---|
| 节点类型字段（`T`） | Node 行（命名子条目 = 其字段） |
| `Value` 字段 | Inline 行 |
| 块类型字段 | Ref 行 |
| `Option<T>` | 0 或 1 行（缺省 = 无行，不是 null 行） |
| `Vec<T>`（元素 = 节点或 `Value`） | Node 容器行（位置子条目，行序 = 语义序） |
| `BTreeMap<K, T>` | Node 容器行（命名子条目，键序） |
| `Vec<块类型>`（chunk 组类型化形态） | ChunkGroup 行 |

**ViewParam 编码细则**：

- `Join`：每键一行（name=`key`，value=Utf8，保序）+ mode 一行（name=`mode`，value=`"inner"`/`"left"`）；
- `Select`：每列一行（name=`column`，Utf8，保序）+ rows 两行（name=`rows_offset`/`rows_len`，value=UInt64）；rows=None 省略；
- `Concat`：无参数；
- `Registered`：参数经 ViewParam 通用行承载（标量 name/value）；参数语义契约归注册方，解码只验标量形状；
- 封闭核参数名集合封闭（`key`/`mode`/`column`/`rows_offset`/`rows_len`）：封闭核 View 上的未知参数名 → 解码报错；Registered View 的参数名不校验。
- **ViewParam 行序（A2-1 澄清，2026-08-22）**：View 行的参数（kind=7）是**有序参数序列**——`key`/`column` 可多次出现且按语义序保序，`mode`/`rows_offset`/`rows_len` 至多一次。ViewParam 命名集**不适用** §5.2「命名集字节字典序严格递增」的 Node 子条目规则（View 行例外，与输入/参数混用例外同源）。

### 5.3 规范化规则（确定性，MUST）

1. **行序 = 先序遍历**；兄弟序：位置集按语义序，命名集按字节字典序。
2. **字段序 = 字典序**：类型化节点编码时按字段名排序（与 `DynamicNode` 的 BTreeMap 一致）⇒ 同构同内容（typed 或 dynamic 任一构造）必同字节同 `TreeId`；derive 声明顺序不影响身份。
3. **Rust 类型名不进 canonical**：同构同内容 ⇒ 同 `TreeId`；跨类型误装由类型化投影的结构校验拒绝（§5.4）。
4. **注记不进 canonical**：persistence / 物化缓存 / ChunkStats（加载后 stats 为空，消费方按需重算；roundtrip 等价性按逻辑内容断言）。
5. Inline / ViewParam 值复用 §2.4.1 DenseUnion + 参数袋映射（NaN 位模式保持；树表是结构表，无同构 typed 路径）。
6. null 槽数据缓冲清零。
7. **列占用相容（解码校验）**：Inline 行 value 非 null 且 ref/combinator/block_kind 为 null；Ref 行 ref 非 null；ChunkGroup 行 block_kind 非 null；View 行 combinator 非 null；name/key16 互斥（不得同时非空）——违者报错。**物理约束（A2-1 落定，2026-08-22 验收回填）**：Arrow IPC V5+ 的 DenseUnion 无 validity bitmap，「value 非 null」不可物理表达——非值行的 value 槽由编码器占 type_id 0（Null child），随既有 null 槽清零管道；「Inline 行携带值」由 kind tag 语义保证，解码侧不做物理 null 检查。

### 5.4 两级解码与编码（与 §2.6 对称）

弱解码的枢纽是 codec 专属的**通用意象 TreeImage**（节点 + 有序子条目列表，定位 = 名字 / 键16 / 位置）——它是全模型完备形；`DynamicNode` 只有命名字段、无位置容器，是通用意象的**动态形状子集**，不能直接充当弱解码目标（typed 树的 `Vec`/`BTreeMap` 字段超出其表达力）。

- **弱解码**：`decode(bytes) -> TreeImage`——任意树字节读为通用意象，零信息丢失。
- **类型化投影**：`project(image, bucket) -> T`——按模板严格校验（字段集 / 多重性 / 期望块种类 / 定位一致性），不符报 `SchemaMismatch`；**块字段经桶显式物化**（`read_block` + 期望 kind 校验——物化是显式的，§4.2.1 原则）；模板无对应目标的条目（如 typed 投影中遇到 View）按结构不符报错；同构异类型由结构校验拒绝。
- **动态化转换**：`TreeImage ↔ DynamicNode` 互转（仅动态形状子集；含 Vec/Map 的 typed 树只投影回 T 或停留在意象层）。
- **编码**：类型化实例 / `DynamicNode` / `TreeImage` → canonical 字节（typed 直走或经意象中转，选择记录进施工日志）；**编码方向无需桶**——`RefId` 从驻留块值直接计算（`Block::ref_id`），块进桶是调用方的独立动作。
- **注册名语义与 AB-2 对齐**：Registered 组合器名 / Named 块名在 canonical 中是结构（解码成功）；resolve 时查注册表，未注册报错。

> （2026-08-22 交底前澄清：投影签名含桶、编码无需桶——类型化实例的块字段持有驻留值，物化必须经桶；此前未言明，属规范空白补全，非偏离。）

**解码负向（必测）**：IPC 截断 / magic 缺失、schema 不符、parent ≥ self（非哨兵）、哨兵行非根、悬挂父、根行 kind ≠ Node、Node 子条目混用定位、命名兄弟序非严格递增（重复/乱序）、name 与 key16 同时非空、ChunkGroup 缺 block_kind 或嵌套组 kind 不一致、封闭核 View 参数名未知或输入数不符（Join ≠ 2、Select ≠ 1、Concat 带参）、value union type_id 越界、ref 列长度错、`Optional` 多于一子条目。

### 5.5 golden 义务（并入 §7 清单 11–15）

11. 空树（单根行）`TreeId` + 列 schema golden；
12. 内联标量树（覆盖多 Value 型含参数袋）`TreeId`；
13. 块引用树 + chunk 组树（嵌套组、保序、stats 缺省）`TreeId`；
14. view 树（Join/Select/Registered + ViewParam + 嵌套 view）`TreeId`；
15. typed/dynamic 同构造同 `TreeId` + 字段声明序无关 + 编码→弱解码→重编码字节相同（canonical 闭环）。

模块落位建议：`src/tree/codec.rs`（偏离记录进施工日志）。

## 7. golden 冻结清单（现行）

golden 以 `assert_eq!` 常量断言冻结于测试；现行清单（AB 批次定稿）：

1. 四空块 `RefId`（空 Table / 0 元素 Sequence / 0 条目 Kv / 0 字节 Blob，AB-1 重冻结）；
2. Value ↔ Arrow 编码 golden：22 型各至少一例（异构 DenseUnion/参数袋 roundtrip，AB-1）；
3. Kv 规范序 golden：同一映射乱序构造两次 → payload 字节相同 → `RefId` 相同（新 comparator，AB-1 重冻结）；
4. Sequence 含 Null 元素样本 golden；
5. 信封帧字节 golden：内建块 v1 帧 + 注册块 v2 帧各一例；
6. 跨 kind 不去重负向：同 payload 不同 kind → 不同 `RefId`；
7. view 组合器确定性 golden：`Concat`/`Join`/`Select` 样本 resolve 结果块的 `RefId`；

## 8. 跨批次既定决策（现行有效）

1. **MSRV 1.89 + std 原生文件锁**：不引入 `fs4`；`rust-189` Pixi 环境是 MSRV 门事实来源。
2. **digest 规范公式**：`canonical_digest`（域前缀 + u64 长度分隔）+ golden 冻结；空 domain = `canonical_digest(b"domain", [])`（零子部分常数，非独立字面量）。
3. **ParquetDir = content-addressed commit-tree**：不可变 blob + tree/commit 修改树 + `committed` 唯一可见性点；GC = 可达性压缩；**双哈希铁律**（存储地址用独立全内容哈希，绝不用语义 `table_digest`）。
4. **`Name` 全 UTF-8**（路径段/表名/domain/child 名）：仅拒 `/`、`%`、ASCII 控制字节、空段、>64 字节与保留名。
5. **身份域世代隔离**：v5 `leaf-*` 与 TB `tb-block-*` 前缀互不碰撞，跨世代不去重。
6. **dyn 兼容三调整**（§4.7）：`kind()` 方法、无关联类型、静态 LUT 反序列化。
7. **树对象独立家族**（§5）：树不是块（铁律 5 推论）；`tb-tree` 身份域、无信封；注记与 Rust 类型名不进 canonical；canonical 字段序 = 字典序。

## 9. 纪律

1. **先文档后实现**：任何偏离本文件的实现决策，先更新本文件对应小节 + `03-开发状态.md` 记录原因，再动代码（施工中发现的偏离按 [`02-施工路线图.md`](02-施工路线图.md) §7.3 处理）。
2. **golden 覆盖**：块身份、值编码、规范序、信封、组合器确定性、注册块契约、树对象序列化（§7 清单）。
3. **领域无关**：两 crate 源码禁止 `mz`/`rt`/质谱字面量；测试数据用领域无关样例。
4. **依赖纪律**：零新增第三方依赖；arrow compute 是既有 feature 的既有用法。
5. **v4 隔离**：v4 路径零改动（§6.1）；`DESIGN_VERSION` 不动。
6. **不做管道**：IO/共享/序列化落盘/polars 桥不在编码批次（TB/AB/A-2），即使「顺手」也不做——范围蔓延会推迟验收（管道已拆分为独立工单）。
7. **Arrow 版本的确定性纪律**：任何 canonical IPC 细化规则（union child 顺序、参数袋布局、null 规范、树表列集）必须进施工日志并配 golden。
