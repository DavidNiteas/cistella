## 5. A-2 批次（树对象 Arrow 化，已立项 2026-08-22）

**目标**：北极星另一半——树对象的序列化形态统一为 canonical Arrow IPC。规范见 [`01-目标与设计.md`](01-目标与设计.md) §5，定稿要点：**树不是块**（铁律 5 推论：独立 `tb-tree` 对象家族、无信封）；平面条目表（行序 = 先序遍历、parent < self 不变量）；字段序 = 字典序；Rust 类型名与注记（persistence / 物化缓存 / ChunkStats）不进 canonical；弱解码枢纽 = TreeImage 通用意象（`DynamicNode` 仅是其动态形状子集）+ 类型化投影（与 §2.6 两级解码对称）。

## 7. 施工协议（给实现者 Luna）

### 7.1 工作方式

1. 开工前通读：[`01-目标与设计.md`](01-目标与设计.md) 全文、[`03-开发状态.md`](03-开发状态.md)、相关归档（[`../V5-树运行时/`](../V5-树运行时/) 背景历史）与 `src/` 现状。
2. 按里程碑顺序施工（可并行项见各批次依赖说明）。每个里程碑：实现 → 自测 → §2 验收命令全绿 → 在 [`04-施工日志.md`](04-施工日志.md) 追加施工日志 → 进入下一里程碑。
3. **不自行宣布里程碑关闭**：日志只陈述「已完成 + 证据」，关闭由验收方裁定（在日志处批注）。

### 7.2 实现反馈要求（施工日志）

每个里程碑完成时，在 [`04-施工日志.md`](04-施工日志.md) 按模板追加一节。这是验收方理解你工作的主要渠道，宁详勿略：

```markdown
### <批次>-<N> 施工日志（日期）
- **实际落位**：模块/文件清单（与推荐布局的差异）。
- **关键实现决策**：每个与规范推荐形状不同的选择 + 理由（含留给实现的自由度选择）。
- **测试证据**：验收命令原文 + 输出摘要（通过数）。
- **golden 值**：本里程碑冻结的全部 golden 数值（验收方将核对）。
- **遇到的问题**：设计歧义点、负向测试暴露的编码缺陷、性能观察。
- **偏离申请**（如有）：已实施但尚未回写规范的偏离，等待验收方裁定。
```

### 7.3 偏离处理协议

- **能停就停**：发现规范缺陷/歧义 → 先编辑 [`01-目标与设计.md`](01-目标与设计.md) 对应小节（附理由与日期）→ 日志注明 → 再实现。这是首选。
- **来不及**：先在日志记「偏离申请」（含理由与影响面），继续施工；验收方裁定后回写或要求返工。
- **禁止静默偏离**：验收时发现未声明的偏离按返工处理。

### 7.4 硬性禁止

- 不碰 v4 路径（[`01-目标与设计.md`](01-目标与设计.md) §6.1 列表；编译传导适配除外且需在日志说明）；
- 不新增第三方依赖（含 dev-dependencies）；
- 不改 `DESIGN_VERSION`、不动 v4 golden；
- 编码批次不实现 IO/共享/序列化/polars（即使看起来「顺手」）；
- 不提交 `target/`、缓存、临时环境等副产物；
- 测试不设 timeout 中断，跑完看汇总。

### 7.5 代码风格

- `cargo fmt` 干净、workspace 零 warning（含 `--all-targets`）；
- 源码 doc 注释沿用现有英文惯例；测试函数命名沿用 `<批次><N>_<主题>_<断言>` 风格；
- 遵守仓库 AGENTS.md：不创建临时虚拟环境，一切经 pixi 环境执行。
