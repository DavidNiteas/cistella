## 7. 施工协议（给实现者）

### 7.1 工作方式

1. 开工前通读：[`01-目标与设计.md`](01-目标与设计.md) 全文、归档工单 [`../archive/树与桶模型改造/01-目标与设计.md`](../archive/树与桶模型改造/01-目标与设计.md)（规范基线）、[`../archive/V4-磁盘协议/设计与路线图-v4.md`](../archive/V4-磁盘协议/设计与路线图-v4.md)（v4 协议）、[`03-开发状态.md`](03-开发状态.md)、`src/`（尤其 `layout/`、`txn.rs`、`codec.rs`）现状。
2. 按里程碑顺序施工。每个里程碑：实现 → 自测 → §2 验收命令全绿 → 在 [`04-施工日志.md`](04-施工日志.md) 追加施工日志 → 进入下一个。
3. **不自行宣布里程碑关闭**：日志只陈述「已完成 + 证据」，关闭由验收方裁定。

### 7.2 实现反馈要求（施工日志）

每个里程碑完成时，在 [`04-施工日志.md`](04-施工日志.md) 按模板追加一节（实际落位 / 关键实现决策 / 测试证据 / golden 值 / 遇到的问题 / 偏离申请）——宁详勿略，模板同归档工单先例。

### 7.3 偏离处理协议

- **能停就停**：发现规范缺陷/歧义 → 先编辑 01 对应小节（附理由与日期）→ 日志注明 → 再实现；
- **来不及**：日志记「偏离申请」继续施工，验收方裁定后回写或返工；
- **禁止静默偏离**。

### 7.4 硬性禁止

- **旧数据破坏**（本工单核心红线）：v4 追加式演进纪律（01 §6 纪律 2）——旧数据必须可读、既有 v4 golden 字节不变、`DESIGN_VERSION` 不得擅动；
- **模型规范冻结**：不改块/树编码格式（01 §6 纪律 3）；
- tree-space / tree-space-derive 零新增第三方依赖；
- 领域无关（业务语义字面量禁入）；
- 不提交 `target/`、缓存、临时环境等副产物；
- 测试不设 timeout 中断，跑完看汇总。

### 7.5 代码风格

- `cargo fmt` 干净、workspace 零 warning（含 `--all-targets`）；
- 源码 doc 注释英文；测试命名 `<批次><N>_<主题>_<断言>` 风格（如 `p_io_2_*`）；
- 遵守仓库 AGENTS.md：一切命令经 pixi 环境。

### 9.3 阶段 1 — 统御（P-IO-7.1）✅ 已完成（2026-08-23 初步验收通过，见 03/04）

**目标**：把 `TbLibrary` 从硬绑 `ParquetDirLayout` 解耦为持有一个「统一数据界面」，并把块物化格式抽象为可插拔物化器。

**实现面（编译单位逐个）**：

- `src/layout/mod.rs`：新增 `TbLayout` trait——抽象 `TbLibrary` 用的 11 个方法（`metadata_lock`/`read_head`/`write_committed`/`read_commit`/`commit_path`/`tb_block_path`/`tb_tree_path`/`tb_ref_path`/`gc`/`root`/块对象读写），`ParquetDirLayout` 与 `SingleFile` 各自实现；
- `TbLibrary`：`layout: ParquetDirLayout` → 持 `Box<dyn TbLayout>` 或泛型 `L: TbLayout`（二选一，依 §7.5 命名风格定；倾向泛型以保单文件 mmap 零动态分派），公共 API 签名不变；
- 新增 `BlockMaterializer` trait：`encode(block) → physical` / `address(physical) → Digest` / `decode(physical) → Result<Block>`；
  - `IpcMaterializer`（默认）：`encode = enveloped canonical IPC`，`decode = envelope 内 Arrow 零拷贝`，`address = digest(b"tb-blob", ipc_bytes)`；
  - `ParquetMaterializer`（复用 `parquet_dir.rs` 的 `ArrowWriter`/`ParquetRecordBatchReaderBuilder`）：`encode = enveloped parquet bytes`，`decode = parquet → RecordBatch → 块重建`，`address = digest(b"tb-blob", parquet_bytes)`；仅 `ArrowTable`；
- 格式探测 helper：读对象开头数魔数字节，`ARROW1` → Ipc，`PAR1` → Parquet，分派对应物化器；
- 身份⊥地址落地：块写入统一经物化器 `encode` 后取地址；`block_ref_id` 仍用 canonical payload（物化无关公式，不动现状）；verify 读对象按探测选物化器 decode → 重算 canonical → 比对 `RefId`；
- 物化选择：布局配置默认物化器 + 块类型约束（`ArrowTable` 可 parquet，`Blob`/opaque 恒原生字节）；统一入口（不走逐块 API 参数）。

**交付物**：`TbLayout`/`BlockMaterializer` trait + 双实现 + 探测 + `TbLibrary` 解耦 + `ParquetDirLayout` 挂靠为 `TbLayout` 首例。

**测试义务**：

- `TbLibrary` 解耦后全量历史回归（P-IO-2..6 全部测试原样通过 = 解耦无行为变化）；
- 物化器单元：`IpcMaterializer` encode/decode/address roundtrip；`ParquetMaterializer` 对 `ArrowTable` roundtrip + address 与 IPC 不同；
- 格式探测：`ARROW1`/`PAR1` 分派正确；
- 身份⊥地址：同逻辑块经 IPC 与 parquet 物化 → 同 `RefId`、异 `address`；
- verify 经探测分派 decode 后身份比对正确。

**关闭标准**：四命令绿 + workspace 全绿；既有测试零回归；物化器/探测/身份分离断言绿。

### 9.5 阶段 3 — 单文件（P-IO-7.3）✅ 已完成（2026-08-23 初步验收通过，见 03/04）

**目标**：TB 对象打包进追加式单文件，强制 IPC 物化（连续 mmap），作为 `TbLayout` 第二种实现。

**实现面**：

- 复用 `single_file.rs` 的容器机制（header/trailer 链/append epoch/compaction GC 骨架）；
- **每 commit 一 epoch**：payload = 该 commit 新增对象（块增量 + 树字节 + 引用表 + commit 记录）+ **对象目录快照**（address → offset/length）；重开读最新 epoch 的目录 → 全部块对象 offset 定位 → 桶重建 + head commit；
- 对象去重：追加前查对象目录 `exists → skip`（对应扁平的文件名去重）；
- **强制 IPC**：单文件内块对象一律 `IpcMaterializer`，拒绝 parquet——物化选择 API 对单文件布局仅 IPC；
- GC：compaction repack——keep 窗口内可达对象（commit 链 → 树/引用表 → 块）重写进临时文件 + rename（对齐 §1.11.5 单文件语义，不逐对象删改）；
- committed 指针 = 尾部 trailer 链（v4 机制），无外部指针文件——真·单文件。

**交付物**：`TbLayout` 的 `SingleFile` 实现（接管 `TbLibrary` 的完整读写路径）。

**测试义务**：

- roundtrip：commit → open → verify/project 等价（与扁平行为一致）；
- epoch 追加正确：多次 commit 各成一 epoch，重开拿最新 head；
- 去重：同块多次引用只存一次；
- 强制 IPC：parquet 物化尝试在单文件布局下被拒；
- GC：窗口内引用保留，窗口外/孤儿对象 compaction 掉；
- 崩溃恢复：读取遇坏 trailer 回退上一 valid epoch（复用 single_file 恢复语义）。

**关闭标准**：四命令绿 + workspace 全绿；SingleFile roundtrip/verify/project 与扁平行为一致（对象字节相同、容器不同）；强制 IPC 断言绿。
