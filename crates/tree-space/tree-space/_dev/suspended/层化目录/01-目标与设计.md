# 层化目录：01 目标与设计

> **本工单状态：挂起（suspended）**。authority 已立、三关系已裁定，但**暂停施工**。挂起原因 / 解锁条件见 [`03-开发状态.md`](03-开发状态.md) 顶部登记。设计上游：管道工单 §1.11.8（`../树与桶管道/01-目标与设计.md`）——三关系裁定与「树中心布局」定位以该处为权威。

## 0. 背景与定位

树+桶模型有三种磁盘布局哲学（2026-08-23 定，管道工单 §1.11）：

| 布局 | 中心 | 本质 |
|---|---|---|
| **扁平**（P-IO-7.2，`FlatDir`） | 块中心 | content-addressed 平铺、去重；树由全局树字节 + 引用表重建 |
| **单文件**（P-IO-7.3） | 打包中心 | 对象打包进追加式单文件（每 commit 一 epoch），连续 mmap |
| **层化（本工单）** | **树中心** | **目录结构即树的物理真相**，块按树位置落文件 |

**引入动机**：兼容 `MassDataModule` 现有的「嵌套模块树」形式——人 / 外部工具 / 脚本可直接按树拓扑浏览目录（「目录即导航」），无需理解 tree-space 全局对象寻址。

**定位**：独立工单（不在 P-IO-7 实施）。层化「装成第三个布局」需重新裁定与扁平/单文件完全不同的语义（去重 / 身份 / 引用表去留），是独立的设计单元。

## 1. 目标：完全层化

**核心**：每一层目录都是**自包含的递归自描述单元**——

```text
<层目录>/
├── <本层 schema 文件>   # 特殊命名，Arrow IPC：本层子树结构（节点列表+叶子列表）
├── <节点子目录>/        # 子节点（子树）
├── <节点子目录>/…       # 递归
└── <块文件>             # 本层叶子数据块
```

- 每层目录存三样：**本层树 schema**（特殊命名、Arrow IPC）+ **节点**（子目录）+ **数据块**（文件）；
- 递归自描述：外部工具逐层读 schema 即可理解子树，无需理解 tree-space 全局格式；
- 完全层化 = 树的物理组织与逻辑拓扑**同构**。

## 2. 三关系裁定（2026-08-23 定，权威见管道工单 §1.11.8）

1. **去重**：层化**不追求跨树去重**——同一块被多路径引用 = 多份文件。理由：层化价值是「物理形态可浏览」，非存储效率；content-addressed 去重是扁平的职责。语义在这个工单内可接受「同一 RefId 多物理副本」。
2. **身份 / verify**：层化仍保一份**全局 canonical 树字节作身份锚**（`TreeId` 据此算）。每层 schema 只作**导航 / 局部读取的派生视图**，不参与身份。verify 口径不变（仍基于 canonical 树字节与块身份比对）。
   - 推论：层化布局内部有一个「隐藏的 canonical 锚」——它是物理层化的、但身份锚是 flat 的；需要本工单裁定这个锚放在哪（如根目录一个特殊文件，或复用扁平系统对象面）。
3. **引用表去留**：层化**不存 `tb-refs`**——「目录结构 + 每层 schema」已编码 `xpath → 块` 的完整映射；引用表是扁平布局为「在平铺对象上重建树」才派生的，层化树结构原生、引用表冗余。验证用每层 schema 反推叶集。

## 3. 设计空间（挂起态先立，实施时逐一展开）

1. **层 schema 文件的特殊命名**：避免与块文件名冲突的保留名（候选 `_schema.ipc`、`__schema__` 等）；Arrow IPC（canonical 一致）；内容结构（节点列表 / 叶子列表 / 顺序 / 每叶的 RefId + 相对路径）。
2. **每叶一文件的粒度与命名**：块按树路径命名（`/runs[0]/peaks` → 目录路径 + 文件名）；Index 步的表示（`runs/0/peaks`）；与 v4 `Name` 纪律（拒 `/ % 控制字节`）的衔接与转义。
3. **身份锚的放置**：全局 canonical 树字节作身份锚——放哪、何时写、与每层 schema 的同步关系；`TreeId` 与扁平/单文件布局的交叉兼容（同一逻辑树三种布局可否互转）。
4. **导航 / 局部读取 API**：层化是「树中心」，读取是「按目录走」；是否需要 `TbLayout` trait 之外的特殊导航接口。
5. **物化**：层化块文件是否支持双物化（IPC/parquet）——待定；当前倾向与扁平一致（IPC 默认，parquet 可选），但单文件那套「强制 IPC」不适用层化。
6. **GC**：树中心布局下去重的含义不同（多副本），GC 语义需与扁平（引用表单跳）重新对齐。
